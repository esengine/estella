# 青岚：脸部网格研究 v3

**状态：用户否决的造型失败稿。** 本目录保留原始网格、形态键和对照证据用于排查与回退，不应作为后续细化的已接受基础。见 [美术审查记录](review/art-review.json)。

问题不仅是缺少细节：眼眶过深、眼裂僵硬，额头到鼻梁以及鼻唇、下颌之间的体积关系不自然。三个称为“分区”的样条变形实际各自影响了几乎整个头部；例如鼻唇步骤移动了 4,287 / 4,350 个顶点。后续变形还让先前控制点偏离目标，最大约 11.9 毫米。此方法没有实现预期的局部编辑约束。

## 网格修改

基网格包含 4,350 个顶点、4,324 个四边面（8,648 个三角面等价量）。这些数量说明编辑规模，不表示美术质量。预览细分位于形态键之后，不改变保存的基网格编号。

| 形态键 | 本轮修改 |
| --- | --- |
| `01_Skull_Cheeks_Jaw` | 颅骨纵深、面颊宽度、耳位、下颌和下巴轮廓 |
| `02_Forehead_Orbit_Eyelids` | 额头深度、眼眶、内外眼角、上下眼睑 |
| `03_Nose_Philtrum_Lips` | 鼻梁与鼻尖、鼻翼、人中、唇峰、唇线和颏唇沟 |
| `04_Eyelid_Volume_Clearance` | 调整朝外的皮肤顶点，修正眼球穿出眼睑的问题 |

四个键同时为 1 是本轮版本；全部设为 0 可恢复上一版。可按区域调整键值或直接进入编辑模式改点。各区域的修正存在相互影响，改动之后仍需核对多个角度。

`source_vertex_id` 保留旧人物的原始顶点编号。`head-cage.json` 保存原始坐标和连接关系；`fitted-cage.json` 保存当前混合结果；`landmark-pins.json` 记录每个控制点的来源、目标、阶段结果及最终结果。控制点残差是几何记录，不能作为相似度评分。

## 对照方法

正面、近侧面与四分之三视图使用固定高度与相同正交尺度：592 × 828 像素，0.432 毫米/像素。参考的“侧面”仍能看到另一只眼睛，因此近侧面采用距正面约 75° 的估计角度；另有真正 90° 侧视检查纵深。四分之三视角约为 29°。这些是记录下来的工作假设，参考图不是经过相机标定的扫描数据。

`cage-*-wire.png` 的每根线都来自基网格中的真实边，显示时关闭细分。主工程中的 `Review_Actual_Cage_Edges` 默认关闭，避免混入普通渲染；查看网格线时应同步关闭头部的预览细分。

## 造型失败的可见表现

- 眼裂开合、内眼角厚度和上眼睑转折仍偏机械，尚未达到参考的柔和神态。
- 嘴唇厚度与唇峰过渡仍简化，尤其需要继续核对侧面的上、下唇关系。
- 面颊到鼻翼、嘴角、下颌的体积过渡仍偏平；下巴与颌下转折需要进一步雕刻。
- 额头和颅顶保留的是裸头结构，不能直接拿参考中头发的外轮廓作为头骨边界。

这些差异由当前灰模与叠加图可见，并已被用户明确指出。下一版需重新建立自然的基础头部体积、约束每次编辑的实际影响范围，并核对多角度造型；不能继续通过堆细分、材质或相机变化掩盖当前问题。

## 检查

已核对原始坐标、顶点编号、面连接关系及形态键混合结果，并运行 blender-skills 的 `shapekeys.run(report=True)` 与 `qa_check.run(profile='render')`。见 `review/shapekey-report.json`、`review/mesh-qa.json` 和 `review/verification.json`。

基网格检查没有错误、退化面、重复顶点、不一致法线、孤立顶点或多面共边。保留一圈 50 条边的颈部开口，全部位于原人物坐标的 z=1.435 米；“未落在地面”的提示在本头部研究中有意接受。未进行绑定、眨眼、口型、UV 制作或引擎验收，本次检查不覆盖这些环节。

## 来源和复现

人体基网格来自上一版保存的 MakeHuman / MPFB 核心 CC0 资产，详见上级 `provenance.json`。使用的 [blender-skills](https://github.com/EL4CTEO/blender-skills) 为 MIT 许可，版本 `71d031dab8bc6729504d11a78cbe91945401045f`。本次实际调用面部形态键与资产检查脚本，并遵循其后台建模约束。

使用 Blender 5.2.1 LTS 后台运行，没有桌面点击或 Sculpt Mode 操作。脚本依赖 Blender 自带 numpy，以及绘制检查图用的 matplotlib。可通过 `scripts/build.ps1` 的 `-SkillsRoot` 指定技能仓库，`-PlotModules` 指定可选的绘图库路径。构建顺序是提取原始头部、修改网格、渲染、检查与线框、绘制对照图；失败时构建立即停止。
