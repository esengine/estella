**Every editor tool calls one thing by one name.** An entity is `entity` in what a tool takes and in what it answers, a component field is `field`, search text is `query` and a cap on the answer is `limit`, across the MCP server's tools. Before this, `get_entity`, `select`, `set_parent` and six more took `id` where `get_inspector`, `set_field` and the running-game tools took `entity`, `set_field` took `key`, and `list_assets` took `match`; agents driving the editor carried one tool's name into the next: in twelve trial runs, 62 of the 69 calls the editor refused were exactly that. The older names are still read as the new ones, so existing scripts keep working. `get_scene_tree` and `search_entities` now answer each entity as `entity` rather than `id`; a script that read `.id` from them reads `.entity`. An `entity` argument also takes a name, looked up in the world the tool acts on (the running game for `inspect_entity`, the open scene for the rest), since the two number the same entity differently: `{ "entity": "Player" }` works in both. A name two entities share is refused with their numbers, and in the scene a path such as `"HUD/ScoreText"` picks one.
