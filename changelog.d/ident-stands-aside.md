**The engine's ident no longer holds a game back.** 0.107 made every target wait for the Estella ident to finish before the game started: playable ads and web pages waited 2.8 s before booting the rest of the game, and a mini-game drew the ident on the engine's own context and only handed it over once it was done. The game now loads and starts its first frames behind the ident, on every target. On a page the ident stays a layer over the canvas until its length has passed, counted from the page's start rather than from when the game's script arrived. On a mini-game, which has one GL context, the manifest is read and the engine is fetched and instantiated while the ident plays, and the engine takes the context the moment the ident ends; drawing the game underneath it on the same context lost that context on software rasterisers. `packaging.splash.ident: false` turns it off; a WeChat build that renders through EmscriptenGLX still does not carry it. Where the GPU is the CPU (SwiftShader, llvmpipe) a page's ident draws a quarter as often, and a page caps it at about 2 megapixels, so it does not take the processor from the boot it covers. The runtime sets `globalThis.__estellaIdentDone` once the ident has gone and the game is what is on screen (on a mini-game, once the game has drawn three frames after it). A build without the ident sets it at boot.

A web page's ident drew only from a worker, which a browser does not count as painting, so the page's first contentful paint waited for the game's first frame (8 s over a slow 4G link); the page now paints the ident's opening black itself and the worker draws the rest. A page opened with `?headless` kept its start screen over the game for the ident's length and swallowed the first clicks; it now goes when the game is ready.
