**A game server can keep what it holds across restarts, with `esengine/persist`.** `PersistStore` is a small asynchronous document store whose writes carry a version, so a stale copy is refused instead of overwriting a newer one; `MemoryStore` and `FileStore` ship with it, and a database is a four-method adapter. On top of it: `RecordBook` writes records with their schema version and migrates old ones forward; `snapshotEntity` and `restoreEntity` save and restore an entity's components the way a scene does; `PlayerPersistence` follows the players present (`track(playerIds)` each tick), loading arrivals, saving leavers and autosaving the rest, in order per player so a quick relog reads what was just written; and `WorldPersistence` restores every entity marked `Persistent` at boot and writes only the ones that changed. With replication's player identity, a player's pawn comes back where they left it after the server restarts. It all runs on the server; what a record holds and which database backs the store are the game's.
