section: Fixed
commits:
  - fix(assets): a shipped asset preloads through the loader that reads it - the addressable manifest names each asset by the runtime loader its .meta type ships to, so a font, an anim clip, a tilemap, a timeline or a state machine no longer ships as binary and finds no loader, and a name-published asset loads through its slot instead of throwing
  - fix(assets): only a name-published asset's typed load goes through its slot - acquireTyped keeps the slot lookup that lets a teardown stop a loader before it starts, and a plain loader is still reached without waiting a turn
---
**`Assets.preload` and `loadGroup` load every shipped asset through its own loader.** A build named most kinds of asset in its manifest as plain binary — fonts, animation clips, tilemaps, tilesets, timelines, state machines, behavior trees, script graphs, animator controllers, environments, probe volumes, avatars and meshes — so preloading one in a shipped game warned `no loader for type 'binary'` and loaded nothing, and `loadGroup` left a group's fonts behind. The manifest now names the loader that reads each asset, and a test holds every type an import can write to a loader the runtime registers. `loadStateMachine`, `loadBehaviorTree`, `loadAnimatorController` and `load()` of a clip, avatar or script graph threw "publishes by name"; they now load it. `getAddressableType`, `getAddressableTypeByEditorType` and `AssetTypeEntry.addressableType` are gone: nothing read them, and what they answered was not what a build ships. `AddressableAssetType` is now any loader's type.
