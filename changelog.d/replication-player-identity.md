**A replicated game can say who a player is, and a player who drops comes back to their own pawn.** Until now every connection was anonymous: a player whose socket dropped came back with a new connection id, and so a new pawn. Give `startServer` an `authenticate` that turns the client's `credentials` into a `playerId`, and connect with `Net.connect(socket, { credentials, reconnect: true })`: a player keeps one connection id for as long as the server remembers them, so `Replicated.owner`, `tickInputOf` and everything keyed by them carry over. A player who drops stays in the new `presentIds` for `reconnectGraceMs` (30 s by default), the client redials with backoff by itself, and the ghosts it already holds stay the same entities, updated to what they missed. A second login with the same player replaces the first, and `server.kick(id)` ends a session at once; the old client is told (`state` `'closed'`, `closeReason` `'replaced'` or `'kicked'`) and does not redial. What the credentials are is the game's. Without `authenticate` nothing changes. The replication protocol is now version 5, so a client and server must both be built from this release or later.
