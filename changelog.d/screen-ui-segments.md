**A screen UI split over several root Canvases rebuilds only the Canvas that changed.** The held screen overlay is now held per screen root Canvas: each root's controls, masks and labels are built into a list of their own and drawn in the roots' order, and a write, addition or removal under one root, a label laid out again there or a particle emitter beneath it rebuilds that root's list alone. A HUD with a ticking counter on one Canvas and a menu on another rebuilds the counter's. One root draws as before. A pass that cannot be split keeps the single held list: a screen effect, a skeleton or other script geometry on the screen, or roots whose draw order interleaves (a label with a `layer` of its own above another root's controls), in which case the pass is drawn as one list until the roots change. `render.overlay.segments` and `render.overlay.rebuiltLast` say how many lists the overlay has and how many the last change rebuilt.
