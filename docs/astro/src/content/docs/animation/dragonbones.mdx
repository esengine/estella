Estella plays [DragonBones](https://docs.egret.com/dragonbones) armatures: bones, meshes, slots and animations, drawn
by the same renderer as the rest of the scene. An armature is placed by the **`DragonBonesAnimation`** component (main
`esengine` package) and controlled at runtime through the **`DragonBones`** resource, exported from the
`esengine/dragonbones` subpath.

DragonBones runs on every target the engine supports: the editor viewport, Play, Web, playable ads, mini-games, and the
iOS and Android hosts.

<Aside type="note">
  The DragonBones runtime is **MIT licensed**. Shipping a game that uses it requires no separate license.
</Aside>

## Importing a project

A DragonBones export consists of three files, imported together as one asset type:

| File | Content |
|---|---|
| `<name>_ske.json` or `<name>.dbbin` | Skeleton: bones, slots, animations. |
| `<name>_tex.json` | Atlas: the position of each piece in the image. |
| `<name>_tex.png` | Atlas image. |

Copy the folder into the project. The skeleton and atlas JSON files are distinguished **by the `_ske` / `_tex` name
suffix**, not by extension.

The PNG is referenced only from inside the atlas, by its `imagePath` field. Packaging follows that reference, so the
image is included in builds without being referenced from a scene.

## The `DragonBonesAnimation` component

Create it with **+ Add → Create entity… → DragonBones**, or add the component to an existing entity.

![The DragonBonesAnimation component in the Details panel — asset slots for the skeleton and atlas, and Armature and Animation dropdowns filled from the file](@/assets/guides/en/dragonbones-inspector.png)

| Property | Type | Default | Description |
|---|---|---|---|
| `skeletonPath` | asset | `''` | Skeleton file (`_ske.json` or `.dbbin`). |
| `atlasPath` | asset | `''` | Atlas file (`_tex.json`). |
| `armature` | string | `''` | Armature within the file. Empty uses the first. |
| `animation` | string | `''` | Animation played on spawn. |
| `loop` | boolean | `true` | Loops the initial animation. |
| `playing` | boolean | `true` | Whether playback advances. |
| `fadeInTime` | number | `0` | Crossfade duration in seconds when the animation changes, including the first play. |
| `timeScale` | number | `1` | Per-entity playback speed (≥ 0). |
| `skeletonScale` | number | `1` | Uniform armature scale (≥ 0). |
| `flipX` / `flipY` | boolean | `false` | Mirrors horizontally / vertically. |
| `color` | Color | `{1,1,1,1}` | Tint (RGBA, 0–1), multiplied onto each slot's authored colour. |
| `layer` | number | `0` | Sorting layer; higher draws on top. |
| `material` | asset | none | Custom material. None uses the default batch shader. |
| `enabled` | boolean | `true` | Off freezes and hides the armature. |

### Editor behaviour

- **Asset slots.** `skeletonPath` and `atlasPath` are asset slots: pick from the popover, drag a file from the Content
  Browser, or use the slot's locate / clear actions. The scene stores them as `@uuid:` references, so moving or
  renaming the files keeps the link.
- **Live preview.** The armature is posed in the viewport in edit mode; changes to the animation, scale or flip are
  shown without entering Play.
- **Tint.** Because `color` multiplies the authored slot colours, opaque white (the default) leaves them unchanged, and
  clearing the field restores the original colours.

## Armature selection

A DragonBones file is a project that can contain several armatures; `armature` selects one.

Once `skeletonPath` is set, **Armature** and **Animation** become dropdowns populated from the file. The animation list
follows the selected armature, since armatures in the same file have separate animation lists. An empty `armature`
uses the first armature in the file.

<Aside type="note">
  A `.dbbin` skeleton does not populate the dropdowns; the fields remain text boxes. A typed name is still used at
  runtime.
</Aside>

## Playback and crossfades

DragonBones has no mix table on the skeleton. A crossfade is specified when an animation starts, as an argument to
`fadeIn`:

```typescript
import { defineSystem, Query, Res, DragonBonesAnimation } from 'esengine';
import { DragonBones } from 'esengine/dragonbones';

const control = defineSystem(
  [Query(DragonBonesAnimation), Res(DragonBones)],
  (q, dragonBones) => {
    // Null until the runtime has loaded; it is fetched on first use.
    if (!dragonBones) return;

    for (const [entity] of q) {
      dragonBones.fadeIn(entity, 'walk', 0.25, true);  // crossfade over 0.25 s
      dragonBones.setTimeScale(entity, 1.5);           // 1.5x speed
    }
  },
);
```

| Method | Description |
|---|---|
| `play(entity, name, loop?)` | Starts an animation immediately, without blending. |
| `fadeIn(entity, name, seconds, loop?)` | Crossfades into an animation. |
| `stop(entity, name?)` | Stops one animation, or all when `name` is omitted. |
| `setTimeScale(entity, scale)` | Per-entity playback speed. |
| `setColor(entity, r, g, b, a)` | Tints the armature (0–1), multiplied onto slot colours. |
| `setEnabled(entity, on)` | Removes the armature from the frame (frozen and hidden) or restores it. |
| `setEntityProps(entity, props)` | Sets `{ skeletonScale?, flipX?, flipY?, layer?, playing?, timeScale?, color? }` in one call. |

`loop` defaults to `true` in `play` and `fadeIn`.

### `playing` and `enabled`

| Setting | Pose | Drawn |
|---|---|---|
| `playing: false` | Frozen | Yes |
| `enabled: false` / `setEnabled(entity, false)` | Frozen | No |

`setEnabled` and the component's `enabled` field control the same switch. Writing the field (in the inspector or with
`world.set`) takes effect when written; `setEnabled` holds until the next such write. The Outliner visibility toggle
uses the same channel, so hiding an entity in the Outliner does not change its authored `enabled` value.

## Querying an armature

```typescript
const anims  = dragonBones.getAnimations(entity);  // string[]
const bounds = dragonBones.getBounds(entity);      // { x, y, width, height } | null
```

`getBounds` is computed from the armature's **posed** geometry, not from bounds recorded by the authoring tool, so it
follows the current pose.

## Shared skeletons

Entities that reference the same skeleton and atlas pair share **one parsed skeleton and one atlas texture**. The data
is unloaded when the last referencing entity is removed. No setting is required.

Per-entity properties remain per entity, so instances of a shared skeleton can be scaled, flipped and tinted
independently:

## Build output

The DragonBones runtime is included only when a packaged scene uses it. The editor determines this by scanning the
scenes being packaged; there is no setting.

| Target | Runtime delivery |
|---|---|
| Web / desktop | `dragonbones.wasm` beside the engine, fetched on first use. |
| Playable ad | Inlined into the single HTML file. |
| Mini-game | Copied into the package. |
| iOS / Android | Compiled into the app binary. |

## Best practices

- **Crossfade transitions** with `fadeIn` (0.15–0.3 s); `play` switches without blending. Set `fadeInTime` on the
  component so the first play also blends.
- **Share the skeleton and atlas pair** across entities; a group of identical characters costs one parse and one atlas.
- **Select the armature from the dropdown** rather than typing it; a name that does not exist in the file draws
  nothing.
- **Use `playing: false`** rather than disabling to hold a visible pose.
