title: Grip Pose
description: Hand posing and object holding for 3D rigs with finger bones — the GripPose component and its named poses, custom pose definitions, hand detection, and holding an object with GripHolder, GripProfile and GripSurface, including the editor's grip section.
---

**`GripPose`** holds a rig's hands in a named pose such as `pistol`, `handle` or `cup`. A pose specifies only how far
each finger bends, how far the fingers spread and what the thumb reaches for; it names no bones, so one pose fits any
rig with finger bones. The bend axes are derived from each rig's hand the first time it is held.

`GripPose` shapes the hand only. Placing the hand on an object is done by **`GripHolder`** and **`GripProfile`**
([Holding an object](#holding-an-object)), or by an entity under the hand joint plus two-bone IK for the arm.

All grip components and functions are exported from `esengine` and are marked experimental.

## The `GripPose` component

Add `GripPose` to the rig's root entity and name a pose for either hand:

```ts
import { GripPose } from 'esengine';

world.insert(hero, GripPose, { rightPose: 'pistol', leftPose: 'support' });

// Squeeze: the index finger moves from resting to pressing; nothing else moves.
world.update(hero, GripPose, (grip) => { grip.rightTrigger = 1; });
```

| Field | Type | Default | Description |
|---|---|---|---|
| `rightPose`, `leftPose` | string | `''` | Pose name for each hand. Empty fades the hand out and leaves it to other animation. |
| `rightWeight`, `leftWeight` | number | `1` | Weight of the pose over the fingers' clip animation (0–1). |
| `rightTrigger`, `leftTrigger` | number | `0` | Index finger position from resting (0) to pressing (1), in poses that define a trigger. |
| `blendSeconds` | number | `0.15` | Approximate duration of a pose change. The transition starts and ends at rest, with no jump. |
| `rightHand`, `leftHand` | string | `''` | Hand joint as a path from this entity. Empty finds the joint by name. Advanced. |

### Execution

- `GripPose` runs after the Animator, so clip animation continues to move the arm while the pose holds the fingers.
  It also works without an Animator.
- It runs during play, not in edit mode.

## Built-in poses

| Name | Hand shape |
|---|---|
| `open` | Flat, as the rig rests. |
| `relaxed` | Hanging at rest. |
| `fist` | Closed, thumb over the fingers. |
| `pistol` | Pistol grip, index finger along the frame. Defines `trigger`. |
| `support` | Under a rifle's foregrip. |
| `handle` | Hammer, sword or tool handle. |
| `pinch` | Thumb and index finger together. |
| `cup` | Around a mug or ball, fingers spread. |

`gripPoseNames()` lists the registered names; `gripPose(name)` returns a definition.

## Custom poses

`registerGripPose(name, def)` adds a pose or replaces one of the same name:

```ts
import { registerGripPose } from 'esengine';

registerGripPose('claw', {
    thumb: { opposition: 1, gap: 0.2 },
    index: { curl: 0.9, base: 0.2 },
    middle: { curl: 0.9, base: 0.2 },
    ring: { curl: 0.9, base: 0.2 },
    pinky: { curl: 0.9, base: 0.2 },
});
```

A `GripPoseDef` has `thumb`, `index`, `middle`, `ring` and `pinky`, and an optional `trigger` (the index finger at
`trigger` 1; without it, `trigger` has no effect).

### Finger values (`GripFinger`)

| Value | Description |
|---|---|
| `curl` | Bend of the finger, from 0 (rest pose) to 1 (closed). Required. |
| `base` | Bend of the first joint where it differs from the rest of the finger, e.g. a finger laid along a frame or hooked. Defaults to `curl`. |
| `spread` | Fan-out of the fingers, −1 to 1. |
| `bend` | Per-joint bend in degrees from the rest pose, knuckle first, e.g. `[30, 45, 20]`. Overrides `curl` and `base`. Written by the editor. |
| `fan` | Lean of this finger away from the middle of the hand, in degrees: index and middle toward the thumb, ring and little finger away. Overrides `spread`. |

### Thumb values (`GripThumb`)

| Value | Description |
|---|---|
| `opposition` | Travel from the thumb's rest position to its reach target, 0 to 1. Required. |
| `to` | Reach target: `fingers` (middle of the middle finger, as in a fist or handle; default) or `index` (index fingertip, as in a pinch). |
| `gap` | Distance short of the target at which the thumb stops, in index-finger lengths: the space taken by the held object. Default 0. |

The thumb has no per-joint bend values. Its tip is placed at a point on the palm side of the other fingers as they are
posed in that frame, and its two joints bend together to reach it, so it lies over the fingers in a fist and wraps a
grip. If the point is out of reach, as with flat fingers, the thumb points toward it.

`gripPoseByJoint(pose)` converts a pose to per-joint `bend` and `fan` values that reproduce the same hand, as a
starting point for editing single joints. `bend` and `fan` are measured on the hand's own axes rather than a bone's,
so a per-joint pose still fits any rig and either hand.

## Rig requirements

- **Hand joint.** Found by name: a joint named like `RightHand` or `hand_r`. Where the names do not match, set
  `rightHand` / `leftHand` to the joint's path.
- **Fingers.** Joints under the hand named `thumb`, `index`, `middle`, `ring`, and `pinky` or `little`. Palm bones such
  as `index_metacarpal_r` are skipped. A hand whose fingers are not named this way cannot be posed.
- **Missing fingers.** A rig with fewer fingers poses the ones it has and logs which are missing.

`gripPoseStatus(app, entity)` reports, per hand, the joint found, the number of finger joints, the missing fingers,
the current pose and weight, and the fingers touching a surface.

## Holding an object

Holding involves three parts:

| Part | Responsibility |
|---|---|
| `GripProfile`, on the object | Where each palm sits on the object (an anchor entity for the leading hand and one for the supporting hand) and the finger pose of each. |
| Arm | Brings the palm to the anchor: two-bone IK for shoulder, elbow and wrist, the elbow keeping the side the clip bends it to, the wrist turned to the anchor. |
| Fingers | Each finger's pose: a captured finger pose or a grip pose by name, blended over the clip as `slerp(clip, grip, weight)`. |

An **anchor** is any entity under the object, placed with the move and rotate gizmos. Its origin is the palm centre
(halfway from the hand joint to the middle knuckle), +Z is the direction the fingers point, and +Y is the direction the
palm faces.

```ts
import { GripHolder, GripPlacement, GripProfile } from 'esengine';

world.insert(rifle, GripProfile, { mainAnchor: gripAnchor, supportAnchor: foregripAnchor, mainPose: 'pistol', supportPose: 'support' });
world.insert(hero, GripHolder, { held: rifle, placement: GripPlacement.Object });
```
### `GripHolder`

On the rig's root.

| Field | Type | Default | Description |
|---|---|---|---|
| `held` | entity | none | The held object, an entity with a `GripProfile`. None releases it. |
| `mainHand` | `GripHand` | `Right` | Leading hand: `Right` or `Left`. |
| `placement` | `GripPlacement` | `Hand` | `Hand`: the object follows the leading hand as the clip moves it. `Object`: game code places the object (for example when aiming) and the leading arm is brought to it. |
| `weight` | number | `1` | Weight of the hold over the clip (0–1). |
| `supportWeight` | number | `1` | Weight of the supporting hand's hold, applied under `weight` (0–1). |
| `blendSeconds` | number | `0.2` | Approximate duration of taking hold, releasing, or changing the held object. Every joint eases from its previous pose, starting and ending at rest. |
| `rightHand`, `leftHand` | string | `''` | Hand joints as paths from this entity. Empty finds them by name. Advanced. |

### `GripProfile`

On the held object.

| Field | Type | Default | Description |
|---|---|---|---|
| `mainAnchor` | entity | none | Anchor of the leading palm. |
| `supportAnchor` | entity | none | Anchor of the supporting palm. None holds the object in one hand. |
| `mainPose`, `supportPose` | string | `'handle'`, `'support'` | Finger pose of each hand: a grip pose by name or a registered finger pose. |
| `mainFingers`, `supportFingers` | string | `''` | Per-joint finger pose as `GripPoseDef` JSON, written by the editor. Overrides the pose by name when set. Advanced. |
| `hand` | number | `0` (Right) | The hand the anchors were placed for. When the other hand leads, both anchors are mirrored. |
| `mirror` | `GripMirror` | `X` | The object's mirror plane: perpendicular to its X (YZ plane), Y (XZ) or Z (XY). |
| `wrap` | boolean | `true` | Closes the fingers onto the object's `GripSurface` shapes. Has no effect without surfaces. |

### Evaluation order

Holding runs after the Animator, in a fixed order every frame:

1. the clip's pose;
2. the object: on the leading hand (`Hand`), or where the game placed it with the leading arm bent to it (`Object`);
3. the supporting anchor, read from the object's current placement;
4. the supporting arm;
5. the fingers of both hands.

The object never reads the supporting hand, so no step depends on its own output. Each frame is solved from the clip's
pose, not from the previous result, and only the game clock is read: the same inputs and steps produce bit-identical
bones.

### Finger poses

`captureFingerPose(world, handJoint)` records the rotation of every named joint under a hand as plain JSON;
`registerFingerPose(name, pose)` registers it under a name a `GripProfile` can use. Pose the hand with a `GripPose`, a
clip or manually, capture it, and save the JSON with the game. A captured pose names the rig's bones and is therefore
specific to that rig; a grip pose by name fits any rig.

### Closing onto the object

A pose sets how far the fingers may close; **`GripSurface`** shapes define what they close onto. Add one to the object
or to any entity under it for each part a hand wraps: a cylinder or capsule for a handle or barrel, a sphere, or a box
for a block grip. Sizes are in the entity's own units, as for a collider.

| Field | Type | Default | Description |
|---|---|---|---|
| `shape` | `GripSurfaceShape` | `Cylinder` | `Cylinder`, `Capsule`, `Sphere` or `Box`. |
| `direction` | number | `1` (Y) | Axis of a cylinder or capsule: the entity's X, Y or Z. |
| `center` | vec3 | `(0, 0, 0)` | Centre of the shape, in the entity's units. |
| `radius` | number | `0.5` | Radius of a cylinder, capsule or sphere. |
| `height` | number | `1` | Full length of a cylinder or capsule, ends included. |
| `size` | vec3 | `(1, 1, 1)` | Size of a box. |

With `wrap` on:

- Each finger closes from open toward the pose's angles, all joints together. The first bone that meets a surface
  stops, together with every joint before it; the joints after it continue closing.
- The thumb approaches along its reach direction and stops where one of its bones meets a surface.
- A finger stops short of the shape by about its own thickness (8% of the index finger's length) and never closes
  beyond the pose; a finger the pose leaves open stays open.
- A bone that starts inside a surface (a handle pressed into the palm) may continue, but not deeper.
- Contact is a point-to-shape distance, a few hundred per hand. It uses no physics and no mesh, and is deterministic.

A `fist` with `wrap` on therefore closes every finger onto the handle regardless of its thickness, and a `pistol` keeps
the index finger along the frame.

### Mirroring for the other hand

Anchors are placed once, for the hand named by `hand`. When the other hand leads, both anchors are mirrored in the
object's `mirror` plane: positions are reflected and rotations converted to the other hand's palm. Poses by name and
per-joint poses describe a hand's shape rather than its bones, so they are mirrored too. Captured poses are not; they
name one hand's bones.

### Different body proportions

Anchors locate the palm, not the hand joint, and the arm is solved each frame from the body it belongs to, so bodies
with longer or shorter arms still put the palm on the anchor. Beyond reach, the arm points straight at the anchor and
the wrist still turns to it; the palm stops short, deterministically.

### Editor

Select an object with a `GripProfile`. Its section in the Details panel edits the grip, and a character holding the
object shows the grip in the viewport while it is edited, without entering Play.

| Control | Behaviour |
|---|---|
| **Preview** | Picks the character. A character without a `GripHolder` receives one, holding this object with `Object` placement, so it reaches for the object where it stands in the scene. The leading-hand switch sets the holder's `mainHand` to show the mirrored grip. A palm that cannot reach its anchor reports the remaining distance. |
| **Anchors** | Picks an anchor entity or creates one under the object. Select moves the selection to it for the move and rotate gizmos. The viewport draws each palm target, mirrored when the other hand leads: a frame for the palm, an arrow for the finger direction, a dashed line for the palm direction, and a stub on the thumb side; amber for the leading hand, blue for the supporting hand. |
| **Clip** | Picks a timeline; dragging the time or playing it poses the character in the viewport with the grip applied on top, as in Play. Only the viewport is posed; removing the clip, turning the preview off or leaving the section restores the pose. |
| **Fingers** | Starts from a grip pose; each joint's bend and each finger's lean can be changed in degrees. The first change writes the pose per joint into `mainFingers` or `supportFingers`; Reset returns to the pose by name. In the viewport, each finger joint of the previewing character has a handle (amber on the leading hand, blue on the supporting hand); dragging it bends that joint, one undo step per drag. |
| **Close onto surfaces** | The `wrap` switch, the fingers currently touching a surface, and the object's surfaces. Create adds a cylinder across the leading palm under its anchor, sized from the character's palm, to be fitted to the handle with the gizmos and fields. The viewport draws surfaces in green with the palms. |

The preview is controlled by **View → Preview FX**, the same switch spring bones use. It moves only the viewport's
bones and the held object, never the scene; turning it off restores them as the scene stores them.

## Limits

- **A `GripPose` alone does not make contact.** A pose is a shape: fingers can sink into a wide grip or stop short of a
  narrow one. Holding with a `GripHolder` and adding `GripSurface` shapes closes them onto the object.
- **Hand axes are computed once,** from the rig's pose when it is first held. A hand mid-animation at that moment has
  its axes taken from that pose; in practice the difference is small.
- **Negative scale on an arm is not supported.** A mirrored bone turns the wrong way.
- **Fingers close onto the surface shapes, not the mesh.** An irregular grip is approximated with several shapes.
- **The thumb has no viewport handle.** It is reached, not bent, and is set by its values. Captured poses are not
  editable in the section.
- **The editor plays a timeline, not an Animator state machine,** under the grip; the state machine runs in Play.
- **Arm solving is limited.** With `Hand` placement only the supporting arm is bent; with `Object` placement the
  leading arm is bent first, then the supporting arm. The shoulder and spine do not lean to extend reach.
- **One held object per holder.**
- **Validation.** The poses were tuned on a Mixamo-named character. The same hand built with other bone orientations
  and names produces the same fingertips, but no second real rig has been tested.
- **Not measured on a device.** The cost is a few quaternion operations for each of up to 30 joints per frame, and none
  once a hand has settled on a rig no clip moves.
