Estella plays [Spine](https://esotericsoftware.com/) skeletons: bones, meshes, IK, skins and events. A skeleton is placed
by the **`SpineAnimation`** component (main `esengine` package) and controlled at runtime through the **`Spine`**
resource; `Spine` and `SpineEvents` are exported from the `esengine/spine` subpath.

![The Spine demo example: a character with a gun, drawn from a Spine skeleton](@/assets/guides/en/play-spine.png)

*The `spine-demo` example: a skeleton played through the **SpineAnimation** component.*

## The `SpineAnimation` component

| Property | Type | Default | Description |
|---|---|---|---|
| `skeletonPath` | asset | `''` | Skeleton file (`.json` or `.skel`). |
| `atlasPath` | asset | `''` | Atlas file (`.atlas`). |
| `skin` | string | `''` | Active skin. Empty uses the default skin. |
| `animation` | string | `''` | Initial animation on track 0. |
| `loop` | boolean | `true` | Loops the initial animation. |
| `playing` | boolean | `true` | Whether playback advances. |
| `timeScale` | number | `1` | Per-entity playback speed (≥ 0). |
| `skeletonScale` | number | `1` | Uniform skeleton scale (≥ 0). |
| `flipX` / `flipY` | boolean | `false` | Mirrors horizontally / vertically. |
| `color` | Color | `{1,1,1,1}` | Tint (RGBA, 0–1). |
| `layer` | number | `0` | Sorting layer; higher draws on top. |
| `material` | asset | none | Custom material. None uses the default batch shader. |
| `enabled` | boolean | `true` | Off freezes and hides the skeleton. Same switch as `Spine.setEnabled` and the Outliner visibility toggle. |

### Editor behaviour

- **Asset slots.** `skeletonPath` and `atlasPath` are asset slots: pick from the popover, drag a file from the Content
  Browser, or use the slot's locate / clear actions. The scene stores them as `@uuid:` references, so moving or
  renaming the files keeps the link.
- **Skeleton formats.** The skeleton slot accepts `.skel` and `.json` skeletons. A `.json` skeleton is recognised by a
  marker inside the file and is listed in the pick popover beside `.skel` files.
- **Live preview.** The viewport poses the skeleton in edit mode and across Play/Stop.
- **Dropdowns.** Once the skeleton has loaded, `animation` and `skin` list the animations and skins it contains.

## Atlases

Spine `.atlas` files are used as exported:

- **Multi-page atlases** — each page texture loads with the atlas.
- **Premultiplied alpha** — a `pma: true` atlas header is honoured; no import setting is required.
- **Texture compression** — with **Compress textures** enabled at export, atlas pages are cooked to KTX2 and
  transcoded on the device like any other texture.
- **Page sampling** follows each image's texture import settings, including filter, wrap, sRGB and mipmaps.
  Standalone loads through `loadSpineAssets` use the same settings as scene loads.

## Playback and mixing

```typescript
import { defineSystem, Query, Res, SpineAnimation } from 'esengine';
import { Spine } from 'esengine/spine';

const control = defineSystem([Query(SpineAnimation), Res(Spine)], (q, spine) => {
  for (const [entity] of q) {
    spine.setAnimation(entity, 'run', true);            // track 0, looped
    spine.setDefaultMix(entity, 0.15);                  // default crossfade
    spine.setMixDuration(entity, 'idle', 'run', 0.25);  // one transition
    spine.setTrackAlpha(entity, 0, 1.0);                // track contribution
  }
});
```

| Method | Description |
|---|---|
| `setAnimation(entity, name, loop)` | Plays an animation on track 0. |
| `setDefaultMix(entity, seconds)` | Default crossfade between any two animations. |
| `setMixDuration(entity, from, to, seconds)` | Crossfade for one transition. |
| `setTrackAlpha(entity, track, alpha)` | Blend weight of a track (0–1). |
| `setEntityProps(entity, props)` | Sets `{ skeletonScale?, flipX?, flipY?, layer?, timeScale?, playing?, color? }` in one call. |
| `setEnabled(entity, on)` | Removes the skeleton from the frame (frozen and hidden) or restores it. |
| `setIKTarget(entity, constraint, x, y, mix)` | Aims an IK constraint at a world point; `mix` 0–1. Returns `false` if the constraint does not exist. |
| `listConstraints(entity)` | Constraint names as `{ ik, transform, path }` (string arrays), or `null`. |
| `getTransformConstraintMix` / `setTransformConstraintMix` | Reads / writes a transform constraint's mix. |
| `getPathConstraintMix` / `setPathConstraintMix` | Reads / writes a path constraint's mix. |

The default mix and per-transition mix durations are stored on the loaded skeleton data, not on the entity: they apply
to every entity that shares the skeleton.

## Skins and attachments

```typescript
spine.setSkin(entity, 'armored');
spine.setAttachment(entity, 'weapon-slot', 'sword');   // swap a slot's attachment
spine.setSlotColor(entity, 'body', 1, 0.5, 0.5, 1);    // r, g, b, a (0–1)
```

| Method | Description |
|---|---|
| `setSkin(entity, name)` | Switches the active skin. |
| `setAttachment(entity, slot, attachment)` | Replaces a slot's attachment. Returns `false` on failure. |
| `setSlotColor(entity, slot, r, g, b, a)` | Tints one slot (four channels, 0–1). Returns `false` on failure. |

## Querying a skeleton

```typescript
const anims  = spine.getAnimations(entity);   // string[]
const skins  = spine.getSkins(entity);        // string[]
const bounds = spine.getBounds(entity);       // { x, y, width, height } | null
```

## Spine in UI

An entity with `SpineAnimation` placed under a Canvas, with or without a `UINode`, is drawn in Canvas tree order like
the controls around it: a skeleton listed after a panel draws over it, one listed before draws under it. It also
follows the UI tree's rules:

- the `opacity` of UI nodes above it fades it;
- a hidden ancestor hides it;
- a `UIMask` above it clips it.

| Placement | Drawing |
|---|---|
| Under a screen-space Canvas, `layer` 0 | In the screen overlay, after every camera, in tree order. |
| Under a screen-space Canvas, `layer` ≠ 0 | In the screen overlay, sorted by its own `layer` against the whole UI instead of tree order. |
| Outside any Canvas | With the world, by `layer` and depth. |

DragonBones armatures under a screen-space Canvas are drawn in the overlay by the same rules.

## Events

The `SpineEvents` resource holds the track events of the current frame. Read it in the same frame:

```typescript
import { defineSystem, Res } from 'esengine';
import { SpineEvents } from 'esengine/spine';

const onSpine = defineSystem([Res(SpineEvents)], (spineEvents) => {
  for (const e of spineEvents.events) {
    // e.type: 'start' | 'interrupt' | 'end' | 'complete' | 'event'
    // e.entity, e.track, e.animationName; for 'event': e.eventName + values
  }
});
```

| `type` | Emitted when |
|---|---|
| `start` | An animation starts on a track. |
| `interrupt` | An animation is interrupted by another. |
| `end` | An animation is removed from a track. |
| `complete` | An animation completes a loop or playthrough. |
| `event` | An authored event keyframe fires. |

| Field | Type | Present for |
|---|---|---|
| `entity` | Entity | All events. |
| `type` | `SpineEventType` | All events. |
| `track` | number | All events. |
| `animationName` | string | All events. |
| `eventName` | string | `event` |
| `floatValue` / `intValue` / `stringValue` | number / number / string | `event` |

## Culling contracts and deferred world poses

Posing a skeleton consists of two steps:

| Step | Cost | When skipped |
|---|---|---|
| **Advance** the animation state | Low | Never. Skipping it would desynchronise playback and events. |
| **Resolve world transforms** | High | For entities no camera can draw, when both conditions below hold. |

World-pose resolution is skipped only when the asset has:

- **A culling contract** — a rectangle in skeleton space that no pose leaves. It is recorded on the asset by the
  author; nothing records it automatically.
- **Stateless world constraints** — reported by the loaded Spine runtime: the world pose carries no state between
  frames. It is not configurable.

Without either, the world pose is resolved every frame, whether the entity is visible or not.

### Recording a contract

Select the skeleton asset and use the **Fixed Culling Bounds** row in the Details panel.

| Action | Result |
|---|---|
| **Scan Animations** | Plays every animation over its full duration in every skin and shows the extent as **Observed Bounds**. |
| **Use as Fixed Culling Bounds** | Copies the observed bounds into the contract. |
| **Remove Fixed Bounds** | Writes a zero-area rectangle, which means "no contract". A newly imported asset carries one. |

Observed bounds are a measurement, not a guarantee: a blend of two animations is not the union of their extents,
game code can move bones beyond the exported animations, and extremes between two samples are not sampled. Pad the
observed bounds before accepting them.

<Aside type="caution">
  The contract must cover **every** pose, including poses driven by game code at runtime. A rectangle that is too
  small makes the character disappear near the screen edge; one that is too large only costs some work.
</Aside>

### Measured effect

1000 skeletons; time for pose, extract and submit:

| Visible | Posed every frame | With contracts |
|---|---|---|
| 1000 / 1000 | 3.39 ms | 3.36 ms |
| 200 / 1000 | 3.29 ms | 1.06 ms |
| 0 / 1000 | 3.26 ms | 0.49 ms |

With every skeleton visible, the cost is unchanged; only work whose result is not drawn is skipped.

## Diagnostics

`Spine` reports what a frame did and why each part was paid. Counting is off by default; while off, the cost is one
branch per entity.

```ts
import { Res } from 'esengine';
import { Spine, formatSpineDiagnostics } from 'esengine/spine';

// In a system taking Res(Spine) — once, then after any later frame:
spine.observe(true);
console.log(formatSpineDiagnostics(spine.diagnostics()));
```

```text
spine — frame 412, 1000 entities across 3 assets
  time      pose 2.31ms   readback 0.98ms   total 3.29ms
  world     400 resolved, 600 unresolved, 150 already current
  logical   1000 advances
  draw      350 extracted, 650 camera declines
  geometry  350 batches, 112000 vertices, 168000 indices
  bytes     3.4MB out of the modules, 3.4MB into the core
  crossings 1000 pose, 400 world, 350 batch data, 350 submit
  3.8       120 frames — total p50 3.28ms  p95 4.01ms  max 5.66ms

  hero.skel#gen1                  800  3.8  may defer
  boss.skel#gen1                  150  3.8  always resolves — no-certificate
  rope.skel#gen1                   50  4.2  always resolves — stateful-constraints

  * 150 entities across 1 asset (boss.skel#gen1) resolve a world pose every
    frame because nothing certified their extent. Scan the asset and record a
    culling contract to let them skip it while no camera wants them.
  * 50 entities across 1 asset (rope.skel#gen1) can never defer: their world
    pose carries state across frames, which no culling contract changes.
  * 600 world poses went unresolved — work this frame did not do.
```

| Line | Meaning |
|---|---|
| `world … unresolved` | World poses skipped this frame. Zero while entities are off screen means none were allowed to skip; the asset rows give the reason. |
| `always resolves — no-certificate` | The asset has no culling contract. Recording one allows deferral. |
| `always resolves — stateful-constraints` | The asset's world pose carries state between frames. A contract does not change this; such assets are listed separately in the findings. |
| `p50 / p95 / max` | Distribution over the preceding frames, for judging whether the reported frame is typical. |

`diagnostics()` returns the same report as data (`SpineSceneDiagnostics`) for a custom panel or overlay;
`formatSpineDiagnostics` renders it as text.

## Supported versions and licensing

Estella supports Spine **2.1, 3.8, 4.1, 4.2 and 4.3**. Each skeleton version loads its own WebAssembly backend on
demand, which is why `Spine` and `SpineEvents` are on the `esengine/spine` subpath. Spine 2.1 skeletons must be
exported as JSON; the 2.1 runtime has no reader for its binary format.

<Aside type="caution">
  The bundled Spine Runtimes are proprietary. Shipping a game that uses Spine requires a valid Spine license from
  Esoteric Software, separate from Estella's license.
</Aside>

## Best practices

- **Set a default mix** with `setDefaultMix` so transitions crossfade; use `setMixDuration` for specific transitions.
- **Layer with tracks** and `setTrackAlpha`, for example an aim overlay on track 1 over locomotion on track 0.
- **Share skeleton and atlas** across entities; entities referencing the same pair share one loaded skeleton.
- **Drive characters from the [Animator](/docs/animation/animator/)** state machine, which can target Spine as well as
  sprites.
- **Record a culling contract** on every skeleton used in quantity, so off-screen instances skip world-pose resolution.
