The `Localization` resource holds a translation catalog per locale, the active and fallback locales, and resolves
strings with `t()`. It does not use `Intl`, so results are identical on the web and on WeChat.

## Installing

`Localization` is opt-in. Install its plugin before any system reads `Res(Localization)`:

```typescript
import { localizationPlugin, LocalizationPlugin } from 'esengine';

app.addPlugin(localizationPlugin);
// or with options:
app.addPlugin(new LocalizationPlugin({
  locale: 'en',
  fallback: 'en',
  catalogs: { en: { play: 'Play' }, 'zh-CN': { play: '开始' } },
}));
```

| `LocalizationOptions` | Type | Default | Description |
|---|---|---|---|
| `locale` | string | `'en'` | Active locale. |
| `fallback` | string | `'en'` | Locale used when a key is missing in the active one. |
| `catalogs` | `Record<string, LocaleCatalog>` | — | Catalogs to register at startup, keyed by locale. |
| `tables` | string[] | — | `.eslocale` assets (paths or `@uuid:` refs) to load at startup through `Assets`. Requires the asset plugin. |

A scene that binds a `Text` to a key installs the plugin automatically ([Binding Text to keys](#binding-text-to-keys)).

## Catalogs and lookup

```typescript
import { defineSystem, Res, Localization } from 'esengine';

const setupI18n = defineSystem([Res(Localization)], (i18n) => {
  i18n.addCatalog('en',    { play: 'Play', score: 'Score: {n}' });
  i18n.addCatalog('zh-CN', { play: '开始', score: '得分:{n}' });

  i18n.setLocale('zh-CN');
  const label = i18n.t('score', { n: 42 });   // "得分:42"
});
```

- `addCatalog(locale, entries)` merges keys into a locale; later calls override earlier keys.
- `t(key, params?)` substitutes `{placeholder}` values. A key missing in the active locale is looked up in the fallback
  locale, then returned unchanged.

## Plurals

An entry can carry plural forms from the CLDR set `zero`, `one`, `two`, `few`, `many`, `other`. `t` selects a form from
the `count` parameter; a `zero` form is always used when `count === 0`. The default selector implements English rules
(`one` / `other`). For other languages register a selector with `setPluralSelector(locale, (count) => category)` that
returns one of the six categories.

```typescript
i18n.addCatalog('en', { apples: { one: '{count} apple', other: '{count} apples' } });
i18n.t('apples', { count: 3 });   // "3 apples"
```

## `Localization` API

| Member | Description |
|---|---|
| `addCatalog(locale, entries)` | Merge keys into a locale. |
| `t(key, params?)` | Look up and interpolate a string. |
| `setLocale(locale)` / `locale` | Set / read the active locale. |
| `setFallbackLocale(locale)` / `fallbackLocale` | Set / read the fallback locale. |
| `setPluralSelector(locale, selector)` | Register a plural rule for a locale. |
| `setPseudoLocalization(options \| null)` | Enable pseudo-localization (`expansion`, `accents`); `null` restores normal lookup. `@experimental`. |
| `availableLocales()` | Registered locales. |
| `has(key)` | Whether a key exists in the active or fallback locale. |

### Pseudo-localization

`setPseudoLocalization({ expansion: 0.35, accents: true })` lengthens and accents every translated string while
keeping placeholders, rich-text tags and line breaks intact, to test layouts against longer languages.
`setPseudoLocalization(null)` restores the real text.

## String tables (`.eslocale`)

An `.eslocale` asset holds the catalog of **one** locale, so a game loads only the languages it needs:

```json
// assets/i18n/zh-CN.eslocale
{
  "version": 1,
  "locale": "zh-CN",
  "entries": {
    "ui.title": "UI 控件",
    "apples": { "other": "{count} 个苹果" }
  }
}
```

Tables are loaded in one of three ways:

- `assets.loadLocaleTable(path)`, which requires the localization plugin and fails otherwise;
- `new LocalizationPlugin({ tables: ['assets/i18n/zh-CN.eslocale'] })`;
- automatically, by a scene with key-bound `Text` ([below](#binding-text-to-keys)).

The cook always ships `.eslocale` files, because they are addressed by key and no scene references them.

### Inspector

Create a table with **Content Browser → right-click → New Locale Table**. Selecting a table turns the Details panel into
its editor: key and text rows (with plural forms), the matching text from the project's other tables as a dimmed
reference, and a list of missing keys that can be added in one click. Each edit is saved immediately.

![A .eslocale string table in the inspector — keys with their values](@/assets/guides/en/localization.png)

### String Table editor

Double-clicking an `.eslocale` opens the **String Table** editor, which shows every language of the project side by
side: one row per key, one column per table, with untranslated cells marked, a filter, and commands to add and remove
keys. Each edit is written to that language's file at once. Plural entries are edited in the inspector.
- **Import** reads an Excel (`.xlsx`), CSV or XLIFF (`.xlf`) file and merges it into the tables by key.
- **Export** writes every language as one Excel or CSV sheet, or as XLIFF 1.2, and lists any problems found first.

## Binding Text to keys

Setting `Text.i18nKey` (the **I18n Key** field in the Details panel, which lists every key across the project's tables
with a translated preview) makes `content` derived: it is resolved again **every frame**, so `setLocale` or a table that
finishes loading later updates every bound label without code.

A scene that binds any key:

- installs the localization plugin when it loads, if the game has not installed it;
- loads every shipped table;
- starts in the **player's system language** when a matching table ships. A game that installs the plugin itself or
  calls `setLocale` is never overridden.

Dynamic labels (`Score: 42`) stay code-driven: a label whose content code rewrites must not carry a key. Call
`t('score', { n })` in the system that owns the label.

## Guidelines

- Resolve every user-facing string through `t()` or `i18nKey`.
- Interpolate (`'Score: {n}'`) rather than concatenate, so word order can differ per language.
- Set a fallback locale so a missing translation falls back to another language rather than to the key.
- Keep one `.eslocale` per language in one folder (`assets/i18n/`), with identical keys.
