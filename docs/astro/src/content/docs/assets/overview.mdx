Every asset in a project has a stable UUID. Scenes and prefabs reference assets by UUID; at build time the **cook**
ships the assets the game reaches; at run time the **manifest** resolves references to files, the typed **loaders** of
the `Assets` resource turn a reference into a handle, and **reference counting** frees what is no longer held
([Lifetime & Memory](/docs/assets/memory/)).

## Referencing assets

Code references an asset by its **project-relative path**. The path is relative to the **project root**, not to the
assets folder, so it starts with `assets/`, as the Content Browser shows it and as the cook's manifest keys it:

```typescript
const tex = await assets.loadTexture('assets/textures/player.png');
```

A ref without the root folder (`'textures/player.png'`) is resolved against the project root, is not found and fails
the load with a 404.

The editor serializes references in scenes and prefabs as a **UUID ref** (`@uuid:<uuid>`), which survives renaming or
moving the file. Every loader accepts both forms and resolves them to the same path. `resolveRef(ref)` returns the
resolved path for either form. UUID refs are written by the editor and are not authored by hand.

## Excluding folders

The editor writes a `.meta` sidecar for every file under the project. Folders that hold no content (source art,
documentation, a server) are excluded with `assetExclude` in `project.esproject`: the asset database does not index
them, writes no `.meta` into them and does not watch them.

```json
{ "assetExclude": ["art", "docs", "server"] }
```

Entries are folders relative to the project root; everything under an entry is excluded.

## Loading by type

The `Assets` resource has a typed loader per asset type. Each returns a handle or id that a component field takes:

```typescript
import { defineSystem, Query, Mut, Res, Sprite, Assets } from 'esengine';

const loadArt = defineSystem([Query(Mut(Sprite)), Res(Assets)], async (q, assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');   // { handle, width, height }
  for (const [entity, sprite] of q) {
    sprite.texture = tex.handle;
  }
});
```

| Loader | Returns |
|---|---|
| `loadTexture(ref)` | `{ handle, width, height }` ([Textures](/docs/assets/textures/)) |
| `loadAudio(ref)` | `{ bufferId }` |
| `loadFont(ref)` | `{ handle, family? }` (`family` for outline fonts) |
| `loadMaterial(ref)` | `{ handle, shaderHandle }` |
| `loadSpine(skeletonRef, atlasRef?)` | `{ skelData, atlasText, isBinary, textures }`: the prepared skeleton and atlas the `Spine` component draws from |
| `loadTilemap(ref)` / `loadTileset(ref)` | `{ sourceId }` / `{ tilesetId }` |
| `loadTimeline(ref)` | `{ timelineId }` |
| `loadAnimClip(ref)` | `{ clipId }` |
| `loadAnimatorController(ref)` | `{ controllerId }` |
| `loadStateMachine(ref)` / `loadBehaviorTree(ref)` | `{ fsmId }` / `{ btId }` |
| `loadLocaleTable(ref)` | `{ locale, keyCount }` ([Localization](/docs/assets/localization/)) |
| `loadPrefab(ref)` | `{ data }` |
| `loadJson<T>(ref)` | `{ data: T }` |

`load<T>(type, ref)` is the generic form for a type chosen at run time, and `register(loader)` adds a loader for a
custom asset type.

## Data assets

A `.json` file that is not a Spine skeleton or a DragonBones pair is a **data asset**: game tables, tuning values,
dialogue. It is loaded with `loadJson`:

```typescript
const { data } = await assets.loadJson<LevelTable>('assets/data/levels.json');
```

`T` is not validated; the result has the guarantees of `JSON.parse` only.

A data asset has a UUID, is parsed once and reference-counted, can be placed in a lazy
[group](#addressable-groups-lazy-loading) or served from a CDN, and can be replaced by
[hot update](/docs/publishing/hot-update/). A direct `fetch` of the project path has none of these properties, and it
works in the editor (which serves the whole project) but fails in a build, which contains only shipped assets.

Data assets are always shipped, whether or not anything references them
([Shipping what only code names](#shipping-what-only-code-names)). Project configuration files (`package.json`,
`tsconfig.json` and similar) are never assets.

## The manifest

The runtime resolves `@uuid:` references to file paths through a manifest produced by the cook:

```typescript
assets.setManifest(manifest);   // normally done by the runtime
```

`getManifest()` returns the active manifest. A ref that is not in the manifest falls back to a direct path lookup.

## Addressable groups (lazy loading)

Assets under a `subpackages/<name>/…` folder form the lazy group `<name>`; all other assets belong to the eagerly
loaded `main` group. `loadGroup` downloads a group (on WeChat through `wx.loadSubpackage`; on the web the download step
is a no-op) and then loads its assets, reporting progress:

```typescript
const bundle = await assets.loadGroup('level2', (loaded, total) => {
  console.log(`${loaded}/${total}`);
});

// When the area the group backs is left:
assets.releaseGroup('level2');
```

`releaseGroup` releases every asset the group acquired through its type's release path. Reference counting decides
the result: an asset another scene or group still holds stays loaded; an asset no one holds moves to the evictable warm
cache ([Lifetime & Memory](/docs/assets/memory/#warm-cache)), from which a later load revives it without a download.

`loadByLabel(...)` loads the assets tagged with a label instead of a folder group. Groups map onto
[WeChat subpackages](/docs/publishing/wechat/).

### Preloading a list

`preload` loads an explicit list of refs that is neither a group nor a label, such as the next area's assets. It infers
each asset's type (from the manifest, then the file extension) and loads through the typed loaders with bounded
concurrency:

```typescript
const { failed } = await assets.preload(
  ['assets/textures/boss.png', 'assets/audio/boss-theme.mp3', 'assets/maps/arena.estilemap'],
  (loaded, total) => console.log(`${loaded}/${total}`),
);
```

`preload` never rejects. Refs whose type cannot be inferred or whose load fails are returned in `failed`. Later loads
of the same refs are served from the caches.

## Cooking, compression & content addressing

At build time the **cook** walks the dependency graph from every scene in the build (the Package dialog's **Scenes in
build** list), excludes everything unreachable, stages the reachable files and writes the manifest. The cook also:

- **Compresses textures.** PNG sources are encoded to **KTX2** (Basis Universal) with their mip chain; the runtime
  transcodes to the best format the device supports (ASTC, then ETC2, then S3TC, falling back to RGBA8). Each texture's
  **Compression** import setting decides whether it is encoded ([Textures](/docs/assets/textures/#import-settings));
  the Package dialog only chooses whether those settings are applied.
- **Content-addresses files.** Each shipped file is named by a hash of its bytes, so URLs are immutable and identical
  files are stored once. On by default for Web and Desktop. The hash is computed on the staged bytes (after KTX2
  encoding), so it identifies the shipped file.
- **Packs auto-atlases** (opt-in build option). Loose PNGs in a `<name>.atlas/` folder are packed into atlas pages and
  the frame UVs are written into the manifest, so the sprites ship as one texture and batch into one draw call.

![The Inspector's Platform Overrides strip — a tab per platform, Android selected with Max Size, Compress and Format](@/assets/guides/en/import-platform-overrides.png)

*A texture's **Platform Overrides**: one tab per target. A platform with no override uses the Default settings.*

### Shipping what only code names

Reachability starts at the scenes and also reads the project's scripts:

- A string literal that is an asset's full path (`'assets/ui/coin.png'`) or an `@uuid:` ref ships that asset.
- A template literal that builds paths inside a folder (`` `assets/sfx/${name}.wav` ``) ships the whole folder and
  produces a build warning.

Paths assembled from separate pieces, names read from data and textures named in rich-text markup are not visible to
the cook and are excluded. The editor serves the project directly from disk, so such an asset is missing only in a
build; a shipped game logs which file it requested and why it is absent.

For these folders, right-click the folder in the **Content Browser** and choose **Delivery → Always include in
builds**. The setting is stored in `.esengine/asset-groups.json`, next to the folder's delivery mode (local,
subpackage or remote), and is off by default:

![The Content Browser folder menu — Delivery, with Local / Subpackage / Remote and Always include in builds](@/assets/guides/en/hot-update-delivery-menu.png)

*Right-click a folder → **Delivery**. The three modes set where an asset ships from; **Always include in builds** sets
whether it ships regardless of reachability.*

```json
{
  "version": "1.0",
  "groups": {
    "markup-images": {
      "folder": "assets/textures",
      "mode": "local",
      "alwaysInclude": true
    }
  }
}
```

<Aside type="note">
  Assets under `subpackages/` are always included, even when unreachable. **Locale tables** (`Text` carries keys, not
  paths) and **data assets** are also always shipped, because no scene can reference them.
</Aside>

## Guidelines

- Reference assets by path in code; UUID refs are written by the editor.
- Load groups (`loadGroup` / `loadByLabel`) or lists (`preload`) at level boundaries so play does not wait on a load.
- Place on-demand content under `subpackages/<name>/` so it forms a lazy group and, on WeChat, a subpackage.
- Mark folders that code loads by computed name as **Always include in builds**.
