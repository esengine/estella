A texture is an image on the GPU. It is referenced by project path, loaded into a **handle**, and assigned to a
component field: `Sprite.texture`, a material sampler, a bitmap font page. For the component that draws a texture see
[Sprites](/docs/graphics/sprites/overview/); for references, groups and the manifest see
[Assets](/docs/assets/overview/).

## Supported formats

| Extension | Notes |
|---|---|
| `.png` | Default for art with transparency. |
| `.jpg` / `.jpeg` | No alpha channel; smaller for photographic art. |
| `.webp` | Alpha and lossy or lossless compression; decoded by the browser or runtime. |
| `.gif` | First frame only; loaded as a still image. |
| `.bmp` | Uncompressed. |
| `.ktx2` | Basis Universal, GPU-compressed. The format the cook produces; can also be authored directly. |
| `.esimage` | A [texture recipe](#texture-recipes), drawn on the device. |

An `.aseprite` / `.ase` file is not a texture: importing it produces a sheet `.png` and a clip per tag, and scenes
reference those ([Sprite Animation](/docs/animation/sprite-animation/#aseprite-import)).

## Loading a texture

`assets.loadTexture(ref)` resolves the ref, uploads the image and returns the handle with the image's pixel
dimensions:

```typescript
import { defineSystem, Res, Assets } from 'esengine';

const measure = defineSystem([Res(Assets)], async (assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');
  tex.handle;   // TextureHandle, the value a component field takes
  tex.width;    // source image width in pixels
  tex.height;   // source image height in pixels
});
```

`width` and `height` are the source image's pixels. They are independent of `Sprite.size`, which is in world units.
To draw a sprite at one world unit per image pixel:

```typescript
import { defineSystem, Query, Mut, Res, Sprite, Assets } from 'esengine';

const showArt = defineSystem([Query(Mut(Sprite)), Res(Assets)], async (q, assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');
  for (const [entity, sprite] of q) {
    sprite.texture = tex.handle;
    sprite.size = { x: tex.width, y: tex.height };
  }
});
```

<Aside type="note">
  `loadTexture` is cached and reference-counted by resolved path: loading the same image twice returns the same handle
  and uploads once. Release with `assets.releaseTexture(ref)`, which takes the **ref that was loaded**, not the handle.
  Textures a scene references are released with the scene
  ([Lifetime & Memory](/docs/assets/memory/#reference-counting)).
</Aside>

`loadTextureRaw(ref)` uploads the image **without the vertical flip** that `loadTexture` applies. The flipped and
unflipped uploads are separate GPU objects and are cached separately. Use it only for a pipeline that expects bottom-up
rows.

### From a handle you did not load

A sprite placed in the editor receives its texture from the scene loader. To read the dimensions of such a handle, use
`getTextureDimensions`:

```typescript
import { defineSystem, Query, Sprite } from 'esengine';
import { getTextureDimensions } from 'esengine/tilemap';

const measurePlaced = defineSystem([Query(Sprite)], (q) => {
  for (const [entity, sprite] of q) {
    const dims = getTextureDimensions(sprite.texture);   // { width, height } | null
    if (dims) { /* … */ }
  }
});
```

It returns `null` until the texture is uploaded. Scene textures load asynchronously, so a system running on the first
frame can receive `null`.

<Aside type="caution">
  `getTextureDimensions` is **`@experimental`**: it may change or be removed in any release
  ([API Stability](/docs/reference/api-stability/)). The `{ width, height }` returned by `loadTexture` is the stable way
  to read an image's size.
</Aside>

## Import settings

Import settings belong to the **image** and apply to every entity that uses it. They are stored in the image's
`.meta` file and edited by selecting the image in the Content Browser.

{/* SHOT: assets-texture-import-settings | sprite-rendering example: assets/textures/ship_K.png selected in the Content Browser; the Details panel shows its Import Settings with advanced fields expanded (Use, Max Size, Compression, Mip Maps, Filter, Wrap, sRGB Color, Alpha Is Transparency, 9-Slice and Sheet categories) */}

| Setting | Key | Default | Description |
|---|---|---|---|
| **Use** | `use` | `Colour` | **Colour**: a picture; a build may shrink it to Max Size, compress it and fill the colour under clear texels. **Data**: numbers per texel (heightmap, measured mask, lookup table); a build keeps its bit depth (16-bit PNG stays 16-bit), never compresses it or decodes it as sRGB, and shrinks it only to an explicit Max Size. See [Data textures](#data-textures). |
| **Max Size** | `maxSize` | `Source size` | Cap on the longest side, applied at cook: 256, 512, 1024, 2048, 4096 or 8192. A larger source is box-filtered down; a smaller one is untouched. **Source size** never shrinks the image. |
| **Compression** | `compress` | `Auto` | **GPU compressed**: ships KTX2 (Basis Universal), which stays compressed in video memory (about a quarter of the decoded size) and is transcoded per device. **Original image**: ships the file unchanged; exact, often smaller to download for flat art, decoded in full on the GPU. **Auto**: GPU compressed for a texture a mesh draws (directly or through its material), original image for sprites and UI. See [Compression and the Build dialog](#compression-and-the-build-dialog). |
| **Compress Format** | `compressFormat` | `uastc` | `uastc`: high quality, larger. `etc1s`: much smaller, lower quality, suited to photographic art. Used only when the texture is GPU compressed. |
| **Mip Maps** | `mipmaps` | on | Keeps a chain of half-size copies so a texture drawn small samples a filtered image. Costs one third more memory. Turn off for pixel art and UI drawn at native size. |
| **Filter** | `filterMode` | `linear` | `nearest` keeps texels sharp; `linear` interpolates. |
| **Wrap** | `wrapMode` | `repeat` | Addressing of UVs outside `[0,1]`: `repeat`, `clamp`, `mirror`. |
| **sRGB Color** | `sRGB` | on | The image stores sRGB-encoded colour (albedo, UI). Turn off for linear data such as normal maps and masks. Only meaningful when the project renders in linear colour. |
| **Alpha Is Transparency** | `alphaIsTransparency` | on | When the texture is cooked (for a build and for the editor), fully clear texels take the colour of their opaque neighbours, so filtering and mip maps do not darken transparent edges. Partly clear and opaque texels keep their colour; premultiplied art is left unchanged. Turn off when a shader reads RGB under alpha 0 as data. |
| **Mip Coverage Cutoff** | `mipCoverage` | `0` | For cutout art (leaves, grass, fences): the alpha cutoff the material tests. Each mip level keeps the full image's share of texels above the cutoff, so the cutout does not thin out with distance. `0` disables it. Range 0–1; applies to UASTC-compressed textures. |
| **Border Left / Right / Top / Bottom** | `sliceBorder.*` | `0` | 9-slice border in **texture pixels**. Inherited by every `UIVisual` in `NineSlice` mode that uses the texture ([Images](/docs/ui/images/#nineslice)). |
| **Cell Width / Cell Height** | `sheet.cellWidth` / `sheet.cellHeight` | `0` | Size of one sprite-sheet cell in pixels. `0` means the image is not a sheet; a non-zero value lets a `Sprite` select one cell as its frame. |
| **Margin** | `sheet.margin` | `0` | Padding before the first cell, on both axes. |
| **Spacing** | `sheet.spacing` | `0` | Gap between neighbouring cells; not applied after the last cell. |

<Aside type="tip">
  For pixel art, set **Filter** to `nearest`, turn **Mip Maps** off and keep **Compression** at **Original image**
  (Auto already ships sprites this way). Linear filtering blurs the authored pixels, and block compression introduces
  artefacts at hard colour edges.
</Aside>

### Compression and the Build dialog

The **Compression** setting is applied only when the Build dialog's **Textures by import settings** option is enabled
(off by default). A build applies the setting as written; it never substitutes one result for the other based on file
size. The editor viewport follows the same option: with it enabled, textures are drawn compressed; otherwise they are
drawn from the source image.

### Data textures

A PNG with 16 bits per sample is imported with **Use: Data**. Assigning a texture to a field that reads texels as
numbers marks it as Data: `Terrain.heightmap`, `splatmap`, `splatmap2` and `occlusionMap`, and `Foliage.densityMap` and
`scaleMap`. **Project Health** lists textures that are read as numbers but imported as Colour and offers a one-click fix.

### Editing several images

With several images selected (Ctrl/Cmd-click, Shift-click or Select All) the inspector edits all of them. A setting
whose value is shared shows that value; a setting whose values differ shows a dash, and entering a value applies it to
every selected image. Saving writes only the settings that were changed. Sprites and textures share a schema and can be
edited together; a selection that includes an audio clip or a model has no common fields and the inspector reports
that. The 9-slice border editor requires a single selection.

### Per-platform overrides

**Max Size**, **Compression** and **Compress Format** can be overridden per platform in the tabs next to **Default**
in Import Settings. One source can ship, for example, as a 2048 UASTC texture on desktop and a 1024 ETC1S texture on
WeChat. A platform without an override uses the Default values
([Cooking, compression & content addressing](/docs/assets/overview/#cooking-compression--content-addressing)).

## Sizing a sprite to its texture

`Sprite.size` is in world units and independent of the image. The editor initialises it from the image:

- **Dragging an image** from the Content Browser into the viewport creates a sprite sized to the image's pixels.
- **Assigning a texture** to an existing sprite resizes it to that texture, and later texture changes follow the new
  image.

Once `size` is edited by hand, texture changes no longer resize the sprite. The undo history records the resize as a
separate **Fit Sprite To Texture** step, so it can be undone while keeping the texture change.

In code, a `Sprite` given only a texture keeps its default `size`; set it from `tex.width` and `tex.height` as shown
above.

## Sub-rectangles and atlases

A sprite draws part of a texture with `uvOffset` and `uvScale`, both normalized to the whole image:

```typescript
// The 32×32 frame at column 2, row 1 of a 256×256 sheet.
sprite.uvOffset = { x: 64 / 256, y: 32 / 256 };
sprite.uvScale  = { x: 32 / 256, y: 32 / 256 };
```

For sheet animation, author a flipbook instead ([Sprite Animation](/docs/animation/sprite-animation/)). For tile art,
see [Tilesets](/docs/world/tilemaps/tilesets/).

## Texture recipes

An **`.esimage`** file is the source of a picture: layers of shapes, gradients, noise and grids, the file the image tools
write and render a `.png` from. Naming the `.esimage` itself where a texture is expected (a sprite, a material) ships the
source instead of the pixels; the picture is drawn on the device when the texture is first loaded, to the same pixels as
its `.png`.

```json
{ "type": "Sprite", "data": { "texture": "assets/tex/plate.esimage", "size": { "x": 512, "y": 512 } } }
```

- **Module.** Recipes are drawn by the `esengine/image` module. An export includes it when a recipe ships; a script that
  loads a recipe from code imports it at startup. A package with no recipe does not include it.
- **Cost and caching.** A recipe is drawn on a worker thread, so the game keeps running while it draws. The pixels are
  stored uncompressed in the device's content cache, and later runs read them instead of drawing. Cached pixels are not
  removed automatically: `assets.cleanDiskCache(budgetBytes, true)` removes the least recently read entries first, and
  a removed picture is drawn again on next use. Without workers the recipe is drawn on the main thread; without a cache
  it is drawn on every run. A changed recipe or raster is a different cache entry.
- **Readers.** A recipe is accepted wherever an image is: as a texture, and by fields that read an image as numbers (a
  terrain's layers and splatmap, a foliage field's density and scale maps).
- **Dependencies.** A recipe may name images it places (an `image` layer's `src`: a PNG or another recipe) and font
  files its text uses. They ship with the recipe, and a change to any of them redraws it.
- **Text** is set with the device's 2D canvas, on the worker where available. A `font` that is a project file is drawn
  with that file's glyphs everywhere; a family name, or none, uses the device's fonts, so output can differ between
  devices. Hosts without a 2D canvas (the native hosts) reject a recipe with text and report that it must be baked.
- **Figure layers** are posed and flattened on the device by the same code that draws them in the editor.

### Surface maps

A recipe with a `material` describes a surface as well as a colour. Each surface map is a separate texture and
therefore a separate `.esimage` that names its picture:

```json
{ "mapOf": "assets/tex/wall.esimage", "map": "normal" }
```

`map` is `normal` or `surface` (roughness in green, metalness in blue; a single pixel when both are constant). Give the
map file **Use: Data** and assign it where the map goes. The picture it maps ships with it. The editor's image tools
write both map files next to a picture that has a `material` (`wall_normal.esimage`, `wall_surface.esimage`), already
set to Data.
