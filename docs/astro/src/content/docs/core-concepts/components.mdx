A **component** is a plain data struct attached to an entity. `defineComponent(name, defaults, metadata?)` declares
one:

```typescript
import { defineComponent } from 'esengine';

const Speed = defineComponent('Speed', { value: 200 });
const Health = defineComponent('Health', { current: 100, max: 100 });
```

The defaults define the component's fields, their types and the initial values of a new instance. Components hold
data only; behaviour belongs in [systems](/docs/core-concepts/systems/). The name is the component's identity: it is
what scenes serialize and what [hot reload](/docs/scripting/script-modules/#hot-reload) matches on.

## Field types

A field's type is inferred from its default value. Structured values receive matching editor controls:

| Default value | Type | Details control |
|---|---|---|
| `400` | number | Number field |
| `true` | boolean | Checkbox |
| `''` | string | Text field |
| `{ x: 0, y: 0 }` | vector | X/Y fields |
| `{ r: 1, g: 1, b: 1, a: 1 }` | colour | Colour picker |

```typescript
const Missile = defineComponent('Missile', {
  speed: 400,
  homing: true,
  targetTag: '',
  velocity: { x: 0, y: 0 },
  tint: { r: 1, g: 1, b: 1, a: 1 },
});
```

## Tags

A **tag** is a component with no fields, used only for filtering (`Player`, `Enemy`, `Frozen`). `defineTag(name)`
declares one; queries require or exclude it with `.with()` and `.without()`:

```typescript
import { defineTag, defineSystem, Query, Mut, Transform } from 'esengine';

const Player = defineTag('Player');
const Frozen = defineTag('Frozen');

defineSystem([Query(Mut(Transform)).with(Player).without(Frozen)], (q) => { /* … */ });
```

## Field metadata

The third argument of `defineComponent` controls how fields are presented in the **Details** panel. `fields` maps a
field name to its presentation:

```typescript
const Turret = defineComponent('Turret', {
  range: 300,
  mode: 0,
}, {
  fields: {
    range: { min: 0, max: 1000, slider: true, unit: 'px' },
    mode: { enum: [{ label: 'Idle', value: 0 }, { label: 'Attack', value: 1 }] },
  },
});
```

| Option | Type | Description |
|---|---|---|
| `min` / `max` | number | Hard range; clamps typed entry and drag-scrub. |
| `step` | number | Scrub and arrow-key granularity. |
| `slider` | boolean | Renders the number as a slider. Requires finite `min` and `max`. |
| `unit` | string | Unit shown after the value (`'px'`, `'°'`, `'%'`). |
| `enum` | `{ label, value }[]` | Dropdown; stores the selected option's integer value. |
| `flags` | `{ label, value }[]` | Bitmask multi-select; each option is one bit. |
| `label` / `tooltip` | string | Overrides the label derived from the field name; hover text. |
| `category` | string | Groups the field under a category header. |
| `advanced` | boolean | Places the field behind a fold. |

Fields without metadata use the control inferred from their value.

## Component metadata

The same argument also carries metadata about the component as a whole:

| Key | Description |
|---|---|
| `assetFields` | Fields holding asset references. Details renders an asset picker, and the cook ships the referenced asset. |
| `entityFields` | Fields holding entity references. |
| `animatableFields` | Fields the [Sequencer](/docs/animation/timeline/sequencer/) can key. Default: all numeric fields. |
| `replicatedFields` | Fields synchronized by [state replication](/docs/scripting/networking/replication/). Omitted: the component does not replicate. |
| `worldUnitFields` | Fields that are world lengths, speeds or accelerations. Their defaults are written at 100 units per metre and scale with the project's units per metre; values stated in a scene are not scaled. |
| `transient` | `true` excludes the component from scene saves. For per-frame runtime state. |
| `renderableField` | Name of the boolean field that gates the component's drawing (see below). |

`renderableField` applies to a component that draws something of its own, for example through a custom draw
callback. When it is declared, hiding the entity reaches the component: the Outliner's visibility toggle,
`setEntityVisible` and scene sleep switch that field off and restore it afterwards. Omit it for components that only
carry data or behaviour; an unrelated `enabled` field must not be declared as the renderable field.

## Built-in components

The engine registers more than 150 components, queried in the same way as user components: `Transform`, `Sprite`,
`ShapeRenderer`, `Camera`, `Light`, `ParticleEmitter`, `SpineAnimation`, `TilemapLayer`, the UI components, the
physics colliders and others. Each subsystem chapter documents the components it owns. The
[component reference](/docs/reference/components/core/) lists every component with its fields, types and authoring
defaults, generated from the same registry the Details panel reads.

Built-in components are C++ structs annotated with `ES_COMPONENT` / `ES_PROPERTY`. Their TypeScript layout is
generated from those annotations, so the SDK and the engine core use the same field layout.

### Entity metadata components

Four built-in components describe the entity itself rather than belong to a subsystem. They appear in the World
Outliner and in scene files.

| Component | Description |
|---|---|
| `Name` | Display name of the entity. Shown in the World Outliner and used by name lookups. |
| `Parent` / `Children` | The hierarchy. The engine keeps both sides consistent; see [Transforms](/docs/core-concepts/transforms/#parenting-and-hierarchy). |
| `Disabled` | Tag. `setEntityActive(world, entity, false)` adds it; `isEntityActive` returns whether it is absent. |
| `RuntimeOnly` | Tag for an entity derived by a system rather than authored, such as the layer entities a `Tilemap` projects or runtime tile colliders. Scene saves skip these entities, because a saved copy would duplicate the next derivation. |

`Disabled` and `RuntimeOnly` are ordinary components: queries filter them with `.with()` / `.without()`, and they can
be inserted or removed directly instead of through `setEntityActive`. The Outliner's visibility toggle is a
separate, edit-time setting; it does not add `Disabled` and does not change what the running game does with the
entity.

## Reading and writing

Systems receive component data through a query. A component the system writes is wrapped in `Mut(...)`, which lets
change detection and the renderer register the write:

```typescript
Query(Mut(Transform), Speed)
// Transform is written; Speed is read-only
```

`Added(C)` and `Changed(C)` narrow a query to entities whose component was just added or changed. See
[Systems](/docs/core-concepts/systems/#filters-and-change-detection) for the full query vocabulary.

A component wrapped in `Mut` is written back after each iteration. Built-in components read in any other way —
`world.get`, `ctx.get` — are decoded from the WebAssembly heap and returned as a copy, which must be written back
with `world.set` / `ctx.set`; see [Components vs. resources](/docs/core-concepts/plugins-resources/#components-vs-resources).
