Estella uses an **Entity-Component-System** (ECS) architecture. Game state is plain data held in components;
behaviour is implemented by systems that run over that data.

| Concept | Definition |
|---|---|
| **Entity** | An identifier. It holds no data and no behaviour; components are attached to it. |
| **Component** | A plain data struct (position, velocity, sprite). An entity is defined by the set of components it carries. |
| **System** | A function that runs every frame over all entities matching a query, reading and writing their components. |

## Storage

Each component type is stored in its own densely packed sparse set, so a system iterating all entities with a
`Transform` and a `Speed` reads contiguous memory. Storage lives in the C++/WebAssembly core. The SDK reads it without
copying through a generated memory layout that is checked by hash, which keeps the TypeScript and C++ views of a
component identical.

## SDK primitives

A game is composed from three SDK primitives:

| Primitive | Purpose | Reference |
|---|---|---|
| `defineComponent` | Declares a component type. | [Components](/docs/core-concepts/components/) |
| `defineSystem` | Declares a system and the data it queries. | [Systems](/docs/core-concepts/systems/) |
| `App` and plugins | Assemble systems, resources and subsystems ([physics](/docs/gameplay/physics-2d/overview/), [Spine](/docs/animation/spine/), [tilemaps](/docs/world/tilemaps/overview/), [UI](/docs/ui/overview/), [audio](/docs/assets/audio/overview/), [scenes](/docs/world/scenes/)) into a running game. | [Plugins & Resources](/docs/core-concepts/plugins-resources/), [App & Factories](/docs/core-concepts/app/overview/) |

```typescript
import { App } from 'esengine';

const app = App.new();
// register components, systems and plugins on the app
app.run();
```

Per-entity logic with an editor-tunable state can also be written with `defineBehavior`, which expands to one
component and one system ([Scripting](/docs/scripting/overview/)).
