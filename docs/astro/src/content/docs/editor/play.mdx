Play mode runs the game in an isolated realm, using the same runtime as shipped builds.

## Controls

| Control | Function | Shortcut |
|---|---|---|
| Play / Stop | Start; while running, stop | **F5** / **Esc** |
| Pause / Resume | | **F6** |
| Restart | | **Shift + F5** |
| Maximize | Maximize or restore the scene view | **F11** |
| Inspect | Editor takes the pointer over the running game | **F8** |

The play-mode menu beside Play selects:

| Option | Values |
|---|---|
| Host | **Play In Viewport** (over the scene view) or **Play In New Window** (a dedicated Game tab) |
| Maximize Viewport on Play | Gives the whole workspace to the game; the layout is restored on Stop |
| Players | **Single Player**, or **2 / 3 / 4 Players (Listen Server)**: the first realm runs as listen server, each further player as a client realm connected by in-editor replication |

![The play-mode menu: Play In Viewport / New Window, Maximize Viewport on Play, Single Player or 2–4 players with a listen server](@/assets/guides/en/play-mode-menu.png)

A running game is indicated by an accent ring around the scene view (amber, with the frame dimmed, while paused).

## The running world in the Outliner

During play the Outliner shows the running world. Entities that came from the scene keep their identity, so
expansion, selection and the Details view carry over. Entities spawned by the game appear under a **Runtime** group
and are removed on Stop.

Structural edits wait for Stop: during play, rows can be selected, searched, folded and hidden, but not renamed,
reparented, created or deleted. Field edits apply to the running world and end at Stop unless kept (below).

## Inspect

With **Inspect** on (above the game, or **F8**), the pointer belongs to the editor: click to select under the cursor,
and move, rotate or scale with the transform tools (**W / E / R**), which appear beside the frame. Picking and dragging
are resolved by the running world and the game's own camera, so a moved entity lands where the game draws it. Inspect
is off by default; with it off, nothing is drawn over the game.

## Keeping play-time changes

If fields were changed during play, Stop offers to **keep** them; the Output Log lists each change with its value
before the decision. Keeping applies each touched field's value as the running world holds it at Stop (including axes
driven by scripts) as one undo step. Entities spawned by the game cannot be kept; they are counted in the log.

## Phone preview

**Scan Preview** saves the scene, builds a web preview and serves it on the LAN with a QR code. The phone browser runs
the project with the same runtime for 2D and 3D.

- The popover shows the address, connected devices and Stop. **More Settings** selects the scene and network interface,
  rebuilds, and reports connection and reload errors.
- Each session issues a new access token; there is no public tunnel. Stop, switching projects or closing the editor
  invalidates the link.
- Saving scenes or assets rebuilds and refreshes connected browsers. Script saves are hot-swapped when the schema is
  compatible; structural changes reload the page with the reason reported. A failed build leaves the previous preview
  available.
- Preview builds skip AOT and asset compression. Without WebGPU on the browser origin, the preview falls back to
  WebGL2; the project's shipping backend setting is unchanged.
- The page may connect to the same servers as play mode. Web exports are restricted to
  **Project Settings → Allowed server origins**.

## Autosave and recovery

The editor periodically snapshots unsaved documents (only when there are unsaved changes and no play session is
running) into the project's workspace folder. Snapshots are not saves. On the next open, a snapshot newer than the file
on disk is offered for **restore**; saving the document supersedes its snapshot. This complements crash minidumps and
the automatic reload after GPU process loss.
