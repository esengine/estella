The scene view displays the edited scene and hosts the transform tools.

![The scene view with the Universal Transform tool on the selected player: move arrows, scale boxes and the rotation ring](@/assets/guides/en/ed-gizmo.png)

*Universal Transform (**Y**) on the selected entity: move arrows and centre plane, scale boxes beyond the arrow tips,
rotation ring.*

## Navigation

| Action | Input |
|---|---|
| Pan | Middle-drag, or **Space** + drag |
| Orbit | Right-drag in a spatial view (perspective or rotated), or **Alt** + drag in any view. In a flat 2D view right-drag pans. |
| Zoom | Mouse wheel, toward the cursor |
| Frame selection | **F** |

## Selection

| Action | Input |
|---|---|
| Select | Click |
| Toggle in selection | **Shift** + click |
| Box select | Drag on empty space |
| Cancel drag / clear selection | **Esc** |

## Transform tools

| Tool | Key | Handles |
|---|---|---|
| Select | `Q` | Picking and box selection only. |
| Move | `W` | Axis arrows. Spatial views add XY / YZ / ZX plane handles and a screen-plane centre; head-on 2D shows X / Y and the centre plane. |
| Rotate | `E` | Axis rings; spatial views add an outer screen-axis ring. Head-on 2D shows the Z ring. |
| Scale | `R` | Axis boxes; spatial views add plane handles and a uniform centre. Head-on 2D shows two-axis centre scaling. |
| Rect | `T` | The rectangle grips of the selected sprite or UI node. |
| Universal | `Y` | Move, scale and rotate handles together. |

Gizmo behaviour:

- **Universal priority.** Move handles take precedence over scale boxes, scale boxes over rotation rings. Scale boxes
  sit beyond the arrow tips; dragging one box-arm length doubles that axis. The operation chosen at press is fixed for
  the drag.
- **Plane handles** face the camera quadrant; edge-on planes are hidden. A World-space plane drag changes only its two
  components; Local uses the rotated plane normal. The spatial move centre drags on a camera-parallel plane through the
  pivot, captured at press.
- **Rotation.** The outer ring rotates about the camera's forward axis captured at press, regardless of Local / World.
  Inner rings use the drawn Local or World axis. Rotations are converted through each target's parent frame. Outer-ring
  snapping rounds the primary object's twist about the view axis.
- **Hover** highlights the handle a press will grab and sets the cursor; it does not modify transforms or open an undo
  step.
- **Settings → Editor → Viewport → Gizmos**: **Transform handle size** (0.5–2, default 1) scales handles and hit areas;
  **Fade occluded transform handles** dims spatial handle segments behind geometry. Both persist across sessions.

## Pivot modes

The pivot button cycles **Center → Pivot → Individual Origins** (also in the **View** menu and the Command Palette):

| Mode | Rotate / scale about |
|---|---|
| Center | The selection centroid. |
| Pivot | The active object's position. |
| Individual Origins | Each target's own position (one handle drawn at the selection centre). |

Translation is identical in all modes. When a parent and its child are both selected, the parent carries the subtree
and the child is not transformed twice. Locked entities are excluded. The mode is captured at the start of a drag.

## Duplicate and nudge

- Each drag is one undo step; **Esc** cancels it.
- **Alt** + drag on a selected handle duplicates the selection and drags the copies.
- Arrow keys nudge by one grid step; **Shift** multiplies by 10.

## Align and distribute

With two or more entities selected, alignment buttons appear in the scene view toolbar: left / centre / right and
top / middle / bottom edges. With three or more, two distribute buttons equalise horizontal or vertical spacing. Each
operation is one undo step and applies to sprites, UI nodes and gizmo-only entities alike.

![Three platforms selected: the align and distribute buttons in the scene view toolbar, the move gizmo at the selection centre](@/assets/guides/en/ed-align.png)

## Snapping

The snapping dropdown enables snapping and sets the grid step, rotation increment and scale increment.

## Show flags and gizmos

The **Show** dropdown toggles grid, gizmos, physics shapes and the performance overlay, and sets World / Local
orientation and the pivot mode. Non-rendering entities — cameras, lights, colliders, joints, particle emitters — are
drawn as gizmos in edit mode (icons, view rectangles, light reach and cone, collider outlines, joint anchors). Many
gizmos have handles that edit their component fields directly (light radius, collider size, emitter shape, joint
anchors).

## Editing modes

The first four Activity Bar icons select the editing mode: **Tilemap**, **UI**, **World**, **Scene**. The mode follows
the selection — a `Canvas` or `UINode` suggests UI, a `TilemapLayer` suggests Tilemap — and switches tools and scene view
aids without changing the panel layout. Clicking a mode's icon, or the mode chip in the scene view, opens its companion
panels (UI Widgets, Tile Palette) and **pins** the mode so that selection changes do not leave it; clicking again
unpins it.

## Design resolution and device preview

Scenes are authored against a **design resolution** (for example `1920 × 1080` landscape or `750 × 1334` portrait). It
is a project setting (**Settings → Project → Game → Display**) and applies in every editing mode, with or without a UI
Canvas. With a Canvas, UI is additionally laid out inside the frame according to its scale mode.

| Control | Function |
|---|---|
| **Design resolution** (toolbar, e.g. `800×600`) | Sets the design resolution and reframes. Edits the Canvas if one exists, otherwise the project value. Undoable. |
| **Device** (reads `Design` when no device is simulated) | Selects a target screen (iPhone, iPad, 1080p, …). In edit mode it draws the screen's aspect as letterbox bars and safe-area insets; in play mode the running game is letterboxed to the same shape, in the scene view and the Game panel. The design resolution is not changed. |
| **Orientation** (Device dropdown) | Swaps the device's width and height. Disabled while `Design` is selected. |
| **Camera Fit** (Settings → Project → Game → Display) | How the main camera scales the design resolution, independent of any Canvas. `None` (default) keeps the camera's own `orthoSize`; other modes letterbox identically on every device, and the device preview shows the actual framing. |

`Design` means no simulation: the game fills the available panel area. Selecting a device applies its shape to both
the edit overlay and the running game.

![A scene running in the scene view, framed to the selected target screen rather than to the panel's shape](@/assets/guides/en/game-target-screen.png)

### Project screen presets

**Settings → Project → Game → Advanced → Screen presets** extends or overrides the built-in device list for everyone
who opens the project:

- **Id** — the key a saved selection resolves through; keep it stable. Reusing a built-in id (`iphone`, `ipad`,
  `1080p`, `720p`) replaces that built-in.
- **Size** — stored in portrait orientation (width ≤ height), like the built-ins.
- **Safe area** (row expander) — notch and home-indicator insets in device pixels. Zero insets are not written to the
  project file.

![Project Settings → Game → Display → Advanced: two screen presets, Steam Deck and iPhone 15 Pro](@/assets/guides/en/settings-screen-presets.png)

Presets are stored in `project.esproject`:

```json title="project.esproject"
{
  "screenPresets": [
    { "id": "steam-deck", "label": "Steam Deck", "width": 800, "height": 1280 },
    {
      "id": "iphone", "label": "iPhone 15 Pro", "width": 1179, "height": 2556,
      "safe": { "top": 59, "bottom": 34, "left": 0, "right": 0 }
    }
  ]
}
```
