An editor plugin adds tools to the editor: commands, docked panels, Inspector sections, viewport gizmos and tools,
asset types, importers and agent tools. Plugins are TypeScript in the project or the user folder. The editor compiles
them with no build step and recompiles on save.

Plugin contributions go through the same registries as the editor's own features: a contributed panel is a dock panel
with a tab, a close button and pop-out. The contribution points are described in
[Contribution Points](/docs/extending/contribution-points/).

## Creating a plugin

<Steps>

1. Open **Window ▸ Plugins** and choose **Add ▸ New Plugin…** (also available in the command palette).

2. Enter a **Name**. The **Id** is derived from it and can be edited; it is dotted and lowercase, such as
   `acme.level-tools`. Under **Install to**, choose **project** (versioned with the project and shared with the team)
   or **user** (personal, available in every project).

3. Under **Start from**, tick the samples to include — Command, Panel, Inspector section, Viewport gizmo, Viewport
   tool — and choose **Create**.

</Steps>
The editor writes a working plugin and loads it:

<FileTree>
- .esengine/
  - plugins/
    - acme.level-tools/
      - plugin.json
      - tsconfig.json
      - src/
        - editor.ts
</FileTree>

```json title="plugin.json"
{
  "id": "acme.level-tools",
  "name": "Level Tools",
  "version": "0.1.0",
  "engines": { "editor": "^0.97" },
  "main": { "editor": "src/editor.ts" }
}
```

```ts title="src/editor.ts"
import { definePlugin, type PluginContext } from '@estella/editor-api';

export default definePlugin({
  activate(ctx: PluginContext) {
    ctx.commands.register({
      id: 'acme.level-tools.hello',
      title: { en: 'Say hello', 'zh-CN': '打个招呼' },
      menu: 'tools',
      run: () => ctx.ui.toast(`${ctx.scene.getSelectionIds().length} selected`),
    });
  },
});
```

The command appears in the Tools menu and the command palette. Saving `editor.ts` recompiles and re-activates the
plugin, and any panel it contributed reopens on the new build.

## Manifest

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Required. Dotted, lowercase, namespaced (`<publisher>.<name>` by convention), such as `acme.level-tools`. |
| `name` | localized string | Required. Display name. |
| `version` | `string` | Required. Plugin version. |
| `description` | localized string | Short description. |
| `publisher` | `string` | Shown under the version in the Plugins window. |
| `engines.editor` | `string` | Editor version range the plugin supports, such as `^0.97`. |
| `main.editor` | `string` | Entry point, relative to the plugin folder; runs in the editor's renderer. |
| `capabilities` | `string[]` | Declared side effects shown at the trust prompt: `fs:project`, `net`, `shell`, `process`. Convenience APIs are gated on them (`fs:project` for project file access). |
| `category` | `string` | Category in the Plugins window tree, such as "Importers" or "Audio". Absent files the plugin under Other. |
| `icon` | `string` | A square picture inside the plugin folder (PNG, JPEG, WebP or SVG), such as `Resources/Icon128.png`. |
| `docsUrl` | `string` | An http(s) address; adds a Documentation link. |
| `beta` | `boolean` | Marks the plugin Beta. |

A localized string is either a string or an object keyed by locale (`{ "en": …, "zh-CN": … }`).

<Aside type="tip" title="engines.editor">
Below 1.0 the **minor version is the breaking-change axis**: `^0.97` does not match `0.98`. **New Plugin** pins the
range to the editor that creates it. A range copied from an older plugin marks the plugin *incompatible*.
</Aside>

## What this API promises

The plugin API is **experimental** and is not part of Estella's 1.x compatibility contract; it will continue to change
after 1.0. [VERSIONING.md](https://github.com/esengine/estella/blob/master/VERSIONING.md) states this alongside the
SDK's [stability tiers](/docs/reference/api-stability/): the extension points are still converging on one mechanism, a
plugin runs as trusted code in the editor's renderer rather than in isolation, and no shipped plugin yet exercises
these shapes.

The following commitments apply:

- **`engines.editor` is honoured.** A plugin outside its declared range is refused with a stated reason and never
  partially loaded.
- **Breaking changes are recorded** in the CHANGELOG under **Editor plugin API**, with migration instructions.
- **Removal is deprecated first.** A contribution point being withdrawn keeps working, with a notice, for at least
  one minor release.

Parts of the API will be frozen individually as shipped plugins exercise them.

## Plugins window

**Window ▸ Plugins** lists every plugin the editor found.

![The Plugins window: a tree of groups and categories with counts on the left, the plugins as cards on the right](@/assets/guides/en/plugins-panel.png)

*Toolbar: **Add** (New Plugin…, Install from Package…), Refresh and search. Left: All Plugins, Needs attention, then
Project, Installed and Built-in by category, each with a count. Right: one card per plugin with its enable box, icon,
version and publisher, and Edit, Package, Show in Folder, Reload and Details.*

| Card action | Effect |
|---|---|
| Enable box | Enables or disables the plugin. |
| **Edit** | Opens `plugin.json`. |
| **Package** | Packs the plugin into an `.esplugin` file ([Sharing a plugin](#sharing-a-plugin)). |
| **Show in Folder** | Opens the plugin folder. |
| **Reload** | Recompiles from source and re-activates. |
| **Details** | Shows the plugin's state, errors and **Contributes** list. |

**Contributes** lists everything the running plugin has registered — commands, panels, settings, tools, gizmos,
Inspector sections, asset types, importers, entity templates, menu items, rail buttons and agent tools — each with its
id. A contribution that does not appear in the editor is either absent from the list (`activate` did not reach the
registration) or registered under a different id.

![The Plugins window: the built-in Audio Mixer plugin expanded with Details, showing what it declares and its three contributions](@/assets/guides/en/extend-plugin-details.png)
## Sharing a plugin

**Package** on a plugin's card packs it into one `.esplugin` file, a ZIP archive. `node_modules`, `dist` and the
generated typings are excluded.

**Add ▸ Install from Package…** installs a package. It first lists the contents — the manifest, the declared
capabilities and every file — without unpacking or writing anything. Installing does not run the plugin: it arrives
needing trust.

### Trust

<Aside type="caution" title="Trust">
A plugin runs with the same access as the editor: project files and anything else the editor can reach. No plugin
loads until it is approved (**Trust and load**). Load only plugins from trusted sources. The prompt lists the
declared capabilities, but declared capabilities describe intent and are not a sandbox.

Approval covers one version from one folder. A new version, or a different folder claiming the same id, asks again.
**Withdraw trust** revokes approval.
</Aside>

## npm packages

A plugin can be an npm package the project depends on:

```bash
npm install estella-plugin-tiled
```

Any **direct** dependency with a `plugin.json` at its root is a plugin. It is listed and requires trust like any other;
approval covers a version, so an update asks again. Packages that arrive as dependencies of other packages are not
considered.

A package can ship both halves of a plugin: the editor half the manifest points at, and runtime code the game imports.

<FileTree>
- node_modules/estella-plugin-tiled/
  - package.json
  - plugin.json  `"main": { "editor": "editor/index.js" }`
  - editor/
    - index.js
  - runtime/
    - index.js
</FileTree>

```ts title="src/main.ts"
import { addPlugin } from 'esengine';
import { TiledPlugin } from 'estella-plugin-tiled';

addPlugin(TiledPlugin);
```

The runtime half is an ordinary module bundled into the game. Declare `esengine` as a **peer** dependency: the
project's bundler keeps every `esengine` import external so the game shares one engine instance, and a vendored copy
would be a second component registry whose systems register into nothing.

## Typings

Each time it opens a project, the editor writes `@estella/editor-api` typings to
`.esengine/plugins/.types/editor-api.d.ts`, matching the running editor. **New Plugin** writes a `tsconfig.json` that
points at them; for a plugin written by hand:

```json
{
  "compilerOptions": {
    "strict": true,
    "moduleResolution": "bundler",
    "paths": { "@estella/editor-api": ["../.types/editor-api.d.ts"] }
  },
  "include": ["src"]
}
```

## Plugin locations

| Location | Use |
|---|---|
| `<project>/.esengine/plugins/<id>/` | Versioned with the project and shared with the team. |
| A direct npm dependency of the project | See [npm packages](#npm-packages). |
| `<userData>/plugins/<id>/` | Personal tools available in every project. |

On an id collision the first location in this order wins; the others are listed as **Shadowed** with the plugin that
took the id.

## Permitted imports

A plugin runs in the editor's realm and imports the editor's own module instances, so what it registers is what the
editor uses. A plugin may import:

- `react`, `react-dom`, `react-dom/client`, `react/jsx-runtime`
- `@estella/editor-api`
- `esengine`, `esengine/terrain`, `esengine/worldgen`, `esengine/water`, `esengine/spline`, `esengine/voxel`,
  `esengine/rig2d`, `esengine/tilemap`, `esengine/replication`

Any other bare specifier is a load error that names this list; bundle such dependencies into the plugin.

### Game-registered providers in the editor

The editor does not run the game's scripts while editing; it reads the declaration module for component schemas only.
A terrain provider the game registers (a `Terrain` with `provider: 'my-game:planet'`) is therefore absent in the
viewport. A project plugin that imports the module registering it makes the provider available, with the same code in
the editor and in the game:

```ts title=".esengine/plugins/my-game.ground/src/editor.ts"
import { definePlugin } from '@estella/editor-api';
import '../../../../src/planet/terrain.ts';   // registerTerrainProvider(...), as the game does

export default definePlugin({ activate: () => {} });
```

The plugin runs project code, so the editor asks to trust it once. New projects' `.gitignore` does not ignore
`.esengine/plugins/`, so the plugin is committed with the project.

## Project platform profiles

A `.esengine/platforms/<id>.mjs` packaging profile ([Mini-Game Platforms](/docs/publishing/minigame-platforms/#project-platforms),
[Playable Ads](/docs/publishing/playable-ads/#custom-ad-network)) is imported into the editor's main process with full
system access. It is listed in the Plugins window and requires the same approval; until approved, its target is shown
as not ready in Package Project.

## Troubleshooting

**Window ▸ Plugins** lists every plugin found, including broken ones with the reason: a manifest that failed to parse,
a compile error, an id already claimed, or an incompatible `engines.editor` range. Errors thrown by a plugin appear in
the **Output Log** tagged `plugin:<id>`, with a stack trace.

A plugin that keeps throwing is disabled so it cannot break a surface on every render. Fix it and click **Reload**.

<Aside type="tip">
A plugin's timings appear in the profiler under `plugin.<id>.<what>`, next to the editor's own work.
</Aside>
