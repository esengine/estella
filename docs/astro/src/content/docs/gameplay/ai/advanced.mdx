`Nav`, `NavAgent` and `Perceiver` cover the common cases. The primitives beneath them are exported as well, as plain
TypeScript with no engine or WebAssembly dependency, for a path without an agent or a sight check without a `Perceiver`.

## Pathfinding by hand

`findPath` is the A\* the nav plugin uses on grids: a uniform-cost search over `NavGrid` cells, 4- or 8-connected, with an
octile or Manhattan heuristic and no corner cutting (a diagonal step needs both shared orthogonal cells open). It suits
movement steered by game code, path previews, reachability for turn-based ranges, or a second grid beside the one active
`Nav` surface.

```typescript
import { NavGrid, findPath, pathToWorld } from 'esengine/ai';

const grid = new NavGrid({ width: 32, height: 24, cellSize: 32 });

const path = findPath(
  grid,
  grid.worldToCell(hero),               // Cell — integer grid coordinates
  grid.worldToCell(chest),
  { diagonal: false },
);
if (path) {
  const waypoints = pathToWorld(grid, path);   // Vec3[] — cell centers, world pixels
}
```

`findPath(grid, start, goal, opts?)` returns the `Cell[]` path including both endpoints, or `null` when the goal is
unreachable. A `Cell` is an integer grid coordinate `{ x, y }`, distinct from `Vec2` to mark cell space. Conversion uses
`grid.worldToCell(point)` / `grid.cellToWorld(gx, gy)`, or `pathToWorld` for a whole path.

| `PathfindOptions` field | Default | Description |
|---|---|---|
| `diagonal` | `true` | Allows 8-connected diagonal moves. |
| `snapRadius` | `8` | When the start or goal is on a blocked cell, snaps to the nearest walkable cell within this ring radius before searching; `0` disables snapping. |
| `clearance` | `0` | Cells of room the body needs on every step (`0` plans for a point). A `NavAgent`'s `radius` is converted to this. |

`navGridFromTiles` builds the walkability mask from any tile reader. `navGridFromTilemapLayer` uses it with
`TilemapAPI.getTile`:

```typescript
import { navGridFromTiles } from 'esengine/tilemap';

const grid = navGridFromTiles((x, y) => level.tiles[y][x], {
  width: 32, height: 24, cellSize: 32,
  blockedTileIds: [WALL_TILE, WATER_TILE],
});
```

| `BuildNavGridOptions` field | Description |
|---|---|
| `width` / `height` / `cellSize` / `origin?` | As the `NavGrid` options ([Building a grid](/docs/gameplay/ai/navigation/overview/#building-a-grid)). |
| `blockedTileIds?` | Tile ids that block movement. |
| `isBlocked?` | Predicate over the tile id (`0` = empty); overrides `blockedTileIds`. With neither, any non-empty tile blocks. |

## Perception internals

The perception plugin wraps exported functions, usable for one-off sight checks from an action, custom senses, or tests
against a fake world:

| Function | Description |
|---|---|
| `senseTarget(observer, facing, target, range, halfFov, isBlocked?)` | The geometry, in 3D (`Vec3` points; a flat scene has constant `z`): a range check, a cone check (`halfFov` is half the cone in radians; π or more is omnidirectional), then the optional occlusion callback. |
| `facingFromRotation(rotation, axis?)` | The world direction an entity faces, from a `Transform` rotation and a `FacingAxis` (`'x'` by default, or `'-z'`). |
| `makeLosCheck(physics)` | Builds an occlusion callback from a 2D physics raycast: occluded when a hit lands short of the target (`fraction < 0.98`, the last 2% being the target itself) on a body other than the observer's or the target's. |
| `stepPerception(world, isBlocked?, noises?, dt?)` | The per-frame step the plugin runs in `PreUpdate`: for every `Perceiver`, senses every `PerceptionTarget`, keeps the nearest visible one, processes this step's `Noise` payloads, ages `sinceHeard` by `dt`, and writes the `Perception` component. |

```typescript
import { Transform, registerCondition } from 'esengine';
import { senseTarget, facingFromRotation } from 'esengine/ai';

// A one-off sight check against a POINT — no PerceptionTarget needed.
registerCondition('seesShrine', (ctx) => {
  const tf = ctx.get(Transform);
  return senseTarget(
    tf.position, facingFromRotation(tf.rotation),
    SHRINE,                      // a { x, y, z } point
    300, Math.PI / 3,            // 300 px range, 120° cone
  ).visible;
});
```

`senseTarget` returns a `SenseResult`:

| `SenseResult` field | Description |
|---|---|
| `visible` | The target is within range, inside the cone and not occluded. |
| `distance` | Distance to the target; always set, even when not visible. |
| `dir` | Unit direction from observer to target as a `Vec3`; zero when not visible. |

The plugin adds a line-of-sight check only when a physics module is loaded: the 3D world if the scene has one,
otherwise 2D. With neither, sensing is range and cone only; the AI layer has no hard physics dependency.

## Custom app setup

Importing `esengine/ai` registers the perception, FSM, BT and navigation plugins, and the editor and the `esengine` web
runtime add them. An app built from a bare `new App()` adds them explicitly:

```typescript
import { perceptionPlugin, fsmPlugin, btPlugin, navPlugin } from 'esengine/ai';

app.addPlugin(perceptionPlugin);
app.addPlugin(fsmPlugin);
app.addPlugin(btPlugin);
app.addPlugin(navPlugin);
```

Each is exported as a ready-to-use instance (`navPlugin`) and as a class (`NavPlugin`) for multiple instances.
