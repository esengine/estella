*The state-machine editor: states (Patrol / Chase) linked by guarded transitions (`?seesPlayer`, `?lostPlayer`).*

A state machine is a set of **states** connected by **transitions**. Exactly one state is active; each tick, its outgoing
transitions are checked in order and the first enabled one is taken. A `StateMachineAgent` runs a machine on its entity:

```typescript
import { StateMachineAgent } from 'esengine/ai';

cmds.spawn()
  .insert(NavAgent, {})
  .insert(Perceiver, { range: 240 })
  .insert(Perception, {})
  .insert(StateMachineAgent, { fsm: 'assets/ai/enemy.esfsm' });   // an editor-authored asset
```

| `StateMachineAgent` field | Description |
|---|---|
| `fsm` | The machine to run: a `registerFsm` name or an `.esfsm` asset path. |
| `current` | Active state name, written each tick (read-only; shown in the Inspector). |

## Defining a machine

Machines are normally authored in the editor as `.esfsm` assets
([Authoring in the Editor](/docs/gameplay/ai/authoring/)); states reference registered action and condition names. A
machine can also be registered in code:

```typescript
import { registerFsm } from 'esengine/ai';

registerFsm('guard', {
  initial: 'Patrol',
  states: [
    {
      name: 'Patrol',
      onUpdate: 'patrol',
      transitions: [{ to: 'Chase', condition: 'seesPlayer' }],
    },
    {
      name: 'Chase',
      onEnter: 'startChase',
      onUpdate: 'chase',
      transitions: [{ to: 'Patrol', condition: 'lostPlayer' }],
    },
  ],
});
```

## States and hooks

Each state has up to three hooks, `onEnter`, `onUpdate` and `onExit`, and a list of `transitions`. A hook is a registered
action name, or `{ name, arg?, params? }` when it needs an argument.

| Hook | Runs |
|---|---|
| `onEnter` | On the first tick the state is active, i.e. the tick after the transition into it. |
| `onExit` | When a transition out of the state is taken. |
| `onUpdate` | On ticks where no transition fires. |

At most one transition is taken per tick. Return values of FSM actions are ignored.

## Transitions

A transition is enabled when **all** of its specified mechanisms hold; a transition with none is unconditional. A
transition that names a condition that is not registered is never enabled.

| Transition field | Description |
|---|---|
| `to` | Destination state name. |
| `trigger` | A one-shot event name that must have been fired; consumed when the transition is taken. |
| `condition` | A registered condition that must return true. |
| `guard` | One or more blackboard comparisons, combined with AND. |

A guard compares a blackboard key with `==`, `!=`, `<`, `<=`, `>`, `>=`, `truthy` or `falsy`, for example
`{ key: 'health', op: '<', value: 20 }`. `value` is ignored by `truthy` / `falsy`; a missing key reads as `undefined`;
the ordering operators compare numerically. Triggers and guard values live on the agent's
[blackboard](/docs/gameplay/ai/blackboard/).
