A 3D model can be imported, animated, skinned and lit. This is what makes it stand
somewhere: a rigid-body world powered by **Jolt Physics**, running in its own
WebAssembly module.

It sits **beside** the [2D physics](/docs/gameplay/physics/), not on top of it. A 2D
scene keeps the solver, the units and the feel it already has, and a project that
never asks for a 3D world never loads it.

## Bodies

An entity is in the world when it carries a `RigidBody3D` **and** a shape. A body
with no shape has no extent to collide with, so it is left out entirely rather than
falling forever as an invisible point.

```typescript
cmds.spawn()
  .insert(Transform, { position: { x: 0, y: 400, z: 0 } })
  .insert(RigidBody3D, { bodyType: BodyType.Dynamic })
  .insert(CapsuleCollider3D, { radius: 30, halfHeight: 50 });
```

| Field | What it does |
|---|---|
| `bodyType` | `Static` never moves, `Kinematic` is moved by hand, `Dynamic` is solved. |
| `gravityScale` | This body's share of world gravity. `0` is weightlessness, not slow falling. |
| `linearDamping` / `angularDamping` | How quickly motion bleeds off. |
| `fixedRotation` | Freezes the orientation the body was given — what keeps a character from toppling. It does not right a body that starts tilted. |

## Shapes

| Component | Extent |
|---|---|
| `BoxCollider3D` | `halfExtents` on each axis. |
| `SphereCollider3D` | `radius`. |
| `CapsuleCollider3D` | An upright capsule: `halfHeight` is the cylinder's half, with a cap of `radius` on each end, so the total height is `2 * (halfHeight + radius)`. |

<Aside>
  Sizes are authored in **world units** and reach the solver in metres, at the same
  `pixelsPerUnit` the 2D world uses (100 by default). A solver tuned for metres
  behaves nothing like itself when a character is 180 units tall, so the conversion
  is not optional — it is why a capsule 60 units wide falls the way a person does.
</Aside>

## Characters

A `CharacterController3D` replaces a `RigidBody3D` rather than accompanying one: a
body the solver pushes and a character that sweeps are two answers to where an
entity is. Set `velocity` from gameplay each step and read the result back.

```typescript
const c = world.get(player, CharacterController3D);
c.velocity.x = input.axis('move') * 200;
if (input.justPressed('jump') && c.isOnFloor) c.velocity.y = 500;
```

| Field | What it does |
|---|---|
| `velocity` | Desired velocity in world units/second. A positive `y` is a jump. |
| `stepHeight` | Tallest step it climbs instead of stopping at. `0` climbs nothing. |
| `snapDown` | How far it reaches down to stay on the floor over a crest. `0` is off. |
| `maxSlope` | Steepest ground it can stand on; beyond this it slides. |
| `isOnFloor` / `floorNormal` / `realVelocity` | Outputs, read after the step. |

<Aside>
  The vertical component is carried for you: `velocity.y = 0` means "walk", not
  "hang in the air". A character does not fall on its own in Jolt — the vertical
  speed belongs to the caller — so the module integrates gravity rather than
  leaving every caller to rediscover it.
</Aside>

## Collision events

Each step publishes what touched what into the `Physics3DEvents` resource. It is
drained per fixed step, so a system reading it must run inside one — a read from
`Update` sees whatever the last step happened to leave.

```typescript
const events = app.getResource(Physics3DEvents);
for (const hit of events.contactEnters) {
  // both entities, and where they met
  spawnSparks(hit.pointX, hit.pointY, hit.pointZ);
}
for (const { sensorEntity, visitorEntity } of events.sensorEnters) {
  if (sensorEntity === goalZone) score(visitorEntity);
}
```

| Channel | What it carries |
|---|---|
| `contactEnters` | Both entities, the contact normal and the point. |
| `contactExits` | Only the pair — see below. |
| `sensorEnters` / `sensorExits` | The **sensor first**, then the visitor. |

<Aside>
  An ended contact carries no geometry: at that moment the solver has both bodies
  locked and one of them may already have been destroyed, so there is nothing left
  to report but who the pair was. A contact also ends when a body falls asleep,
  not only when it moves away — treat an exit as "this pair is no longer touching",
  not as "something moved".
</Aside>

A collider with `isSensor` reports overlaps and stops nothing: the visitor passes
straight through and shows up in `sensorEnters` instead of `contactEnters`.

## Which world a scene is in

Nothing stops an entity carrying both sets, but nothing merges them either: the two
worlds do not see each other, and a 2D collider will never stop a 3D body. Pick one
per scene.
