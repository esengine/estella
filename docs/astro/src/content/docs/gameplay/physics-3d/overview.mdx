3D physics is a rigid-body world that runs on **Jolt Physics** by default, or on **PhysX** when the project selects it,
in its own WebAssembly module. It is separate from [2D physics](/docs/gameplay/physics-2d/overview/): the two use their
own components and solvers, and a project that uses no 3D body never loads the 3D module.

## Setup

In the editor and the web runtime, the 3D module loads automatically when a scene uses a 3D body. A custom app adds the
plugin:

```typescript
import { Physics3DPlugin } from 'esengine/physics3d';

app.addPlugin(new Physics3DPlugin('physics3d.js', { gravity: { x: 0, y: -9.81, z: 0 } }));
```

`physics3dPlugin(url, config)` is an equivalent factory function. Every configuration field is optional:

| Field | Default | Description |
|---|---|---|
| `gravity` | `{ x: 0, y: -9.81, z: 0 }` | World gravity, m/s². |
| `fixedTimestep` | `1/60` | Physics step in seconds. The plugin also sets the app's fixed step to this value. |
| `collisionSteps` | `1` | Collision steps per physics step. |
| `pixelsPerUnit` | `100` | World units per metre. |
| `maxBodies` | `1024` | Maximum number of bodies in the world. |
| `layerMasks` | none | Collision matrix, one mask per layer ([Collision layers](#collision-layers)). Absent: every layer collides with every layer. |
| `velocityIterations` / `positionIterations` | `0` / `0` | Solver passes; `0` keeps the backend's own (Jolt 10 / 2, PhysX 1 / 6). |
| `enableSleep` | `true` | Resting bodies stop being simulated until something touches them. |
| `bounceThreshold` | `0` | Impacts slower than this (m/s) do not bounce; `0` keeps the backend's own (Jolt 1, PhysX 2). |

`RigidBody3D`, the 3D colliders and joints, `CharacterController3D`, `Ragdoll`, `Physics3D`, `Physics3DEvents` and
`Physics3DDebugDraw` are exported from the main `esengine` barrel; `CompoundCollider3D`, `Hitboxes` and `hitPartOf` from
`esengine/physics3d`. The gameplay controllers (`ThirdPersonController`, `FirstPersonController`, `MeleeAttack`,
`Health`, `Damage`, …) come from `esengine/gameplay`.

## Choosing the solver

The 3D world runs on Jolt by default. **Project Settings → Physics → 3D solver** switches it to PhysX. The manifest
stores the choice as:

```json
"features": { "physics": { "backend3d": "physx" } }
```

Both backends implement the same components, joints, characters, queries and collision events, and the engine's 3D
physics behaviour checks run against each (`node tools/check-physics3d.mjs`, `node tools/check-physics3d-physx.mjs`).
A build ships only the selected module: `physics3d.wasm` for Jolt, `physics3d-physx.wasm` for PhysX. Editor Play uses
the same choice.

PhysX is configured with projected Gauss-Seidel, patch friction, average friction and restitution combine, a 0.01 m
contact offset, a 2 m/s bounce threshold, a 0.005 sleep threshold, 6 position and 1 velocity iterations, and a 50 rad/s
maximum angular speed. Behaviour that differs between the backends:

| Behaviour | Jolt | PhysX |
|---|---|---|
| Character entering a trigger | Not reported: a Jolt character is not a body. | Reported. |
| Body falling asleep inside a trigger | Reported as an exit. | Still inside. |
| Character skin | — | One tenth of the character radius; a PhysX character stands that much higher than a Jolt character. |
| Character meeting a dynamic body no taller than its step height | — | Climbs onto it; a taller one is pushed with at most the character's push force. |

The PhysX web module is 3.5 MB (1.14 MB gzipped); the Jolt module is 1.3 MB. The two solvers can produce different
outcomes for chaotic scenes, such as a ball glancing off the edge of a hinged door.

| Platform | Solver |
|---|---|
| Web, Windows, Linux, Android | The project's choice. Windows executables compile both solvers in (adds 4 MB). An Android package carries PhysX as `libestella_physx.so` only when the project selects PhysX (about 2 MB download, 4.9 MB installed, per ABI). |
| WeChat, Douyin | The package carries the selected 3D solver when a scene uses it. A scene that also uses 2D physics adds Box2D. |
| macOS, iOS | Jolt only. A PhysX project runs on Jolt there and logs this once at startup. |

## Units

Sizes, positions and speeds are authored in **world units** and reach the solver in metres, converted at
`pixelsPerUnit` (100 by default, the same value the 2D world uses). Component defaults are written at the reference
scale of 100 units per metre: a default `BoxCollider3D` is a 1 m cube (`halfExtents` 50).

Masses are kilograms, angles radians, forces newtons and torques newton metres. Gravity set through
`Physics3D.setGravity` is in m/s².

## Collision layers

Every body is in one of sixteen layers (`RigidBody3D.layer`, `CharacterController3D.layer`, `MeshCollider3D.layer`). The
plugin's `layerMasks` says which layers collide: layer *i* collides with layer *j* when bit *j* of `layerMasks[i]` is set
**and** bit *i* of `layerMasks[j]` is set. Either side refusing keeps the pair apart.

```typescript
app.addPlugin(physics3dPlugin(url, {
  layerMasks: [
    0xFFFF,             // 0: everything
    0xFFFF,             // 1: the world
    ~(1 << 3),          // 2: bullets — not their own team
    0xFFFF,             // 3: that team
  ],
}));
```

<Aside type="note">
  A 3D body has a single layer, not the category/mask bit sets of the 2D world. A body's layer is fixed when it enters
  the world, so the plugin installs the matrix before any body is created.
</Aside>

Query and event layer masks use the same numbering; a mask of `0` means every layer.

## 2D and 3D in one scene

The 2D and 3D worlds do not see each other: a 2D collider never stops a 3D body. An entity may carry components of both,
but they are not merged. Each scene uses one of the two.

## Debug draw

In the editor, the viewport draws every 3D collider as a wireframe under the **Physics** show flag
([Seeing a shape](/docs/gameplay/physics-3d/bodies/#seeing-a-shape)). Editor gizmos are hidden in Play; the
`Physics3DDebugDraw` resource draws the running game's colliders and contacts:

```typescript
app.getResource(Physics3DDebugDraw).enabled = true;
```

| Field | Default | Description |
|---|---|---|
| `enabled` | `false` | Master switch for the overlay. |
| `showColliders` | `true` | The shape of every body the solver built. |
| `showContacts` | `false` | A cross at each contact point reported this step. |

The overlay draws only what the solver built; a disabled collider is not drawn. It ignores the depth buffer, so shapes
inside other geometry remain visible.
