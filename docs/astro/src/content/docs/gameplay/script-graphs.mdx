A **script graph** is gameplay logic authored as nodes and wires in a `.esgraph` asset and run on an entity by a
`ScriptGraphAgent`. Its leaves are the same registered **actions** and **conditions** that
[state machines and behavior trees](/docs/gameplay/ai/actions/) use. It is suited to short, event-driven logic: on
start, spawn an object; on a key press, branch on a condition.

The `.esgraph` file is the runtime definition. It is not compiled ahead of time, so the graph the editor runs and the
graph the package ships are the same data.

## Creating and running a graph

1. In the **Content Browser**, choose **New → New Script Graph**. The asset opens in a document tab; double-clicking an
   `.esgraph` reopens it.
2. Right-click the canvas to add an event, then wire the nodes it triggers.
3. On the entity that runs the graph, add a **`ScriptGraphAgent`** component and set its `graph` field to the asset.

The asset is referenced by path and preloaded with the scene, so it is ready before the agent's first tick. Graphs run in
**Play** and in the exported game, in the `Update` schedule beside the state-machine interpreter.

When two scenes share a graph, each agent uses its own texture import settings for prefabs, including spawns in a
called graph. A scene-owned agent's `entity.spawn` adds the whole prefab to its scene, so unloading that scene also
removes the spawned hierarchy. An agent outside any scene creates an unowned instance.

## Wires

| Wire | Carries | Direction |
|---|---|---|
| **Exec** (control) | "run next" | Pushed: an event activates its entry node and the wire is walked depth-first. |
| **Data** (number, boolean, string, entity, any) | A value | Pulled: a node evaluates its inputs backwards along the wire when it runs. |

Wires connect only compatible types. An input with nothing wired into it holds a **literal** typed on the node.

Execution order follows the graph: a **Sequence** node completes pin 0's whole chain before pin 1 starts. A pure node (no
exec pins) that feeds two pins of the same node is evaluated **once** per activation, so both pins see the same value;
the next activation evaluates it again, which lets a **While** condition become false.

## Nodes

The **Node** button in the toolbar, or right-clicking the canvas, lists nodes in groups:

| Group | Nodes |
|---|---|
| **Events** | **Start**, **Every frame**, **Destroy**, **On event** (a named entity event). Each is an entry point; a graph can have several. |
| **Flow** | **Branch**, **Sequence** (configurable pin count), **While**, **Delay**. |
| **Variables** | **Get variable**, **Set variable**. |
| **Values** | **Number**, **Boolean**, **String** literals. |
| **Actions** | Nodes with an exec pin: `timeline.play` / `timeline.pause`, `spriteAnim.play` / `restart` / `stop`, `audio.play` / `stop`, `soundEvent.trigger` / `stop`, `property.set`, `entity.spawn` (spawns a named prefab at an x / y, optionally under a parent, and outputs the new entity), `entity.despawn`, `debug.log`, `scene.load` / `reload`, `ui.setVisible`, `ui.setPage`, `fsm.fire`, `blackboard.set`, and every action registered in code. |
| **Queries** | Value-only nodes (no exec pin): `math.*` (add, subtract, multiply, divide, min, max, abs, clamp, lerp, random), `compare.*` (equal, less, greater), `logic.*` (and, or, not), `string.concat`, `property.get`, `entity.self`, `entity.byName`, `input.down` / `pressed` / `axis` / `pointer`, and every registered condition. |
| **Graphs** | Every other callable graph in the project, called through a **Call graph** node (empty until a graph declares an input). |

Node details:

- **Every frame** outputs `dt`, the frame delta in seconds.
- **On event** listens for an entity event by type (for example `trigger_enter` from a
  [Trigger Area](/docs/gameplay/markers/#trigger-areas), or `click` from a button) and outputs `target` (the entity the
  event was sent to) and `other` (the other entity it names, such as the other body of a contact; `0` when none). With
  the node selected, Details shows its **Type** and its **Inputs**: each input is a name and a type (`number`, `bool`,
  `string`, `entity` or `any`) and becomes a pin carrying that field of the event or of its `payload` (as a timeline
  event has), converted to the type, or the type's zero value when the event has no such field. The graph file stores
  the inputs as the node's `payload` literal, `name:type` pairs separated by commas.
- **Sequence** has 1–16 pins (2 by default). **While** has a `body` and a `done` pin.
- **Delay** waits `seconds`, then continues. Entering a Delay that is already counting has no effect, so a frequent
  caller cannot restart it. A graph called by another graph cannot contain a Delay (a call completes within one step);
  the graph reports it as a problem.

The menu lists actions and conditions by their registry name; a placed node shows a readable title (**Find entity by
name**, **Key pressed**, **Set property**, …) with the name underneath.

An action or condition registered with `registerAction` / `registerCondition` appears with the ports its declaration
gives it. The file stores only the name, so an existing graph is redrawn from the current declaration and does not keep
ports the declaration no longer has.

**Arrange** lays the nodes out left to right by data flow. Node positions are editor-only and ignored at run time.

## Variables

The panel beside the canvas has three sections, **Inputs**, **Outputs** and **Variables**, each with a count, an **Add**
button and search, and each entry shows how often it is read and written (or *unused*).

- **Add** under **Variables** declares a typed variable with a default value. Variables are declared by the asset but
  valued per entity: two entities running the same graph each keep their own values.
- Dragging a variable onto the canvas asks whether to create **Get** or **Set**; with `Ctrl/⌘` held it creates a Get, with
  `Alt` held a Set.
- A variable is renamed or retyped from its row. Deleting a variable that nodes still use asks for confirmation and
  leaves those nodes on the canvas without a variable.

## Callable graphs

A graph becomes **callable** when it declares an entry under **Inputs** (an input pin) or **Outputs** (an output pin).
Another graph runs it with a **Call graph** node, passing values in and reading results back. The signature belongs to
the callee; changing it redraws every caller.

A call runs the callee **to completion, synchronously**, within the caller's step. Each call site keeps its own frame
for the callee, the callee spends the caller's step budget, and nesting is bounded.

## Execution limits

| Limit | Value | Behaviour |
|---|---|---|
| Steps per tick | 4096 (`DEFAULT_STEP_BUDGET`) | Every node activation costs a step. A graph that exceeds the budget (a **While** that never becomes false) stops, names the node that exhausted it, and stays stopped. |
| Call depth | 16 (`MAX_CALL_DEPTH`) | A deeper call, including a graph that reaches itself through a cycle, stops with a reported problem. |

A reference to a graph, prefab or action that does not exist is reported once, not every frame.

## From code

Graphs can also be registered without an asset:

```typescript
import { registerScriptGraph, ScriptGraphAgent } from 'esengine/logic';

registerScriptGraph('door-open', graphData); // a ScriptGraph object

cmds.spawn().insert(ScriptGraphAgent, { graph: 'door-open' });
```

`ScriptGraphAgent.graph` takes a registered name or a `.esgraph` path.
