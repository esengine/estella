Every `Camera` is a virtual camera: a view described by the scene. The components on this page move a camera each frame
so that it follows, frames and keeps its target in view, without camera code in the game.

## The camera pipeline

Each frame, before a view is chosen, every camera is moved by the components it carries, in this fixed order:

| Stage | Purpose | Components |
|---|---|---|
| 1. Position | Where the camera stands | `FollowTarget`, `CameraDolly` or `PositionComposer` (one per camera) |
| 2. Rotation | Where the camera looks | `LookAtTarget` |
| 3. Finalize | Limits on the result | `GroupFraming`, `CameraDeoccluder`, `CameraBounds` |
| 4. Noise | Drift on the drawn view | `CameraNoise`, `CameraImpulseListener` ([Noise, shake & impulses](/docs/graphics/camera/shake/)) |

Behaviour:

- The pipeline runs after the game's Update systems and reads each target's position for the current frame.
- Each stage computes in world space and writes through the camera's parent. A stage reads what earlier stages wrote in
  the same frame, so a camera that follows and looks at one character aims from where it stands in that frame.
- Noise moves only the drawn view, per camera, before the blend. The [camera director](/docs/graphics/camera/blending/#the-camera-director)
  then selects one live camera and blends into it. Camera shake is applied after that, to the drawn view only, never to
  a camera's `Transform`.
- The pipeline runs in **play mode only**; the editor's navigation view is not moved by it.

The `camera-shots` example combines every stage without camera code: a tracking shot on a rail, a crane on an orbit and
a wide shot.

## Follow a target

`FollowTarget` moves the camera after an entity. The follow is a frame-rate-independent damped move with a dead zone:
the camera ignores movement inside the dead zone and eases after the target outside it. A dead zone prevents jitter on
small movements; a larger `damping` gives a slower follow.

![The camera holds the target at a fixed offset from the view centre; the target roams free inside a deadzone circle and the camera eases after it once it leaves](@/assets/guides/camera-follow.svg)

```typescript
import { defineSystem, Query, Commands, Camera, FollowTarget } from 'esengine';

const follow = defineSystem([Query(Camera), Commands()], (cameras, cmds) => {
  for (const [cameraEntity] of cameras) {
    cmds.entity(cameraEntity).insert(FollowTarget, {
      target: playerEntity,   // the Entity to follow
      offsetY: 40,
      deadzone: 24,
      damping: 0.25,
    });
  }
});
```

| Property | Type | Default | Description |
|---|---|---|---|
| `target` | Entity | `0` | Entity to follow (`0` = none; `-1` from an older scene also reads as none). |
| `offsetX` | number | `0` | World-space X offset from the target (in world space also under a parent). |
| `offsetY` | number | `0` | World-space Y offset from the target. |
| `offsetZ` | number | `0` | World-space Z offset from the target (used by 3D follow). |
| `followZ` | boolean | `false` | Also follow the target's depth. Off for a flat scene, where the camera's z is its distance back from the plane. |
| `deadzone` | number | `0` | Radius in world units (a sphere in 3D) the target may move in before the camera moves. |
| `damping` | number | `0.25` | Smoothing time constant in seconds (larger = slower; `0` = snap). |

The data shape is exported as the `FollowTargetData` type. The follow writes the camera's `Transform` directly, so the
director blends views that are already followed.

## Frame a target by moving the camera

`PositionComposer` holds a target at a screen point by moving the camera, without turning it; it is the usual 2D
follow camera. Inside the dead zone the target moves while the camera stays still; past it the camera catches up, eased
by `damping`; the soft zone is the outer limit, and past its edge the camera moves at once. A 3D camera also keeps
`cameraDistance` from the target along its view direction.

```typescript
import { PositionComposer } from 'esengine';

cmds.entity(cameraEntity).insert(PositionComposer, {
  target: player,
  screenX: 0.4, screenY: 0.4,              // left of and below centre: room ahead of the player
  deadzoneWidth: 0.1, deadzoneHeight: 0.2, // walking does not move the camera
  softzoneWidth: 0.6, softzoneHeight: 0.6, // a dash never takes the player past here
  damping: 0.25,
});
```

| Property | Type | Default | Description |
|---|---|---|---|
| `target` | Entity | `0` | Entity framed (`0` = none). |
| `offsetX` / `offsetY` / `offsetZ` | number | `0` | Point framed, as a world-space offset from the target. |
| `screenX` / `screenY` | number | `0.5` | Where the target is held: `0` left or bottom edge, `1` right or top edge. |
| `deadzoneWidth` / `deadzoneHeight` | number | `0` | Share of the screen the target may move in with the camera still. |
| `softzoneWidth` / `softzoneHeight` | number | `0.8` | Share of the screen the target is kept inside; past its edge the camera moves at once. |
| `damping` | number | `0.3` | Seconds to catch up most of the way across the screen (`0` = at once). |
| `cameraDistance` | number | `0` | 3D: distance in front of the camera at which the target is kept. `0` keeps the current distance. |
| `depthDamping` | number | `0.3` | 3D: seconds to catch up most of the way to that distance. |

The camera moves across its own screen plane (its right and up axes), so a rotated camera moves like a dolly. An
orthographic camera's screen is `orthoSize` tall at any depth. `PositionComposer` is a position stage: a camera uses
it, `FollowTarget` or `CameraDolly`. The selected camera's viewport preview draws the dead and soft zones. The Follow
Camera 2D rig uses this component.

![A Follow Camera 2D created in a platformer scene: its camera preview inset in the scene view, and its Camera, Position Composer and Camera Impulse Listener components in Details](@/assets/guides/en/cam-position-composer-zones.png)
## Look at a target

`FollowTarget` determines where a camera stands; `LookAtTarget` determines where it looks. On a perspective camera,
`LookAtTarget` turns the camera so the target sits at a chosen screen point. The target may move inside a dead zone
around that point without the camera turning; outside it the camera turns only enough to bring the target back to the
zone's edge, eased by `damping`.

```typescript
import { LookAtTarget } from 'esengine';

cmds.entity(cameraEntity).insert(LookAtTarget, {
  target: hero,
  offsetY: 160,          // the head, not the feet
  screenX: 0.5,          // held in the middle...
  screenY: 0.6,          // ...above centre
  deadzoneWidth: 0.1,    // free to move across a tenth of the screen
  deadzoneHeight: 0.1,
  damping: 0.2,
});
```

| Property | Type | Default | Description |
|---|---|---|---|
| `target` | Entity | `0` | Entity to look at (`0` = none). |
| `offsetX` / `offsetY` / `offsetZ` | number | `0` | Point looked at, as a world-space offset from the target. |
| `screenX` | number | `0.5` | Horizontal screen position of the target: `0` left edge, `0.5` centre, `1` right edge. |
| `screenY` | number | `0.5` | Vertical screen position of the target: `0` bottom edge, `0.5` centre, `1` top edge. |
| `deadzoneWidth` / `deadzoneHeight` | number | `0` | Share of the screen the target may move in without the camera turning. |
| `damping` | number | `0.1` | Seconds to turn most of the way to the target (`0` = at once). Independent of frame rate. |

Constraints:

- The camera turns about world up and its own right axis, so it never rolls.
- A camera under a parent is turned in world space; its local rotation is derived through the parent.
- An orthographic camera is not turned: it draws a plane, and turning it would show the plane's edge.
- The screen point is measured on the camera's own `viewport` share of the screen, so the framing is the same on any
  screen aspect.

### Composition guides

When a camera with a `LookAtTarget` is selected, its viewport preview draws the composition: the screen point the
target is held at and the dead zone around it. Dragging the point sets `screenX`/`screenY`; dragging an edge of the
dead zone resizes it about the point. Each drag is one undo step.

## Ride a track

`CameraDolly` places a camera on a track: a `Spline` entity in the scene. It is a position stage, used instead of
`FollowTarget` or `PositionComposer`. `mode` selects the place on the track:

| Mode | Place on the track |
|---|---|
| `DollyMode.Fixed` | At `position`, for a script or an animation to move. |
| `DollyMode.TrackTarget` | At the point of the track nearest `target`, moved along it by `offset`. |
| `DollyMode.Speed` | Moving at `speed`, round a closed track or to the end of an open one. |

```typescript
import { CameraDolly, DollyMode, LookAtTarget } from 'esengine';

cmds.entity(cameraEntity)
  .insert(CameraDolly, { spline: railEntity, mode: DollyMode.TrackTarget, target: runner, offset: -150, damping: 0.4 })
  .insert(LookAtTarget, { target: runner });
```

| Property | Type | Default | Description |
|---|---|---|---|
| `spline` | Entity | `0` | The entity whose `Spline` is the track. |
| `mode` | number | `Fixed` | How the place on the track is chosen (`DollyMode`). |
| `position` | number | `0` | Place on the track, in world units from its start. Written back every frame, in every mode. |
| `target` | Entity | `0` | Entity a Track Target dolly keeps level with. |
| `offset` | number | `0` | World units ahead of (negative: behind) the point nearest the target. |
| `speed` | number | `0` | World units per second along the track in Speed mode; negative runs backwards. |
| `damping` | number | `0.3` | Seconds for a Track Target dolly to catch up most of the way; `0` is at once. |

Distances are measured along the curve in world units, so a scaled spline is longer. On a closed track a Track Target
dolly takes the shorter way round, so a target crossing the seam does not send the camera round the loop. The track is
the same curve a `PathFollower` follows.

## Frame several targets

`CameraTargetGroup` makes several entities one target. Each frame the group's entity is placed at the members' centre,
so any stage that takes a target (`FollowTarget`, `LookAtTarget`, `PositionComposer`, `CameraDolly`) frames the whole
group when given the group's entity. `GroupFraming` on the camera then sizes the shot: the box around the members, each
a sphere of the group's `radius`, is made to fill `framingSize` of the screen, by zooming or by dollying.

```typescript
import { CameraTargetGroup, GroupFraming, PositionComposer, FramingAdjustment } from 'esengine';

const players = cmds.spawn()
  .insert(Transform, {})
  .insert(CameraTargetGroup, { members: [p1, p2], weights: [1, 1], radius: 40 })
  .id();

cmds.entity(cameraEntity)
  .insert(PositionComposer, { target: players })
  .insert(GroupFraming, { framingSize: 0.7, adjustment: FramingAdjustment.Zoom });
```

| `CameraTargetGroup` | Type | Default | Description |
|---|---|---|---|
| `members` | Entity[] | `[]` | Entities framed together. |
| `weights` | number[] | `[]` | Each member's weight, in order; a missing weight is `1`, `0` excludes the member. |
| `radius` | number | `50` | Size of each member as a sphere about its origin: what the framing keeps on screen. |
| `center` | number | `Bounds` | Group position: `GroupCenter.Bounds` (middle of the box) or `GroupCenter.Average` (weighted average). |

| `GroupFraming` | Type | Default | Description |
|---|---|---|---|
| `group` | Entity | `0` | Group framed. `0` takes the group targeted by the camera's composer, look-at or follow. |
| `framingSize` | number | `0.8` | Share of the screen the group fills. |
| `mode` | number | `Both` | Fit `FramingMode.Horizontal`, `Vertical`, or whichever needs more room (`Both`). |
| `adjustment` | number | `Zoom` | `FramingAdjustment.Zoom` changes the lens (`orthoSize` or field of view); `DollyThenZoom` first moves the camera along its view direction, then zooms for what its distance range does not cover. |
| `damping` | number | `0.5` | Seconds to catch up most of the way (`0` = at once). |
| `minFov` / `maxFov` | number | `10` / `80` | Lens range in degrees. |
| `minOrthoSize` / `maxOrthoSize` | number | `1` / `5000` | Orthographic camera range. |
| `minDistance` / `maxDistance` | number | `100` / `5000` | Nearest and farthest dolly distance from the group's centre. |

The dolly is held separately from the position the rig gives the camera, so a camera that also follows the group backs
away smoothly instead of being moved one step per frame. The Target Group Camera 2D and Target Group Camera rigs create
a group and a camera framing it.

## Keep the target in sight

`CameraDeoccluder` keeps a 3D camera's target visible when geometry comes between them. A sphere is swept from the
target back to where the rig placed the camera; when it hits something, the camera is moved in along that line to just
short of the hit. Moving along that line keeps the target at its composed screen position. When the obstruction is
gone, the camera eases back out to where its rig places it; the rig's own stages never see the pulled-in position.

```typescript
import { CameraDeoccluder } from 'esengine';

cmds.entity(cameraEntity).insert(CameraDeoccluder, {
  radius: 15,               // stop this far short of a wall
  minimumDistance: 30,      // never closer to the target than this
  dampingWhenOccluded: 0,   // move in at once, so the wall is never seen through
  damping: 0.4,             // move back out over about 0.4 s
});
```

| Property | Type | Default | Description |
|---|---|---|---|
| `target` | Entity | `0` | Entity kept in sight. `0` takes the `LookAtTarget`'s target (with its offset), else the `FollowTarget`'s. |
| `radius` | number | `15` | Radius of the swept sphere: how far short of a wall the camera stops. |
| `layers` | number | `0` | Physics layers that hide the target; `0` is every layer. |
| `minimumDistance` | number | `30` | Minimum distance from the camera to the target. |
| `dampingWhenOccluded` | number | `0` | Seconds to move in when something hides the target; `0` is at once. |
| `damping` | number | `0.4` | Seconds to move back out once nothing does. |

The sweep queries the 3D physics world, so only bodies with 3D colliders hide a target; in a scene without 3D physics
the camera stays where its rig placed it. The Tracking Camera rig includes this component.

## Keep the camera inside the level

`CameraBounds` keeps the camera's view inside a world rectangle, so the level's edge stays at the edge of the screen.

```typescript
import { CameraBounds } from 'esengine';

cmds.entity(cameraEntity).insert(CameraBounds, {
  minX: -1280, maxX: 1280,   // the level's world rectangle
  minY: -768,  maxY: 768,
});
```

| Property | Type | Default | Description |
|---|---|---|---|
| `minX` / `maxX` | number | `0` | Horizontal interval the view stays inside. |
| `minY` / `maxY` | number | `0` | Vertical interval the view stays inside. |

Behaviour:

- Each axis is constrained only when it names a real interval (`max > min`). An axis left at `0`/`0`, or with
  `max ≤ min`, is unconstrained. A level that scrolls sideways without limit bounds only the vertical axis.
- When an interval is narrower than the view, the whole interval is shown centred.
- The clamp runs after every stage that moves a camera, `FollowTarget` included: it constrains where the camera ends
  the frame, regardless of what moved it.
- Orthographic cameras only. A perspective camera's half extents depend on the distance to the subject, which no
  camera property describes.
- Play mode only.
