The `Video` component decodes a clip into a GPU texture that is refreshed every frame and writes that texture to a
renderable on the same entity: a `Sprite`, a `UIVisual` or a `MeshRenderer`. On the web an `HTMLVideoElement` decodes
the clip; on native and mini-game targets an engine-owned MPEG-1 decoder compiled to wasm decodes a cooked copy. The
texture contract is the same on every platform.

## The `Video` component

In the editor, add a **Video** component to an entity that has a **Sprite** and set its **Source**. In code, insert it
alongside the renderable:

```typescript
import { defineSystem, Commands, Transform, Sprite, Video } from 'esengine';

const spawnScreen = defineSystem([Commands()], (cmds) => {
  cmds.spawn()
    .insert(Transform, { position: { x: 0, y: 0, z: 0 } })
    .insert(Sprite, { size: { x: 360, y: 360 } })
    .insert(Video, { source: 'assets/clip.mp4', autoplay: true, loop: true, muted: true });
});
```

| Property | Type | Default | Description |
|---|---|---|---|
| `source` | asset | `''` | The video clip. Changing it stops the current stream and starts the new clip. |
| `autoplay` | boolean | `true` | Start as soon as the first frame is ready. |
| `loop` | boolean | `true` | Restart from the beginning at the end. |
| `muted` | boolean | `true` | Mute audio. Muted clips autoplay; unmuted playback needs a user gesture. |
| `volume` | number | `1.0` | Audio volume, 0–1 (ignored while `muted`). |
| `playbackRate` | number | `1.0` | Playback speed and pitch (`1` = normal). |
| `fitSize` | boolean | `true` | Resize the `Sprite` to the video's native pixel size once frames arrive. Applies to `Sprite` only. |
| `enabled` | boolean | `true` | `false` stops and releases the stream without removing the component. |

`volume`, `muted`, `loop` and `playbackRate` are applied to the running stream when they change. Clearing `source`,
disabling the component or despawning the entity stops and releases the stream.

### Renderables

The video system writes the frame texture to the first renderable it finds on the entity, in this order:

| Renderable | Written fields | Use |
|---|---|---|
| `Sprite` | `texture`; `size` when `fitSize` is set | Video in the world. |
| `UIVisual` | `texture`; `visualType` set to `Image` | A video panel in screen UI. |
| `MeshRenderer` | `texture` | A clip mapped onto custom geometry. |

An entity with a `Video` and no renderable decodes but displays nothing, and the console logs a warning once for it.

### Behaviour

- Video decodes in **play mode only**; nothing decodes while the scene is being edited.
- The video plugin is part of the default plugin set, as audio is; no plugin needs to be added.
- The frame texture is **pathless** (never evicted) and its handle is stable for the life of the stream, so a handle
  written once stays valid.

<Aside type="note">
  Muted clips autoplay on every platform. Unmuted autoplay is blocked by browsers until a user gesture, so sound-on
  playback starts from a tap or a key press.
</Aside>

## Sharing one stream across surfaces

The frame texture is a plain texture handle, so any number of sprites can use it: read the playing sprite's `texture`
and assign it to the others. Each surface selects a **region** of the frame with the Sprite's `uvOffset` / `uvScale`
(the convention atlas frames use, where `v = 0` is the image's bottom row). One decode feeds every surface.

```typescript
// Mirror the live video texture onto every tile; each tile samples a 1/N region.
const shareVideoTexture = defineSystem(
  [Query(Sprite, Video), Query(Mut(Sprite), PuzzlePiece)],
  (preview, pieces) => {
    let texture = 0;
    for (const [, sprite] of preview) { texture = sprite.texture; break; }
    if (!texture) return;                       // first frame not decoded yet
    for (const [, sprite] of pieces) {
      if (sprite.texture !== texture) sprite.texture = texture;   // one write per piece
    }
  },
);
```

The **video-puzzle** example uses this pattern to turn one clip into a board of live, swappable tiles.

## `VideoPlayer`

The `VideoPlayer` resource plays a source without a component and returns a **stream handle** whose `textureHandle`
can be assigned to any sprite or material:

```typescript
import { defineSystem, Res, VideoPlayer } from 'esengine';

const playIntro = defineSystem([Res(VideoPlayer)], (video) => {
  const stream = video.play('assets/intro.mp4', { loop: false, muted: true });
  stream.onEnded = () => { /* advance past the intro */ };
  // assign stream.textureHandle onto a Sprite/MeshRenderer once stream.isReady
});
```

| `VideoPlayer` method | Description |
|---|---|
| `play(source, options?)` | Starts a stream and returns its handle. |
| `stop(handle)` | Stops and releases one stream. |
| `stopAll()` | Stops every stream. |

`play` options are those of the component, with different defaults:

| Option | Default |
|---|---|
| `autoplay` | `true` |
| `loop` | `false` |
| `muted` | `false` |
| `volume` | `1` |
| `playbackRate` | `1` |

Stream handle members:

| Member | Kind | Description |
|---|---|---|
| `play()` / `pause()` / `stop()` | method | Transport control. |
| `seek(seconds)` | method | Jump to a time. |
| `setVolume(v)` / `setMuted(m)` | method | Audio adjustment. |
| `setLoop(l)` / `setPlaybackRate(r)` | method | Loop and speed adjustment. |
| `textureHandle` | readonly | The live frame texture: `0` until the first frame, then pathless (never evicted). |
| `width` / `height` | readonly | Native pixel size. |
| `isReady` | readonly | The first frame has decoded. |
| `isPlaying` | readonly | Currently playing. |
| `currentTime` / `duration` | readonly | Seconds. |
| `onReady` / `onEnded` / `onError` | callback | Lifecycle hooks. |

## Import settings

Selecting a video asset shows a looping, muted preview and its **Import Settings**. Playback settings (autoplay, loop,
muted) belong to the `Video` component, not to the asset. Two **advanced** settings control the transcode for the wasm
decode path:

| Setting | Range | Default | Description |
|---|---|---|---|
| **Cook Quality** | `2`–`31` | `4` | MPEG-1 quantizer. `2` is near-lossless with the largest file; `31` is the smallest. |
| **Cook Audio Bitrate** | `96` / `128` / `192` kbps | `128` | AAC bitrate of the demuxed audio track. |

{/* SHOT: video-import-settings | Details panel with an .mp4 video asset selected in the Content Browser: the video preview at the top and the Import Settings with the Advanced group expanded, showing Cook Quality 4 and Cook Audio Bitrate 128 kbps. */}

Video assets are `.mp4`, `.m4v` and `.mov` containers, MPEG-1 `.mpg` / `.mpeg` sources, and cooked `.esv` files. A
`.webm` file is classified as audio unless its `.meta` type is `video`.

## Cooked video

Exports for Android, iOS, native desktop, WeChat and the other mini-game platforms transcode each shipped video into a
codec-tagged **`.esv`** (MPEG-1 Program Stream) plus an **`.m4a`** audio-track sibling. This is the format the wasm
decoder reads; the audio track plays through the audio pipeline and serves as the video's clock. Web exports ship the
original file unchanged.

## Platform backends

The texture-handle contract is the same on every backend; only the decoder differs.

| Platform | Decoder | Notes |
|---|---|---|
| Web, editor Play | `HTMLVideoElement` | Any browser-supported codec (H.264 `.mp4`, WebM, …). WebGL2 uploads each frame zero-copy; WebGPU uses a canvas readback. |
| Native (Android, iOS, desktop) | The engine-owned wasm decoder, acquired as a side module | Plays the cooked `.esv` + `.m4a`; there is no other video path on a device. |
| WeChat | Engine-owned MPEG-1 wasm decoder (`videodec`, pl_mpeg) | Deterministic on every device; `wx.createVideoDecoder` is absent on PC and unreliable on phones. Ships automatically when a scene uses `Video`; plays the cooked `.esv` + `.m4a`. |
| Other mini-game platforms | The same engine-owned wasm decoder, by default on every vendor | Host video decoders are absent on desktop clients and unreliable on phones. |

## Guidelines

- Keep `muted: true` for autoplay; start sound-on playback from a user gesture.
- Share one stream across surfaces through the texture handle and `uvOffset` / `uvScale`, rather than several `Video`
  components decoding the same clip.
- Turn `fitSize` off when the Sprite has an explicit size (a fixed screen).
- Keep clips short and modest in resolution for native and mini-game targets: software decode cost and download size
  both grow with resolution.
