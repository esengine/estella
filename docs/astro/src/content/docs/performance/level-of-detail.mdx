**`LODGroup`** replaces a mesh with cheaper stand-ins as it shrinks on screen and stops drawing it below a minimum size.
**`Impostor`** replaces a distant mesh with a camera-facing picture of it.

## The LODGroup component

`LODGroup` sits on the **same entity as a `MeshRenderer`**. The renderer's mesh is level 0, the full-detail mesh; the
group lists the meshes that replace it as it shrinks:

```typescript
world.insert(rock, MeshRenderer, { mesh: 'assets/models/rock-lod0.esmesh', lit: true });
world.insert(rock, LODGroup, {
    lod1: 'assets/models/rock-lod1.esmesh',
    lod2: 'assets/models/rock-lod2.esmesh',
    lod1Size: 0.25,   // below a quarter of the screen height, lod1 is drawn
    lod2Size: 0.11,   // below 0.11, lod2
    cullSize: 0.02,   // below a fiftieth, nothing is drawn
    hysteresis: 0.1,
});
```

Removing the component restores the full-detail mesh.

![Details of a LOD Group: the current level, the projected size, the level table and the three level meshes](@/assets/guides/en/details-lod-group.png)

*A **LOD Group** in the editor: the level in use, the entity's projected size and the threshold table.*

| Field | Type | Default | Description |
|---|---|---|---|
| `lod1` / `lod2` / `lod3` | mesh | — | Stand-in meshes, coarsest last. |
| `lod1Size` | number | `0.5` | Screen-height fraction below which `lod1` is drawn. |
| `lod2Size` | number | `0.25` | Screen-height fraction below which `lod2` is drawn. |
| `lod3Size` | number | `0.1` | Screen-height fraction below which `lod3` is drawn. |
| `cullSize` | number | `0.02` | Screen-height fraction below which nothing is drawn; `0` never culls. |
| `hysteresis` | number | `0.1` | Fraction an object must grow past a threshold before the finer level returns (0–1). |
| `enabled` | boolean | `true` | Off: the renderer's own mesh is always drawn. |

`LODMember` draws its own `MeshRenderer` only while another entity's `LODGroup` selects its level, for levels that are
whole entities (such as a groom's strands and its cards).

## Screen-size thresholds

`lod1Size` and the other sizes are the fraction of the **viewport height** covered by the object's bounds: `1.0` is an
object exactly one screen tall, `0.02` a fiftieth of it.

A screen fraction, unlike a distance, accounts for object size, field of view and orthographic projection, and is
independent of resolution, so one value applies on phones and desktops. The quality level's **LOD distance scale**
multiplies the measured size ([View Distance & Draws](/docs/performance/quality-levels/settings/#view-distance--draws)).

<Aside type="tip">
To choose thresholds, place the camera where the action happens and estimate the fraction of the window height the
object covers. Objects under about 5% are candidates for the coarsest mesh.
</Aside>

## Hysteresis

A threshold crossed at a single value flips back and forth when the camera moves slightly. `hysteresis` makes each
threshold asymmetric: an object switches to the coarser mesh at the threshold and returns only after growing past it by
that fraction. With the default `0.1` and `lod1Size: 0.20`:

- shrinking below **0.20** switches to level 1;
- growing above **0.22** returns to level 0.

`0` gives a bare threshold. Hysteresis also applies to `cullSize`.

## Selection

- **Per camera.** Two cameras in one frame (a main view and a minimap, or split screen) can draw the same object at
  different levels. The entity has no `currentLOD` field.
- **Measured on the union of all levels' bounds**, so the measured size does not change with the level drawn.
- **After frustum culling.** Objects outside the frustum are not measured.
- **Compatible with instancing.** Selecting a level only changes the mesh a draw references, so props at the same level
  are still drawn as one instanced call.

## Authoring rules

- Fill the slots in order: `lod1`, then `lod2`, then `lod3`. An empty slot ends the chain; later slots are never reached,
  and the engine warns.
- The sizes must decrease: `lod2Size` below `lod1Size`, and so on.
- `cullSize: 0` disables culling, so the group is never invisible.
- A group may have no stand-ins. With only `cullSize`, it draws the renderer's mesh while large enough and nothing below
  that, which suits objects with no cheaper version, such as grass tufts.
- Levels can be generated at import with **Generate LODs**, which also adds the `LODGroup`
  ([Generated levels of detail](/docs/assets/models/geometry/#generated-levels-of-detail)).
- Every level of a skinned group must share one skeleton (the same joint count). A level that differs is drawn in its
  bind pose, and the engine reports it.

## Impostors

An `Impostor` next to a `MeshRenderer` replaces the mesh with a camera-facing card once the object covers less than
`screenSize` of the view height. The card shows a picture of the mesh taken from the direction of the view.

```typescript
world.insert(tree, Impostor, { screenSize: 0.06, frames: 8, resolution: 1024 });
```

| Field | Type | Default | Description |
|---|---|---|---|
| `screenSize` | number | `0.06` | Screen-height fraction below which the card replaces the mesh. |
| `frames` | number | `8` | Pictures along each side of the atlas (`frames × frames` in all), 2–16. More pictures give smaller steps as the view goes round, each at a lower resolution. |
| `resolution` | number | `1024` | Atlas side in pixels, 128–4096; each picture is `resolution / frames`. |
| `enabled` | boolean | `true` | Off: the mesh is always drawn. |

- **Capture.** Pictures are taken while the game runs, once per kind: `frames × frames` orthographic cameras look at a copy
  of the mesh from directions over the upper hemisphere, each into its own atlas cell. They are ordinary cameras, so the
  pictures include the mesh's material, textures and the scene's light on every backend. Entities with the same mesh,
  material, texture and colour share one atlas; kinds are captured one after another, a frame or two each.
- **Drawing.** Each view draws the picture taken closest to its direction on a square facing it. Cards are drawn through
  the sprite batch, so cards whose atlases fit in one draw's texture slots are one draw. The quality level's **LOD distance
  scale** also applies to `screenSize`.
- **Limits.** A picture keeps the lighting it was captured in, in the object's own frame: a rotated object is lit as if
  the light rotated with it, so impostors suit objects that are softly lit or not rotated. The picture changes in steps as
  the view goes round. Cards cast no shadow and are not seen from below. Pictures are captured in Play and in built games,
  not in the editor viewport.

## Baking static cluster proxies

Node authoring tools can call `bakeStaticProxy` from `@estella/pipeline` to merge and simplify an already-partitioned
cluster of static surfaces. Each source supplies decoded mesh data, a world matrix, its draw state and an explicit motion
and blending classification. The baker uses the same geometry merge and draw grouping as static batching.

```typescript
import { bakeStaticProxy } from '@estella/pipeline';

const proxy = await bakeStaticProxy(sources, {
    origin: [1000, 0, 2000],
    ratio: 0.25,
    maxWorldError: 0.05,
});
```

| Option | Description |
|---|---|
| `origin` | Cluster-local origin; the returned meshes are placed here. |
| `ratio` | Target triangle share, in (0, 1]. The error limit takes precedence and can keep more triangles. |
| `maxWorldError` | Maximum simplification error in world units, independent of the cluster's extent. |
| `pruneDisconnected` | Allows small disconnected pieces to be removed within the error bound. Off by default; requires visual review. |
| `maxVertices` | Vertex budget per group before simplification. |

- The result contains cluster-local meshes with their original draw state, source ids, triangle and byte counts before
  and after, the measured error and input fingerprints. Material, texture, tint, layer, lighting and shadow differences
  remain separate draws.
- The caller writes the mesh assets and resolves draw identifiers to asset references; the API does not modify a scene.
- Vertex colours and both UV sets contribute to the simplification error. Setting `preserveGeometry: true` on a source
  (emissive or other high-contrast surfaces) preserves the geometry of its whole group while still allowing merging.
- Moving, deformed, billboard, blended, baked-light, skinned and morphing surfaces are returned in `refused` and remain
  the caller's responsibility.

A streamed world uses the same grouping for its cells: with **Far proxies** enabled on `StreamedWorld`, each cell ships a
baked stand-in that is shown while the cell is not resident ([World Streaming](/docs/world/streaming/)). The proxy does
not bake its own texture or emission, and there is no chain of coarser proxies further out.

## Scope

`LODGroup` changes how one object is drawn at different sizes. It does not stream: every level's mesh is resident, and an
object below `cullSize` is not drawn but remains in the world. Related systems:

- [World Streaming](/docs/world/streaming/) loads a world in cells, with far proxies from the baker above.
- [Foliage](/docs/graphics/foliage/): far versions of plants (`Foliage`, `PlacedFoliage`).
- [Terrain](/docs/graphics/terrain/overview/): the terrain's distance-based quadtree.
- [Static Batching](/docs/performance/static-batching/) merges different meshes to save draws without simplifying them.
- [Texture streaming](/docs/performance/quality-levels/texture-streaming/) holds textures at the size their views need.
- [Cluster LOD](/docs/assets/models/geometry/#cluster-lod) draws dense static meshes per view without a `LODGroup`.
