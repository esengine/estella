The renderer already draws **copies of one mesh** as a single instanced draw. **Different meshes** are separate ranges of
GPU memory and cost one draw each per material. `StaticBatch` merges different static meshes that share their draw state
into one mesh per area; `CompositeBatch` does the same for a model that moves as a whole.

| Content | Use |
|---|---|
| Many copies of one mesh | Instancing (automatic) |
| Many different meshes that do not move | `StaticBatch` |
| A model of many parts that moves as a whole (ship, vehicle, platform) | `CompositeBatch` |

## `StaticBatch`

Add `StaticBatch` to a mesh that will not move. While the game runs, the marked meshes that share material, texture,
colour and layer are merged into one mesh per area.

```typescript
world.insert(wall, MeshRenderer, { mesh: 'builtin:cube', material });
world.insert(wall, StaticBatch, {});
```

In the editor, select the meshes and choose **Static Batch** from the Outliner's menu.

| Field | Type | Default | Description |
|---|---|---|---|
| `group` | string | `''` | Meshes merge only with others of the same group, so two rooms can be kept apart. Empty is the default group. |
| `state` | `StaticBatchState` | Waiting | Read-only: what the last pass did with this mesh (merged, or the reason it was not). |
| `batched` | number | `0` | Read-only: meshes drawn together with this one, itself included; `0` unless merged. |

`StaticBatch` is `@experimental`.

## Merging

- Meshes are grouped by everything a draw owns (material, texture, normal map, colour, layer, culling, lighting and
  shadow-casting flags) and by `group`.
- Each group is divided into world cells, so a batch covers a neighbourhood and remains cullable. A cell is 1,600 world
  units on a side and holds at most 262,144 vertices.
- Marked entities stay as authored: scripts find them, colliders collide and the editor picks them. Only their drawing
  moves to the merged mesh, which is a separate entity.
- A merged mesh **must not move**. Destroying one is supported (its batch is rebuilt without it); moving one is not
  detected.
- Batches are rescanned every **Batch scan interval** frames of the quality level (60 at Low, 30 at Medium and High;
  [View Distance & Draws](/docs/performance/quality-levels/settings/#view-distance--draws)).

## Meshes that are not merged

A mesh that cannot be merged keeps drawing itself and reports why in `state` and in the Profiler's **Static batch**
section.

| Reason | Cause |
|---|---|
| Skinned | A draw has a single pose. |
| Morphing | A draw has a single shape. |
| Level of detail | The renderer selects among levels at run time. |
| Billboard | It turns to each view; a merged mesh stays where it was baked. |
| Blended | Its result depends on draw order, which merging discards. |
| Moves | A dynamic body or character controller. |
| Baked light | The scene has light probes or a bake; a merged mesh cannot keep each part's own baked lighting. |
| No mesh yet | The mesh is still loading or failed to load. |
| Switched off | Nothing is drawn. |
| Vertex layout | Positions or normals that are not 32-bit floats, which the merge cannot transform. |
| Alone in its group | Merging one mesh saves nothing and costs memory. |

## Memory cost

Merging copies every part's vertices into the merged mesh: it **spends memory to save draws**. A mesh that stood for a
hundred instances becomes a hundred copies. The Profiler shows, for each merged mesh, the parts it holds, the draws they
cost before merging and the memory of the copy.

Merged vertices are transformed on the CPU in 32-bit floats, so pixels along geometry edges can differ slightly from the
unmerged frame.

## `CompositeBatch`: moving models

`StaticBatch` bakes each part where it stands in the world, so a moving model assembled from parts cannot use it. Add
**`CompositeBatch`** to the model's **root**; the parts need no component.

```typescript
const ship = world.spawn('Ship');
world.insert(ship, Transform, {});
world.insert(ship, CompositeBatch, {});
// planks, posts and props are parented under `ship`, each with its own MeshRenderer.
```

| Field | Default | Description |
|---|---|---|
| **Instance at** (`instanceMin`) | `4` | Parts of one mesh at or above this count are drawn as one instanced set, without copying vertices; fewer are merged. Minimum 2. |
| **Chunk size** (`cellSize`) | `0` | Side of a merge chunk in the root's space; `0` chooses from the model's size. Smaller chunks re-merge less on edits and cull better. |
| **Batched parts** (`parts`) | — | Read-only: meshes under the root the pass draws. |
| **Instanced parts** (`instanced`) | — | Read-only: parts drawn as instanced sets. |
| **Draws** (`draws`) | — | Read-only: draws the model takes now. |
| **Draws before** (`drawsBefore`) | — | Read-only: draws the same parts took before batching. |
| **Moving parts** (`moving`) | — | Read-only: parts that kept moving and were released to draw themselves. |

While the game runs, parts are merged in the **root's own space** and the meshes that draw them are children of the root:

- Moving, rotating or scaling the root moves the whole model without re-merging.
- A mesh repeated at least **Instance at** times (a deck plank, a rail post) stays one resident mesh, drawn as one
  instanced set.
- Other parts are merged by draw state into chunks of the root's space. Adding, removing, re-meshing or moving a part
  re-merges only its chunk at the next scan (**Batch scan interval**).
  `app.getResource(CompositeBatchingRes).refresh(root)` rescans at once.
- Changing a part's `MeshRenderer.castShadows` regroups it at the next scan. Shadow casters and non-casters are kept in
  separate instance sets and chunks, even with the same material.
- A part that keeps moving within the model (a door, a wheel) is released after three consecutive changed scans and draws
  itself, so it does not cause a merge every frame.
- The `StaticBatch` exclusions apply: skinned, morphing, LOD, billboard and blended parts and dynamic bodies draw
  themselves. A part under a composite is never also statically batched.

The saving of `CompositeBatch` is mostly on the CPU (collecting, culling and sorting every part each frame), since
repeated meshes are already instanced. It grows with the part count; for a model with few parts, the periodic scans can
cost as much as they save.

`CompositeBatch` is `@experimental`.

## Instance bounds

Native instance groups, also used by foliage, bound every placement using both mesh LODs and the material's declared
`vertexbounds`, including placement rotation, scale and shear. A material that moves vertices must declare its full local
displacement, or a visible surface can be culled at a view edge.

Shadow-map coverage uses the same LOD geometry and declared displacement, transformed through every placement and its
parent. Empty instance groups add no bounds. Receiver, caster and hair-focus bounds are gathered in one traversal, so
instancing does not move a shadow map away from the geometry it must cover.
