Steam is a **channel of the Desktop target**. It adds no runtime, renderer or asset format: a Steam build is a desktop
build plus the files SteamPipe needs.

The desktop build is a native app: the engine's C++ core with an embedded [Dawn](https://dawn.googlesource.com/dawn)
(Metal on macOS, D3D12 on Windows, Vulkan on Linux) on SDL3, and a JavaScript engine — [V8](https://v8.dev/) with JIT
on Windows, [QuickJS-ng](https://github.com/quickjs-ng/quickjs) on macOS and Linux. The process contains no browser, so
the Steam overlay, Steam Input and exclusive fullscreen work as for any native game.

<Aside type="note" title="Runtime template">
  The desktop runtime is a **runtime template** installed once per editor version from the Desktop row of Package
  Project, one per OS. The assembler is plain Node, so a Windows template installed on a Mac produces the Windows build
  from the same export.
</Aside>

## Prerequisites

<Steps>

1. **A Steamworks app.** An App ID from the Steamworks partner backend. Depots, launch options and achievements are
   configured there; no build writes to them.

2. **The Steamworks SDK**, downloaded from the partner site. Estella does not ship it: its redistribution is licensed
   to Steamworks partners, and the runtime template is one prebuilt binary shared by every game.

3. **`steamcmd`**, Valve's uploader. Log in once in a terminal so Steam Guard is satisfied and cached; Estella stores
   no password.

</Steps>

## Channel settings

In **Build → Package Project…**, select **Steam** under Desktop in the target list. Selecting it sets the Desktop
target's **Channel** to Steam.

![The Package Project dialog on Desktop → Steam: the Channel row set to Steam, and the Steam group with App ID, Steamworks SDK and the per-OS depot ids](@/assets/guides/en/steam-channel.png)

| Setting | Description |
|---|---|
| **Channel** | `Steam` writes the depot scripts beside the build. Same value as selecting Steam in the target list. |
| **Steam App ID** | From the partner backend. Without it no scripts are written. |
| **Steamworks SDK** | The downloaded SDK. Its `redistributable_bin/<os>/` library ships inside the app. |
| **Depot IDs** | 0 uses `App ID + 1`, and so on. Valve assigns depot ids; `STEAM.md` lists the ones used for verification. |

Achievement ids are a project-wide setting: **Settings → Project → Build and modules → Packaging → Achievement IDs**
([Achievements](#achievements)).

The CLI equivalents are `--steam-sdk <dir>` and `--steam-appid <id>` on `pipeline/bin/estella.mjs export --platform desktop`.

## Output

```
dist-desktop/
  MyGame.app/            ← macOS, and/or
  MyGame/                ← Windows: MyGame.exe + Content/
                         ← Linux:   MyGame     + Content/
  steam/
    app_build_<appid>.vdf
    depot_<id>_<os>.vdf
  STEAM.md               ← this build's own values
```

`STEAM.md` lists the values to enter in the partner backend for this build: the launch executable per OS, the depot
ids used, the Auto-Cloud paths the game writes to, and the achievement ids to create. **Open STEAM.md** in the build
result opens it.

<Aside type="caution" title="steam_appid.txt is never written">
  `steam_appid.txt` lets a build run outside Steam, and shipping it in a depot disables Steam's launch check. The
  export never writes it.
</Aside>

## Uploading

```bash
steamcmd +login <your-account> +run_app_build "…/steam/app_build_<appid>.vdf" +quit
```

The generated build script contains `Preview "1"`, so the first run uploads nothing and reports what it would do.
Remove the line to upload. `SetLive` is empty: setting a branch live is done in the partner backend.

## Achievements

`Achievements` is an engine service, like `Ads` and `Leaderboard`, so game code is the same with or without a store:

```ts
import { Achievements } from 'esengine';

const achievements = world.getResource(Achievements);
achievements.setStat('enemies_defeated', count);
await achievements.unlock('FIRST_BLOOD');
await achievements.store();      // pushes to Steam; stores batch behind this
```

Unlocks are always recorded locally, in the same data an in-game achievements screen reads. `available` reports
whether a store also receives them, which a UI uses to choose between the platform's notification and its own.

| Failure mode | Handling |
|---|---|
| An id the backend does not define | Ids are declared in **Achievement IDs**; an unlock outside that list is refused at the call, with the declared ids listed. |
| A build without the Steam library | The export warns when the SDK setting is missing, and `STEAM.md` states it at the top. |

## Cloud saves

`Storage` writes to the OS's standard per-user location, which Steam Auto-Cloud can sync without code. Under
**Steam Cloud → Auto-Cloud** in the partner backend, use the roots listed in `STEAM.md`:

| OS | Root | Subdirectory |
|---|---|---|
| Windows | `WinAppDataRoaming` | `Estella/<Name>` |
| macOS | `MacHome` | `Library/Application Support/Estella/<Name>` |
| Linux | `LinuxHome` | `.local/share/Estella/<Name>` |

## Limitations

- **macOS builds are signed ad-hoc**, and only when built on a Mac. Notarize with a Developer ID before public
  release.
- **`steamcmd` is not run by the editor.** `STEAM.md` gives the exact command.
- **Not covered:** Workshop, DLC, microtransactions and Steam Input action sets.
