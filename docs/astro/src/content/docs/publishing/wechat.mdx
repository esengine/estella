The **WeChat** target exports the project as a WeChat MiniGame package, which is opened, tested and submitted in
WeChat DevTools.

## WeChat runtime

WeChat loads WebAssembly through `WXWebAssembly`, so it uses a separate engine build with WeChat shims, plus WeChat
builds of the side modules. The editor download includes them. In an engine source checkout, build them once:

```bash
node build-tools/cli.js build -t wechat
# side modules, only if the game uses them:
node build-tools/cli.js build -t physics-wechat     # physics
node build-tools/cli.js build -t spine-wechat       # Spine (builds 2.1 + 3.8 + 4.1 + 4.2 + 4.3)
node build-tools/cli.js build -t dragonbones-wechat # DragonBones
node build-tools/cli.js build -t basis-wechat       # KTX2 / compressed textures
node build-tools/cli.js build -t videodec-wechat    # video (MPEG-1 wasm decoder)
```

<Aside type="note">
  **A missing runtime is an export error.** If a scene uses physics or Spine, or the build ships KTX2 textures, and the
  matching `*-wechat` module is not built, the export stops and names the build command. Only the side modules the
  scenes need are staged into the package.
</Aside>

## Exporting

<Steps>

1. Open **Build → Package Project…** and select **WeChat** under Mini-Games.
2. In the WeChat target settings, set the **AppID**. Orientation is the project-wide setting **Settings → Project →
   Game → Display → Orientation**, written as `deviceOrientation` in `game.json`.
3. Review **Scenes in build** and click **Package**. The export cooks assets, bundles the SDK and scripts as CommonJS
   with esbuild, transforms scenes, and writes the package.
4. Open the output folder in **WeChat DevTools** to compile, test and submit. If the AppID was left empty, set it in
   `project.config.json` from DevTools.

</Steps>

### Target settings

| Setting | Default | Description |
|---|---|---|
| **AppID** | empty | Written into `project.config.json`. |
| **Compress wasm binaries** | off | Ships the engine and every side module as `.wasm.br`. See [Engine binary](#engine-binary). |
| **Engine in a subpackage** | off | Moves the engine binary into a subpackage loaded at startup. |
| **Render through EmscriptenGLX** | off | Links the engine with WeChat's EmscriptenGLX. See [EmscriptenGLX](#emscriptenglx). |

### Package layout

| Path | Contents |
|---|---|
| `game.js` | Entry; boots `game-bundle.js`. |
| `game-bundle.js` | The SDK and the project's scripts. |
| `game.json`, `project.config.json` | WeChat configuration. |
| `asset-manifest.json` | The addressable asset manifest. |
| `scenes/<name>.json` | Each scene in the build; non-startup scenes load on their first `SceneManager.switchTo` ([Scenes](/docs/world/scenes/)). |
| `wasm/` | The engine and the side modules the scenes need. |

<Aside type="caution">
  Do not edit `game.js` or rename files under `wasm/`. The boot sequence instantiates exactly those staged files.
</Aside>

## Compressed textures

With **Textures by import settings** ticked under Compression, textures cook to KTX2 according to their
**Compression** import setting (Auto, GPU compressed or Original image). WeChat-specific handling:

- The Basis transcoder ships as the `basis-wechat` side module; without it the export fails with the build command.
- WeChat's code package accepts only whitelisted file suffixes, and `ktx2` is not one. The exporter stages each
  `.ktx2` as `.ktx2.bin`, and the runtime resolves both spellings. The exporter also writes `packOptions.include`
  rules in `project.config.json` for every staged custom extension (`.skel`, `.atlas`, `.bin`, …) so DevTools packs
  them.

## Engine binary

The engine `.wasm` is the largest single file in a mini-game. Two settings keep it out of the 4 MB main package:

- **Compress wasm binaries** (also **Compress the engine binary** under Compression; same setting) ships the engine
  and every side module as `.wasm.br`, about a third of the size, decompressed by WeChat on load. It requires **base
  library 2.14.0** or later. The package carries only the compressed file and the version is not checked at run time,
  so set the mini-game's minimum base library to 2.14.0 in the WeChat console.
- **Engine in a subpackage** moves the binary into a subpackage (分包) loaded at startup. It no longer counts toward
  the main package; startup waits for the download, and the loading bar shows its progress.

## EmscriptenGLX

WeChat's EmscriptenGLX executes the engine's GL calls inside the wasm and passes them to the host in batches instead
of calling into JavaScript for each one; in a draw-heavy scene render time is about 12% lower. Turn on **Render
through EmscriptenGLX** and build the engine once:

```bash
node build-tools/cli.js build -t wechat-glx
```

The build downloads WeChat's library at a pinned version, checks its hash, and uses emsdk 4.0.10 (installed into
`tools/emsdk-glx` on first use), the version the library is published for. It adds about 310 KB of wasm.

It takes effect on Android with base library 3.8.12 or later, and on iOS in 高性能+ mode. Other hosts, including
DevTools, render through WebGL2. The log's `rendering through …` line states which path a device used.

## Subpackages

Lazy asset groups become WeChat `subPackages` in `game.json`. The first read of a file in `level2` waits for
`wx.loadSubpackage` to succeed. You can also load the whole group ahead of time with `assets.loadGroup('level2')`.

```json
{
  "deviceOrientation": "landscape",
  "subPackages": [
    { "name": "level2", "root": "subpackages/level2" }
  ]
}
```

## Recommendations

- **Keep the main package under 4 MB** by moving on-demand content into subpackages ([Assets](/docs/assets/overview/)).
  The export sets `bigPackageSizeSupport`, so an oversized package still previews in DevTools, but upload enforces the
  limit. See [Package Size](/docs/publishing/package-size/).
- **Compress textures** with **Textures by import settings**.
- **Test in WeChat DevTools** and on devices; the file system, storage and socket backends differ from the web.
- **Preload the next level's group** with `loadGroup` during play so the subpackage download does not delay the
  transition.

## Starter project

The **WeChat Mini Game** template in the launcher creates a CC0 fleet game with a login-code/server-exchange hook, a
share request, a configured rewarded video and device-local saved credits. Its `README.md` covers creating,
customizing, exporting and submitting. The `wechat` export profile enables the engine subpackage; the `web` profile
runs the game locally with host-only buttons disabled. Set the ad unit and server integration in `src/config.ts`. No
AppSecret or sample account is included. A login code is not an authenticated identity, a share request does not
confirm a share, and saved credits are not a cloud backup.
