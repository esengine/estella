## The `server` block

A project with a server declares it in `project.esproject`:

```json
"server": {
  "entry": "server/main.ts",
  "path": "/play",
  "port": 8090,
  "args": ["--port", "{port}", "--host", "{host}", "--data", "{data}/world.json"],
  "health": "/healthz"
}
```

| Field | Description |
|---|---|
| `entry` | Server entry module. |
| `path` | URL path of the WebSocket endpoint. Only the WebSocket upgrade at this path reaches the server. |
| `port` | Port the server listens on. |
| `args` | Command-line arguments. `{port}`, `{host}`, `{data}` and `{wasm}` are substituted for each deployment form. |
| `health` | Health-check path. |
| `url` | Server address for a page hosted elsewhere ([External hosting](#external-hosting)). |

## Export

```bash
node pipeline/bin/estella.mjs export my-game --platform server
```

The export writes `dist-server/`:

| Output | Content |
|---|---|
| `server.mjs` | The server bundled into one file that Node 20 runs without installed packages (`esengine` is the SDK's headless build). |
| `web/` | The game's web export. `--no-web` omits it. |
| `wasm/` | The engine, when the server runs it. |
| `compose.yaml`, `Dockerfile` | Container deployment: `SITE_ADDRESS=play.example.com docker compose up -d --build`; Caddy obtains the certificate. |
| `deploy/<game>.service`, `deploy/Caddyfile` | systemd deployment behind Caddy. |

The page and the server share one address.

## Server address on the client

The client resolves the server without an address compiled into the game code:

```ts
import { serverAddress } from 'esengine/session';

// wss://<the page's host>/play, or ?server=ws://127.0.0.1:8090/play during development.
const url = serverAddress({ path: '/play' });
```

Resolution order: the `?server=` query parameter, then the address written into the build, then the page's own host.

## External hosting

A page served from elsewhere (GitHub Pages, a CDN, a desktop app) names its server: `"url":
"wss://sector.example.com/play"` in the `server` block, or `--server-url` on the export. The web and desktop exports
write it into the page and allow its origin in the page's content policy, and `serverAddress` dials it. The server's
`compose.yaml` and `Caddyfile` then answer at that host.

## Token sign-in

For a test with known players, `TokenBook` signs players in with one token each. The book is read from the data folder,
not from the game's code, and each token is created with `newToken()`:

```ts
const book = TokenBook.parse(JSON.parse(readFileSync(`${data}/players.json`, 'utf8')));
// in authenticate: const who = book.check(raw.account, raw.token); if (!who) throw new SessionRejected('UNKNOWN PLAYER');
```
