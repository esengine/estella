Estella's UI is an ECS-based retained UI with a CSS flexbox layout engine in the C++ core. Screens are composed of
entities and components, authored in the editor or in code against the same data model, laid out in design pixels,
rendered in screen space, and driven by pointer, keyboard and touch input. There is no `RectTransform`: `UINode` is a
flexbox box sized in `px`, `percent` or `auto` and positioned by anchors, flex layout or `Absolute` insets.

<Aside type="caution" title="Sprite is a world-space renderer">
  `Sprite` renders through the camera in world space. Screen-space images (icons, buttons, panels, bars) are
  `UINode` + `UIVisual` under a Canvas, created via *Create → UI → Image* or by dropping a texture on a Canvas. A
  `Sprite` on a `UINode` entity is not rendered. See [Sprite or UI Image](/docs/ui/sprite-or-ui/).
</Aside>

## Component model

| Component | Role | Chapter |
|---|---|---|
| `Canvas` | The root of a screen: the design resolution and how it fits the real screen. | [Canvas](/docs/ui/canvas/) |
| `UINode` | The box: size, margins, anchors, insets, display, opacity. Every UI element has one. | [Layout](/docs/ui/layout/) |
| `FlexContainer` | Lays a node's children out — row or column, alignment, gap, padding, wrapping. | [Layout](/docs/ui/layout/) |
| `UIVisual` | What the box draws: a colour, an image, a 9-slice frame, a tiled pattern, a filled bar. | [Images](/docs/ui/images/) |
| `Text` | Text: font, size, colour, alignment, wrapping, outline, shadow, rich text. | [Text](/docs/ui/text/) |
| `UIMask` | Clips its children to its box or to its shape. | [Masks & Visibility](/docs/ui/masks/) |
| `UIScroll` | Turns a clipped node into a scroll area. | [Lists & Scrolling](/docs/ui/lists/) |
| `Interactable` | Makes a node hoverable and clickable; the engine writes `UIInteraction` and sends `UIEvents`. | [Interaction](/docs/ui/interaction/) |
| `UIController` + `UIGear` | Named states (tabs, button states, screens) and the fields each state sets — no code. | [Controllers](/docs/ui/controllers/) |

Editor presets under *Create → UI*: **Canvas**; **Text** (`UINode` + `Text`); **Image** (`UINode` + `UIVisual`,
`Image` mode); **Container** (`UINode`); and widget prefabs (Button, Toggle, Slider, Progress, Dialog, Dropdown,
TextInput, ListView, ScrollView and others).

## Architecture

Each layer depends on the previous one:

1. **Canvas** — the screen's root and its design resolution. → [Canvas](/docs/ui/canvas/)
2. **Layout** — `UINode` boxes solved by the flexbox engine; `FlexContainer` arranges children, anchors and
   `Absolute` insets place overlays. → [Layout](/docs/ui/layout/)
3. **Visuals and text** — `UIVisual` fills the box, `Text` draws glyphs, `UIMask` clips.
   → [Images](/docs/ui/images/), [Text](/docs/ui/text/), [Masks & Visibility](/docs/ui/masks/)
4. **Interaction** — `Interactable` makes a box hit-testable; the engine writes pointer state into `UIInteraction` and
   emits bubbling `UIEvents`; drag and drop and keyboard focus sit on top. → [Interaction](/docs/ui/interaction/)
5. **Widgets** — `createButton`, `createSlider`, … and the editor's widget prefabs compose the layers above into
   ready-made controls; `createListView` adds virtualized lists. → [Widgets](/docs/ui/widgets/),
   [Lists & Scrolling](/docs/ui/lists/)
6. **State** — controllers switch named pages with no code; signals keep UI in sync with game state; a theme skins
   every widget. → [Controllers](/docs/ui/controllers/), [Data Binding](/docs/ui/data-binding/),
   [Theming](/docs/ui/theming/)

## Authoring

The editor and code write the same components; there is no separate editor format.

- **Editor** — UI workspace (Canvas framing, UI Widgets palette), *Create → UI*, hierarchy editing in the Outliner,
  field editing and the anchor picker in Details, preview against design resolution and device presets.
  See [Your First Screen](/docs/ui/first-screen/).
- **Code** — `spawnUIEntity` and the widget factories from a startup system
  ([Your First Screen → Code equivalent](/docs/ui/first-screen/#code-equivalent)).

## Guidelines

- Use `UIVisual` for screen-space images; `Sprite` is world-space only.
- Prefer flex layout (`FlexContainer`, `flexGrow`); reserve `Absolute` insets for overlays and badges.
- Use anchors and `percent` / `auto` sizes for aspect-ratio independence; use `px` for intentionally fixed sizes.
- Use `NineSlice` for resizable framed elements.
- Treat `UIInteraction` and `UIEvents` as read-only inputs to game logic.
- Use the widget factories and prefabs for consistent interaction states.
