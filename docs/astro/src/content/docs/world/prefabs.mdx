A **prefab** is a saved entity tree stored as an `.esprefab` asset. It is authored once in the editor and instantiated
any number of times, in scenes or at runtime through the **`Prefabs`** resource. The asset is the single source of
truth; each instance can layer its own values (overrides) on top of it.

## Creating a prefab

*World Outliner → right-click an entity → Create Prefab* writes the entity and its whole subtree to
`assets/prefabs/<Name>.esprefab`, named after the entity. The original entities remain in the scene unchanged; they
are not replaced by an instance.

To place instances, drag the `.esprefab` from the Content Browser into the scene, or create one from the **Prefabs**
category of *+ Add → Create entity…*.

If the subtree references entities outside the selection, the editor asks *Expose external references?* first. Those
references are left **unbound** in the prefab, and each instance binds them to a scene entity in the Inspector.

## Prefab Mode

Double-clicking an `.esprefab`, or *Edit Prefab* on an instance, enters **Prefab Mode**. The prefab opens as its own
entity tree in the viewport, Outliner and Details, framed by an accent border under the **Editing Prefab** banner.
Entities and components are edited as in a scene. **Save Prefab** writes the asset, and every instance in every scene
takes the change. **Back to Scene** returns to the scene.

![The editor in Prefab Mode, editing a Coin prefab in isolation](@/assets/guides/en/prefab-mode.png)

*Prefab Mode: the **Editing Prefab** banner with **Save Prefab** and **Back to Scene**; the prefab open as its own
entity tree.*

- **UI prefabs** open inside a host canvas at the project's reference resolution, so percentage sizes resolve and
  layout, selection outlines and gizmos match a scene. The host is not part of the prefab: it does not appear in the
  Outliner and is not saved.
- **Not supported in Prefab Mode:** editing a nested prefab in place, and editing a variant whose base is not flat.
- **Disabled while editing a prefab:** Play and *Save As*.

## Instances and overrides

An instance placed in a scene stays linked to its source. Changing a field on the instance creates an **override**: a
per-instance value layered over the prefab's value. The editor marks overrides:

| Indicator | Location |
|---|---|
| Root name tinted in the accent colour | Outliner, on the instance root |
| ↺ *Reset to default* button on the field | Details |
| Amber dot on the component header | Details |
| Filter that shows only overridden fields | Details |

↺ on a field reverts that field to the prefab's value.
When the prefab changes, instances in the open scene update immediately. This applies to a save from Prefab Mode,
*Apply to Prefab* from another instance, a rewrite on disk (a version-control pull or another tool), and a re-bake
from the 2D rig the prefab came from. Each instance keeps its overrides and any entities the scene parented inside it.
Entities the prefab still contains keep their identity, so the selection and references from other entities remain
valid. The scene is not marked as modified, because its file stores only the overrides.

## Prefab actions

Right-clicking an instance in the Outliner, or the prefab bar at the top of Details, offers:

| Action | Effect |
|---|---|
| **Edit Prefab** | Opens the source in Prefab Mode. |
| **Select Prefab Source** | Reveals the `.esprefab` in the Content Browser. |
| **Apply to Prefab** | Writes this instance's overrides into the source, changing the base for every instance. |
| **Revert to Prefab** | Discards this instance's overrides and resynchronises it with the source. |
| **Create Variant** | Saves a new `.esprefab` that inherits the base and contains this instance's overrides. |
| **Unpack Prefab** | Detaches the subtree: its entities become ordinary scene entities without a prefab link. Undoable. |

*Apply to Prefab* is the only action that rewrites the shared asset. It first shows an itemized diff
(*Apply changes to prefab?*): edits in amber, additions in green, removals in red, with structural changes marked as
destructive.
<Aside type="caution">
  Deleting an `.esprefab` does not delete its instances. The editor lists the documents that reference it and moves the
  file to the trash (recoverable with Undo). Remaining instances can no longer be resolved and are dropped the next
  time their scene loads. Use **Unpack Prefab** first to keep the entities.
</Aside>

When components that an instance overrode are renamed or removed from the prefab, those overrides no longer match and
are dropped on scene load, with a notification. The Inspector flags the affected instance and offers **Repair**;
saving the scene persists the cleaned state.

Prefabs nest: a prefab can contain instances of other prefabs, and overrides apply through the nesting.

## Virtual instances

A **virtual** instance is shown and edited whole in the editor, but a running scene creates only its root and builds
the rest when the instance is opened. It suits screens composed of many pages, where only the open page needs its
entities.

- Toggle it with **Virtual** in the prefab bar of Details, or *Make Virtual (load on demand)* in the Outliner context
  menu.
- Open it at runtime through [`UIPages`](/docs/ui/overview/): `registerDeferred(entity)` registers a virtual instance
  as a page named after its root.
- An instance that adds, removes or re-parents entities is always created whole, not virtual.
- The page address parameter `?expand-virtual` creates every virtual instance whole at boot, for test harnesses that
  expect every node. Instances marked as an alternative layout of the same page are excluded, since the layouts would
  otherwise appear side by side.
- `deferredEntities` and `deferredRecord` are exported for games that keep alternative layouts this way.

## Instantiating at runtime

`instantiate` loads the prefab asset (and its dependencies) on first use and spawns it. It is asynchronous and
resolves to the spawned tree; `root` is the new root entity.

```typescript
import { defineSystem, Res, Prefabs } from 'esengine';

const spawnEnemy = defineSystem([Res(Prefabs)], async (prefabs) => {
  const { root } = await prefabs.instantiate('assets/prefabs/enemy.esprefab');
});
```

### Parent and children

`parent` places the instance under an existing entity at spawn, so its transforms resolve on the first frame. The
returned `entities` map gives access to the spawned children.

```typescript
const { root, entities } = await prefabs.instantiate('assets/prefabs/turret.esprefab', {
  parent: mountPointEntity,
});
// root      → the instance root
// entities  → Map<number, Entity> of every spawned entity, root included
```

### Per-instance overrides

`overrides` changes values for this instance only, without editing the asset — for example the same enemy with
different health or tint. An override names the component and property and targets the prefab's **root** unless it
names another entity.

```typescript
const { root } = await prefabs.instantiate('assets/prefabs/enemy.esprefab', {
  overrides: [
    { type: 'property', componentType: 'Health', propertyName: 'value', value: 250 },
  ],
});
```

To target a child, set `prefabEntityId` to that entity's string id in the `.esprefab` (a UUID for prefabs saved by the
editor). An override without `prefabEntityId` targets the root. An id that matches no entity in the prefab **throws**,
and the error names the root id and the ids that exist.

<Aside type="caution" title="prefabEntityId: '0'">
  `'0'` was the root id of every prefab before stable ids were introduced and appears in older sample code. Prefabs
  saved by the editor since then use UUIDs, so an override with `prefabEntityId: '0'` throws. Omit the field to target
  the root.
</Aside>

| Override `type` | Fields used |
|---|---|
| `'property'` | `componentType`, `propertyName`, `value` |
| `'name'` | `value` (string) |
| `'visibility'` | `value` (boolean) |
| `'parent'` | `value` (the new parent's `prefabEntityId`, or `null`) |
| `'component_added'`, `'component_replaced'` | `componentData` (`{ type, data }`) |
| `'component_removed'` | `componentType` |
| `'metadata_set'` | `metadataKey`, `value` |
| `'metadata_removed'` | `metadataKey` |

### Prepared spawns

Pass `{ owner: entity }` to `prefabs.instantiate(path, options)` or to a prepared prefab's `spawn(options)` to give
the instance to that entity's scene. An asynchronous spawn follows the owner if it moves to another scene while
loading. The `parent` option controls where the root attaches. Timeline spawn tracks use their player as the owner.

`prepare(path)` loads a prefab and every asset its entities use (meshes, materials, textures) and holds them until
released. Spawning from the result is synchronous: the entities exist on the line that requests them.

```typescript
const bullet = await prefabs.prepare('assets/prefabs/bullet.esprefab');
const { root } = bullet.spawn({ parent: gunEntity });   // synchronous
// …
bullet.release();                                         // a spawn after release throws
```

`spawn` accepts `parent` and `scene`; it takes no overrides.

## `instantiate` reference

| Option | Type | Description |
|---|---|---|
| `parent` | Entity | Places the instance under this entity. |
| `overrides` | override[] | Per-instance changes. |
| `baseUrl` | string | Base URL for resolving the prefab's assets. |
| `scene` | boolean | Default `true`: the spawned entities are adopted by the scene active when the spawn completes and are removed with it. `false` keeps them out of any scene, for entities that must outlive the area that spawned them. |

| Result field | Description |
|---|---|
| `root` | The instance root `Entity`. |
| `entities` | `Map<number, Entity>` of every spawned entity, root included. |

Reach children through `entities` rather than walking the hierarchy by index.
