Estella 编辑器是一个 **Model Context Protocol（MCP）** 服务器。支持 MCP 的 AI 工具——Claude Code、Cursor 或自定义智能体——通过与界面相同的流水线驱动编辑器：创建和打开项目与场景、从创建菜单目录生成实体、编辑组件字段、检查运行中的引擎 World、运行游戏、截图以及导出构建。编辑器提供 180 多个工具。

<Aside type="tip">
智能体的操作经由编辑器的命令层执行：编辑可撤销，运行模式不会修改编辑中的场景，保存即工具栏上的保存。智能体的工作在编辑器窗口中可见，用户可以同时操作。
</Aside>

## 连接 AI 工具

**窗口 → 连接 AI 工具…**（也可点击状态栏中的 AI 智能体标记，或设置中的 *连接 AI 工具…* 按钮）打开连接对话框。它列出本机安装的 Claude Code、Cursor、Claude Desktop 和 VS Code，每项带有 **连接** / **断开** 按钮。
- **连接** 会在该工具自己的 MCP 配置中写入 `estella` 条目（文件中的其他条目保持不变），并开启 *允许 AI 代理连接*。该条目用编辑器自身的可执行文件（`ELECTRON_RUN_AS_NODE`）运行内置的 MCP 脚本，因此无需安装 Node.js，并附加到已打开的编辑器（`--attach`）。连接状态读取自配置文件，因此手动删除的条目会显示为未连接。无法解析的配置文件不会被修改。
- **权限**——*只读* 或 *可修改*——在对话框中设置。它属于设置它的那个编辑器窗口，不会保存（每个编辑器都以只读启动），也不影响其他已打开的编辑器。编辑器在调用时决定权限，配置条目不携带任何权限，因此更改会立即作用于所有已连接的工具。
- **最近一次调用**（例如“最近一次调用：Claude Code，12 秒前”）确认某个工具确实在使用该连接。
- **其它工具** 以 JSON、TOML 或命令形式给出条目（已填好路径），供对话框无法写入的工具（Windsurf、Zed、Codex 等）复制使用。

### 手动配置

MCP 服务器是编辑器内的一个 Node 脚本。它通过 stdio 与 AI 工具通信 MCP，并驱动一个编辑器实例——启动新实例或附加到已打开的实例。在已安装的编辑器中，其路径为：

- **Windows**——`%LOCALAPPDATA%\Programs\@estellaeditor\resources\app.asar.unpacked\dist-electron\mcp\editor-mcp.mjs`
- **macOS**——`/Applications/Estella Editor.app/Contents/Resources/app.asar.unpacked/dist-electron/mcp/editor-mcp.mjs`

<Tabs>
<TabItem label="Claude Code">

```sh
claude mcp add estella --env ESTELLA_MCP_ALLOW_WRITES=1 -- \
  node "<path-to>/editor-mcp.mjs" --editor
```

</TabItem>
<TabItem label="任意 MCP 客户端">

```json
{
  "mcpServers": {
    "estella": {
      "command": "node",
      "args": ["<path-to>/editor-mcp.mjs", "--editor"],
      "env": { "ESTELLA_MCP_ALLOW_WRITES": "1" }
    }
  }
}
```

</TabItem>
</Tabs>

手动配置的服务器要求 `PATH` 上有 Node.js 20 或更高版本。

| 选项 | 作用 |
|---|---|
| `--editor` | 启动已安装的编辑器并开启 MCP 端点。 |
| `--attach` | 附加到已打开的编辑器（[附加到已打开的编辑器](#附加到已打开的编辑器)）。 |
| `--eager` | 客户端连接后立即在后台启动编辑器，而不是等到第一次工具调用。 |
| `--hidden` | 与 `--editor` 一起使用，以无窗口方式驱动编辑器。 |
| `--all-tools` | 一开始就列出所有工具，供不跟踪工具列表变化的客户端使用。 |
| `--instance <pid \| project name>` | 固定本会话驱动的编辑器（也可用 `ESTELLA_MCP_INSTANCE`）。 |

| 环境变量 | 作用 |
|---|---|
| `ESTELLA_MCP_ALLOW_WRITES=1` | 允许修改项目的工具，不受编辑器 *只读* / *可修改* 设置的约束。没有权限设置的宿主需要它。未设置时由编辑器的设置决定。 |
| `ESTELLA_MCP_INSTANCE` | 同 `--instance`。 |
| `ESTELLA_MCP_CALL_LOG=0` | 关闭本地调用日志（[调用日志](#调用日志)）。 |

编辑器在第一次工具调用时启动，而不是在 AI 工具启动服务器时：服务器立即响应握手，没有调用任何工具的会话不会启动编辑器。

<Aside type="caution">
不允许写入时，所有修改项目的工具（创建实体、编辑字段、保存、导出）都会从工具列表中隐藏并被拒绝。请审慎授予写权限。
</Aside>

## 附加到已打开的编辑器

`--attach` 驱动一个已经打开的编辑器会话：

<Steps>

1. 用 `--attach` 配置 AI 工具：

   ```json
   "args": ["<path-to>/editor-mcp.mjs", "--attach"]
   ```

2. 确认 **设置 → 编辑器 → 工具与 AI → AI 代理 → 允许 AI 代理连接** 已开启（默认开启）。编辑器在仅限本机的端口上监听，并在其用户数据目录中写出发现文件 `mcp-endpoint.json`，`--attach` 会自动找到它；只有文件被移动时才需要显式传入路径。该设置行显示正在监听的端口。

   用 `--mcp` 启动编辑器（`estella-editor --mcp`）会为该次会话开启端点，并在会话期间覆盖该设置。

3. 智能体驱动同一个窗口——选择、编辑和运行模式——用户可以同时观看和干预。

</Steps>

服务器在每次调用时解析编辑器，因此 AI 工具可以先于编辑器启动；会话中途重启编辑器会自动重新连接。

### 多个编辑器

每个编辑器在用户数据目录的 `mcp-instances/<pid>.json` 中声明自身，包括进程 id、项目、端口和权限。只有一个编辑器打开时，会话直接驱动它。打开两个或更多时，除 `list_editors` 和 `select_editor` 外，所有工具都会返回编辑器列表，直到选定其中一个。

| 工具 | 说明 |
|---|---|
| `list_editors` | 列出已打开的编辑器：pid、项目、端口，以及是否允许智能体修改项目。 |
| `select_editor` | 接受 pid、端口，或项目名称/路径的一部分。此后会话只驱动该编辑器；之后打开的编辑器不会接管。所选编辑器关闭后，会话会再次询问。 |

`--instance` 或 `ESTELLA_MCP_INSTANCE` 可在工具配置中固定选择。权限属于每个编辑器窗口，并以只读开始。连接对话框通过项目、进程 id 和端口标明其所属编辑器。

## 工具分组

约五十个日常工具（场景、运行、打开与保存、截图、日志）一开始就会列出。其余工具位于分组中，由智能体通过 `enable_tools` 开启：

`look`、`assets`、`timeline`、`prefab`、`authoring`、`view`、`play`、`render`、`project`、`code`、`image`、`rig`、`sound`、`terrain`、`modeling`、`tripo`、`device`，以及 `plugins`（项目编辑器插件添加的工具）。

任何工具都可以不经列出直接按名称调用。`--all-tools` 一开始就列出全部工具。连接时智能体会收到操作规则：工具分组、打开的场景与运行中游戏的区别、用 `step` 代替等待，以及每次调用对应一个撤销步骤。

| 领域 | 工具（节选） |
| --- | --- |
| 观察 | `get_scene_tree`、`get_inspector`、`get_stats`、`get_diagnostics`、`capture_viewport`（PNG）、`screenshot`（整个窗口，含运行画面）、`world_component`（运行中 World 探查）、`capture_frame` / `frame_draws` / `replay_draw`（帧调试器：每个绘制调用、其起因及绘制的实体） |
| 编辑场景 | `apply_scene_ops`（批量编辑）、`create_entity`（通过 `list_entity_templates` 使用创建菜单目录）、`set_field`、`set_entity_xy`、`set_parent`、`duplicate_entity`、`undo` / `redo` |
| 项目与资产 | `create_project` / `open_project` / `close_project` / `reopen_project`、`open_scene`、`open_asset`（在资产自己的编辑器中打开）、`get_document`、`save_scene`、`create_scene_file`、`create_asset`、`import_assets`、`list_assets`、`get_import_settings` / `set_import_settings` |
| 预制体 | `create_prefab_from_entity`、`edit_prefab` / `exit_prefab_mode`（预制体模式）、`apply_prefab`、`revert_prefab`、`unpack_prefab`、`create_prefab_variant` |
| 无代码行为 | `get_event_bindings` / `set_event_bindings`、`add_component` / `remove_component` |
| 游戏代码 | `read_project_file`、`write_project_file`、`list_project_files` |
| 运行与发布 | `set_play`（playing / paused / stopped）与 `get_play_state`、`step`、`play_input`、`export_game`（打包项目中的任意目标：web、desktop、wechat、playable、android 等） |

典型流程：`open_project` → `open_scene` → `list_entity_templates` → `apply_scene_ops` → `get_diagnostics` → `screenshot` → `save_scene` → `set_play` → `screenshot` → `export_game`。

### 工具约定

- **描述** 足够简短，客户端会完整传递。带有扩展说明的工具（`model_write`、`image_write`、`music_write` 等）在描述末尾列出主题；智能体通过 `tool_guide` 阅读，它由工具目录直接回答，不会启动编辑器。
- **参数名称** 统一：实体为 `entity`（打开的场景或运行中游戏里的编号），组件字段为 `field`，搜索文本为 `query`，结果上限为 `limit`。旧名称（`id`、`key`、`match`、`maxResults`）仍被接受。
- **按名称指定实体。** `entity` 也接受名称，在工具作用的世界中查找（打开的场景，或 `inspect_entity` 对应的运行中游戏），因为两者对实体的编号不同。两个实体同名时会被拒绝并列出各自编号；在场景中可用 `"HUD/ScoreText"` 这样的路径指定其一。

## 2D 骨骼角色

`rig` 分组让智能体制作 2D 骨骼角色并做动画。它以一张角色各部件分开画的图为起点，这张图可以用 `image_write` 画。`rig_write` 按“关节到末端”给出骨骼，并给出每个部件在图上的框，写出 `.esrig` 以及配套的 `.esmesh` 和 `.esprefab`。它返回一张图：姿势、每个部件跟随哪些骨骼，以及每个关节向两边各弯一次的效果。关节裂开、部件跟错骨骼这类问题，在做动画之前就能看出来。`rig_clip_write` 把动作写成 `.estimeline`，并把各帧并排、叠在一起显示，画出手脚的运动轨迹，还会测量落地的脚滑了多远。`rig_read` 和 `rig_clip_read` 以同样的描述格式读回，改完可以直接再写。骨骼在骨骼编辑器里打开，片段在 Sequencer 里打开。

## Tripo AI

`tripo` 分组通过 [Tripo AI](https://www.tripo3d.ai/) 从文字或图片生成带纹理的 3D 模型，并像拖入 `.glb` 一样导入；结果给出智能体可放置的预制体，以及 Tripo 的预览图。

| 设置（设置 → 编辑器 → 工具与 AI → AI 代理） | 说明 |
|---|---|
| **Tripo 站点** | 国际站（tripo3d.ai）或国内站（tripo3d.com）。两个站点的账号、密钥和额度相互独立。正在进行的生成保持在发起它的站点上。 |
| **Tripo API 密钥（国际站）** | 在 developers.tripo3d.ai 获取的密钥。 |
| **Tripo API 密钥（国内站）** | 在 developers.tripo3d.com 获取的密钥，站点为国内站时使用。 |

密钥保存在本机钥匙串中，从不写入项目，编辑器窗口也不会读回。每次生成都会消耗账号额度；`tripo_balance` 报告余额。

| 工具 | 说明 |
|---|---|
| `tripo_generate` | 从文字或图片发起生成（`images` 接受 `tripo_image` 生成的四视图），并立即返回任务 id。 |
| `tripo_task` | 等待任务并返回其预制体，不会再次消耗额度。也可恢复文件缺失的已列出结果。 |
| `tripo_process` | 基于已有模型生成新模型：重新贴图、减面到指定面数、展开 UV、拆分部件并封闭、检查能否绑定骨骼（免费）、绑定骨骼、应用预设动画或转换格式。还可将模型或图片智能分割为命名部件，以及将图片转换为高斯泼溅（`.splat`，引擎暂不渲染）。 |
| `tripo_image` | 从文字或图片生成图片，包括物体的四视图。 |
| `tripo_history` | 列出项目的 Tripo 任务（请求内容、结果位置、花费）以及项目中由 Tripo 生成的模型（依据其 `.meta`）；`remote_days: 31` 还会加入该账号近一个月生成的全部内容。 |
| `tripo_balance` | 报告剩余额度。 |

- 一次生成需要两到五分钟。编辑器轮询 Tripo，并在模型就绪时导入，无论智能体是否仍在等待。角落的通知显示正在进行的生成（单个显示名称和百分比，多个显示数量，**Details** 中列出明细），内容浏览器在每个模型的落点显示带进度的占位项。编辑器关闭时仍在进行的生成会在下次打开项目时继续。
- Tripo 生成的模型在其 `.meta` 中保存任务 id，因此后续操作引用该任务而无需上传文件；其他模型会被上传。
- 每个工具的描述中注明其额度消耗；除骨骼绑定检查外，所有操作都会消耗额度。
- 导入发生在智能体的撤销步骤之外：撤销不会移除生成的模型，需在内容浏览器中删除。

## 编辑预制体

对 `.esprefab` 使用 `open_asset`，或对实例使用 `edit_prefab`，会进入**预制体模式**：此后所有场景工具都作用于预制体，`save_scene` 为所有实例写入预制体资产。`get_document` 报告当前打开的文档；打开后、以及假定保存会写入场景之前，都应先检查。`exit_prefab_mode` 返回场景。

在用户会看到确认对话框的地方，智能体会收到可据以处理的拒绝：打开会丢弃未保存工作的内容时，除非传入 `discardChanges`，否则会被拒绝；`apply_prefab` 会为所有实例重写预制体，需要传入 `confirm: true`。

## 批量场景程序

`set_field` 每次调用写入一个字段。`apply_scene_ops` 接受一个**程序**——创建、重新设置父级、添加组件和写入字段——按顺序执行，作为**一个可撤销步骤**。操作通过 `ref` 引用自己创建的实体，因此一次调用即可生成整个子树：

```json
{
  "label": "Build HUD",
  "ops": [
    { "op": "create", "ref": "hud", "name": "HUD", "template": "ui-container" },
    { "op": "create", "ref": "coins", "name": "Coins", "template": "ui-text", "parent": "$hud",
      "fields": { "Text.content": "1440", "Text.fontSize": 28 } }
  ]
}
```

程序是原子的：任一操作失败时，错误会指明该操作（`op[7] set: …`），整个批次回滚，包括已经创建的实体。

字段路径可以指定结构化字段的单个成员（`"Transform.position.x"`、`"FlexContainer.gap.y"`、`"UINode.width.value"`）；其他成员保持不变。

较大的程序可以先用 `write_project_file` 写入文件，再按路径传入：

```json
{ "opsPath": "assets/scenes/shop.ops.json", "label": "Build the shop" }
```

## 事件绑定

[事件绑定](/docs/zh-cn/scripting/events/)行在事件触发时运行具名动作，使按钮无需游戏代码即可具备行为。`set_event_bindings` 在一个撤销步骤中替换实体的所有行（空列表即移除），`get_event_bindings` 读取它们：

```json
{ "entity": 42, "rows": [
  { "event": "click", "action": "panel.open",
    "params": { "prefab": "assets/prefabs/Shop.esprefab" } }
] }
```

`action` 是动作注册表中的任意名称——引擎内置动作（`property.set`、`ui.setVisible`、`fsm.fire` 等）或项目注册的动作。`target` 指定在另一个实体上运行，从当前实体起按就近原则解析。

<Aside type="caution">
`EventBinding` 没有“添加组件”入口（细节面板在添加第一个绑定时自动添加），因此 `add_component` 无法创建它；请使用 `set_event_bindings`。`add_component` 会拒绝未知的组件名称。
</Aside>

<Aside type="note">
有些属性属于**导入设置**而非组件字段。NineSlice 模式的 `UIVisual` 从纹理元数据读取切片边界，因此未经 `set_import_settings` 设置的边框会拉伸四角。`get_import_settings` 列出每项设置及其默认值。`set_import_settings` 接受路径**数组**，可将同一补丁应用到多个资产；每个资产保留补丁未涉及的设置。
</Aside>

## 撤销、权限与进度

- **一次调用即一个撤销步骤。** 一次调用改动的所有内容——场景编辑及其写入的项目文件——用一次 **Ctrl/⌘ + Z** 撤销，用重做恢复。该步骤在 **历史** 中显示为 **AI · *tool***。只写入文件的调用不会将场景标记为未保存。智能体的 `undo` / `redo` 工具在文件恢复后返回。保存、导出、创建项目以及对运行中游戏的操作不是撤销步骤。
- **历史中的智能体运行。** 历史在每次智能体运行开始处画一条分隔线（**AI run · *client* · *time***）；点击其上方紧邻的一行即可撤销整次运行。写入文件的副本最多保留 512 MB；副本被丢弃的步骤标记为 **files kept**，撤销时只恢复场景部分。
- **工具注解。** 每个工具都带有 MCP 注解：读取类工具标记为只读，只有离开项目或运行任意代码的工具（编辑器命令、运行中游戏里的探针）标记为破坏性。
- **进度。** 请求进度的客户端每五秒收到一次通知，说明正在运行的工具及其耗时。开始前被取消的调用不会运行；组合调用在下一步停止；已在运行的编辑器操作（导出、烘焙）会执行完毕。
- **启动失败。** 编辑器无法启动时，调用返回编辑器给出的原因，下一次调用会重试；连接保持打开。

### 调用日志

服务器将每次调用——工具、客户端、结果、时间以及错误的开头部分，从不记录参数——写入 `~/.estella/mcp-calls.jsonl`。`node desktop/scripts/mcp-call-stats.mjs` 列出最常失败的工具及失败方式。日志不会发送到任何地方。`ESTELLA_MCP_CALL_LOG=0` 关闭日志。

## 从源码检出运行

在源码检出中，`pnpm --filter @estella/editor editor:mcp` 在无头 fixtures 宿主上提供工具注册表（仅场景工具）；`editor:mcp -- --editor` 启动开发版编辑器（`--hidden` 隐藏其窗口）。`editor:mcp:e2e` 和 `editor:mcp:editor-e2e` 两套测试验证完整流程。
