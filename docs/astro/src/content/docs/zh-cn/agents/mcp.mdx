Estella 编辑器支持 **Model Context Protocol (MCP)**。任何支持 MCP 的 AI 工具——
Claude Code、Cursor，或你自己写的代理——都能驱动真实的编辑器：打开或创建项目、
打开场景、用与你相同的"创建"菜单目录生成实体、编辑组件字段、在活的引擎 World
里验证结果、进入 Play 模式、截图*亲眼看到*它搭出来的东西，并把成品游戏导出
——走的都是 UI 自己的管线，共一百多个工具。

<Aside type="tip">
代理做的每件事都经过编辑器自己的命令面——创建可撤销、Play 模式不会弄脏编辑
场景、保存就是工具栏的保存。你可以在编辑器窗口里看着它干活，随时接手。
</Aside>

## 接入 AI 工具

### 一键加入

菜单**窗口 → 连接 AI 工具…**（或状态栏上的"AI 代理"标记、设置里"连接 AI 工具…"按钮）
打开连接对话框。它会列出本机已安装的 Claude Code、Cursor、Claude Desktop、VS Code，
每个一个"连接 / 断开"按钮：连接就是把编辑器写进那个工具自己的 MCP 配置（只动
`estella` 这一条，其余内容原样保留），并同时开启"允许 AI 代理连接"。状态读的是配置文件
里的实际内容，所以手动删掉条目后它会自己变回"未连接"。配置文件读不懂时，编辑器会拒绝写入，
不会覆盖你的文件。

- **不需要另装 Node.js**：写进去的条目用编辑器自己的可执行文件运行内置脚本。
- **代理权限**在对话框里切换：只读 / 可修改。它属于你切换它的那个编辑器窗口：不会被保存，每个编辑器启动时都是只读，在一个打开的编辑器里授权不影响另一个。它由编辑器实时决定，条目里不带权限，
  所以切换立即对所有已连接的工具生效，不需要重启它们，也不会改写它们的配置。
- **是否真的连上了**看对话框底部："最近一次调用：Claude Code，12 秒前"。条目写进去不等于
  工具在用它，这一行才是证据。
- Windsurf、Zed、Codex 等编辑器不能替你写的工具，在"其它工具"里给出同一条配置的现成文本
  （JSON、TOML 或命令），路径已填好，复制即可。

MCP 服务器是随编辑器一起分发的一个小 node 脚本。它对你的 AI 工具讲 stdio MCP，
并为你驱动一个编辑器实例（拉起新的，或挂到已打开的那个上）。

它在安装版编辑器里的路径：

- **Windows** — `%LOCALAPPDATA%\Programs\@estellaeditor\resources\app.asar.unpacked\dist-electron\mcp\editor-mcp.mjs`
- **macOS** — `/Applications/Estella Editor.app/Contents/Resources/app.asar.unpacked/dist-electron/mcp/editor-mcp.mjs`

<Tabs>
<TabItem label="Claude Code">

```sh
claude mcp add estella --env ESTELLA_MCP_ALLOW_WRITES=1 -- \
  node "<path-to>/editor-mcp.mjs" --editor
```

</TabItem>
<TabItem label="任意 MCP 客户端">

```json
{
  "mcpServers": {
    "estella": {
      "command": "node",
      "args": ["<path-to>/editor-mcp.mjs", "--editor"],
      "env": { "ESTELLA_MCP_ALLOW_WRITES": "1" }
    }
  }
}
```

</TabItem>
</Tabs>

`--editor` 会以启用 MCP 端点的方式启动安装版编辑器。PATH 里需要 Node.js 20+。

编辑器在第一次调用工具时才启动,而不是在 AI 工具启动服务器的时候:服务器立刻就能应答,一次工具都没调用的会话不会拉起编辑器,冷启动慢的编辑器也不会让 AI 工具放弃这个服务器。加 `--eager` 可以在 AI 工具连上后就在后台启动它,加 `--hidden` 则不显示窗口。

<Aside type="caution">
不设 `ESTELLA_MCP_ALLOW_WRITES=1` 时代理只能**观察**——所有会产生修改的工具
（创建实体、改字段、保存、导出）都被隐藏并拒绝。写权限请有意识地授予。
</Aside>

## 驱动你正看着的编辑器

想让代理在你已经打开的编辑器会话里干活，把 `--editor` 换成 `--attach` 即可：

<Steps>

1. AI 工具的配置里用 `--attach`：

   ```json
   "args": ["<path-to>/editor-mcp.mjs", "--attach"]
   ```

2. 打开**设置 → 编辑器 → 工具与 AI → AI 代理 → 允许 AI 代理连接**。编辑器会开启一个仅限本机的端口，
   并往自己的 user-data 目录写一个发现文件 `mcp-endpoint.json`，`--attach` 会自己
   找到它——只有你把它挪了位置，才需要显式传路径。那一行会显示当前监听的端口；
   这个开关会被记住，所以此后你双击图标启动的编辑器同样是就绪状态。

   在终端里用 `--mcp` 启动（`estella-editor --mcp`）效果相同，只对当次会话生效，
   且在该会话内优先于这个设置。

3. 代理现在驱动的就是你眼前的这个窗口——选择、编辑、Play 全部同步——你可以
   一边看一边随时介入。

</Steps>

启动顺序无所谓：服务器**每次调用时**才去解析编辑器，所以你可以先开 AI 工具、
后开编辑器；会话中途重启编辑器也会自动重连，不会把代理晾在那儿。

### 同时打开多个编辑器

每个编辑器都在 user-data 目录里写一个属于自己的文件（`mcp-instances/<pid>.json`），带上进程 id、当前项目、端口和它自己的权限，代理因此能把它们分开。
只开了一个编辑器时，会话直接驱动它。开了两个或更多时，不让代理去猜——调用落到错误的窗口，改的就是错误的项目：在它选定之前，除了两个工具外，其他工具都只会回答编辑器列表。

- `list_editors` 列出每个已打开的编辑器：pid、项目、端口，以及是否允许代理修改项目。
- `select_editor` 接受 pid、端口，或项目名/路径的一部分。此后会话只驱动那一个编辑器，之后才打开的编辑器不会把它抢走；那个编辑器关闭后，会话会再次询问。
- 想把选择固定在工具配置里，可以给脚本传 `--instance <pid | 项目名>`，或设置环境变量 `ESTELLA_MCP_INSTANCE`。

权限（只读 / 可修改）属于每个编辑器窗口，启动时都是只读，所以给一个编辑器授权不会授权另一个。连接对话框会显示这是哪个编辑器：它的项目、进程 id 和端口。

## 代理能做什么

常用的工具(约五十个:场景、Play、打开和保存、截图、日志)一开始就列出;其余分在若干组里,代理需要时用 `enable_tools` 打开:`assets`、`prefab`、`authoring`、`view`、`play`、`render`、`project`、`code` 和 `device`。第一次调用之前就把全部工具交过去,每个会话都要多花几千 token,也更难挑出合适的那个;不管列没列出,任何工具都可以直接按名字调用。客户端跟不上工具列表变化的,加 `--all-tools`。下表列出的工具来自所有组。

| 领域 | 工具（节选） |
| --- | --- |
| 观察 | `get_scene_tree`、`get_inspector`、`get_stats`、`get_diagnostics`、`capture_viewport`（PNG）、`screenshot`（整窗截图，含 Play 画面）、`world_component`（活 World 探针）、`capture_frame` / `frame_draws` / `replay_draw`（帧调试器：每个 draw call、断批原因、画了哪些实体） |
| 编辑场景 | `apply_scene_ops`（批量搭建）、`create_entity`（配合 `list_entity_templates` 的创建目录）、`set_field`、`set_entity_xy`、`set_parent`、`duplicate_entity`、`undo` / `redo` |
| 项目与资产 | `create_project` / `open_project`、`open_scene`、`open_asset`（把任意资产在它自己的编辑器里打开）、`get_document`、`save_scene`、`create_scene_file`、`create_asset`、`import_assets`、`list_assets`、`get_import_settings` / `set_import_settings` |
| 预制体 | `create_prefab_from_entity`、`edit_prefab` / `exit_prefab_mode`（Prefab Mode）、`apply_prefab`、`revert_prefab`、`unpack_prefab`、`create_prefab_variant` |
| 零代码行为 | `get_event_bindings` / `set_event_bindings`（给按钮接线）、`add_component` / `remove_component` |
| 游戏代码 | `read_project_file`、`write_project_file`、`list_project_files` |
| 运行与发布 | `set_play`（playing / paused / stopped）+ `get_play_state`、`step`、`play_input`、`export_game`（打包对话框列表里的任一目标：web、desktop、wechat、playable、android 等） |

典型的代理循环：`open_project` → `open_scene` → `list_entity_templates` →
`apply_scene_ops` → `get_diagnostics` → `screenshot` 检查成果 → `save_scene` →
`set_play` → 再次 `screenshot` → `export_game`。

### 编辑预制体

对 `.esprefab` 调 `open_asset`（或对实例调 `edit_prefab`）就进入 **Prefab Mode**：
从此每个场景工具作用的都是**那个预制体**，`save_scene` 写的是资产——每个实例都会跟着变。
`get_document` 告诉你当前开着哪个文档：打开之后先查它，别默认保存写的是场景。
`exit_prefab_mode` 回到原来的场景。

人看到对话框的地方，代理拿到的是能据此行动的答复：会丢掉未保存改动的打开一律**被拒绝**，
除非你传 `discardChanges`；而 `apply_prefab`（它会重写每个实例的基）要求 `confirm: true`
——人是靠那张逐条 diff 确认的，代理则把意图直接说出来。

### 规模化搭建场景

`set_field` 一次只写一个字段——改一个值够用，搭一个场景就没戏了：一个 UI 面板
动辄上百个节点、每个十几个字段。`apply_scene_ops` 收的是一段**程序**：创建、
改父子、加组件、写字段按顺序执行，合成**一个可撤销步骤**。操作之间用名字互相
引用，所以整棵子树一次调用就能落地：

```json
{
  "label": "Build HUD",
  "ops": [
    { "op": "create", "ref": "hud", "name": "HUD", "template": "ui-container" },
    { "op": "create", "ref": "coins", "name": "Coins", "template": "ui-text", "parent": "$hud",
      "fields": { "Text.content": "1440", "Text.fontSize": 28 } }
  ]
}
```

它是原子的：任何一步失败，报错会指名是哪一步挂的（`op[7] set: …`），整批回滚
——**包括它已经创建出来的实体**——一段写错的程序不会留下一棵搭到一半的子树。

字段路径可以只点名结构字段里的**一个成员**（`"Transform.position.x"`、
`"FlexContainer.gap.y"`、`"UINode.width.value"`），其余部分会被读出来原样写回，
所以只挪一个轴不必先读再改再写。

节点数量上到几百之后，程序本身就成了负担——一个真实面板是几百 KB 的 JSON，
不该塞进对话里。用 `write_project_file` 写成文件，再把路径交给 `apply_scene_ops`：

```json
{ "opsPath": "assets/scenes/shop.ops.json", "label": "搭建商店" }
```

### 给按钮接线

场景不写一行游戏代码也能给按钮行为——一行[事件绑定](/docs/zh-cn/scripting/events/)
说的是*当这个事件发生，就跑那个具名动作*。`set_event_bindings` 在**一个撤销步骤**
里整体替换某实体的绑定行（传空列表即拆线），`get_event_bindings` 读回来：

```json
{ "entity": 42, "rows": [
  { "event": "click", "action": "panel.open",
    "params": { "prefab": "assets/prefabs/Shop.esprefab" } }
] }
```

`action` 是动作注册表里的任意名字——引擎内置的（`property.set`、`ui.setVisible`、
`fsm.fire`……）或项目自己注册的——而 `target` 点名要在哪个实体上跑，从当前实体
就近解析。

<Aside type="caution">
`EventBinding` **没有 Add Component 入口**（你加第一条线时细节面板会隐式加上它），
所以拿这个名字调 `add_component` 建不出来——`set_event_bindings` 才是它的门。
另外 `add_component` 现在会拒绝不认识的组件名而不是默默接受，所以打错字会当场报错。
</Aside>

<Aside type="note">
有些东西在**导入设置**里，不在组件上——最容易踩的是纹理的九宫格边框：
`UIVisual` 设成 NineSlice 后，边框是从纹理元数据读的，所以没配
`set_import_settings` 就搭出来的边框和按钮，四角会被拉伸变形。
`get_import_settings` 会把每个选项连同默认值一起列出来。
`set_import_settings` 的 path 可以传**数组**——一次调用把同一份 patch 打到整个文件夹上，
每个资产保留 patch 没点名的设置。
</Aside>

## 撤销、权限与进度

- **一次调用就是一步撤销。** 一次调用改的所有东西——场景改动*和*它写的项目文件——按一次 **Ctrl/⌘ + Z** 一起退回,重做再一起回来。
  这一步在**历史**里显示为 **AI · *工具名***。只写了文件的调用不会把场景标成未保存。代理自己的 `undo` / `redo` 工具会等文件回到磁盘上才回复。
  保存、导出、新建项目以及对运行中游戏做的事不算步骤:撤销不会把一次保存退回去。
  历史面板会在每次代理运行开始的地方画一条线(**AI 运行 · *客户端* · *时间***):点它上面那一行,就把整次运行退回去。
  写过的文件副本在 512 MB 以内都会保留;副本不得不清掉的步骤会标出**文件不可撤回**,撤销它只退回场景部分。
- **客户端知道每个工具会做什么。** 每个工具都带 MCP 注解:读取类标为只读,只有离开当前项目、或执行没人列得清后果的代码(编辑器命令、在运行中的游戏里跑探针)的才标为破坏性。
  会在这类调用前询问的客户端,只会在这些调用前问。
- **长调用会说自己还在跑。** 请求了进度的客户端每五秒会收到一次:哪个工具在跑、跑了多久——打开大场景或导出不再像卡住了。
  开始前就被取消的调用不会执行,组合调用会在下一步停下;已经在跑的单个编辑器操作(导出、烘焙)会跑完。
- **编辑器起不来时**,这次调用会用编辑器自己的话说明原因,下一次调用会重试——连接不会断。
- **代理一连上就知道规矩**:工具分组、打开的场景和运行中的游戏的区别、用 `step` 而不是干等、一次调用一步撤销。
  跟不上工具列表变化的客户端,也能用 `enable_tools` 的 `plugins` 组拿到插件工具。
- **在这台机器上,哪些工具最常失败。** 连接会把每次调用(工具、客户端、成败、耗时、报错开头——从不记参数)记在 `~/.estella/mcp-calls.jsonl`。
  `node desktop/scripts/mcp-call-stats.mjs` 列出最常失败的工具和原因。不会发到任何地方;`ESTELLA_MCP_CALL_LOG=0` 可以关掉。

## 从源码仓库使用（贡献者）

源码仓库里，`pnpm --filter @estella/editor editor:mcp` 用无头夹具宿主提供同一套
注册表（仅场景工具），`editor:mcp -- --editor` 拉起开发版编辑器(加 `--hidden` 不显示窗口)；两套 e2e
（`editor:mcp:e2e`、`editor:mcp:editor-e2e`）验证完整闭环。
