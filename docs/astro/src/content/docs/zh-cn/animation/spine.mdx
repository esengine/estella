Estella 可播放 [Spine](https://esotericsoftware.com/) 骨骼：骨骼、网格、IK、皮肤与事件。骨骼由 **`SpineAnimation`**
组件（主包 `esengine`）放置，运行时通过 **`Spine`** 资源控制；`Spine` 与 `SpineEvents` 从 `esengine/spine` 子路径导出。

![Spine 示例：由 Spine 骨骼绘制的持枪角色](@/assets/guides/zh/play-spine.png)

*`spine-demo` 示例：通过 **SpineAnimation** 组件播放的骨骼。*

## `SpineAnimation` 组件

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `skeletonPath` | 资源 | `''` | 骨骼文件（`.json` 或 `.skel`）。 |
| `atlasPath` | 资源 | `''` | 图集文件（`.atlas`）。 |
| `skin` | string | `''` | 当前皮肤。为空时使用默认皮肤。 |
| `animation` | string | `''` | 轨道 0 上的初始动画。 |
| `loop` | boolean | `true` | 初始动画是否循环。 |
| `playing` | boolean | `true` | 播放是否推进。 |
| `timeScale` | number | `1` | 单个实体的播放速度（≥ 0）。 |
| `skeletonScale` | number | `1` | 骨骼的统一缩放（≥ 0）。 |
| `flipX` / `flipY` | boolean | `false` | 水平 / 垂直镜像。 |
| `color` | Color | `{1,1,1,1}` | 着色（RGBA，0–1）。 |
| `layer` | number | `0` | 排序层；值越大越靠上绘制。 |
| `material` | 资源 | 无 | 自定义材质。为空时使用默认批处理着色器。 |
| `enabled` | boolean | `true` | 关闭后骨骼冻结并隐藏。与 `Spine.setEnabled` 及大纲视图的可见性开关是同一个开关。 |

### 编辑器行为

- **资源槽。** `skeletonPath` 与 `atlasPath` 是资源槽：可从弹出列表选择、从内容浏览器拖入文件，或使用槽上的定位 / 清除操作。场景以
  `@uuid:` 引用保存它们，移动或重命名文件不会断开引用。
- **骨骼格式。** 骨骼槽接受 `.skel` 与 `.json` 骨骼。`.json` 骨骼通过文件内的标记识别，并与 `.skel` 文件一起列在选择弹出列表中。
- **实时预览。** 视口在编辑模式下以及 Play/Stop 前后都会为骨骼摆姿势。
- **下拉框。** 骨骼加载后，`animation` 与 `skin` 列出该骨骼包含的动画和皮肤。

## 图集

Spine `.atlas` 文件按导出原样使用：

- **多页图集**——每一页纹理随图集一起加载。
- **预乘 Alpha**——图集头部的 `pma: true` 会被采用，无需导入设置。
- **纹理压缩**——导出时启用 **Compress textures** 后，图集页被烘焙为 KTX2，并像其他纹理一样在设备上转码。
- **图集采样**遵循每张图像的过滤、环绕、sRGB 和 mipmap 导入设置。通过 `loadSpineAssets` 单独加载时，效果与场景加载一致。

## 播放与混合

```typescript
import { defineSystem, Query, Res, SpineAnimation } from 'esengine';
import { Spine } from 'esengine/spine';

const control = defineSystem([Query(SpineAnimation), Res(Spine)], (q, spine) => {
  for (const [entity] of q) {
    spine.setAnimation(entity, 'run', true);            // 轨道 0，循环
    spine.setDefaultMix(entity, 0.15);                  // 默认交叉淡入
    spine.setMixDuration(entity, 'idle', 'run', 0.25);  // 单个过渡
    spine.setTrackAlpha(entity, 0, 1.0);                // 轨道贡献
  }
});
```

| 方法 | 说明 |
|---|---|
| `setAnimation(entity, name, loop)` | 在轨道 0 上播放动画。 |
| `setDefaultMix(entity, seconds)` | 任意两段动画之间的默认交叉淡入时长。 |
| `setMixDuration(entity, from, to, seconds)` | 单个过渡的交叉淡入时长。 |
| `setTrackAlpha(entity, track, alpha)` | 轨道的混合权重（0–1）。 |
| `setEntityProps(entity, props)` | 一次设置 `{ skeletonScale?, flipX?, flipY?, layer?, timeScale?, playing?, color? }`。 |
| `setEnabled(entity, on)` | 将骨骼移出帧（冻结并隐藏）或恢复。 |
| `setIKTarget(entity, constraint, x, y, mix)` | 使 IK 约束指向一个世界坐标点；`mix` 为 0–1。约束不存在时返回 `false`。 |
| `listConstraints(entity)` | 约束名称，形如 `{ ik, transform, path }`（字符串数组），或 `null`。 |
| `getTransformConstraintMix` / `setTransformConstraintMix` | 读取 / 写入变换约束的混合值。 |
| `getPathConstraintMix` / `setPathConstraintMix` | 读取 / 写入路径约束的混合值。 |

默认混合时长与逐过渡的混合时长保存在已加载的骨骼数据上，而非实体上：它们作用于共享该骨骼的所有实体。

## 皮肤与附件

```typescript
spine.setSkin(entity, 'armored');
spine.setAttachment(entity, 'weapon-slot', 'sword');   // 替换插槽的附件
spine.setSlotColor(entity, 'body', 1, 0.5, 0.5, 1);    // r, g, b, a（0–1）
```

| 方法 | 说明 |
|---|---|
| `setSkin(entity, name)` | 切换当前皮肤。 |
| `setAttachment(entity, slot, attachment)` | 替换插槽的附件。失败时返回 `false`。 |
| `setSlotColor(entity, slot, r, g, b, a)` | 为单个插槽着色（四个通道，0–1）。失败时返回 `false`。 |

const anims  = spine.getAnimations(entity);   // string[]

## UI 中的 Spine

带 `SpineAnimation` 的实体放在 Canvas 下（可带或不带 `UINode`）时，与周围控件一样按 Canvas 树顺序绘制：排在面板之后的骨骼绘制在面板之上，排在之前的绘制在其下。它同时遵循 UI 树的规则：

- 上层 UI 节点的 `opacity` 使其淡化；
- 隐藏的祖先使其隐藏；
- 上层的 `UIMask` 对其裁剪。

| 位置 | 绘制方式 |
|---|---|
| 屏幕空间 Canvas 下，`layer` 为 0 | 在屏幕叠加层中、所有相机之后，按树顺序绘制。 |
| 屏幕空间 Canvas 下，`layer` 不为 0 | 在屏幕叠加层中，按自身 `layer` 与整个 UI 排序，而非按树顺序。 |
| 不在任何 Canvas 下 | 与世界一起，按 `layer` 与深度绘制。 |

屏幕空间 Canvas 下的 DragonBones 骨架按相同规则在叠加层中绘制。

## 事件

`SpineEvents` 资源保存当前帧的轨道事件，需在同一帧读取：

```typescript
import { defineSystem, Res } from 'esengine';
import { SpineEvents } from 'esengine/spine';

const onSpine = defineSystem([Res(SpineEvents)], (spineEvents) => {
  for (const e of spineEvents.events) {
    // e.type: 'start' | 'interrupt' | 'end' | 'complete' | 'event'
    // e.entity, e.track, e.animationName；'event' 另有 e.eventName 与数值
  }
});
```

| `type` | 触发时机 |
|---|---|
| `start` | 动画在轨道上开始。 |
| `interrupt` | 动画被另一段动画打断。 |
| `end` | 动画从轨道上移除。 |
| `complete` | 动画完成一次循环或播放。 |
| `event` | 编写的事件关键帧触发。 |

| 字段 | 类型 | 出现于 |
|---|---|---|
| `entity` | Entity | 所有事件。 |
| `type` | `SpineEventType` | 所有事件。 |
| `track` | number | 所有事件。 |
| `animationName` | string | 所有事件。 |
| `eventName` | string | `event` |
| `floatValue` / `intValue` / `stringValue` | number / number / string | `event` |

## 剔除契约与延迟的世界姿势

为骨骼摆姿势包含两个步骤：

| 步骤 | 开销 | 何时跳过 |
|---|---|---|
| **推进**动画状态 | 低 | 从不跳过。跳过会使播放与事件失去同步。 |
| **解算世界变换** | 高 | 对任何相机都无法绘制的实体，且下列两个条件均满足时。 |

仅当资源同时具备以下两项时，才会跳过世界姿势解算：

- **剔除契约**——骨骼空间中的一个矩形，任何姿势都不会超出它。由作者记录在资源上，不会自动生成。
- **无状态的世界约束**——由加载的 Spine 运行时报告：世界姿势在帧之间不携带状态。不可配置。

缺少任一项时，无论实体是否可见，每帧都会解算世界姿势。

### 记录契约

选中骨骼资源，使用细节面板中的 **Fixed Culling Bounds** 行。

| 操作 | 结果 |
|---|---|
| **Scan Animations** | 在每个皮肤下完整播放每段动画，并将范围显示为 **Observed Bounds**。 |
| **Use as Fixed Culling Bounds** | 将观测范围复制到契约中。 |
| **Remove Fixed Bounds** | 写入面积为零的矩形，表示"无契约"。新导入的资源带有此值。 |

观测范围是测量结果而非保证：两段动画的混合不等于两者范围的并集，游戏代码可能把骨骼移到导出动画之外，两次采样之间的极值也不会被采到。接受前应先为观测范围留出余量。

<Aside type="caution">
  契约必须覆盖**所有**姿势，包括运行时由游戏代码驱动的姿势。矩形过小会使角色在屏幕边缘附近消失；过大只会多消耗一些计算。
</Aside>

### 实测效果

1000 个骨骼；姿势、提取与提交的耗时：

| 可见 | 每帧摆姿势 | 带契约 |
|---|---|---|
| 1000 / 1000 | 3.39 ms | 3.36 ms |
| 200 / 1000 | 3.29 ms | 1.06 ms |
| 0 / 1000 | 3.26 ms | 0.49 ms |

全部可见时开销不变；被跳过的只是结果不会被绘制的计算。

## 诊断

`Spine` 可报告一帧做了什么，以及每部分开销的原因。计数默认关闭；关闭时的开销为每个实体一次分支判断。

```ts
import { Res } from 'esengine';
import { Spine, formatSpineDiagnostics } from 'esengine/spine';

// 在接收 Res(Spine) 的系统中——调用一次，之后任意一帧读取：
spine.observe(true);
console.log(formatSpineDiagnostics(spine.diagnostics()));
```

```text
spine — frame 412, 1000 entities across 3 assets
  time      pose 2.31ms   readback 0.98ms   total 3.29ms
  world     400 resolved, 600 unresolved, 150 already current
  logical   1000 advances
  draw      350 extracted, 650 camera declines
  geometry  350 batches, 112000 vertices, 168000 indices
  bytes     3.4MB out of the modules, 3.4MB into the core
  crossings 1000 pose, 400 world, 350 batch data, 350 submit
  3.8       120 frames — total p50 3.28ms  p95 4.01ms  max 5.66ms

  hero.skel#gen1                  800  3.8  may defer
  boss.skel#gen1                  150  3.8  always resolves — no-certificate
  rope.skel#gen1                   50  4.2  always resolves — stateful-constraints

  * 150 entities across 1 asset (boss.skel#gen1) resolve a world pose every
    frame because nothing certified their extent. Scan the asset and record a
    culling contract to let them skip it while no camera wants them.
  * 50 entities across 1 asset (rope.skel#gen1) can never defer: their world
    pose carries state across frames, which no culling contract changes.
  * 600 world poses went unresolved — work this frame did not do.
```

| 行 | 含义 |
|---|---|
| `world … unresolved` | 本帧跳过的世界姿势数。有实体在屏幕外时仍为零，说明没有实体被允许跳过；原因见各资源行。 |
| `always resolves — no-certificate` | 该资源没有剔除契约。记录契约后即可延迟。 |
| `always resolves — stateful-constraints` | 该资源的世界姿势在帧之间携带状态。契约无法改变这一点；此类资源在结论中单独列出。 |
| `p50 / p95 / max` | 之前若干帧的分布，用于判断所报告的帧是否典型。 |

`diagnostics()` 以数据形式（`SpineSceneDiagnostics`）返回同一份报告，供自定义面板或叠加层使用；`formatSpineDiagnostics` 将其渲染为文本。

## 支持的版本与许可

Estella 支持 Spine **2.1、3.8、4.1、4.2 与 4.3**。每个骨骼版本按需加载各自的 WebAssembly 后端，因此 `Spine` 与 `SpineEvents` 位于
`esengine/spine` 子路径。Spine 2.1 骨骼必须导出为 JSON；2.1 运行时不带其二进制格式的读取器。

<Aside type="caution">
  内置的 Spine Runtimes 为专有软件。发布使用 Spine 的游戏需要 Esoteric Software 颁发的有效 Spine 许可，与 Estella 自身的许可相互独立。
</Aside>

## 最佳实践

- **设置默认混合**：用 `setDefaultMix` 使过渡交叉淡入；特定过渡用 `setMixDuration`。
- **用轨道分层**并配合 `setTrackAlpha`，例如轨道 1 上的瞄准叠加动画覆盖轨道 0 上的移动动画。
- **共享骨骼与图集**：引用同一对资源的实体共享一份已加载的骨骼。
- **用 [Animator](/docs/zh-cn/animation/animator/) 状态机驱动角色**，它可以驱动 Spine，也可以驱动精灵。
- **为大量使用的骨骼记录剔除契约**，使屏幕外的实例跳过世界姿势解算。
