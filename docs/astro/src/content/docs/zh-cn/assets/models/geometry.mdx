模型导入可以在导入过程中改写几何。每个选项都是源文件的一项[导入设置](/docs/zh-cn/assets/models/overview/#导入设置)；源文件本身从不修改，因此任何选项都可以修改后重新导入。

## 切线

带法线与 UV 的网格会为每个顶点写入**切线**，使法线贴图在其烘焙时所用的坐标系中读取，而不是由屏幕空间导数逐像素推导（在 UV 接缝和拉伸纹理上会出错）。

- glTF 的 `TANGENT` 属性保持其方向。其他网格由 UV 计算切线，并按每个三角形在该顶点处的夹角加权。
- 副切线的符号始终由存储的几何计算，因此无论导入器如何翻转 V 都正确。
- 在写入切线之前导入的网格不含切线，着色与以前相同；重新导入即可加上。
- 调用 `perturbNormal` 的自定义着色器无需修改即可使用网格的切线坐标系。

## 三角形预算

**Max Triangles**（`maxTriangles`，默认 `0`）在导入时把模型削减到最多这么多三角形，每个网格按相同比例削减。`0` 保留全部三角形。

- 蒙皮网格同样被简化，并保留其绑定与动画；变形（morph）网格保持不变。
- 源文件保留全部三角形，因此之后可以提高预算。
- 用编辑器的 Tripo 工具生成的模型默认是低多边形（少于 20,000 个三角形）。以完整拓扑生成时保留全部三角形，除非同时指定预算（`max_triangles`）。

## 簇 LOD

**Cluster LOD**（`clusterLod`，默认关）保留高密度静态网格的全部三角形，并按视图只绘制该视图能分辨的细节。

- 每个网格被切分为最多 128 个三角形的簇。相邻的簇一起简化为一半三角形，逐级进行，直到只剩少量三角形。
- 每帧，网格的每个部分都以在相机位置处误差小于一个像素的级别绘制。各级别之间无接缝，也不需要 `LODGroup`。阴影使用与表面相同的三角形。

| 开销或限制 | 说明 |
|---|---|
| 文件大小 | `.esmesh` 约增加其索引数据的大小；各级别的三角形都被存储，并共享网格的顶点。 |
| 内存 | 引擎常驻所有级别的索引。 |
| CPU | 相机移动时，簇选择发生变化的网格会重写其索引缓冲。 |
| 下载 | 不减少。包体大小受限的场合（小游戏）应使用[三角形预算](#三角形预算)。 |
| 排除的网格 | 蒙皮网格、变形网格，以及通过 `MeshInstances` 放置的网格整体绘制。 |
| 自动生成 LOD | 启用簇 LOD 的网格不生成[自动 LOD 级别](#自动生成-lod)。 |

### 查看簇

| 计数器 | 含义 |
|---|---|
| `render.cluster.sourceTriangles` | 场景中所有簇化网格的三角形数。 |
| `render.cluster.triangles` | 其中本帧绘制的三角形数。 |
| `render.cluster.rebuilt` | 本帧重写了索引缓冲的簇化网格数。 |

视口着色菜单中的 **Clusters** 以不同颜色绘制每个簇，色块大小表明表面各部分绘制所用的级别。选中一个簇化网格时，视口的选择信息显示该视图绘制了多少（例如 **8,512 of 9,216 tris drawn · 67 clusters**），并随相机移动更新。

## 自动生成 LOD

**Generate LODs**（`lodLevels`，Off 或 1–3 级）把每个网格简化为三角形约为原来 50%、20% 与 7% 的副本，写在其旁边，命名为 `<mesh>_lod1.esmesh`、`_lod2` 与 `_lod3`，并给绘制它的实体添加 [`LODGroup`](/docs/zh-cn/performance/level-of-detail/)。物体缩小到视口高度的 40%、18% 与 7% 以下时，该组切换到对应级别。命令行导入使用 `--lods <0-3>`。

- 简化使形状保持在相对网格尺寸的较小误差之内，且不拆开 UV 接缝或硬边，因此纹理位置不变。
- 保留下来的每个顶点都是某个源顶点的副本，因此顶点色与 lightmap UV 得以保留。
- 若某一级比上一级减少的三角形不足 15%，则省略该级。
- 三角形少于 **LOD Minimum Triangles**（`lodMinTriangles`，默认 256）的网格不生成级别。
- 蒙皮与变形网格只保留一级。

级别是额外的文件；三个级别会给项目增加约为原网格四分之三的大小。它们降低的是绘制开销而不是包体大小，且只有在视图选中时才占用内存。

## Lightmap UV

烘焙的光照贴图通过**第二套** UV 读取，其中任意两个表面都不共享纹素。主 UV 通常会复用纹素（镜像部件共用一张图），会导致某个部件的烘焙阴影出现在另一个部件上。

**Generate Lightmap UVs**（`lightmapUV`，默认关）展开第二套 UV：

- 表面被切分为近似平坦的图块（chart），各自投影到自身平面上，再以**统一的**世界到纹素比例打包进单位正方形，因此相邻表面的光照贴图分辨率相同。
- 图块边界上的顶点会被拆分，因此网格的顶点数多于源文件。位置不变，混合形状、蒙皮权重与顶点色随其顶点一起保留。
- 导入会报告图块占满图集的比例。比例低说明图块多而小；增大图块角度可以合并图块，代价是每个图块内的拉伸增加。

该选项默认关闭，因为大多数模型从不烘焙，而拆分的顶点无论如何都占用内存。以下两类模型从不生成 lightmap UV：

- **蒙皮**网格，因为骨骼会移动它们，烘焙无法跟随。
- **已带有**第二套 UV 的模型，其布局由作者决定（例如用 Blender 的 *Smart UV Project* 创建的第二套 UV）。

结果的使用方式见[烘焙光照](/docs/zh-cn/graphics/lighting/baked/)。
