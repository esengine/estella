项目中的每个资源都有稳定的 UUID。场景与预制体按 UUID 引用资源；构建时**烘焙（cook）**只发布游戏可达的资源；运行时由**清单（manifest）**把引用解析为文件，由 `Assets` 资源的类型化**加载器**把引用转换为句柄，并由**引用计数**释放不再被持有的资源（[生命周期与内存](/docs/zh-cn/assets/memory/)）。

## 引用资源

代码按**项目相对路径**引用资源。路径相对于**项目根目录**而不是资源文件夹，因此以 `assets/` 开头，与内容浏览器显示的路径及烘焙清单的键一致：

```typescript
const tex = await assets.loadTexture('assets/textures/player.png');
```

省略根文件夹的引用（`'textures/player.png'`）按项目根目录解析，找不到文件，加载以 404 失败。

编辑器在场景与预制体中把引用序列化为 **UUID 引用**（`@uuid:<uuid>`），文件重命名或移动后引用仍然有效。所有加载器都接受这两种形式，并解析到同一路径。`resolveRef(ref)` 对两种形式都返回解析后的路径。UUID 引用由编辑器写入，不需要手写。

## 排除文件夹

编辑器为项目下的每个文件写入 `.meta` 附属文件。不含内容的文件夹（源美术、文档、服务器代码）可在 `project.esproject` 中用 `assetExclude` 排除：资源库不为其建立索引，不在其中写入 `.meta`，也不监视其变化。

```json
{ "assetExclude": ["art", "docs", "server"] }
```

条目为相对于项目根目录的文件夹，其下全部内容都被排除。

## 按类型加载

`Assets` 资源为每种资源类型提供一个类型化加载器，返回组件字段所接受的句柄或 id：

```typescript
import { defineSystem, Query, Mut, Res, Sprite, Assets } from 'esengine';

const loadArt = defineSystem([Query(Mut(Sprite)), Res(Assets)], async (q, assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');   // { handle, width, height }
  for (const [entity, sprite] of q) {
    sprite.texture = tex.handle;
  }
});
```

| 加载器 | 返回值 |
|---|---|
| `loadTexture(ref)` | `{ handle, width, height }`（[纹理](/docs/zh-cn/assets/textures/)） |
| `loadAudio(ref)` | `{ bufferId }` |
| `loadFont(ref)` | `{ handle, family? }`（`family` 用于轮廓字体） |
| `loadMaterial(ref)` | `{ handle, shaderHandle }` |
| `loadSpine(skeletonRef, atlasRef?)` | `{ skelData, atlasText, isBinary, textures }`：`Spine` 组件绘制所用的、已准备好的骨架与图集 |
| `loadTilemap(ref)` / `loadTileset(ref)` | `{ sourceId }` / `{ tilesetId }` |
| `loadTimeline(ref)` | `{ timelineId }` |
| `loadAnimClip(ref)` | `{ clipId }` |
| `loadAnimatorController(ref)` | `{ controllerId }` |
| `loadStateMachine(ref)` / `loadBehaviorTree(ref)` | `{ fsmId }` / `{ btId }` |
| `loadLocaleTable(ref)` | `{ locale, keyCount }`（[本地化](/docs/zh-cn/assets/localization/)） |
| `loadPrefab(ref)` | `{ data }` |
| `loadJson<T>(ref)` | `{ data: T }` |

`load<T>(type, ref)` 是运行时才确定类型时使用的通用形式；`register(loader)` 为自定义资源类型添加加载器。

## 数据资源

既不是 Spine 骨架、也不属于 DragonBones 文件对的 `.json` 文件是**数据资源**：游戏数据表、调参数值、对白等，用 `loadJson` 加载：

```typescript
const { data } = await assets.loadJson<LevelTable>('assets/data/levels.json');
```

`T` 不做校验，结果只具备 `JSON.parse` 本身的保证。

组件可以用 `assetFields` 声明 JSON 字段。场景会在创建实体之前读取对应的文档。

```typescript
const Dialogue = defineComponent('Dialogue', { table: '' }, {
    assetFields: [{ field: 'table', type: 'json' }],
});
```

字段会保留场景文件中填写的路径或 UUID。对于资源列表，可以用 `discoverAssets` 为每项返回
`{ type, path }`。`type` 可以使用项目通过 `assets.register` 注册的加载器名称。
这些文件计入加载进度和缺失资源报告。常驻实体、被其他场景接管的实体和预制体实例都会持有列表中的资源，直到实体销毁。

数据资源有 UUID，只解析一次并参与引用计数，可放入懒加载[寻址组](#寻址组懒加载)或由 CDN 提供，并可由[热更新](/docs/zh-cn/publishing/hot-update/)替换。直接 `fetch` 项目路径不具备上述任何特性；它在编辑器中可用（编辑器提供整个项目），但在构建中失败，因为构建只包含发布的资源。

数据资源始终发布，无论是否被引用（[只有代码点名的资产](#只有代码点名的资产)）。项目配置文件（`package.json`、`tsconfig.json` 等）不是资源。

## 清单

运行时通过烘焙生成的清单把 `@uuid:` 引用解析为文件路径：

```typescript
assets.setManifest(manifest);   // 通常由运行时完成
```

`getManifest()` 返回当前清单。不在清单中的引用回退为直接按路径查找。

## 寻址组（懒加载）

可以在编辑器中将文件夹设为按需分包，也可以沿用 `subpackages/<name>/…` 的目录约定。
场景首次用到组里的精灵或网格时，运行时会先挂载分包，再读取文件。多个并发请求共用一次挂载。Web 构建直接读取文件。
需要一次加载整个组并显示进度时，使用 `loadGroup`。

```typescript
const bundle = await assets.loadGroup('level2', (loaded, total) => {
  console.log(`${loaded}/${total}`);
});

// 玩家离开第二关时
bundle.release();
```

`bundle.release()` 释放本次加载取得的引用，即使热更新改变了组成员也能正确释放。
其他场景或组仍在使用的资源会保留。无人引用的纹理可以留在[温缓存](/docs/zh-cn/assets/memory/#温缓存)中。

在资源的 `.meta` 顶层添加 `"labels": ["encounter"]`，构建会包含该资源及其依赖。
`await assets.loadByLabel('encounter')` 可以跨组加载带此标签的纹理、字体、网格和光照资源，并先挂载所需的[微信分包](/docs/zh-cn/publishing/wechat/)。
通过 `bundle.failed` 查看加载失败的资源。关卡结束时调用 `bundle.release()`，即使期间标签发生变化，也能准确释放本次取得的引用。

### 预加载列表

`preload` 加载一个既不是组也不是标签的显式引用列表，例如下一区域的资源。它推断每个资源的类型（先查清单，再看扩展名），并以有限并发通过类型化加载器加载：

```typescript
const { failed } = await assets.preload(
  ['assets/textures/boss.png', 'assets/audio/boss-theme.mp3', 'assets/maps/arena.estilemap'],
  (loaded, total) => console.log(`${loaded}/${total}`),
);
```

无法推断类型、解析出错或加载失败的引用会列在 `failed` 中。成功预加载的资源会进入缓存，供后续加载使用。如果进度回调抛出异常，`preload` 返回的 Promise 会被拒绝。

## 烘焙、压缩与内容寻址

构建时，**烘焙**从构建中的每个场景（打包对话框中的 **Scenes in build** 列表）出发遍历依赖图，排除所有不可达的内容，暂存可达文件并写出清单。烘焙还会：

- **压缩纹理。** PNG 源连同 mip 链编码为 **KTX2**（Basis Universal）；运行时转码为设备支持的最佳格式（依次为 ASTC、ETC2、S3TC，最后回退到 RGBA8）。是否编码由每张纹理的 **Compression** 导入设置决定（[纹理](/docs/zh-cn/assets/textures/#导入设置)）；打包对话框只决定是否应用这些设置。
- **内容寻址。** 每个发布文件以其字节的哈希命名，URL 不可变，相同文件只存一份。Web 与桌面端默认开启。哈希基于暂存后的字节计算（KTX2 编码之后），因此标识的是实际发布的文件。
- **打包自动图集**（可选构建选项）。`<name>.atlas/` 文件夹中的零散 PNG 被打包成图集页，帧 UV 写入清单。过滤方式、环绕模式、mipmap、色彩空间和九宫格边框兼容的图片共用一页，可以合批绘制。
  压缩图集页采用这些图片的色彩空间，并按设置写入 mip 层级。标记为 **Data** 的图片和 16 位 PNG 会作为独立文件导出，保留原始位深。
  每张图片按自己的环绕模式填充四周的留白，线性过滤时能保留原图的边缘透明度。全透明像素的颜色由该图的 **Alpha Is Transparency** 设置决定。
  网格、网格材质和烘焙光照贴图用到的纹理会整张导出，以保留原有 UV。使用同一纹理的精灵会共享这张图片。

![检视器中的平台覆盖条——每个平台一个页签，选中 Android，显示 Max Size、Compress 与 Format](@/assets/guides/zh/import-platform-overrides.png)

*纹理的**平台覆盖**：每个目标一个页签。没有覆盖的平台使用 Default 设置。*

### 只有代码点名的资产

可达性从场景出发，同时读取项目的脚本：

- 内容为资源完整路径（`'assets/ui/coin.png'`）或 `@uuid:` 引用的字符串字面量，会发布该资源。
- 在某文件夹内拼接路径的模板字面量（`` `assets/sfx/${name}.wav` ``）会发布整个文件夹，并产生一条构建警告。

由多段拼接的路径、从数据中读取的名称、富文本标记中引用的纹理对烘焙不可见，因而被排除。编辑器直接从磁盘提供项目，因此这类资源只在构建中缺失；发布的游戏会记录它请求了哪个文件以及缺失的原因。

对于这类文件夹，在**内容浏览器**中右键该文件夹，选择 **Delivery → Always include in builds**。该设置保存在 `.esengine/asset-groups.json` 中，与文件夹的分发方式（本地、分包或远程）放在一起，默认关闭：

![内容浏览器的文件夹菜单——Delivery，含 Local / Subpackage / Remote 与 Always include in builds](@/assets/guides/zh/hot-update-delivery-menu.png)

*右键文件夹 → **Delivery**。三种方式决定资源从哪里发布；**Always include in builds** 决定资源是否不论可达性都发布。*

```json
{
  "version": "1.0",
  "groups": {
    "markup-images": {
      "folder": "assets/textures",
      "mode": "local",
      "alwaysInclude": true
    }
  }
}
```

<Aside type="note">
  `subpackages/` 下的资源即使不可达也始终包含。**本地化字符串表**（`Text` 携带的是键而非路径）与**数据资源**也始终发布，因为没有场景能引用它们。
</Aside>

## 使用建议

- 代码中按路径引用资源；UUID 引用由编辑器写入。
- 在关卡切换处加载组（`loadGroup` / `loadByLabel`）或列表（`preload`），避免游玩过程中等待加载。
- 按需内容放在 `subpackages/<name>/` 下，使其成为懒加载组，并在微信上成为分包。
- 代码按计算出的名称加载的文件夹，标记为 **Always include in builds**。
