纹理就是显存里的一张图。你用项目路径引用它，加载成一个**句柄**（handle），再把句柄放到组件上
——`Sprite.texture`、材质采样器、位图字体页。本页讲图片本身：它可以是什么、你能在它上面设什么、
以及怎么知道它有多大。

画纹理的那个组件见[精灵](/docs/zh-cn/graphics/sprites/)；资源系统整体（引用、分组、清单）见
[资源](/docs/zh-cn/assets/overview/)。

## 支持的格式

| 扩展名 | 说明 |
|---|---|
| `.png` | 带透明通道的美术资源首选。 |
| `.jpg` / `.jpeg` | 没有 alpha 通道；照片类美术体积更小。 |
| `.webp` | 带 alpha 且压缩率好，由浏览器/运行时解码。 |
| `.gif` | **只取第一帧**——这是一张静态图，不是动画。 |
| `.bmp` | 未压缩;能用，但基本不该发出去。 |
| `.ktx2` | Basis Universal，已经是 GPU 压缩格式。这是构建的 cook 步骤**产出**的东西——你也可以直接提供。 |

`.aseprite` / `.ase` 不是纹理——导入它**产出**一张精灵表 `.png`(以及每个 tag 一个剪辑),
场景引用的是产物。见[精灵动画](/docs/zh-cn/animation/overview/#从-aseprite-文件导入)。

日常创作用 `.png`、`.jpg`、`.webp`。开了压缩时，构建的 cook 步骤会把它们转成 `.ktx2`
（见[导入设置](#导入设置)）。

## 加载纹理

`assets.loadTexture(ref)` 解析引用、上传图片，并**连同图片的像素尺寸一起**返回句柄——
「怎么取宽高」的答案就在这里：

```typescript
import { defineSystem, Res, Assets } from 'esengine';

const measure = defineSystem([Res(Assets)], async (assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');
  tex.handle;   // TextureHandle —— 组件字段要的就是它
  tex.width;    // 图片的像素宽
  tex.height;   // 图片的像素高
});
```

宽高是**源图片**的像素数,不是任何东西的绘制尺寸。画这张纹理的 `Sprite` 有它自己的世界单位
`size`,是另一个可以随便设的数(初始会跟图片对齐——见[精灵按纹理定尺寸](#精灵按纹理定尺寸)）。

按图片自身像素尺寸放到精灵上：

```typescript
import { defineSystem, Query, Mut, Res, Sprite, Assets } from 'esengine';

const showArt = defineSystem([Query(Mut(Sprite)), Res(Assets)], async (q, assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');
  for (const [entity, sprite] of q) {
    sprite.texture = tex.handle;
    sprite.size = { x: tex.width, y: tex.height };   // 1 图片像素 = 1 世界单位
  }
});
```

<Aside type="note">
  `loadTexture` 按解析后的路径做缓存和引用计数：同一张图加载两次返回同一个句柄，不会上传两遍。
  自己取了引用就用 `assets.releaseTexture(ref)` 释放——它收的是**你加载时用的那个 ref**，
  不是句柄。场景引用到的资源随场景一起释放。见
  [生命周期与引用计数](/docs/zh-cn/assets/overview/#生命周期与引用计数)。
</Aside>

### 从一个不是你加载的句柄取尺寸

编辑器里摆好的精灵早就有纹理了：场景文件写了它，加载器解析了它，你的代码从来没见过
`TextureResult`。要量这种纹理，直接按句柄问资源管理器：

```typescript
import { defineSystem, Query, Sprite } from 'esengine';
import { getTextureDimensions } from 'esengine/tilemap';

const measurePlaced = defineSystem([Query(Sprite)], (q) => {
  for (const [entity, sprite] of q) {
    const dims = getTextureDimensions(sprite.texture);   // { width, height } | null
    if (dims) { /* … */ }
  }
});
```

纹理真正上传之前它返回 `null` —— 场景的纹理是异步加载的，所以第一帧就跑的系统看不到东西
是完全正常的。

<Aside type="caution">
  `getTextureDimensions` 是 **`@experimental`**：不作任何兼容性承诺，任何版本都可能改动或消失
  （见 [API 稳定性](/docs/zh-cn/reference/api-stability/)）。想知道图片尺寸，
  `loadTexture` 返回的 `{ width, height }` 才是稳定那条路。
</Aside>

### 一张图，两种加载

`loadTextureRaw(ref)` 上传图片时**不做** `loadTexture` 那次垂直翻转。翻转与不翻转是真正不同的
GPU 对象，所以分开缓存。除非你在喂一条本来就要求自下而上行序的管线，否则用 `loadTexture`。

## 导入设置

导入设置属于**图片**，不属于任何用它的实体。它们存在图片旁边的 `.meta` 文件里，在内容浏览器里
选中图片即可编辑——用这张纹理的每个精灵都继承这套设置。

| 设置 | 默认 | 作用 |
|---|---|---|
| **Max Size** | `2048` | cook 时的降采样上限（2 的幂）。最长边超过它的源图会被 box 滤波缩下来；更小的源图原样保留。 |
| **Compression** | `Auto` | **GPU compressed**(GPU 压缩)发布 KTX2(Basis Universal),在显存里保持压缩——约为解码后的四分之一——并按设备转码。**Original image**(原图)按原文件发布:画质无损,平涂美术下载体积小得多,但在 GPU 上是完整解码的大小。**Auto**(自动)对网格用到的贴图(直接引用或经由材质)用 GPU 压缩,对精灵和 UI 用原图。构建严格按这一项执行,不会因为哪个文件更小就擅自替换。 |
| **Compress Format** | `uastc` | `uastc` —— 质量高、体积大。`etc1s` —— 小得多、质量低(适合照片类/低频美术)。仅在贴图使用 GPU 压缩时生效。 |
| **Mip Maps** | 开 | 保留一串逐级减半的副本,让画得很小的贴图采样的是滤波后的图而不是闪烁;多占三分之一内存。始终以原尺寸绘制的像素美术和 UI 可以关掉。 |
| **Filter** | `linear` | 采样过滤。`nearest` 保持像素锐利；`linear` 平滑。 |
| **Wrap** | `repeat` | `[0,1]` 之外的 UV 如何寻址：`repeat`、`clamp`、`mirror`。 |
| **sRGB Color** | `true` | 图片存的是 sRGB 编码的颜色(albedo、UI)。法线图、遮罩这类本来就是线性的数据要关掉。仅在项目按线性色渲染时有意义。 |
| **Alpha Is Transparency** | `true` | 纹理烹饪时(构建和编辑器同样适用),完全透明的像素会取周围不透明像素的颜色,这样透明边缘(比如圆角面板的角)在过滤和 mip 时不会把 alpha 为 0 下的黑色混进来形成黑边。半透明和不透明像素保持原色;预乘内容不处理。如果某张图 alpha 为 0 处的 RGB 被 shader 当作数据读取,请关掉。 |
| **Mip Coverage Cutoff** | `0` | 用于镂空(树叶、草、栅栏):材质测试的 alpha 阈值。每一级 mip 都保留与完整图像相同比例的高于阈值的像素,镂空就不会随距离变稀。`0` = 关;对 UASTC 压缩贴图生效。 |
| **9-Slice Border** | `0,0,0,0` | 左/右/上/下边框，单位是**纹理像素**：图片的角在哪里结束。在这里授权一次，每个设成 Sliced 的 `UIVisual` 都继承。 |
| **Cell Width / Cell Height** | `0` | 精灵表里一个格子的大小，单位像素。`0` 表示这张图不是精灵表；设了之后，`Sprite` 可以选取图中的某一帧，而不是显示整张。 |
| **Margin** | `0` | 第一个格子之前的内边距，两个轴相同。 |
| **Spacing** | `0` | 相邻格子之间的间隙，只算在格子之间，最后一格之后不算。 |

<Aside type="tip">
  **像素画**：Filter 设 `nearest`，Compression 设为 **Original image**(原图;自动模式下精灵本来就是原图)。线性过滤会把你画的像素糊掉，
  而块压缩的瑕疵恰恰出现在硬色边上。
</Aside>

### 一次改一整个文件夹

多选若干张图片（ctrl/cmd 点选、shift 点选，或者全选），Inspector 就在编辑**它们全部**。
一项设置它们本来就一致，就显示那个值；不一致就显示一个横杠——往里填一个值，所选的每张图片
都会取这个值。保存只写你动过的设置，各自不同的其它设置原样保留。精灵和纹理共用一套导入
设置，可以一起批量改；选择里混进音频或模型则会直接说明——它们没有共同的字段。

九宫格边框编辑器只在单选时出现：它画的是一张图，而四十张没有一张诚实的图可画。

### 按平台覆盖

Max Size、Compression、Compress Format 可以**按平台覆盖**——就是导入设置里 Default 旁边那排页签。
这就是「编码一次、按 GPU 转码」的管线：同一个源文件，桌面端发 2048 的 UASTC，微信发 1024 的
ETC1S。见[烘焙与压缩](/docs/zh-cn/assets/overview/#烘焙压缩与内容寻址)。

## 精灵按纹理定尺寸

`Sprite.size` 的单位是**世界单位**，并且刻意与图片无关——正因如此你才能不改文件就缩放美术。
但没人愿意手敲图片尺寸，所以编辑器替你填：

- 从内容浏览器**把图拖**进视口，生成的精灵已经按图片像素定好尺寸。
- **给已有精灵指定纹理**同样会按那张纹理定尺寸，之后换图也会跟着走。

一旦这个数是你自己定的，它就停手：你手动设过 `size` 之后，换纹理不会再动它。
（撤销历史里这次自动匹配是独立的一步 **Fit Sprite To Texture**，所以你可以保留尺寸、只撤掉匹配。）

代码里没有这个便利：只给 `Sprite` 一个纹理，`size` 保持默认值，所以要像上面那样自己传
`tex.width` / `tex.height`。

## 子矩形与图集

精灵可以用 `uvOffset` / `uvScale` 只画纹理的一部分，两者都是相对整张图的归一化比例：

```typescript
// 256×256 图集里第 2 列第 1 行的 32×32 帧。
sprite.uvOffset = { x: 64 / 256, y: 32 / 256 };
sprite.uvScale  = { x: 32 / 256, y: 32 / 256 };
```

做序列帧动画不要手算这些，去授权一个 flipbook——见[动画](/docs/zh-cn/animation/overview/)。
瓦片美术见[瓦片地图](/docs/zh-cn/world/tilemaps/)。

## 贴图配方

贴图可以按"怎么画"发布,而不是按像素发布。**`.esimage`** 是一张图的源文件:由形状、渐变、噪声和网格组成的图层,也就是图像工具写出并据此
画出 `.png` 的那个文件。在需要贴图的地方(精灵、材质)直接写 `.esimage`,包里带的就是源文件;贴图第一次加载时在设备上画出来,和它的
`.png` 逐像素一致。

```json
{ "type": "Sprite", "data": { "texture": "assets/tex/plate.esimage", "size": { "x": 512, "y": 512 } } }
```

一块 512 像素、带噪声、锈迹、色带和铆钉的钢板,作为配方是 691 字节,作为 PNG 是 351 KB。负责画配方的是 `esengine/image` 模块,压缩前约占
web 包 220 KB(gzip 后 81 KB):导出时只要包里有配方就会自动带上,用脚本按代码加载配方的话,在游戏启动处导入它。没有配方的包不会带它。

配方的代价是时间,而且只付一次。它在工作线程上绘制,画的时候游戏照常运行;画出的像素存进设备的内容缓存,下次运行直接读取,什么都不画。
一块 2048 像素的钢板第一次访问时在桌面工作线程上画了 4.1 秒,主线程的最长占用没有超过平常启动的水平;第二次访问一笔没画。存下来的像素
没有压缩(那块钢板是 16 MB),也不会被自动清掉:`assets.cleanDiskCache(budget, true)` 先清最久没读过的,被清掉的图下次再画一遍。没有工作线程的环境里配方在主线程绘制;没有缓存的环境里每次运行都画。配方变了,
或者光栅器变了,就是另一个缓存项,所以不会读到过期的像素。

凡是读图片的地方都认配方:作为贴图,以及把图片当数值读的地方(地形图层、地形的 splatmap、植被的密度图和缩放图)。

**表面贴图。** 带 `material` 的源文件既是颜色也是表面。它的每张表面贴图都是独立的贴图,所以是独立的文件,两行,指向那张图:

```json
{ "mapOf": "assets/tex/wall.esimage", "map": "normal" }
```

`map` 是 `normal` 或 `surface`(绿通道粗糙度,蓝通道金属度;两者处处同值时只有一个像素)。存成 `.esimage`,给它贴图该有的导入设置
(用途:数据或法线贴图),在需要这张贴图的地方引用它。它所指向的那张图会随它一起进包,不管别处有没有引用。编辑器的图像工具会在带 `material` 的图旁边写好这两个文件
(`wall_normal.esimage`、`wall_surface.esimage`),并设为数据;贴图字段可以像选图片一样选图的源文件。

**配方可以引用什么。** 铺进来的图片(`image` 图层的 `src`:PNG 或另一个配方),以及文字所用的字体文件。它们随配方一起进包,其中任何
一个变了,配方都会重画。

**文字**由设备自己的 2D 画布绘制,工作线程有画布时就在工作线程上画。`font` 写的是项目里的字体文件时,各处画出的字形一致;写字体族名
或不写时,用的是设备上的字体,所以同一个配方在两台设备上可能不一样。没有 2D 画布的宿主(原生宿主)会拒绝带文字的配方,并提示改为烘焙。

**`figure` 图层**在设备上摆姿势、压平,用的就是创作时画它的那份代码。

## 内存与驻留

纹理通常是 2D 游戏里最大的一块，它们是引用计数 + 可驱逐的，不会永远常驻。预算、LRU、以及怎么读
真实占用，见[纹理内存与预算](/docs/zh-cn/assets/overview/#纹理内存与预算)。

一句话版本：没人引用的纹理会在内存压力下被驱逐，下次按同一路径加载时透明地复活。
