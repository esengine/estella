纹理是 GPU 上的图像。它按项目路径引用，加载为**句柄**，再赋给组件字段：`Sprite.texture`、材质采样器、位图字体页。绘制纹理的组件见[精灵](/docs/zh-cn/graphics/sprites/overview/)；引用、寻址组与清单见[资源](/docs/zh-cn/assets/overview/)。

## 支持的格式

| 扩展名 | 说明 |
|---|---|
| `.png` | 带透明度美术的默认格式。 |
| `.jpg` / `.jpeg` | 无 alpha 通道；照片类美术体积更小。 |
| `.webp` | 支持 alpha 与有损或无损压缩；由浏览器或运行时解码。 |
| `.gif` | 只取第一帧，作为静态图像加载。 |
| `.bmp` | 未压缩。 |
| `.ktx2` | Basis Universal，GPU 压缩格式。烘焙生成的格式，也可以直接制作。 |
| `.esimage` | [纹理配方](#纹理配方)，在设备上绘制。 |

`.aseprite` / `.ase` 文件不是纹理：导入后生成一张图表 `.png` 和每个标签一个片段，场景引用的是这些产物（[精灵动画](/docs/zh-cn/animation/sprite-animation/#aseprite-导入)）。

## 加载纹理

`assets.loadTexture(ref)` 解析引用、上传图像，并返回句柄及图像的像素尺寸：

```typescript
import { defineSystem, Res, Assets } from 'esengine';

const measure = defineSystem([Res(Assets)], async (assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');
  tex.handle;   // TextureHandle，组件字段接受的值
  tex.width;    // 源图像宽度（像素）
  tex.height;   // 源图像高度（像素）
});
```

`width` 与 `height` 是源图像的像素数，与以世界单位计的 `Sprite.size` 无关。按每个图像像素一个世界单位绘制精灵：

```typescript
import { defineSystem, Query, Mut, Res, Sprite, Assets } from 'esengine';

const showArt = defineSystem([Query(Mut(Sprite)), Res(Assets)], async (q, assets) => {
  const tex = await assets.loadTexture('assets/textures/player.png');
  for (const [entity, sprite] of q) {
    sprite.texture = tex.handle;
    sprite.size = { x: tex.width, y: tex.height };
  }
});
```

<Aside type="note">
  `loadTexture` 按解析后的路径缓存并计数：同一图像加载两次返回同一句柄，只上传一次。用 `assets.releaseTexture(ref)` 释放，参数是**加载时使用的引用**而不是句柄。场景引用的纹理随场景释放（[生命周期与内存](/docs/zh-cn/assets/memory/#引用计数)）。
</Aside>

`loadTextureRaw(ref)` 上传图像时**不做** `loadTexture` 所做的垂直翻转。翻转与未翻转的上传是不同的 GPU 对象，分别缓存。仅用于期望自下而上行序的管线。

### 从非自行加载的句柄读取尺寸

编辑器中放置的精灵由场景加载器赋予纹理。要读取这类句柄的尺寸，使用 `getTextureDimensions`：

```typescript
import { defineSystem, Query, Sprite } from 'esengine';
import { getTextureDimensions } from 'esengine/tilemap';

const measurePlaced = defineSystem([Query(Sprite)], (q) => {
  for (const [entity, sprite] of q) {
    const dims = getTextureDimensions(sprite.texture);   // { width, height } | null
    if (dims) { /* … */ }
  }
});
```

纹理上传完成之前它返回 `null`。场景纹理异步加载，因此第一帧运行的系统可能得到 `null`。

<Aside type="caution">
  `getTextureDimensions` 标记为 **`@experimental`**：可能在任何版本中变更或移除（[API 稳定性](/docs/zh-cn/reference/api-stability/)）。`loadTexture` 返回的 `{ width, height }` 是读取图像尺寸的稳定方式。
</Aside>

## 导入设置

导入设置属于**图像**本身，对所有使用该图像的实体生效。它们保存在图像的 `.meta` 文件中，在内容浏览器中选中图像即可编辑。

![sprite-rendering 示例中 ship_K.png 的细节面板：含 Use、Max Size、Compression、Mip Maps、Filter、Wrap 与 sRGB Color 的导入设置](@/assets/guides/zh/assets-texture-import-settings.png)
| 设置 | 键 | 默认值 | 说明 |
|---|---|---|---|
| **Use** | `use` | `Colour` | **Colour**：图片；构建可按 Max Size 缩小、压缩，并填充透明纹素下的颜色。**Data**：每个纹素存数值（高度图、测量遮罩、查找表）；构建保留其位深（16 位 PNG 仍为 16 位），从不压缩、不按 sRGB 解码，只在显式设置 Max Size 时缩小。见[数据纹理](#数据纹理)。 |
| **Max Size** | `maxSize` | `Source size` | 烘焙时对最长边的上限：256、512、1024、2048、4096 或 8192。更大的源图按盒式滤波缩小，更小的不变。**Source size** 从不缩小。 |
| **Compression** | `compress` | `Auto` | **GPU compressed**：发布 KTX2（Basis Universal），在显存中保持压缩（约为解码尺寸的四分之一），并按设备转码。**Original image**：原样发布文件；精确，对平涂美术通常下载更小，但在 GPU 上完整解码。**Auto**：网格绘制的纹理（直接或经材质）用 GPU 压缩，精灵与 UI 用原图。见[压缩与构建对话框](#压缩与构建对话框)。 |
| **Compress Format** | `compressFormat` | `uastc` | `uastc`：质量高、体积大。`etc1s`：体积小得多、质量较低，适合照片类美术。仅在 GPU 压缩时使用。 |
| **Mip Maps** | `mipmaps` | 开 | 保留一串逐级减半的副本，使缩小绘制的纹理采样到经过滤波的图像。多占三分之一内存。像素画与按原尺寸绘制的 UI 应关闭。 |
| **Filter** | `filterMode` | `linear` | `nearest` 保持纹素锐利；`linear` 插值平滑。 |
| **Wrap** | `wrapMode` | `repeat` | `[0,1]` 之外 UV 的寻址方式：`repeat`、`clamp`、`mirror`。 |
| **sRGB Color** | `sRGB` | 开 | 图像存储 sRGB 编码的颜色（反照率、UI）。法线贴图、遮罩等线性数据应关闭。仅在项目以线性色彩渲染时有意义。 |
| **Alpha Is Transparency** | `alphaIsTransparency` | 开 | 烘焙纹理时（构建与编辑器均是），完全透明的纹素取相邻不透明纹素的颜色，使过滤与 mip 不会让透明边缘变暗。半透明与不透明纹素保持原色；预乘美术不变。若着色器把 alpha 为 0 处的 RGB 当作数据读取，应关闭。 |
| **Mip Coverage Cutoff** | `mipCoverage` | `0` | 用于镂空美术（树叶、草、栅栏）：材质测试的 alpha 阈值。每级 mip 保持与完整图像相同的高于阈值纹素比例，镂空不会随距离变稀。`0` 表示关闭。范围 0–1；适用于 UASTC 压缩纹理。 |
| **Border Left / Right / Top / Bottom** | `sliceBorder.*` | `0` | 九宫格边界，以**纹理像素**计。所有使用该纹理、处于 `NineSlice` 模式的 `UIVisual` 都继承它（[图片](/docs/zh-cn/ui/images/#nineslice)）。 |
| **Cell Width / Cell Height** | `sheet.cellWidth` / `sheet.cellHeight` | `0` | 精灵图表中单元格的像素尺寸。`0` 表示不是图表；非零时 `Sprite` 可以选取一个单元格作为帧。 |
| **Margin** | `sheet.margin` | `0` | 第一个单元格之前的边距，两个轴相同。 |
| **Spacing** | `sheet.spacing` | `0` | 相邻单元格之间的间隙；最后一个单元格之后不计。 |

<Aside type="tip">
  像素画：把 **Filter** 设为 `nearest`，关闭 **Mip Maps**，**Compression** 保持 **Original image**（Auto 已经这样发布精灵）。线性过滤会模糊绘制的像素，块压缩会在硬颜色边缘产生瑕疵。
</Aside>

### 压缩与构建对话框

只有在构建对话框的 **Textures by import settings** 选项开启时（默认关闭）才应用 **Compression** 设置。构建严格按设置执行，不会因文件大小而改用另一种结果。编辑器视口遵循同一选项：开启时纹理以压缩形式绘制，否则按源图绘制。

### 数据纹理

每通道 16 位的 PNG 以 **Use: Data** 导入。把纹理赋给按数值读取纹素的字段时，它会被标记为 Data：`Terrain.heightmap`、`splatmap`、`splatmap2`、`occlusionMap`，以及 `Foliage.densityMap` 与 `scaleMap`。**Project Health** 列出被按数值读取却以 Colour 导入的纹理，并提供一键修复。

### 同时编辑多张图像

选中多张图像（Ctrl/Cmd 单击、Shift 单击或全选）后，检视器同时编辑全部图像。取值相同的设置显示该值；取值不同的显示短横，输入值后应用到每张选中的图像。保存时只写入改动过的设置。精灵与纹理共用同一套设置，可以一起编辑；包含音频片段或模型的选择没有公共字段，检视器会提示这一点。九宫格边界编辑器要求只选中一张图像。

### 按平台覆盖

**Max Size**、**Compression** 与 **Compress Format** 可以在导入设置中 **Default** 旁边的页签里按平台覆盖。同一源图可以在桌面端以 2048 的 UASTC 纹理发布，在微信上以 1024 的 ETC1S 纹理发布。没有覆盖的平台使用 Default 的值（[烘焙、压缩与内容寻址](/docs/zh-cn/assets/overview/#烘焙压缩与内容寻址)）。

## 按纹理设定精灵尺寸

`Sprite.size` 以世界单位计，与图像无关。编辑器会用图像初始化它：

- 从内容浏览器**拖动图像**到视口，创建的精灵尺寸等于图像像素尺寸。
- 给已有精灵**指定纹理**，会按该纹理调整尺寸，之后更换纹理也会跟随新图像。

手动编辑 `size` 之后，更换纹理不再改变精灵尺寸。撤销历史把尺寸调整记录为单独的 **Fit Sprite To Texture** 步骤，因此可以只撤销尺寸而保留纹理更换。

在代码中，只赋了纹理的 `Sprite` 保持默认 `size`；如上文所示，用 `tex.width` 与 `tex.height` 设置。

## 子矩形与图集

精灵通过 `uvOffset` 与 `uvScale` 绘制纹理的一部分，两者都相对整张图像归一化：

```typescript
// 256×256 图表中第 2 列、第 1 行的 32×32 帧。
sprite.uvOffset = { x: 64 / 256, y: 32 / 256 };
sprite.uvScale  = { x: 32 / 256, y: 32 / 256 };
```

图表动画应改用翻页动画（[精灵动画](/docs/zh-cn/animation/sprite-animation/)）。瓦片美术见[瓦片集](/docs/zh-cn/world/tilemaps/tilesets/)。

## 纹理配方

**`.esimage`** 文件是图像的源：由形状、渐变、噪声与网格组成的图层，图像工具据此写出并渲染 `.png`。在需要纹理的地方（精灵、材质）直接引用 `.esimage`，发布的是源而不是像素；纹理首次加载时在设备上绘制，得到与其 `.png` 相同的像素。

```json
{ "type": "Sprite", "data": { "texture": "assets/tex/plate.esimage", "size": { "x": 512, "y": 512 } } }
```

- **模块。** 配方由 `esengine/image` 模块绘制。发布配方时导出会包含该模块；从代码加载配方的脚本需在启动时导入它。不含配方的包不包含该模块。
- **开销与缓存。** 配方在工作线程上绘制，绘制期间游戏继续运行。像素以未压缩形式存入设备的内容缓存，之后的运行直接读取而不再绘制。缓存的像素不会自动清除：`assets.cleanDiskCache(budgetBytes, true)` 优先清除最久未读取的条目，被清除的图像在下次使用时重新绘制。没有工作线程时在主线程绘制；没有缓存时每次运行都绘制。配方或栅格改变后是另一个缓存条目。
- **读取方。** 凡是接受图像的地方都接受配方：作为纹理，以及按数值读取图像的字段（地形的图层与 splatmap、植被区的密度与缩放贴图）。
- **依赖。** 配方可以引用它放置的图像（`image` 图层的 `src`：PNG 或另一个配方）以及文本所用的字体文件。它们随配方一起发布，任何一个改变都会重新绘制配方。
- **文本**用设备的 2D canvas 排版，有条件时在工作线程上进行。项目文件形式的 `font` 在所有设备上都用该文件的字形绘制；字体族名或不指定时使用设备字体，因此不同设备的结果可能不同。没有 2D canvas 的宿主（原生宿主）拒绝含文本的配方，并提示需要烘焙。
- **figure 图层**在设备上由与编辑器中相同的代码摆好姿势并展平。

### 表面贴图

带 `material` 的配方除颜色外还描述表面。每张表面贴图是一张独立纹理，因此是一个独立的 `.esimage`，指向其图像：

```json
{ "mapOf": "assets/tex/wall.esimage", "map": "normal" }
```

`map` 为 `normal` 或 `surface`（绿色通道为粗糙度，蓝色通道为金属度；两者都为常量时只有一个像素）。给贴图文件设置 **Use: Data**，并在贴图所在位置引用它。它所对应的图像随之发布。编辑器的图像工具会在带 `material` 的图像旁写出两个贴图文件（`wall_normal.esimage`、`wall_surface.esimage`），并已设为 Data。
