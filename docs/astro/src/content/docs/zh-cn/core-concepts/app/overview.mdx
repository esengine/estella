Estella 中的一切都运行在 **`App`** 内：它是持有[世界](/docs/zh-cn/core-concepts/ecs/)、资源、系统调度与帧循环的容器。
编辑器的运行模式、导出的 Web 或桌面游戏、小游戏以及无头权威服务器都构建同一个 `App` 类；区别仅在于组装它的工厂函数。

| 页面 | 内容 |
|---|---|
| 应用与工厂函数（本页） | `createWebApp`、`createHeadlessApp`、已安装的插件、侧模块。 |
| [App API](/docs/zh-cn/core-concepts/app/app-api/) | `App` 的成员：资源、系统、帧循环、执行挂起、错误与统计。 |
| [生命周期与状态](/docs/zh-cn/core-concepts/app/lifecycle/) | 页面生命周期事件、子系统注册表、热重载。 |

插件接口见[插件与资源](/docs/zh-cn/core-concepts/plugins-resources/#插件)。

<Aside type="note">
  在由编辑器驱动的项目中，`App` 由导出的运行时构造。工厂函数在以下场景中直接使用：将引擎嵌入自定义宿主页面、运行无头服务器，或编写测试。
</Aside>

## `createWebApp(module, options)`

浏览器或 Electron 游戏的入口。它接收已实例化的引擎 WebAssembly 模块（`ESEngineModule`），初始化渲染器并安装完整的插件栈：

```typescript
import { createWebApp } from 'esengine';

const app = createWebApp(module, {
  wasmBaseUrl: '/engine',        // where physics.wasm / spine42.wasm are served
  colorSpace: 'linear',
  getViewportSize: () => ({ width: innerWidth, height: innerHeight }),
});
await app.run();
```

### `CreateWebAppOptions`

所有字段均为可选。`CreateWebAppOptions` 在 `WebAppOptions`（二者均从 `esengine` 导出）的基础上增加了 `wasmBaseUrl`。

| 选项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `wasmBaseUrl` | `string` | — | 提供[侧模块](#侧模块)产物（`physics.wasm`、`spine38.js`/`.wasm` 等）的基础 URL，通常为 `esengine.wasm` 所在目录。未显式给出 `sideModules` 时，据此构建一个基于 fetch 的 `SideModuleHost`。 |
| `sideModules` | `SideModuleHost` | 由 `wasmBaseUrl` 构建，否则无 | 可选原生模块的获取器。将模块内联的宿主（试玩广告、微信）传入宿主对象而不是 URL。 |
| `ownsSideModules` | `boolean` | 由 `wasmBaseUrl` 构建时为 `true` | 该宿主仅属于此 app，退出时销毁。 |
| `plugins` | `Plugin[]` | `[]` | 附加插件，在默认插件集**之后**安装。 |
| `getViewportSize` | `() => { width, height }` | — | 供相机系统使用的视口尺寸，以及 WebGPU 的初始尺寸（缺省时为 `800×600`）。 |
| `renderSurface` | `RenderSurfaceSource` | `{ kind: 'default' }` | 宿主提供渲染表面的方式（见下文）。 |
| `colorSpace` | `'gamma' \| 'linear'` | `'gamma'` | 项目色彩空间。`'linear'` 在线性光下渲染：采样时 sRGB 解码、线性混合、在最终 blit 中显式编码。创建时固定；着色器据此编译。 |
| `randomSeed` | `number` | — | 为引擎的随机性设定种子，使运行可复现（回放、缺陷报告、帧断言）。不设置时每次运行都不同。各子系统从独立的具名随机流中取值，因此添加一个发射器不会改变其他子系统的取值。 |
| `ySortLayers` | `number` | `0` | 在层内按世界 Y 排序的渲染层位掩码（第 0–31 位）。 |
| `depthLayers` | `number` | `0` | 按深度而非画家顺序解析的渲染层位掩码（第 0–31 位）。不透明绘制写入深度并从前到后排序；混合绘制只测试不写入。同时启用 Y 排序的层保持 Y 排序。 |
| `outputTransform` | `'none' \| 'aces' \| 'neutral'` | `'none'` | 在输出到显示器前最后应用一次的曲线。`'aces'` 是面向受光 3D 场景的电影感曲线；`'neutral'`（Khronos PBR Neutral）保持色相与饱和度。 |
| `msaaSamples` | `number` | `4` | 场景目标的多重采样数；`1` 表示禁用。设备会限制该值。 |
| `skinCache` | `SkinCacheConfig` | 开启，全部网格，128 MB | 计算蒙皮缓存（项目设置 → Rendering → Skinning）。 |
| `asyncCompute` | `boolean` | `false` | 允许符合条件的 GPU 计算通道与渲染重叠执行。 |
| `quality` | `QualityConfig` | — | 质量模式（`'off'`、`'auto'`、`'low'`、`'medium'`、`'high'`）、目标帧率、动态分辨率、各级别配置、设备规则、异步着色器编译与按需渲染。仅在给出时安装。 |
| `screenFit` | `ScreenScalingData` | 关闭（`scaleMode: -1`） | 项目相机适配（[相机适配](/docs/zh-cn/core-concepts/screen/camera-fit/#screenscaling-资源)）。`scaleMode` ≥ 0 时适配生效；`SCREEN_FIT_OFF`（-1）使用 `Canvas` 适配或原始 `orthoSize`。`renderPolicy` 不是 `Surface` 时同样会安装该资源。 |

`renderSurface` 的变体：

| `kind` | 行为 |
|---|---|
| `'default'` | 模块通过 `initRenderer()` 创建自己的 WebGL2 上下文。 |
| `'gl-context'` | 渲染到预先注册的 WebGL2 上下文 `handle` 中。`glx: true` 标记微信的 EmscriptenGLX 上下文。 |
| `'webgpu'` | 启动注入设备的路径。宿主获取 `GPUDevice`，并在实例化前将其作为模块工厂的 `preinitializedWebGPUDevice` 传入。`canvasSelector` 默认为 `'#canvas'`，且必须存在于 DOM 中；`readback` 允许引擎回读自身的帧（`captureFrame`）。 |
| `'threaded-webgl2'` / `'threaded-webgpu'` | 使用事先以 `await Renderer.prepareThreadedSurface(module)` 准备好的渲染线程画布。 |

### 已安装的插件

`createWebApp` 按以下顺序安装：

1. **核心**：`corePlugin`（渲染门面）与一个新的 `RenderPipeline`、相机插件、`assetPlugin`、`prefabsPlugin`、`breakablePlugin`、
   `inputPlugin`、`sceneManagerPlugin`。
2. **UI**：`uiPlugins`——布局、文本、文本输入、遮罩、渲染顺序、交互、拖拽、焦点、安全区。
3. **内容**，排入一个固定的构建顺序：
   - 基础插件——诊断、计时器、速度、生命周期、动画、音频、视频、粒子、拖尾、弹簧骨骼、网格渲染、静态合批、组合合批、
     公告板替身（impostor）、纹理流送、后处理、事件绑定与服务；
   - 通过导入注册的可选子系统。导入 `esengine/tilemap`、`esengine/timeline`、`esengine/ai`（感知、FSM、行为树、导航）、
     `esengine/logic`（脚本图）、`esengine/gameplay`、`esengine/replication`、`esengine/spine`、`esengine/dragonbones`，
     或地形、植被、水体与 worldgen 子路径，即会注册该子系统的插件。不导入某个子路径的游戏既不安装也不打包该子系统。
     Spine 仅在场景使用 Spine 时，才按需从 `app.sideModules` 获取对应版本的运行时。
4. **`options.plugins`**，按给出的顺序安装。

### 物理

物理不在默认插件集中：`Physics2DPlugin`（以及 3D 世界所用的 `Physics3DPlugin`）需要其 WebAssembly 模块。
当项目声明了物理或场景包含物理组件时，导出的运行时从侧模块宿主获取 `'physics'` 并安装该插件。手动组装 app 时，
直接构造 `Physics2DPlugin`；它与 `loadPhysicsModule` 从 `esengine` 导出，完整 API 位于 `esengine/physics`。

## 无头应用

`createHeadlessApp(module, options)` 构建一个**带完整模拟栈、无呈现层**的 app：没有渲染器、渲染管线、输入设备或 UI。
这是权威服务器的配置（相同的 WebAssembly 模块、相同的玩法代码、相同的固定节拍循环），也用于 worker 与测试。

```typescript
import { createHeadlessApp, runHeadless } from 'esengine';

const app = createHeadlessApp(module, { plugins: [gameplayPlugin] });
const stop = runHeadless(app, { fps: 60 });
// later
stop();
```

| `HeadlessAppOptions` | 类型 | 说明 |
|---|---|---|
| `plugins` | `Plugin[]` | 玩法插件，在基础插件集之后安装。 |
| `sideModules` | `SideModuleHost` | 可选原生模块的获取器（服务器上的物理）。 |

| 包含 | 不包含 |
|---|---|
| `assetPlugin`、`prefabsPlugin`、`breakablePlugin`、`sceneManagerPlugin`；诊断、计时器、速度、生命周期、事件绑定与服务插件；`audioPlugin`（在没有音频设备的宿主上静默）；项目导入的所有可选子系统（游戏 AI、脚本图、复制等）。 | `corePlugin`（其渲染门面仅在 `initRenderer()` 之后存在）、相机插件、UI、输入，以及呈现类插件：动画、视频、粒子、拖尾、弹簧骨骼、网格渲染、静态与组合合批、公告板替身、纹理流送、后处理。 |

`runHeadless(app, { fps? })` 以基于挂钟时间的 `setInterval`（默认 60 fps）驱动 app，因为服务器没有 `requestAnimationFrame`。
帧间隔经实测得到，因此固定步长累加器在定时器抖动下仍能保持精确的模拟速率，且耗时较长的异步 tick 不会被重入。
它返回一个停止函数。也可以用 `app.tick(dt)` 手动驱动 app。

<Aside type="caution">
  `createHeadlessApp` 与 `runHeadless` 为 `@beta`：在无头宿主上加载不含纹理的玩法数据的方式尚未定型，工厂函数的选项可能变化。
</Aside>

## 侧模块

可选的原生子系统以按需加载的**独立 WebAssembly 模块**发布，使引擎基础下载保持精简。每个侧模块是一对 emscripten 产物——
`<file>.js` 胶水代码与 `<file>.wasm`——通过 `SideModuleHost` 获取；不同宿主之间只有传输方式不同。

`SIDE_MODULES` 将内置 id 映射到产物：

| `SideModuleId` | 产物 | 内容 |
|---|---|---|
| `'physics'` | `physics.js` / `.wasm` | Box2D 2D 物理。 |
| `'physics3d'` | `physics3d.js` / `.wasm` | Jolt 3D 物理。 |
| `'physics3d:physx'` | `physics3d-physx.js` / `.wasm` | PhysX 3D 物理；接口与 Jolt 相同。项目选择其中一个后端（项目设置 → Physics）并只打包该后端。 |
| `'spine:2.1'` / `'3.8'` / `'4.1'` / `'4.2'` / `'4.3'` | `spine21` … `spine43` `.js` / `.wasm` | 每个骨骼格式版本对应一个 Spine 运行时。 |
| `'dragonbones'` | `dragonbones.js` / `.wasm` | DragonBones 运行时（仅一个版本；格式已冻结）。 |
| `'basis'` | `basis.js` / `.wasm` | 用于压缩纹理的 Basis Universal KTX2 转码器。 |
| `'videodec'` | `videodec.js` / `.wasm` | MPEG-1 软件视频解码器。 |

`SPINE_VERSIONS` 是只读列表 `['2.1', '3.8', '4.1', '4.2', '4.3']`，`spineModuleId(version)` 返回对应的 id。

项目可以在 `.esengine/modules/<id>/` 中提供自己的模块；导出时将其写入打包游戏的配置，该 id 的获取与传输方式与内置模块相同。
通过其他途径得知其模块的宿主调用 `registerSideModule(id, descriptor)`。引擎所拥有的 id 不能被注册。

宿主以一个解析为已实例化模块的 promise 响应 `acquire(id)`。结果按 id 缓存；失败结果缓存为 `null`，因此缺失的产物不会被再次请求。内置传输方式：

| 函数 | 传输方式 |
|---|---|
| `createFetchSideModuleHost(baseUrl)` | 从基础 URL 获取胶水代码与二进制（即 `wasmBaseUrl` 构建的宿主）。用于编辑器、Web 与桌面。 |
| `createEmbeddedSideModuleHost(registry)` | 以 base64 内联的模块（试玩广告）。 |
| `createMiniGameSideModuleHost(...)`，也以 `createWeChatSideModuleHost` 导出 | 小游戏宿主的预编译模块工厂。 |

游戏不直接调用 `acquire`。设置 `app.sideModules`（通过 `wasmBaseUrl` 或 `sideModules`）即可；Spine 插件与物理安装流程在需要时从中获取。

<Aside type="note">
  主 `esengine` 入口重新导出物理与 Spine 的**接线**部分——`Physics2DPlugin`、`Physics2DEvents`、`Physics2D`、`loadPhysicsModule`、
  `Physics3DPlugin`、`Physics3D`、`SpinePlugin`、`SpineEvents`、`Spine`——使宿主无需子路径导入即可注册这些插件。完整 API 位于
  `esengine/physics` 与 `esengine/spine` 子路径（[物理](/docs/zh-cn/gameplay/physics-2d/overview/)、[Spine](/docs/zh-cn/animation/spine/)）。
</Aside>

## 建议

- 使用工厂函数。`createWebApp` 与 `createHeadlessApp` 固化了受支持的插件顺序；用插件列表手动组装 `App.new()` 面向引擎嵌入者。
- 在创建时声明 `colorSpace` 与 `renderSurface`。二者在 app 的整个生命周期内固定（着色器编译、设备注入）。
