**组件**是挂在实体上的一小块纯数据结构。用 `defineComponent` 声明一个组件，给它一个
名字和默认值：

```typescript
import { defineComponent } from 'esengine';

const Speed = defineComponent('Speed', { value: 200 });
const Health = defineComponent('Health', { current: 100, max: 100 });
```

默认值同时定义了组件的形状（字段与类型）和新实例的初始值。组件是纯数据——没有方法、
没有行为。行为存在于[系统](/docs/zh-cn/core-concepts/systems/)里。

## 字段类型

字段的类型由默认值推断。数字、布尔、字符串如你所想，结构化形状会得到对应的编辑器
控件：

```typescript
const Missile = defineComponent('Missile', {
  speed: 400,                          // number
  homing: true,                        // boolean
  targetTag: '',                       // string
  velocity: { x: 0, y: 0 },            // 向量——以 X/Y 一对编辑
  tint: { r: 1, g: 1, b: 1, a: 1 },    // {r,g,b,a} 字段渲染成拾色器
});
```

## 标签——没有数据的组件

**标签（tag）**是零字段的标记组件，纯粹用于过滤——`Player`、`Enemy`、`Frozen`。
用 `defineTag` 声明，在查询里配合 `.with()` / `.without()` 使用：

```typescript
import { defineTag, defineSystem, Query, Mut, Transform } from 'esengine';

const Player = defineTag('Player');
const Frozen = defineTag('Frozen');

defineSystem([Query(Mut(Transform)).with(Player).without(Frozen)], (q) => { /* … */ });
```

## 编辑器元数据

第三个参数控制字段在编辑器 Details 面板里的呈现——范围、滑杆、单位、枚举：

```typescript
const Turret = defineComponent('Turret', {
  range: 300,
  mode: 0,
}, {
  fields: {
    range: { min: 0, max: 1000, slider: true, unit: 'px' },
    mode: { enum: [{ label: 'Idle', value: 0 }, { label: 'Attack', value: 1 }] },
  },
});
```

常用的 `fields` 选项：`min` / `max` / `step`、`slider`、`unit`、`enum`（下拉，
存储选项的整数值）、`flags`（位掩码多选）、`tooltip`。其他组件级元数据：
`assetFields`（把字段标记为资产引用，Details 渲染选择器、cook 会带上依赖）、
`animatableFields`（[Sequencer](/docs/zh-cn/animation/timeline/) 可打关键帧的字段
——默认为全部数字字段）、`transient`（永不存进场景——用于逐帧运行时状态），以及
`replicatedFields`（由[联网](/docs/zh-cn/scripting/networking/)的状态复制同步）。

## 内置组件

引擎注册了 77 个组件，与你自己的组件一起查询——`Transform`、`Sprite`、
`ShapeRenderer`、`Camera`、`Light2D`、`ParticleEmitter`、`SpineAnimation`、
`TilemapLayer`、UI 组件族、物理碰撞体等等。每个子系统指南讲它自己那一批；
[组件参考](/docs/zh-cn/reference/components/core/)则逐个列出全部组件的字段、类型与
创作默认值——数据来自编辑器 Details 面板读的同一份注册表。

### 引擎用来描述实体的那几个

有四个不属于任何子系统——它们是引擎和编辑器用来描述一个实体本身的方式，你在 Outliner
里和场景文件里遇到它们，会远早于你去查询它们。

| 组件 | 是什么 |
|---|---|
| `Name` | 实体的显示名——World Outliner 显示的就是它，按名字查找也解析到它。 |
| `Parent` / `Children` | 层级关系。引擎保证这一对同步；见[变换](/docs/zh-cn/core-concepts/transforms/#父子层级)。 |
| `Disabled` | 一个标签。`setEntityActive(entity, false)` 加上它，而 `isEntityActive` 就是「它不在」——所以「是否激活」是关于一个组件的问题，而不是一个要额外同步的标志位。 |
| `RuntimeOnly` | 标记一个由系统**派生**出来、而非你手工创作的实体——`Tilemap` 投影出的层实体、运行时瓦片碰撞体。场景保存会跳过它们，因为把派生实体存下来，会在下一次派生时变成重复。 |

这两个标签都是普通组件：像别的组件一样用 `.with(Disabled)` / `.without(Disabled)` 查询，
你也可以直接增删它们而不走 `setEntityActive`。注意 Outliner 的眼睛是**另一回事**——那是
编辑期的可见性折叠，完全不碰 `Disabled`，所以编辑时把实体藏起来不会改变运行中的游戏。

## 读取与写入

系统通过查询拿到组件数据。当系统要写入某个组件时，把它包进 `Mut(...)`，这样变更检测
和渲染器就知道这块数据被改动过：

```typescript
Query(Mut(Transform), Speed)
// Transform 会被写入；Speed 只读
```

因为写入被跟踪，系统也能响应生命周期：`Added(Comp)` / `Changed(Comp)` 把查询收窄到
组件刚出现 / 刚变化的实体——完整的查询词汇见
[系统](/docs/zh-cn/core-concepts/systems/)。

<br />

在底层，一个组件是带 `ES_COMPONENT` / `ES_PROPERTY` 注解的 C++ 结构体；跨边界的内存
布局是生成的，因此 TypeScript 组件与 C++ 结构体始终保持一致。
