Estella 游戏是由**插件**组成的 `App`。每个子系统——物理、音频、瓦片地图、粒子、UI 等——都是一个插件，
它注册自己的系统，并将运行时 API 发布为**资源**。

## 资源

### 取用子系统：`Res(XxxAPI)`

系统在参数数组中列出所需的资源；回调在相同位置接收该资源：

```typescript
import { defineSystem, Res, Audio } from 'esengine';

defineSystem([Res(Audio)], (audio) => {
  audio.playSFX('assets/hit.wav');
});
```

每个子系统的命令式 API 都以这种方式取用：

| 子系统 | 资源 | 指南 |
|---|---|---|
| 输入 | `Res(Input)` | [输入](/docs/zh-cn/scripting/input/overview/) |
| 音频 | `Res(Audio)` | [音频](/docs/zh-cn/assets/audio/overview/) |
| 资源 | `Res(Assets)` | [资源](/docs/zh-cn/assets/overview/) |
| 瓦片地图 | `Res(Tilemaps)`——来自 `esengine/tilemap` | [瓦片地图](/docs/zh-cn/world/tilemaps/code/) |
| 粒子 | `Res(Particle)` | [粒子](/docs/zh-cn/world/particles/overview/#播放控制) |
| 后处理 | `Res(PostProcess)` | [后处理](/docs/zh-cn/graphics/post-processing/scripting/) |
| 场景 | `Res(SceneManager)` | [场景](/docs/zh-cn/world/scenes/) |
| 补间 | `Res(Tween)` | [补间](/docs/zh-cn/animation/tweens/) |
| 帧动画 | `Res(SpriteAnimation)` | [精灵动画](/docs/zh-cn/animation/sprite-animation/) |
| 动画控制器 | `Res(AnimatorController)` | [动画控制器](/docs/zh-cn/animation/animator/) |
| 计时器 | `Res(TimerRes)` | [计时器与 Velocity](/docs/zh-cn/scripting/timers/) |
| 时间轴 | `Res(Timeline)` | [时间轴](/docs/zh-cn/animation/timeline/playback/) |
| 预制体 | `Res(Prefabs)` | [预制体](/docs/zh-cn/world/prefabs/) |
| 导航 / AI | `Res(Nav)`——来自 `esengine/ai` | [游戏 AI](/docs/zh-cn/gameplay/ai/overview/) |
| 本地化 | `Res(Localization)` | [本地化](/docs/zh-cn/assets/localization/) |
| 相机视图 | `Res(CameraView)` | [相机](/docs/zh-cn/graphics/camera/overview/#屏幕--世界坐标) |
| UI 事件 | `Res(UIEvents)` | [UI](/docs/zh-cn/ui/overview/) |
| 2D 物理 | `Res(Physics2D)`——来自 `esengine/physics` | [物理](/docs/zh-cn/gameplay/physics-2d/overview/) |
| 3D 物理 | `Res(Physics3D)`——来自 `esengine/physics3d` | [3D 物理](/docs/zh-cn/gameplay/physics-3d/overview/) |
| Spine | `Res(Spine)`——来自 `esengine/spine` | [Spine](/docs/zh-cn/animation/spine/) |

物理（2D 与 3D）和 Spine 是按需加载的可选[侧模块](/docs/zh-cn/core-concepts/app/overview/#侧模块)；
瓦片地图与 AI 是可选的子路径包。它们的完整 API 从子路径导出，因此基础包不包含它们。其余 API 都在主 `esengine` 包中。
编辑器与 Web 运行时会安装项目用到的插件；手动构建的 `App` 需自行安装。

部分子系统以同样方式发布**事件资源**——保存当前帧事件、在同一帧内读取的资源：`Res(Physics2DEvents)`（碰撞接触）、
`Res(SpineEvents)`（动画事件）、`Res(UIEvents)`（控件点击与输入）。

### `Res` 与 `ResMut`

| 参数 | 回调接收 | 用途 |
|---|---|---|
| `Res(X)` | 资源值本身。 | 读取资源，以及调用资源对象上的方法。 |
| `ResMut(X)` | 句柄：`.get()` 返回值，`.set(v)` 替换值，`.modify(fn)` 原地修改。 | 替换或修改资源的状态。 |

`ResMut` 对资源的作用与 `Mut` 对组件的作用相同。

### 定义资源

资源是由 app 持有的值；它不必是纯数据。上表中的每个子系统 API 都是作为资源发布的类实例：`Res(Audio)` 是一个
`AudioAPI`，`Res(SceneManager)` 是带有 `switchTo`、`load` 与 `unload` 的 `SceneManagerState`。

`defineResource(defaultValue, name)` 创建资源**定义**——一个身份标识，而不是值本身：

```typescript
import { defineResource } from 'esengine';

class ScoreState {
  value = 0;
  combo = 1;

  add(points: number): void {
    this.value += points * this.combo;
  }
}

export const Score = defineResource<ScoreState>(null!, 'Score');
```

默认值 `null!` 是占位符。实例在插件构建时插入，因此每个 app 拥有各自的实例。引擎的子系统也以同样方式接线：
`SceneManager` 声明为 `defineResource<SceneManagerState>(null!, 'SceneManager')`，其插件调用
`app.insertResource(SceneManager, new SceneManagerState(app))`。

```typescript
import type { App, Plugin } from 'esengine';

export const scorePlugin: Plugin = {
  name: 'score',
  build(app: App) {
    app.insertResource(Score, new ScoreState());
  },
};
```

之后即可像其他资源一样取用该资源：

```typescript
import { defineSystem, Res, ResMut } from 'esengine';

defineSystem([Res(Score)], (score) => {
  // score is the ScoreState instance
  if (score.value > 1000) { /* … */ }
});

defineSystem([ResMut(Score)], (score) => {
  // score is the handle
  score.modify((s) => s.add(100));
});
```

在系统之外——宿主代码、`defineBehavior` 钩子——`app.getResource(Score)` 返回同一个活动实例。

### 默认值

从未插入过的资源会在首次读取时通过克隆传给 `defineResource` 的默认值来生成。克隆按结构进行：

| 默认值 | 每个 app 得到的结果 |
|---|---|
| 纯对象或数组 | 深拷贝——每个 app 一份独立副本。 |
| 类实例 | 同一个对象，由所有读取它的 app 共享。 |
| 函数值属性 | 按引用共享；方法得以保留。 |

类实例按引用传递，因为将其克隆为纯对象会丢失原型与方法。因此，`defineResource(new ScoreState(), 'Score')`
会创建**进程内所有 app 共享的一个实例**；编辑器运行两个 app（编辑模式与运行模式）。保存状态的资源应使用上文所示的
`null!` + `insertResource` 形式。

<Aside type="caution">
  **纯对象**默认值上的方法必须写成方法或 `function` 表达式，而不是箭头函数。箭头函数捕获模块作用域，其 `this` 并不是该资源：

  ```typescript
  defineResource({ value: 0, add(n: number) { this.value += n; } }, 'Score');        // ✅
  defineResource({ value: 0, add: (n: number) => { this.value += n; } }, 'Score');   // ❌
  ```
</Aside>

### 组件与资源的区别

| | 组件 | 资源 |
|---|---|---|
| 作用范围 | 每个实体。 | 每个 app（单例）。 |
| 挂载方式 | 编辑器或 `Commands`。 | `app.insertResource`，或首次读取默认值。 |
| 访问方式 | `Query`、`world.get`。 | `Res`、`ResMut`、`app.getResource`。 |
| 得到的值 | 在 `Mut` 查询之外读取的内置（C++）组件从 WebAssembly 堆解码并以**副本**返回；修改必须写回（[脚本](/docs/zh-cn/scripting/overview/#上下文)）。 | **活动对象**；调用方法或设置字段立即生效。 |

## 插件

插件是在 app 上注册系统、资源与事件的普通对象：

```typescript
import type { App, Plugin } from 'esengine';
import { defineResource, defineSystem, Res } from 'esengine';

const Score = defineResource({ value: 0 }, 'Score');
const scoreSystem = defineSystem([Res(Score)], (score) => { /* … */ });

export const scorePlugin: Plugin = {
  name: 'score',
  build(app: App) {
    app.insertResource(Score, { value: 0 });
    app.addSystem(scoreSystem);
  },
};
```

| 成员 | 类型 | 说明 |
|---|---|---|
| `name` | `string?` | 建议设置。具名插件登记在[子系统注册表](/docs/zh-cn/core-concepts/app/lifecycle/#子系统注册表)中，其 `build()` 中添加的系统继承该名称，用于活跃状态报告。 |
| `dependencies` | `PluginDependency[]?` | 前置条件：插件**名称**（`string`）或**资源定义**。缺少任一项时 `addPlugin` 抛错；`addPlugins` 还会按名称依赖边对批次排序。 |
| `before` / `after` | `string[]?` | 相对于其他插件名称的排序提示，在用 `addPlugins` 安装批次时生效。 |
| `build(app)` | 必需 | 注册系统、资源与事件。在 `addPlugin` 时立即运行。 |
| `activeWhen` | `ComponentDef[]?` | 插件工作所依赖的组件。没有任何实体带有其中任一组件时，其 `build()` 中注册的系统被跳过；最后一个被移除后系统再运行一帧，以便插件释放所持有的内容。省略时始终运行。 |
| `finish(app)` | 可选 | 在**所有**插件构建完成后运行一次，时机为 app 的首次 tick 或 `run()`。用于需要完整插件集的接线。 |
| `cleanup(app?)` | 可选 | 在 `app.quit()` 时（按安装的逆序）或构建失败后释放已获取的资源。必须能处理只完成了一部分的构建。 |

`PluginDependency = string | ResourceDef<any>`。名称要求该插件先行安装；资源定义要求该资源已存在。

引擎的水体、地形、行星、植被、瓦片地图、导航、行为树、状态机、感知与速度插件声明了 `activeWhen`。单个系统以
`app.addSystemToSchedule(schedule, system, { activeWhen: [MyComponent] })` 同样受控。

### 安装

| 调用 | 行为 |
|---|---|
| `app.addPlugin(plugin)` | 安装一个插件。按实例幂等：同一对象添加两次不产生效果。 |
| `app.addPlugins([...])` | 安装一批插件，按 `dependencies`、`before` 与 `after` 拓扑排序；成环时抛错。 |

`build()` 抛错时插件会被回滚，失败以 `error` 条目的形式保留在子系统注册表中。

### 模块级注册

在模块作用域（导入时，任何插件之外）调用的 `addPlugin`、`addSystem`、`addStartupSystem` 与 `defineBehavior`
排队登记在环境上下文中，而不是某个特定 app 上。由[工厂函数](/docs/zh-cn/core-concepts/app/overview/)创建的运行时会将该队列
导入 app——先插件，后系统。手动构建的 `App` 调用 `flushPendingRegistrations(app)` 安装它们。

## 实体

### 获取实体

子系统 API 作用于实体，实体从 `Query` 或生成操作中获得：

```typescript
import { defineSystem, Query, Res, SpriteAnimator, Tween, TweenTarget } from 'esengine';

defineSystem([Query(SpriteAnimator), Res(Tween)], (q, tween) => {
  for (const [entity] of q) {
    tween.to(entity, TweenTarget.PositionX, 0, 100, 1.0, {});
  }
});
```

### 用 `Commands` 生成实体

系统通过 `Commands()` 创建实体并挂载组件：

```typescript
import { defineSystem, Commands, Transform, Sprite } from 'esengine';

defineSystem([Commands()], (cmds) => {
  cmds.spawn()
    .insert(Transform, { position: { x: 0, y: 0, z: 0 } })
    .insert(Sprite, { size: { x: 32, y: 32 } });
});
```
