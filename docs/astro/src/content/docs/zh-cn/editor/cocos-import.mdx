编辑器可以把一个 **Cocos Creator 3.x** 项目整个带过来:它的场景、预制体、脚本和资源会变成一个
Estella 项目,你可以在这里继续编辑。Cocos 文件夹只会被读取,不会被修改。

## 打开 Cocos 项目

在**打开项目**里选择一个 Cocos Creator 文件夹。编辑器通过其 `package.json` 里的 Creator 版本识别它,
并询问是否把它转换成旁边的新项目 `<名字>-estella`,然后打开那个项目。再次打开同一个 Cocos 文件夹
会直接打开已转换的项目,而不会转换两次。

转换会显示进度:当前所处阶段和完成程度,以进度条覆盖在窗口上。转换跑在独立线程里,窗口不会卡住。

- **图片、字体和 spine 文件是链接而不是复制。** 它们以硬链接放进转换后的项目(只有跨盘才复制),
  数 GB 的美术目录既不会被复制,也不会存两份。项目只读这些文件,从不往里写。
- **项目像游戏一样启动。** 它直接打开 Cocos 的启动场景,使用 Cocos 的设计尺寸;只定义全局变量的脚本
  (游戏配置)先于场景点名的脚本运行。场景按 uuid 引用的编辑器内置资源(例如默认的进度条图片)
  从你安装的 Creator 里读取。
- **没能带过来的组件会列出来。** 首次转换后会有一条消息,按使用量从多到少列出没有对应物的组件。
  它们的数据保留在实体上,但不会有任何逻辑运行。
- **Cocos 项目自己的 effect 会被转换**成 Estella 的着色器和材质,用了它的精灵、网格或粒子保持原来的外观。

## 转换保留了什么

**屏幕适配。** Cocos 的设计适配(适配宽度、适配高度)变成项目相机的缩放模式(固定宽度、固定高度),
所以按设计单位布局的 UI 在每种屏幕上大小一致。见[屏幕与设计分辨率](/docs/zh-cn/core-concepts/screen/)。

**层。** 节点在 Cocos 里的层(层序号)会成为它的精灵、文本、图形、spine、粒子和网格所在的层,
相机的剔除掩码就是在这些层之间选择。所以只画某一层的 UI 相机,画出的内容和在 Cocos 里一致。

**UI。** 转换后的 UI 表现与 Cocos 一致:

- UI 层按层级顺序绘制,所以弹窗会盖住下面视图的文字
  (见[层级顺序层](/docs/zh-cn/graphics/sprites/#层级顺序层))。
- `Widget` 变成引擎的 [`RectAnchors`](/docs/zh-cn/ui/overview/#rectanchors--跟随父级的世界内容),配合
  [`ContentRect`](/docs/zh-cn/ui/overview/#contentrect--世界内容的矩形),所以场景在编辑器里就按运行时的
  位置排好。钉在屏幕上的根节点存放在引擎在设计框里放置它的位置。Cocos 的 `Layout` 在引擎的两遍锚点对齐之间运行。
- 没有溢出规则的 Label 不换行,从它的锚点开始排版。
- `EditBox` 变成引擎的输入框,两个标签折叠进去。
- 未激活的节点变成 `Disabled` 标签,整个子树跟着一起关。
- 位图字体的页保持完整尺寸。

**脚本。** 每个脚本的组件类都会声明给编辑器,因此出现在检查器里。脚本打包时容忍 Cocos 容忍的那些缺口
(缺少的 `cc` 名字、被重新赋值的 `const`、`exports` 之外的包文件、只在预览里用到的 import)。两个脚本写了
同一个 `@ccclass` 名字时会被区分开:第二个得到自己的组件名(`Name_2`,按路径顺序),转换器在入口旁写明
是哪个脚本,打包器把新名字写进那个脚本的装饰器。运行时只有当它读过的文件变了,脚本包才会重新构建。

## 重新导入而不丢失你的修改

在由 Cocos Creator 转换来的项目里执行**重新导入 Cocos 项目**。Cocos 一侧改动过的场景和预制体会被带过来,
新增的会被加入;你在这里编辑过的文档保持原样,并计入结果,例如“新增 3,更新 2,5 个因你改过而保留”。
唯一的例外是被编辑过的文档里的 `Cocos.Widget` 组件,它们会变成 `RectAnchors`(字段相同),
这样由旧版导入器转换的项目也能保留对齐。

转换后的项目会记录导入器的修订号;编辑器打开由更旧导入器写出的项目时,会重新转换一次。

在不是由 Cocos 转换来的项目里执行该命令,只会提示这一点,不会改动任何东西。

## `cc` 兼容层

Cocos 脚本之所以能继续工作,是因为项目脚本构建时 `cc` 被解析到引擎的 Cocos 层(`esengine/cocos`)。
那里的 `Node` 就是实体,`Component` 子类就是 Estella 组件。Cocos 中没有对应物的部分不做模拟:`cc` 模块里
这一层没有提供的部分是一个可以被读取、调用、构造的占位,并只提示一次它缺失,而不是 `undefined`。
转换后项目的每个脚本各自加载,所以某个模块抛错不会阻止其他脚本注册。

已覆盖的内容:

| 方面 | 提供的能力 |
|---|---|
| 场景与 `director` | `director.loadScene` 通过引擎的场景管理器运行项目场景(常驻根是 `SceneOwner.persistent`)。场景的组件在帧更新之前的同一阶段启动。`director` 有调度器并触发帧事件,而且是脚本可以打补丁的类。节点的脚本在它加入已激活的父级或被打开时就加载并启用,帧与帧之间创建的节点会加入运行中的世界。 |
| 节点与组件 | `setSiblingIndex` 通过引擎的实体顺序重排。`getComponent` 可按它派生自的基类或 `cc.` 名字查找组件。`Component.EventHandler`、`Node.getParent`、`Camera.screenPointToRay` 都有。设计分辨率在脚本运行前就已知。 |
| 加载资源 | `resources.load` 按路径给出图片、精灵帧和音频,并按路径末尾找到图片的 `spriteFrame` 和 `texture`。目录加载会略过这一层加载不了的东西,而不是失败。`loadAny` 接受 uuid。加载的资源以文件名命名并统计持有者。`assetManager` 有下载器、工厂和 `AssetManager.Cache`。 |
| 网格与材质 | `MeshRenderer` 是引擎网格渲染器的视图:`getSharedMaterial`、`getMaterialInstance`(每个渲染器一个实例,只创建一次)、`material`、`setMaterial`。`Material.setProperty` / `getProperty` 直接写穿到引擎材质(颜色 0..255 变成 0..1);`mainColor`、`albedo`、`baseColor`、`color` 写的是渲染器的色调。还有 `ModelRenderer`、`UIMeshRenderer` 和 `cc.geometry`(`AABB`、`Ray`、`Plane` 以及盒、射线、平面的相交测试)。 |
| 工具 | `js`(类名与查找、`isChildClassOf`、`mixin`、`addon`、属性定义器)、`ccenum`、`NodePool`(处理组件会收到 `unuse` 和 `reuse`)、`cc.profiler`(`showStats`、`hideStats`)。 |
| UI 组件 | Widget、Layout、Button、Toggle(Toggle 属于其父级持有的容器;给 `isChecked` 赋值会关掉同组的其他项)、ProgressBar、ScrollView、Label、Sprite、EditBox 等。精灵、标签和图形接受脚本发出的重建请求。 |

<Aside type="note">
  两个可点击的东西在同一深度和层上重叠时,点击交给层级位置上后绘制的那个,所以从对象池取出、
  加到面板下的节点不会抢走本该给覆盖它的东西的点击。
</Aside>
