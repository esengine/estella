编辑器插件为编辑器添加工具：命令、停靠面板、检视器分区、视口 gizmo 和工具、资产类型、导入器以及 Agent 工具。插件以 TypeScript 编写，位于项目或用户目录中。编辑器直接编译插件，无需构建步骤，保存后即重新编译。

插件的贡献与编辑器自身功能使用同一套注册表：插件贡献的面板就是一个带标签页、关闭按钮和弹出功能的停靠面板。各贡献点见[贡献点](/docs/zh-cn/extending/contribution-points/)。

## 创建插件

<Steps>

1. 打开 **窗口 ▸ 插件**，选择 **添加 ▸ 新建插件…**（也可在命令面板中执行）。

2. 填写 **名称**。**标识** 由名称派生，可以修改；它是点分隔的小写名称，例如 `acme.level-tools`。在 **安装到** 中选择 **项目**（随项目版本管理，团队共享）或 **用户**（个人使用，在所有项目中可用）。

3. 在 **起始样例** 中勾选要包含的样例——命令、面板、检视器分区、视口 gizmo、视口工具——然后选择 **创建**。

</Steps>

{/* SHOT: extend-new-plugin | Plugins window (Window ▸ Plugins) with the New plugin dialog open from Add ▸ New Plugin…: Name, Id, Install to (project / user) and the Start from sample checkboxes, with the Create button; any example project */}

编辑器写出一个可直接运行的插件并加载它：

<FileTree>
- .esengine/
  - plugins/
    - acme.level-tools/
      - plugin.json
      - tsconfig.json
      - src/
        - editor.ts
</FileTree>

```json title="plugin.json"
{
  "id": "acme.level-tools",
  "name": "Level Tools",
  "version": "0.1.0",
  "engines": { "editor": "^0.97" },
  "main": { "editor": "src/editor.ts" }
}
```

```ts title="src/editor.ts"
import { definePlugin, type PluginContext } from '@estella/editor-api';

export default definePlugin({
  activate(ctx: PluginContext) {
    ctx.commands.register({
      id: 'acme.level-tools.hello',
      title: { en: 'Say hello', 'zh-CN': '打个招呼' },
      menu: 'tools',
      run: () => ctx.ui.toast(`${ctx.scene.getSelectionIds().length} selected`),
    });
  },
});
```

该命令出现在“工具”菜单和命令面板中。保存 `editor.ts` 后插件重新编译并重新激活，其贡献的面板会在新构建上重新打开。

## 清单

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `string` | 必填。点分隔、小写、带命名空间（约定为 `<publisher>.<name>`），例如 `acme.level-tools`。 |
| `name` | 本地化字符串 | 必填。显示名称。 |
| `version` | `string` | 必填。插件版本。 |
| `description` | 本地化字符串 | 简短描述。 |
| `publisher` | `string` | 在插件窗口中显示于版本号下方。 |
| `engines.editor` | `string` | 插件支持的编辑器版本范围，例如 `^0.97`。 |
| `main.editor` | `string` | 入口，相对插件目录；运行在编辑器渲染进程中。 |
| `capabilities` | `string[]` | 在信任提示中展示的声明能力：`fs:project`、`net`、`shell`、`process`。便捷 API 依据它们开放（项目文件访问需要 `fs:project`）。 |
| `category` | `string` | 插件窗口分类树中的类别，例如 "Importers"、"Audio"。未设置时归入“其他”。 |
| `icon` | `string` | 插件目录内的一张方形图片（PNG、JPEG、WebP 或 SVG），例如 `Resources/Icon128.png`。 |
| `docsUrl` | `string` | 一个 http(s) 地址；添加“文档”链接。 |
| `beta` | `boolean` | 将插件标记为 Beta。 |

本地化字符串可以是字符串，也可以是以语言区域为键的对象（`{ "en": …, "zh-CN": … }`）。

<Aside type="tip" title="engines.editor">
1.0 之前，**次版本号是破坏性变更的维度**：`^0.97` 不匹配 `0.98`。**新建插件** 会把范围固定为创建它的编辑器版本。从旧插件复制来的范围会使插件被标记为 *版本不兼容*。
</Aside>

## 这套 API 承诺什么

插件 API 是 **experimental（实验性）**，不属于 Estella 1.x 的兼容契约；1.0 之后它仍会继续变化。[VERSIONING.md](https://github.com/esengine/estella/blob/master/VERSIONING.md) 将这一点与 SDK 的[稳定性等级](/docs/zh-cn/reference/api-stability/)一并说明：扩展点仍在向统一机制收敛；插件作为受信代码运行在编辑器渲染进程中，而非隔离环境；目前还没有已发布的插件在实际使用这些接口形态。

以下承诺适用：

- **`engines.editor` 一定被遵守。** 超出声明范围的插件会被拒绝加载并给出原因，绝不会部分加载。
- **破坏性变更一定有记录**，写在 CHANGELOG 的 **Editor plugin API** 标题下，并附迁移说明。
- **移除前一定先弃用。** 将要撤除的贡献点至少在一个次版本内继续可用，并给出提示。

API 的各部分会在已发布插件实际使用后逐个冻结。

**窗口 ▸ 插件** 列出编辑器找到的所有插件。

| 卡片操作 | 作用 |
|---|---|
| 启用复选框 | 启用或停用插件。 |
| **编辑** | 打开 `plugin.json`。 |

## 分享插件

插件卡片上的 **打包** 将插件打包为一个 `.esplugin` 文件，即 ZIP 压缩包。`node_modules`、`dist` 和生成的类型定义不包含在内。

**添加 ▸ 从插件包安装…** 用于安装插件包。它先列出包内容——清单、声明的能力和每个文件——而不解包或写入任何内容。安装不会运行插件：插件安装后处于待信任状态。

### 信任

<Aside type="caution" title="信任">
插件拥有与编辑器相同的访问权限：项目文件以及编辑器能访问的其他任何内容。插件在获得批准（**信任并加载**）之前不会加载。只加载来源可信的插件。提示中会列出声明的能力，但声明的能力只表示意图，并不是沙箱。

批准针对某个目录中的某个版本。新版本，或声明同一 id 的另一个目录，会再次请求批准。**撤销信任** 可取消批准。
</Aside>

## npm 包

插件也可以是项目依赖的 npm 包：

```bash
npm install estella-plugin-tiled
```

根目录含有 `plugin.json` 的任何**直接**依赖都是插件。它与其他插件一样列出并需要信任；批准针对版本，因此更新后会再次请求。作为其他包的依赖间接引入的包不会被视为插件。

一个包可以同时提供插件的两部分：清单指向的编辑器部分，以及游戏导入的运行时代码。

<FileTree>
- node_modules/estella-plugin-tiled/
  - package.json
  - plugin.json  `"main": { "editor": "editor/index.js" }`
  - editor/
    - index.js
  - runtime/
    - index.js
</FileTree>

```ts title="src/main.ts"
import { addPlugin } from 'esengine';
import { TiledPlugin } from 'estella-plugin-tiled';

addPlugin(TiledPlugin);
```

运行时部分是普通模块，随游戏一起打包。应将 `esengine` 声明为 **peer** 依赖：项目的打包器把所有 `esengine` 导入保留为外部引用，使整个游戏共享一个引擎实例；包内自带的副本会成为第二个组件注册表，其中的系统不会注册到实际运行的引擎中。

## 类型定义

每次打开项目时，编辑器都会将 `@estella/editor-api` 的类型定义写入 `.esengine/plugins/.types/editor-api.d.ts`，与正在运行的编辑器一致。**新建插件** 会写出指向它的 `tsconfig.json`；手写插件时可使用：

```json
{
  "compilerOptions": {
    "strict": true,
    "moduleResolution": "bundler",
    "paths": { "@estella/editor-api": ["../.types/editor-api.d.ts"] }
  },
  "include": ["src"]
}
```

## 插件位置

| 位置 | 用途 |
|---|---|
| `<project>/.esengine/plugins/<id>/` | 随项目版本管理，团队共享。 |
| 项目的直接 npm 依赖 | 见 [npm 包](#npm-包)。 |
| `<userData>/plugins/<id>/` | 个人工具，在所有项目中可用。 |

id 冲突时按上表顺序先出现者生效；其余的标记为 **被遮蔽**，并注明占用该 id 的插件。

## 允许的导入

插件运行在编辑器的运行环境中，导入的是编辑器自身的模块实例，因此它注册的内容就是编辑器所使用的内容。插件可以导入：

- `react`、`react-dom`、`react-dom/client`、`react/jsx-runtime`
- `@estella/editor-api`
- `esengine`、`esengine/terrain`、`esengine/worldgen`、`esengine/water`、`esengine/spline`、`esengine/voxel`、`esengine/rig2d`、`esengine/tilemap`、`esengine/replication`

其他任何裸模块说明符都会导致加载错误，错误信息中会列出上述清单；此类依赖应打包进插件。

### 在编辑器中使用游戏注册的提供方

编辑时编辑器不运行游戏脚本；它只读取声明模块以获取组件结构。因此游戏注册的地形提供方（`provider: 'my-game:planet'` 的 `Terrain`）在视口中不存在。导入注册该提供方的模块的项目插件可以使其可用，编辑器与游戏使用同一份代码：

```ts title=".esengine/plugins/my-game.ground/src/editor.ts"
import { definePlugin } from '@estella/editor-api';
import '../../../../src/planet/terrain.ts';   // registerTerrainProvider(...), as the game does

export default definePlugin({ activate: () => {} });
```

该插件运行项目代码，因此编辑器会请求一次信任。新项目的 `.gitignore` 不忽略 `.esengine/plugins/`，因此插件随项目一起提交。

## 项目平台配置

`.esengine/platforms/<id>.mjs` 打包配置（[小游戏平台](/docs/zh-cn/publishing/minigame-platforms/#项目平台)、[试玩广告](/docs/zh-cn/publishing/playable-ads/#自定义广告平台)）以完整系统权限导入编辑器主进程。它会列在插件窗口中，需要同样的批准；批准之前，其目标在打包项目中显示为未就绪。

## 故障排查

**窗口 ▸ 插件** 列出找到的所有插件，包括出错的插件及原因：清单解析失败、编译错误、id 已被占用，或 `engines.editor` 范围不兼容。插件抛出的错误显示在 **输出日志** 中，标记为 `plugin:<id>`，并附调用栈。

持续抛出错误的插件会被停用，以免每次渲染都破坏界面。修复后点击 **重新加载**。

<Aside type="tip">
插件的耗时显示在性能分析器的 `plugin.<id>.<what>` 下，与编辑器自身的工作并列。
</Aside>
