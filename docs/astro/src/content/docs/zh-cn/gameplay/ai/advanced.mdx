`Nav`、`NavAgent` 与 `Perceiver` 覆盖常见情形。它们之下的底层函数同样导出，是不依赖引擎或 WebAssembly 的纯 TypeScript，用于不需要代理的寻路或不需要 `Perceiver` 的视线检测。

## 手动寻路

`findPath` 是导航插件在网格上使用的 A\*：在 `NavGrid` 格子上的一致代价搜索，4 连通或 8 连通，使用八方向距离或曼哈顿启发函数，不允许切角（斜向一步需要两个共享的正交格都可通行）。它适用于由游戏代码操控的移动、路径预览、回合制的可达范围，或在唯一激活的 `Nav` 表面之外的第二张网格。

```typescript
import { NavGrid, findPath, pathToWorld } from 'esengine/ai';

const grid = new NavGrid({ width: 32, height: 24, cellSize: 32 });

const path = findPath(
  grid,
  grid.worldToCell(hero),               // Cell — integer grid coordinates
  grid.worldToCell(chest),
  { diagonal: false },
);
if (path) {
  const waypoints = pathToWorld(grid, path);   // Vec3[] — cell centers, world pixels
}
```

`findPath(grid, start, goal, opts?)` 返回包含两个端点的 `Cell[]` 路径，目标不可达时返回 `null`。`Cell` 是整数网格坐标 `{ x, y }`，与 `Vec2` 区分以标明格子空间。换算使用 `grid.worldToCell(point)` / `grid.cellToWorld(gx, gy)`，整条路径使用 `pathToWorld`。

| `PathfindOptions` 字段 | 默认值 | 说明 |
|---|---|---|
| `diagonal` | `true` | 允许 8 连通的斜向移动。 |
| `snapRadius` | `8` | 起点或终点位于阻挡格时，在搜索前吸附到该环半径内最近的可通行格；`0` 表示不吸附。 |
| `clearance` | `0` | 每一步身体所需的格子余量（`0` 按点规划）。`NavAgent` 的 `radius` 会被换算为该值。 |

`navGridFromTiles` 由任意瓦片读取函数构建可通行掩码。`navGridFromTilemapLayer` 以 `TilemapAPI.getTile` 调用它：

```typescript
import { navGridFromTiles } from 'esengine/tilemap';

const grid = navGridFromTiles((x, y) => level.tiles[y][x], {
  width: 32, height: 24, cellSize: 32,
  blockedTileIds: [WALL_TILE, WATER_TILE],
});
```

| `BuildNavGridOptions` 字段 | 说明 |
|---|---|
| `width` / `height` / `cellSize` / `origin?` | 同 `NavGrid` 选项（[构建网格](/docs/zh-cn/gameplay/ai/navigation/overview/#构建网格)）。 |
| `blockedTileIds?` | 阻挡移动的瓦片 id。 |
| `isBlocked?` | 针对瓦片 id 的谓词（`0` 为空）；优先于 `blockedTileIds`。两者均未给出时，任何非空瓦片都会阻挡。 |

## 感知内部

感知插件封装了以下导出函数，可用于动作中的一次性视线检测、自定义感知或针对模拟世界的测试：

| 函数 | 说明 |
|---|---|
| `senseTarget(observer, facing, target, range, halfFov, isBlocked?)` | 三维几何计算（`Vec3` 点；平面场景的 `z` 恒定）：范围检测、视野锥检测（`halfFov` 为锥角的一半，弧度；π 及以上为全向），然后是可选的遮挡回调。 |
| `facingFromRotation(rotation, axis?)` | 由 `Transform` 旋转与 `FacingAxis`（默认 `'x'`，或 `'-z'`）得到实体朝向的世界方向。 |
| `makeLosCheck(physics)` | 由 2D 物理射线构建遮挡回调：当命中点明显早于目标（`fraction < 0.98`，最后 2% 为目标自身）且命中的不是观察者或目标的刚体时，视为被遮挡。 |
| `stepPerception(world, isBlocked?, noises?, dt?)` | 插件在 `PreUpdate` 中运行的逐帧步骤：对每个 `Perceiver` 感知所有 `PerceptionTarget`，保留最近的可见目标，处理本步的 `Noise` 负载，按 `dt` 累加 `sinceHeard`，并写入 `Perception` 组件。 |

```typescript
import { Transform, registerCondition } from 'esengine';
import { senseTarget, facingFromRotation } from 'esengine/ai';

// A one-off sight check against a POINT — no PerceptionTarget needed.
registerCondition('seesShrine', (ctx) => {
  const tf = ctx.get(Transform);
  return senseTarget(
    tf.position, facingFromRotation(tf.rotation),
    SHRINE,                      // a { x, y, z } point
    300, Math.PI / 3,            // 300 px range, 120° cone
  ).visible;
});
```

`senseTarget` 返回 `SenseResult`：

| `SenseResult` 字段 | 说明 |
|---|---|
| `visible` | 目标在范围内、视野锥内且未被遮挡。 |
| `distance` | 到目标的距离；即使不可见也会设置。 |
| `dir` | 从观察者指向目标的单位方向（`Vec3`）；不可见时为零。 |

插件仅在加载了物理模块时添加视线检测：场景有 3D 世界时使用 3D，否则使用 2D。两者都没有时，感知仅检查范围与视野锥；AI 层不强依赖物理。

## 自定义应用

导入 `esengine/ai` 会注册感知、FSM、BT 与导航插件，编辑器与 `esengine` Web 运行时会添加它们。从裸 `new App()` 构建的应用需显式添加：

```typescript
import { perceptionPlugin, fsmPlugin, btPlugin, navPlugin } from 'esengine/ai';

app.addPlugin(perceptionPlugin);
app.addPlugin(fsmPlugin);
app.addPlugin(btPlugin);
app.addPlugin(navPlugin);
```

每个插件既导出为可直接使用的实例（`navPlugin`），也导出为类（`NavPlugin`），以便创建多个实例。
