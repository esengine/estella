导航沿着一条避开被阻挡格子的路线,把 agent 移动到某个世界坐标,底层用 A\* 在一个 **`NavGrid`**
上寻路。

### 构建网格

`NavGrid` 是一个由可走/被阻挡格子构成的矩形网格。把它装到 `Nav` 资源上,agent 才能对它寻路:

```typescript
import { defineSystem, Res, Nav, NavGrid } from 'esengine';

export const setupNav = defineSystem([Res(Nav)], (nav) => {
  nav.setGrid(new NavGrid({
    width: 60,          // 列数
    height: 44,         // 行数
    cellSize: 20,       // 每格的世界像素
    origin: { x: -600, y: -440 },  // 格子 (0,0) 中心的世界坐标
  }));
}, { name: 'SetupNav' });
```

| `NavGrid` 选项 | 类型 | 说明 |
|---|---|---|
| `width` | number | 格子列数。 |
| `height` | number | 格子行数。 |
| `cellSize` | number | 每格的世界像素(正方形)。 |
| `origin` | `Vec2` | 格子 `(0,0)` 中心的世界坐标。默认 `(0,0)`。 |
| `walkable` | `Uint8Array` | 可选的行主序 `width*height` 掩码,`1` = 可走,`0` = 阻挡。省略则全部可走。 |
| `plane` | `'xy' \| 'xz'` | 格子躺在哪个世界平面上。`xy`(默认)是平面场景自己的平面;`xz` 是 3D 场景的地面。 |
| `surface` | `Float32Array` | 每格地面的高度,在平面留出的那个轴上。省略则每格都位于原点的第三轴。 |
| `stepHeight` | number | 相邻格之间 agent 能爬上去的高度差。`0`(默认)表示任何高差都放行。 |

若想从已绘制的瓦片地图推导网格,而不是手写掩码,用 `navGridFromTilemapLayer`(把某图层的
实心瓦片视作阻挡)或 `navGridFromTiles`。

### 3D 场景的网格

3D 场景有的是几何而不是瓦片掩码,所以它的网格是从**它本来就在碰撞的那些刚体**上**烘焙**出来的
——在一个实体上放 **`NavVolume`**,导航插件就会把它描述的那个盒子填满:

| `NavVolume` 字段 | 说明 |
|---|---|
| `halfExtents` | 要采样的盒子半尺寸,单位世界像素;实体的 Transform 是盒子中心。 |
| `cellSize` | 每格的世界像素。越小路线越细、烘焙越慢。 |
| `maxSlopeDegrees` | agent 能站住的最陡地面。比这更陡的就是墙。 |
| `agentHeight` | agent 需要的头顶空间——不够的格子是爬行空间不是走廊。`0` 跳过这项检查。 |
| `stepHeight` | 相邻格之间 agent 能爬上去的台阶高度。 |
| `layers` | 地面射线投射的物理层;`0` = 所有层。 |

每格一条向下的射线就回答了全部:没命中是洞,命中面倾斜就是坡或墙,命中点上方净空不够就不可走。
烘焙会等 3D 求解器把刚体建出来,所以网格是在开始运行后一两帧出现的,不是加载时。

<Aside type="caution">
  **每一列只有一个面。**桥和桥下的路会塌成射线先碰到的那一个——墙顶会变成两米高处一块
  完全可站的地面,把 agent 挡在墙外的是 `stepHeight` 而不是可走性。多层路网需要真正的
  navmesh,这里不是。
</Aside>

`bakeNavGrid` 也可以直接调用,让游戏按自己的方式烘焙;它只要一个带 `raycast` 的对象,
而 `Physics3D` 资源本身就是。

### 看见烘出来的东西

体积的线框说的是烘焙**往哪看**。想看它**找到了什么**,在运行中的游戏里打开 `NavDebugDraw`:

```typescript
app.getResource(NavDebugDraw).enabled = true;
```

可走的格子按各自地面的高度描边,被台阶限制拒绝的相邻对标成红色——这是唯一能解释
「路线为什么绕远」的东西,因为台沿两边都是可走的格子。默认关闭(一张网格是每帧几千个
四边形),而且画到几千格就停:想看清更大的世界,调 `cellSize`。

<Aside type="tip">
  `Nav` 资源也能直接回答一次性查询:`nav.findWorldPath(from, to)` 返回一组世界空间路点
  (没有路线时返回 `null`),无需 `NavAgent`。
</Aside>

### 移动 agent

加一个 `NavAgent`,然后给它指一个目的地。内置的导航插件会规划路径并每帧沿路径推进 agent——
你只管设目标。

```typescript
import { NavAgent, setNavDestination, stopNavAgent } from 'esengine';

cmds.spawn()
  .insert(Transform, { position: { x: 0, y: 0, z: 0 } })
  .insert(NavAgent, { speed: 140, arriveRadius: 8 });

// 从任何能访问 world 的系统/动作里——每帧调用都安全:
setNavDestination(world, entity, { x: 320, y: -120 });
// ……以及原地停下:
stopNavAgent(world, entity);
```

| `NavAgent` 字段 | 默认 | 说明 |
|---|---|---|
| `speed` | `120` | 移动速度(世界像素/秒)。 |
| `radius` | `0` | 身体有多宽(像素)。寻路会绕开它挤不过去的地方;`0` 按质点寻路。 |
| `arriveRadius` | `6` | 距最终目标的停止距离。 |
| `repathInterval` | `0.5` | 移动中两次重规划的间隔秒数;`0` = 只在目标改变时重规划。 |
| `hasTarget` | `false` | 是否已设目的地(自动管理)。 |
| `targetX`、`targetY` | `0` | 当前目的地(世界像素)。 |
| `arrived` | `false` | agent 到达目标的那一帧被置真。 |

`setNavDestination` 每帧调用都安全,可用于追一个移动的目标——只有当目标真的移动、或
`repathInterval` 到点时,agent 才重新规划。读 `agent.arrived`(或 `Perception`)来判断何时
切换行为。

## agent 是有宽度的

把 `radius` 设成身体的实际半宽,寻路就会绕开它挤不过去的缝隙。留在 `0` 表示按质点寻路——
没有碰撞体的东西就该这样;而这也正是那个经典画面的成因:敌人信心十足地走进门洞然后
永远停在那里,因为它被规划到的那一格是可走的,而挂在隔壁那一格上的半个身子不是。

身体站不下的目标(墙角里的拾取物)依然到得了:路径规划到身体站得下的最近处为止,
剩下的交给 `arriveRadius`。
