3D 场景拥有的是几何而非瓦片掩码，因此其导航表面由其碰撞所用的刚体**烘焙**而来。导航插件烘焙 **`NavVolume`** 所描述的盒体。

## `NavVolume`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `halfExtents` | `{1000, 500, 1000}` | 烘焙盒体的一半尺寸，世界单位；实体的 Transform 为其中心。 |
| `cellSize` | `50` | 地面平面内的体素尺寸。越小越贴合几何，烘焙越慢。 |
| `cellHeight` | `10` | 竖直方向的体素尺寸；决定阳台与其下方地面是否为两个层级。 |
| `maxSlopeDegrees` | `45` | 可行走的最陡地面。更陡的地面视为墙。 |
| `agentHeight` | `180` | 代理所需的净空高度。不足的地面被排除。 |
| `agentRadius` | `30` | 代理宽度。网格会从每面墙后退这一距离。 |
| `stepHeight` | `40` | 代理可直接爬上而非绕行的最高台阶。 |
| `layers` | `0` | 取地面所用的物理层；`0` 为所有层。 |

烘焙会把盒体内的碰撞三角形体素化，保留该尺寸代理可站立的表面，并把结果转换为凸多边形。每一列都保留其**所有**地面，因此桥与桥下的道路是两个地方，路线可以使用任一个。

- **每个场景一个体积。** 烘焙第一个体积；其余体积会记录在日志中。盒体只限定烘焙查找的范围；可通行性来自其中的几何。较大的盒体只增加体素数量，不影响正确性。
- **仅静态刚体。** 需要在其上行走或绕行的几何需要刚体类型为 **Static** 的 `RigidBody3D`（或没有 `RigidBody3D` 的碰撞体，它本身是静态的）。动态刚体不参与烘焙。
- 每个体积在其几何可用的第一帧烘焙一次。网格碰撞体在资源加载完成前不提供任何内容，因此烘焙会等待它。

`buildNavMesh(verts, indices, options)` 可直接烘焙网格，`collectNavGeometry(world, { min, max, layers? })` 用于收集三角形。

<Aside type="caution">
  **每个网格只有一种代理尺寸。** `agentRadius` 是烘焙进去的：网格就是该宽度的身体可以站立的位置集合。比网格半径更宽的 `NavAgent` 会按较窄的尺寸规划路线，并记录一次日志。
</Aside>

### 在流送世界里

在[流送世界](/docs/zh-cn/world/streaming/)中，体积按世界网格（烘焙配置的 `cellSize`）**每个方格一块**进行烘焙，取材于该方格内及其周边的碰撞体：持久世界的碰撞体以及常驻单元的碰撞体。方格在其单元常驻期间拥有一块；没有单元覆盖的方格（只有持久世界持有的地面）则始终拥有一块。单元载入或卸载时，它所涉及的块会重新烘焙，每帧两块，并合并为代理行走的同一张网格：单元中的墙在单元载入后会被绕开，路线跨越两块之间的接缝时没有间断。

单元未常驻的方格没有块，因此通往该处的路线止于已加载区域的边缘，即使下方是持久地面也是如此。出于同样的原因，体积只在地面平面上裁切，并且按整个方格裁切：伸入某个方格的体积会烘焙整个方格。

## `NavLink`

网格只包含代理可以行走的地面，因此被间隙隔开的两层地面是两个地方。`NavLink` 声明地面本身不提供的连接：可以跳下的边缘、梯子、木板。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `start` | `{0, 0, 0}` | 连接的起点，为实体自身坐标系中的偏移。 |
| `end` | `{0, 0, 150}` | 连接的终点。 |
| `bidirectional` | `true` | 是否可双向通行。从边缘跳下不可反向。 |
| `radius` | `50` | 两端与所连接地面之间允许的最大距离。 |
| `enabled` | `true` | 该连接当前是否存在。 |

两端都是实体坐标系中的偏移，因此连接随实体移动与旋转：预制体内的梯子在预制体放置到任何位置时都有效。端点触及不到地面的连接不连接任何东西。

移动或开关连接只需一次查找，而不需要烘焙：它连接已经存在的多边形。因此连接可以低成本地动画化，这与障碍物不同。

<Aside type="note">
  路线会在连接的两端断开：路径点总是包含连接所连的两个点，跟随的代理会经过它们。代理穿越连接期间不在可导航表面上，因此此时请求的重新规划没有结果，代理保留当前路线。
</Aside>

## `NavArea`

网格说明代理可以在哪里行走；`NavArea` 说明这些地面的代价。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `halfExtents` | `{200, 100, 200}` | 盒体的一半尺寸，世界单位；Transform 为其中心。随实体旋转。 |
| `cost` | `3` | 其内单位距离的代价，开阔地面为 `1`。 |
| `enabled` | `true` | 该代价当前是否生效。 |

代价低于 1 会被优先选择，高于 1 会被规避：半价的道路会吸引路线，四倍代价的沼泽在有其他路可走时会被绕开。区域从不阻挡：没有其他路时代理会穿过它。

移动或缩放区域会重建可导航表面，与障碍物相同。修改 `cost` 则不会：网格记录了每个多边形所属的区域，代价在每次搜索时读取。网格路线平滑从不穿越与捷径起点价格不同的地面。

## `NavObstacle`

任何带碰撞体的物体都已经构成阻挡，因为网格由碰撞几何烘焙而来。`NavObstacle` 用于不是几何却需要阻挡的物体，或无需移动即可停止阻挡的物体。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `halfExtents` | `{50, 100, 50}` | 阻挡盒体的一半尺寸，世界单位；Transform 为其中心。与体积不同，它随实体旋转。 |
| `enabled` | `true` | 当前是否阻挡；打开的门清除该字段。 |

阻挡是烘焙输入：障碍物在可行走区域被腐蚀之前就移除其地面，因此路线会为代理的全宽留出余量。移动、缩放或开关障碍物最多每 200 ms 重建一次网格。在网格表面上，障碍物的变化会在下一次导航 tick 中标记，没有这一延迟，因此新关闭的通道在代理规划或移动之前就被排除。网格单独保存自身的可通行性，因此门关上再打开后，恢复的正是原来的地面。

```typescript
// A door swinging open, from any system with world access:
const door = world.get(entity, NavObstacle);
door.enabled = false;
world.set(entity, NavObstacle, door);
```

<Aside type="caution">
  障碍物用于阻挡后保持不动的物体：门、栅门、新建的塔。持续移动的障碍物每秒会多次重建表面，并记录警告。移动的物体应由与其碰撞的角色控制器处理。
</Aside>

## 查看烘焙结果

![开启视图 → 显示导航网格的 3D 视口：烘焙出的可行走表面以琥珀色填充并描边](@/assets/guides/zh/view-navmesh.png)

*由**视图 ▸ 显示导航网格**在视口中填充并描边的烘焙可行走表面。*

体积的线框显示烘焙查找的范围。**视图 → 显示导航网格**（或视口工具栏上的导航按钮）会在编辑器中烘焙场景的体积，并绘制可行走的面及其边界边。场景变化时会重新烘焙，因此修改 `agentRadius` 会立即更新网格。

运行时由 `NavDebugDraw` 资源绘制同样的画面：

```typescript
import { NavDebugDraw } from 'esengine/ai';

app.getResource(NavDebugDraw).enabled = true;
```

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关。 |
| `showFaces` | `true` | 可行走面的轮廓，对网格绘制在地面高度，对格子网格绘制在场景平面中。 |
| `showBorders` | `true` | 可行走表面终止处的边，红色。 |
| `showLinks` | `true` | `NavLink` 连接。 |

叠加层最多绘制 4096 个面；较大的 `cellSize` 可显示大型世界的更多部分。
