*状态机编辑器：由带守卫的转移（`?seesPlayer`、`?lostPlayer`）连接的状态（Patrol / Chase）。*

状态机是由**转移**连接的一组**状态**。任一时刻只有一个状态处于激活；每次 tick 按顺序检查其出向转移，并执行第一个可用的转移。`StateMachineAgent` 在其实体上运行状态机：

```typescript
import { StateMachineAgent } from 'esengine/ai';

cmds.spawn()
  .insert(NavAgent, {})
  .insert(Perceiver, { range: 240 })
  .insert(Perception, {})
  .insert(StateMachineAgent, { fsm: 'assets/ai/enemy.esfsm' });   // an editor-authored asset
```

| `StateMachineAgent` 字段 | 说明 |
|---|---|
| `fsm` | 要运行的状态机：`registerFsm` 名称或 `.esfsm` 资源路径。 |
| `current` | 当前激活的状态名，每次 tick 写入（只读；显示在 Inspector 中）。 |

## 定义状态机

状态机通常在编辑器中创作为 `.esfsm` 资源（[在编辑器中创作](/docs/zh-cn/gameplay/ai/authoring/)）；状态引用已注册的动作与条件名称。也可以在代码中注册：

```typescript
import { registerFsm } from 'esengine/ai';

registerFsm('guard', {
  initial: 'Patrol',
  states: [
    {
      name: 'Patrol',
      onUpdate: 'patrol',
      transitions: [{ to: 'Chase', condition: 'seesPlayer' }],
    },
    {
      name: 'Chase',
      onEnter: 'startChase',
      onUpdate: 'chase',
      transitions: [{ to: 'Patrol', condition: 'lostPlayer' }],
    },
  ],
});
```

## 状态与钩子

每个状态最多有三个钩子 `onEnter`、`onUpdate`、`onExit`，以及一个 `transitions` 列表。钩子是已注册的动作名称，需要参数时写作 `{ name, arg?, params? }`。

| 钩子 | 运行时机 |
|---|---|
| `onEnter` | 状态激活后的第一次 tick，即转入后的下一次 tick。 |
| `onExit` | 执行离开该状态的转移时。 |
| `onUpdate` | 没有转移触发的 tick。 |

每次 tick 最多执行一个转移。FSM 动作的返回值被忽略。

## 转移

当转移指定的**所有**机制都满足时，该转移可用；未指定任何机制的转移是无条件的。引用未注册条件的转移永远不可用。

| 转移字段 | 说明 |
|---|---|
| `to` | 目标状态名。 |
| `trigger` | 必须已被触发的一次性事件名；执行转移时被消费。 |
| `condition` | 必须返回 true 的已注册条件。 |
| `guard` | 一个或多个黑板比较，以 AND 组合。 |

守卫以 `==`、`!=`、`<`、`<=`、`>`、`>=`、`truthy` 或 `falsy` 比较黑板键，例如 `{ key: 'health', op: '<', value: 20 }`。`truthy` / `falsy` 忽略 `value`；缺失的键读作 `undefined`；大小比较运算符按数值比较。触发器与守卫值存放在代理的[黑板](/docs/zh-cn/gameplay/ai/blackboard/)上。
