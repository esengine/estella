**标记（Marker）**是具名的玩法兴趣点（出生点、路径点、门、拾取位置），作为普通实体放置在编辑器中。**触发区（Trigger Area）**是带传感碰撞体的标记：一个在物体进入或离开时发出报告的区域。二者都随场景序列化，在 Inspector 中编辑，并通过 `Query(Marker)` 读取。

## `Marker` 组件

标记是位于同时带有 `Transform` 的实体上的 `Marker` 组件。`Marker` 从主 `esengine` 入口导出，无需插件。

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `type` | string | `''` | 标记的种类（`spawn`、`waypoint`、`door` 等）。自由文本，词汇由游戏定义。 |
| `properties` | `Record<string, string>` | `{}` | 每个标记的数据（`team`、`targetScene`、`event` 等），在 Inspector 中以键值表编辑。导入的 Tiled 对象的属性也存放在这里。 |

<Aside type="note">
  `properties` 的值是字符串。在读取处自行解析（`Number(marker.properties.hp)`、`marker.properties.locked === 'true'`）。
</Aside>

## 在编辑器中放置标记

- **+ 添加 → 创建实体… → Common → Marker** 在场景原点创建一个具名点。标记在视口中显示为图钉 gizmo。
- **+ 添加 → 创建实体… → Physics → Trigger Area** 创建一个传感区域：`Transform`、静态 `RigidBody2D`、`isSensor: true` 的 `BoxCollider2D` 与 `Marker`。它还会绘制碰撞体轮廓，可用[碰撞体 gizmo](/docs/zh-cn/gameplay/physics-2d/bodies/) 编辑。

在 Inspector 中，**Type** 设置标记的类型，**Properties** 可容纳任意数量的键值行。二者随场景保存并包含在构建中。

![Inspector 中的 Marker 组件——Type 字段与键值 Properties 表,以及添加属性按钮](@/assets/guides/zh/marker-inspector.png)

*Inspector 中的 `spawn` 标记：**Type** 是 `Query(Marker)` 代码过滤所依据的值；**Properties** 的每一行是字符串到字符串映射中的一项。*

## 读取标记

```typescript
import { defineSystem, Commands, Query, Marker, Transform } from 'esengine';

// Find every spawn marker and place the player at the first one.
// Register it with app.addSystemToSchedule(Schedule.Startup, placePlayer) to run it once.
const placePlayer = defineSystem([Commands(), Query(Marker, Transform)], (cmds, markers) => {
  for (const [entity, marker, transform] of markers) {
    if (marker.type !== 'spawn') continue;
    cmds.spawn().insert(Transform, { position: { ...transform.position } });
    // …then chain .insert(Player, {…}), .insert(Sprite, {…}), and so on.
    break;
  }
});
```

`marker.properties` 以字符串携带每个标记的数据（`marker.properties.targetScene`、`marker.properties.team`）。

## 触发区

触发区的碰撞体是传感器：检测重叠但不产生物理响应。进入与离开从 `Physics2DEvents` 资源读取。每个传感事件指明 `sensorEntity`（触发区）与 `visitorEntity`（穿过它的物体）；由触发区的 `Marker` 决定如何响应。

```typescript
import { defineSystem, Res, Query, Marker } from 'esengine';
import { Physics2DEvents } from 'esengine/physics';

const onTrigger = defineSystem([Res(Physics2DEvents), Query(Marker)], (events, markers) => {
  const markerOf = (e) => {
    for (const [entity, marker] of markers) if (entity === e) return marker;
    return null;
  };
  for (const s of events.sensorEnters) {
    const m = markerOf(s.sensorEntity);
    if (m?.type === 'door') loadScene(m.properties.targetScene);
    if (m?.type === 'hazard') damage(s.visitorEntity, Number(m.properties.dps));
  }
  for (const s of events.sensorExits) { /* left the zone — clear an effect, etc. */ }
});
```

触发区使用 2D 物理模块。编辑器和 Web 运行时在场景使用物理组件时加载它；自定义应用需添加插件（[2D 物理基础](/docs/zh-cn/gameplay/physics-2d/overview/#安装)）。

同样的穿越还会以 `trigger_enter` / `trigger_exit` 事件发送给实体，触发区上的[事件绑定](/docs/zh-cn/scripting/events/)无需代码即可响应。完整的事件接口见[碰撞与传感事件](/docs/zh-cn/gameplay/physics-2d/queries/#碰撞与传感事件)。把触发区及需要感知它的物体放在专用的[碰撞层](/docs/zh-cn/gameplay/physics-2d/bodies/#碰撞过滤)上，可限制每个传感器需要考虑的范围。

触发区不阻挡移动。阻挡用的几何应使用非传感碰撞体或瓦片地图的[碰撞层](/docs/zh-cn/world/tilemaps/collision/#碰撞层)。

## 从 Tiled 导入

[`Tilemap`](/docs/zh-cn/world/tilemaps/tiled/) 加载 `.tmj` 地图时，其对象层会转换为同样的实体：

| Tiled 对象 | 转换为 |
|---|---|
| **点（Point）** | 一个 `Marker`：`type` 为 Tiled 类名；自定义属性进入 `Marker.properties`。 |
| **矩形 / 椭圆 / 多边形 / 折线** | 一个触发区域：`Marker`（`type` 为 Tiled 类名）加静态刚体与匹配的碰撞体：盒体、圆、最多 8 个顶点的多边形（更多顶点时退化为包围盒）或开放链。它是传感器；对象组名为 `collision` 时则为实心几何。 |
| **图块对象**（带 gid） | 地图的一个精灵子实体。 |

因此一次 `Query(Marker)` 即可读取在编辑器中放置的标记与在 Tiled 中绘制的标记。导入的对象在每次加载时由 `.tmj` 重新生成，只存在于运行模式中；在编辑器中放置的标记是序列化的实体。原始的对象组数据可通过 `esengine/tilemap` 的 `tilemapSource(assets, ref)` 获取，例如用于形状的精确顶点。

## 最近的标记

`esengine/gameplay` 的 `nearestMarkers(world, from, options)` 返回某点附近的标记，近者在前，例如用于决定交互按钮的行为：

```typescript
import { nearestMarkers, nearestEntities } from 'esengine/gameplay';

const near = nearestMarkers(world, { x: player.x, y: player.y }, { radius: 60, type: ['door', 'tree', 'bed'], limit: 1 });
if (near[0]) promptFor(world.get(near[0].entity, Marker).type);    // what the button says is the game's
```

| 选项 | 说明 |
|---|---|
| `type` | 一个类型或类型数组。 |
| `has` | 只保留 `properties` 包含所有给定键值的标记。 |
| `radius` | 最大距离。 |
| `limit` | 最大结果数。 |
| `plane` | `'xy'`（默认）或 `'xz'`（在地面平面上测量）；使用 `'xz'` 时 `from.y` 表示地面的 z。 |

每个结果为 `{ entity, distance, x, y }`。`nearestEntities(world, Component, from, options)` 对任意组件执行相同操作，并可用 `filter` 过滤其数据。被 `Disabled` 关闭的实体不会返回。每次调用都会遍历一次带该组件的实体。

## 使用准则

- 用一组小而稳定的 `type` 值表示角色，可变数据放入 `properties`。
- 出生点、路径点图与巡逻路线在场景开始时读取一次并缓存。
- 编辑器场景与 Tiled 地图使用相同的标记词汇；查询代码不依赖来源。
