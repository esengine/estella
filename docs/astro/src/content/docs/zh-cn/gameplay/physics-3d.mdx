一个 3D 模型已经能导入、能动、能变形、能被照亮。这一页讲的是让它**站在某处**:
一个由 **Jolt Physics** 驱动的刚体世界,跑在它自己的 WebAssembly 模块里。

它与 [2D 物理](/docs/zh-cn/gameplay/physics/)**并存**,不是取代:2D 场景保留它已经有的
求解器、单位和手感,而一个从不索取 3D 世界的项目也从不加载它。

## 配置

与 2D 侧模块一样,在编辑器和 Web 运行时里,场景用到 3D 刚体时 3D 世界会自动加载。自定义应用则自己加插件,
所有选项都可省略(重力默认 `{ x: 0, y: -9.81, z: 0 }`,`fixedTimestep` 默认 `1/60`,`collisionSteps` 默认 `1`,`pixelsPerUnit` 默认 `100`,
`maxBodies` 默认 `1024`;`layerMasks` 见[碰撞层](#碰撞层)):

```typescript
import { Physics3DPlugin } from 'esengine/physics3d';

app.addPlugin(new Physics3DPlugin('physics3d.js', { gravity: { x: 0, y: -9.81, z: 0 } }));
```

## 选择求解器：Jolt 或 PhysX

3D 世界默认运行在 **Jolt** 上。**项目设置 → 物理 → 3D 求解器** 可以切换到 **PhysX**，
也就是 Unity 使用的求解器，适合需要和 Unity 原项目表现一致的项目。清单里的写法：

```json
"features": { "physics": { "backend3d": "physx" } }
```

其余都不变。两个后端响应同样的组件、关节、角色、查询和碰撞事件，同一套 98 项行为检查
分别在两者上运行（`node tools/check-physics3d.mjs`、`node tools/check-physics3d-physx.mjs`）。
构建只带选中的模块：Jolt 是 `physics3d.wasm`，PhysX 是 `physics3d-physx.wasm`。
编辑器的 Play 也使用同一个选择。

PhysX 按 Unity 的默认值设置：投影高斯-赛德尔求解、patch 摩擦、摩擦与弹性按 Average 合并、
0.01 m 接触偏移、2 m/s 弹跳阈值、0.005 休眠阈值、6 次位置迭代和 1 次速度迭代、
50 rad/s 最大角速度。两个引擎行为不同的地方，PhysX 跟 Unity 一致：

- 角色进入触发器会被报告，和 CharacterController 触发 `OnTriggerEnter` 一样。
  Jolt 的角色不是刚体，所以 Jolt 的传感器看不到它。
- 在触发器里睡着的刚体仍然算在里面。Jolt 会在刚体休眠时报告一次离开。
- 角色保留半径十分之一的皮肤厚度（Unity 推荐的 skin width），所以比 Jolt 角色站得略高。
- 角色会走上不高于台阶高度的动态刚体；更高的会被推开，推力不超过它的推力强度。

代价：PhysX 的 Web 模块 3.5 MB（gzip 1.14 MB），Jolt 是 1.3 MB；只有选了它的项目才加载。
混沌的场景（比如球擦过铰链门的边缘）在两个求解器上的结果会不同，任何两个引擎之间都会这样。
Windows、Linux 和 Android 的原生包运行项目选的那个求解器，所以原生游戏和它的 Web 版用的是同一个求解器。
桌面应用把两个求解器都编进去，每个 Windows 可执行文件大约多 4 MB。Android 包把 PhysX 作为单独的库
`libestella_physx.so`，只有选了 PhysX 的项目才带：下载包大约多 2 MB（每个 ABI 安装后多 4.9 MB），
用 Jolt 的项目不增加任何体积。
macOS 和 iOS 包目前只编进了 Jolt，选了 PhysX 的项目在这两个平台上运行 Jolt，启动时会记一条日志说明。

## 刚体

一个实体同时带着 `RigidBody3D` **和**一个形状时才在世界里。没有形状的刚体没有任何
广延可供碰撞,所以它干脆不被注册——而不是变成一个永远下落的隐形点。

```typescript
cmds.spawn()
  .insert(Transform, { position: { x: 0, y: 400, z: 0 } })
  .insert(RigidBody3D, { bodyType: BodyType.Dynamic })
  .insert(CapsuleCollider3D, { radius: 30, halfHeight: 50 });
```

| 字段 | 作用 |
|---|---|
| `bodyType` | `Static` 从不移动,`Kinematic` 由你搬动,`Dynamic` 由求解器解。 |
| `gravityScale` | 这个刚体分担的重力比例。`0` 是失重,不是「掉得慢」。 |
| `mass` | 千克。`0`(默认)按形状以水的密度计算:半径 10 cm 的球是 4.2 kg。用它让空箱子变轻、小铁砧变重;运行中修改也会生效。静态和运动学刚体没有质量。 |
| `linearDamping` / `angularDamping` | 运动衰减的快慢(默认都是 `0.05`;2D 刚体默认是 `0`)。 |
| `fixedRotation` | 冻结刚体被给定的朝向——让角色不会倒下的那个开关。它不会把一个一开始就歪的刚体扶正。 |
| `layer` | 刚体所在的十六个[碰撞层](#碰撞层)之一。 |
| `continuousCollision` | 检查这一步走过的整条路径,而不只是它最后停在哪。子弹需要它;默认关闭,因为它更贵。 |

## 形状

| 组件 | 广延 |
|---|---|
| `BoxCollider3D` | 每个轴上的 `halfExtents`。 |
| `SphereCollider3D` | `radius`。 |
| `CapsuleCollider3D` | 一个直立胶囊:`halfHeight` 是圆柱段的一半,两端各扣一个 `radius` 的半球,所以总高是 `2 * (halfHeight + radius)`。 |

默认值:`halfExtents` `{ 0.5, 0.5, 0.5 }`,`radius` `0.5`(胶囊为 `0.3`),`halfHeight` `0.5`——都是世界单位,
所以新加的形状很小,要自己调大。三者还都有 `friction`(`0.3`)、`restitution`(`0`)和 `isSensor`(`false`)。

这三种碰撞体都还有可选的 `center`:形状相对实体原点的位置,单位为世界单位(默认 `{ 0, 0, 0 }`)。
刚体仍位于实体处,所以动态刚体绕自己的原点转动,偏离中心的形状会绕着它甩动。

<Aside>
  尺寸按**世界单位**书写,以米为单位抵达求解器,用的是 2D 世界同一个 `pixelsPerUnit`
  (默认 100)。一个按米调好的求解器在角色高 180 单位时完全不是它自己,所以这次换算
  不是可选项——它正是一个 60 单位宽的胶囊会像人一样倒下的原因。
</Aside>

### 用导入的几何做碰撞

`MeshCollider3D` 直接拿网格自己的三角形做碰撞——地形、楼梯、房间内部,
这些正是盒子和胶囊说不出来的东西。

```typescript
cmds.spawn()
  .insert(Transform, {})
  .insert(RigidBody3D, { bodyType: BodyType.Static })
  .insert(MeshCollider3D, { mesh: 'assets/models/level.esmesh' });
```

<Aside>
  它永远是静态的,不管 `RigidBody3D` 怎么写:三角汤没有惯性张量,求解器没有东西可推。
  而且三角形是**单面的**——一块绕序朝下的地板,射线照样报命中,刚体却会直接穿过去。
  导入的几何拦不住任何东西时,先怀疑这个。
</Aside>

需要**会动**的导入几何,就用 `ConvexCollider3D`:它拿同一批顶点最紧的那个凸体去碰撞,
而凸体对求解器来说和盒子一样容易。一块石头、一个倒角的箱子、一只会滚的木桶——
凡是凹陷细节不需要被摸出来的东西。

```typescript
cmds.spawn()
  .insert(Transform, { position: { x: 0, y: 400, z: 0 } })
  .insert(RigidBody3D, { bodyType: BodyType.Dynamic })
  .insert(ConvexCollider3D, { mesh: 'assets/models/rock.esmesh' });
```

## 看见形状

视口把每个 3D 碰撞体画成线框,并跟着实体一起转——屏幕上没有任何别的东西
能说出「模型外面那个盒子有多大」。它和 2D 碰撞体 gizmo 共用同一个开关。

一个实体只会拿到**一个**刚体形状,按 `BoxCollider3D`、`SphereCollider3D`、
`MeshCollider3D`、`ConvexCollider3D`、`CapsuleCollider3D` 的顺序挑。落选的那些——被禁用的、
被这个顺序盖住的、以及所有挂在没有启用 `RigidBody3D` 的实体上的——画成暗淡虚线:
仍然摆得动,但一眼就看得出世界不会拿它去碰撞。`CharacterController3D` 的胶囊
画在它旁边,因为角色是被扫掠的而不是被求解的。

<Aside>
  网格碰撞体画的是它三角形的**包围盒**而不是每一条边——那些三角形就是你已经在看的
  这个网格,几千条投影出来的边只会把它埋掉。
</Aside>

### 游戏跑起来的时候

编辑器的 gizmo 在 Play 时全部隐藏,所以由运行中的游戏画它自己的。
需要弄清「它为什么卡在那儿」时,把 `Physics3DDebugDraw` 资源打开:

```typescript
app.getResource(Physics3DDebugDraw).enabled = true;
```

| 字段 | 作用 |
|---|---|
| `enabled` | 默认关闭——每帧每条边一根线,这是有代价的。 |
| `showColliders` | 求解器真的建出来的每个刚体的形状。 |
| `showContacts` | 这一步报告的每个接触点上画一个十字。 |

<Aside>
  这里只画**求解器真的建了的**那些。被禁用的碰撞体属于编辑态,该在编辑器里看——
  运行中的游戏把它画出来就是在描述一场不可能发生的碰撞。

  这层覆盖**不参与深度测试**,所以埋在墙里的形状照样看得见。调试视图就是要这样。
</Aside>

带有 `gravity` 大于 0 的 `Planet` 会把每个动态刚体拉向自己的中心,而不是沿世界唯一的重力向量,
圆形世界因此处处有"下"(行星本身见[地形](/docs/zh-cn/graphics/terrain/))。

## 角色

`CharacterController3D` **取代** `RigidBody3D` 而不是与它并存:被求解器推的刚体
和自己扫掠的角色,是「这个实体在哪」的两个答案。每步从游戏逻辑设 `velocity`,再把结果读回来。

```typescript
const drive = defineSystem([Query(Mut(CharacterController3D)), Res(Input)], (q, input) => {
  for (const [, c] of q) {
    c.velocity.x = (input.isKeyDown('KeyD') ? 200 : 0) - (input.isKeyDown('KeyA') ? 200 : 0);
    if (input.isKeyPressed('Space') && c.isOnFloor) c.velocity.y = 500;
  }
});
app.addSystemToSchedule(Schedule.FixedUpdate, drive);
```

| 字段 | 作用 |
|---|---|
| `velocity` | 期望速度,世界单位/秒。`y` 为正就是跳。 |
| `radius` / `halfHeight` | 被扫掠的直立胶囊(默认 `0.3` / `0.5`,世界单位),形状与 `CapsuleCollider3D` 相同。 |
| `stepHeight` | 能迈上去而不是被挡住的最高台阶(默认 `0.4`)。`0` 就什么都迈不上。 |
| `snapDown` | 过坡顶时向下够多远以贴住地面(默认 `0.5`)。`0` 是关掉。 |
| `maxSlope` | 能站住的最陡地面,弧度(默认 `0.87`,约 50°);比这更陡就会滑下去。 |
| `mass` | 角色质量,千克(默认 `70`),推东西时用。 |
| `pushForce` | 撞上动态刚体时能推多用力(默认 `5000`)。`0` 什么都推不动。 |
| `layer` | 所在的[碰撞层](#碰撞层)(0–15)。 |
| `isOnFloor` / `floorNormal` / `realVelocity` | 输出,步进之后读。 |

<Aside>
  垂直分量由引擎替你维护:`velocity.y = 0` 的意思是「走」,不是「悬在空中」。
  在 Jolt 里角色**不会自己下落**——垂直速度属于调用者——所以这一层替你积分重力,
  而不是让每个调用者各自重新发现这件事。

  角色是被**扫掠**的而不是被求解的,所以没有任何东西会自己给它让路:`pushForce`
  就是它可以花在推东西上的力。默认值足以推动一个和它自己差不多大的箱子;
  更重的要给更多,而 `0` 会让它把所有东西都当成墙。
</Aside>

## 第三人称

`ThirdPersonController` 与 `ThirdPersonCamera` 是角色之上的 gameplay 层：输入
变成一个请求，角色控制器给出答复，而动画听到的是这个答复。

```typescript
// 不需要写脚本，两者都是场景声明的组件。
world.insert(player, ThirdPersonController, { moveSpeed: 320, jumpSpeed: 520 });
world.insert(rig, ThirdPersonCamera, { target: player, distance: 420 });
```

摇杆是在相机的**地面**平面里读的，所以镜头再怎么俯视，角色仍然沿地面走。俯仰
永远不会传到角色身上。

| 字段 | 作用 |
|---|---|
| `moveSpeed` | 地面上的最高速度，世界单位/秒(默认 `320`)。 |
| `acceleration` / `deceleration` | 加速到该速度的快慢，以及减速的快慢,单位/秒²(默认 `2400` / `3200`)。 |
| `rotationSpeed` | 转向「实际去过的方向」的角速度，度/秒(默认 `720`)。 |
| `jumpSpeed` | 起跳的初始向上速度。`0`(默认)表示不能跳。 |
| `airControl` | 离地时 `acceleration` 生效的比例，0..1(默认 `0.3`)。 |
| `cameraRelative` | 在相机的地面平面里读摇杆(默认 `true`),而不是世界的。 |
| `camera` | 摇杆以谁的前方为准;`0`(默认)表示找到的第一个 `ThirdPersonCamera`。 |
| `idleThreshold` | 低于这个速度,就告诉动画角色是站着的(默认 `8`)。 |

`ThirdPersonCamera` 在指针控制下绕 `target` 旋转:

| 字段 | 作用 |
|---|---|
| `target` | 它绕着转的实体;`0` 让相机不动。 |
| `distance` | 没有东西挡路时它在后方多远,世界单位(默认 `420`)。 |
| `yaw` / `pitch` | 绕世界上方向的转角,以及高出地平线的角度(正值向下看),度(默认 `0` / `15`)。 |
| `minPitch` / `maxPitch` | 俯仰限位,度(默认 `-30` / `70`)。 |
| `sensitivity` | 指针每移动一像素转多少度(默认 `0.2`)。 |
| `followDamping` | 位置追上的快慢,每秒;`0` 为刚性(默认 `12`)。 |
| `targetOffset` | 把支点从目标原点抬高,让镜头框住胸口而不是脚(默认 `{ 0, 90, 0 }`)。 |
| `obstruction` / `obstructionRadius` / `obstructionLayers` | 支点与眼睛之间有实体时拉近(默认开)、探针的粗细(默认 `15`)、能撞到的层(`0` 为所有层)。 |

<Aside>
  告诉动画的是角色**实际达到**的速度，而不是它请求的速度。顶着墙的角色摇杆推满
  却没有位移，它不该在原地跑步；爬不上去的斜坡也靠同一个读数表现为「停住」。

  相机会在支点与眼睛之间扫掠物理世界，有实体挡住时把自己拉近。它只移动自己。
</Aside>

## 第一人称

`FirstPersonController` 在 `CharacterController3D` 里看、走、跳、蹲,和第三人称层一样:它提出请求,物理世界作答。放在身体上,相机作为它的子节点;身体跟着玩家的偏航转,相机跟着俯仰抬。

```typescript
// 场景里声明的组件。
world.insert(player, CharacterController3D, { radius: 30, halfHeight: 90 });
world.insert(player, FirstPersonController, { moveSpeed: 320, jumpSpeed: 420 });
// ……再在 `player` 的子节点上放一个 Camera。
```

- **看。** 在 Web 上,第一次点击会拿到指针(`pointerLock`),鼠标转动视角;关掉它则按住鼠标键时才转。触屏上,从屏幕横向 `touchLookFrom` 像素(默认 480)之后开始的手指拖动会转动视角,把左边留给摇杆。小游戏没有指针可拿,靠触摸看。
- **走。** WASD 或方向键,**Shift** 冲刺,**空格** 跳,**Ctrl** 或 **C** 蹲。速度、冲刺和蹲伏倍率、加速度、空中控制力度都是字段。
- **蹲** 会用 `crouchHalfHeight` 重新生成胶囊,脚的位置不变:物理世界不能改变角色的大小,所以旧的会先放掉一步。站起来之前先查头顶,没有空间就继续蹲着。

### 视图模型

手持物如果用世界的相机画,会穿墙,还会随广角一起拉伸。放在玩家相机上的 `FirstPersonViewModel` 改用第二台相机来画:在该相机下生成一台,只画你指定的排序层(`layer`,默认 20),有自己的视场角和近裁剪面,画在世界之上、不清除它。玩家的相机则被告知不再画这一层。把手持物放在相机下,把它的渲染器设到这一层。

```typescript
world.insert(camera, FirstPersonViewModel, { layer: 20, fov: 50, nearPlane: 1 });
world.insert(weapon, MeshRenderer, { mesh: 'builtin:cube', layer: 20 });
```

两者都在 `esengine/gameplay` 里。里面没有武器系统、弹道和伤害,也还没有模板;输入读键盘、指针和触屏,不读虚拟摇杆和手柄。

## 布娃娃

蒙皮角色上的 `Ragdoll`,把 `active` 打开,骨头就变成用关节连起来的刚体;关掉,姿态再还给动画。它读角色已有的骨架(蒙皮网格列出的关节),所以除了开关和几个数字,没有别的要设。

```typescript
world.insert(enemy, Ragdoll, { active: false });
// 被击倒时:
world.insert(enemy, Ragdoll, { ...world.get(enemy, Ragdoll), active: true });
```

- 够长的骨头各得到一个沿骨头方向的盒子,用摆动/扭转关节接到上方最近有盒子的骨头,以动画当帧的姿态生成,所以不会瞬间弹开。动画在下面照常运行,每帧把刚体的姿态盖回去。
- **限位。** 默认的 `Humanoid` 配置按骨头名字判断它在身体的哪个部位,各取 `swing` 和 `twist` 的一个比例(脊柱硬、肩松、小腿近似铰链)。膝盖和手肘是最多 `bend` 度的单向铰链:小腿向后折,小臂向前折,方向由 `facing`(角色在自己的坐标轴上朝哪边看)决定。
- **站起来** 会在 `recoverTime` 秒内,从刚体留下的姿态平滑混回动画的姿态。
- **单根骨头。** 骨头实体上的 `RagdollJoint` 可以让它没有刚体,或者用自己的限位(度数),还能用 `bend` 和 `fold` 把任意骨头变成单向铰链。
- 在编辑器里选中布娃娃,会按骨架当前的姿态显示它将要生成的盒子和关节限位。

这是被动布娃娃,没有任何东西驱动四肢。目标设备的验收另行记录。

## 近战

三件事，把它们分开就是战斗系统的全部：

```text
动画事件   ≠   命中   ≠   伤害
```

剪辑只说明这一刀到了它的有效时刻。那片空间里有谁，是物理世界的答案。这对谁造成什么，
是玩法的事。任何两件合并，就得到一个不改另外两件就无法重新瞄准、重新配时、重新平衡的
战斗系统。

`MeleeAttack` 挂在一个 `Animator` 旁边，它的攻击剪辑用 `customEvent` 轨道声明三个节拍
——`attack-start`、`hit`、`attack-end`：

```typescript
world.insert(player, MeleeAttack, { radius: 70, damage: 25, anchor: swordSocket });
world.insert(dummy, Health, { current: 100, max: 100 });
```

| 字段 | 作用 |
|---|---|
| `radius` | `hit` 节拍测试的球半径，世界单位(默认 `60`)。 |
| `damage` | 一次落地的攻击扣掉多少(默认 `25`)。 |
| `layers` | 这一刀能够到的物理层；`0` 表示所有层。 |
| `anchor` | 查询以哪个实体的**世界**位置为中心。 |
| `attackId` | 引擎写入：正在进行的那一刀，没有时为 `0`。 |
| `hitCount` | 引擎写入：这一刀已经打中了几个目标。 |

<Aside type="caution">
  `anchor` 应该是挂在动画骨骼下的插槽，而不是角色本身。把查询放在角色身上，攻击范围
  就变成了从脚底算起的一个固定偏移：骨架被画出来了，却从来没有被问过，屏幕上明明挥空
  的一刀照样命中。查询前会先合成 anchor 的世界位置，所以它问的就是动画真正做到的地方。
</Aside>

一刀是一个带自己 id、自己「已经打到过谁」集合的**实例**，所以一刀对一个目标最多命中
一次，而下一刀可以再次命中。命中窗口通常就是好几个 `hit` 节拍，靠「事件只触发一次」来
保证单次命中，在剪辑第一次声明两个节拍时就会破——而且是静默地破，表现为双倍伤害，
看起来像数值没配好而不是 bug。

这一刀不写任何血量。落地的攻击发到 `Damage` 总线上，由一个系统来回应，所以 `Health`
只有一个作者，将来任何要坐在「命中」与「血条」之间的规则都有唯一一个位置可坐：

```typescript
import { defineSystem, EventReader, GetWorld, Res, Damage, Children, ParticleEmitter, Particle } from 'esengine';

const hitSparks = defineSystem(
  [EventReader(Damage), GetWorld(), Res(Particle)],
  (blows, world, particles) => {
    for (const blow of blows) {
      if (!world.has(blow.target, Children)) continue;
      for (const child of world.get(blow.target, Children).entities) {
        if (world.has(child, ParticleEmitter)) particles.play(child);
      }
    }
  },
  { name: 'HitSparkSystem' },
);
```

一次攻击携带 `target`、`source`、`amount` 和它落在哪个点(`x`、`y`、`z`)——这个点事后是找不回来的，
等火花画出来的时候，那一刀早就挥过去了。总线是双缓冲的，本帧发出的攻击在下一帧落地。

<Aside type="tip">
  物理查询只回答碰撞体，别的什么都不答。「不能打自己」「已经打过了」「打不动」这三条是
  玩法的规则，跟着这一刀走——地板也是碰撞体，而一个实体能不能被打，是 `Health` 说了算。
</Aside>

## 关节

门、绳桥、升降台、布娃娃:它们都不是「一个刚体加一个形状」,
而是**两个刚体**外加一条「它们之间可以怎么动」的规则。
关节挂在声明它的那个实体上,并指名另一个实体。

```typescript
cmds.spawn()
  .insert(Transform, { position: { x: 100, y: 0, z: 0 } })
  .insert(RigidBody3D, {})
  .insert(BoxCollider3D, { halfExtents: { x: 50, y: 100, z: 5 } })
  .insert(HingeJoint3D, {
    connectedEntity: frame,
    anchor: { x: -50, y: 0, z: 0 },   // 门自己的那条边
    axis: { x: 0, y: 1, z: 0 },       // 竖直
    enableLimit: true, lowerAngle: 0, upperAngle: Math.PI / 2,
  });
```

| 组件 | 规则 |
|---|---|
| `PointJoint3D` | 共享一个点,三轴自由转动。 |
| `HingeJoint3D` | 一根转轴,可选限位与马达。 |
| `SliderJoint3D` | 一条滑轨,可选限位与马达。 |
| `DistanceJoint3D` | 保持一段距离:只给 `maxLength` 就是绳,两个长度相等就是杆,给了 `frequency` 就是弹簧。 |
| `FixedJoint3D` | 完全不给自由度——两者作为一个整体运动。 |

`anchor` 与 `axis` 写在**声明关节的那个实体自己的局部空间**里,用世界单位,
在关节建立的那一刻按它的变换解算成世界量。那个姿态同时也是所有限位的**零点**:
一扇摆成关闭状态的门,`angle` 就是 0,开到 `upperAngle`。

`motorSpeed` 随时可以由游戏逻辑改写——变了就会重新驱动世界。反方向上,
`HingeJoint3D.angle` 与 `SliderJoint3D.translation` 每步写回,
所以游戏可以直接问「门开了多少」,不必自己再积分一遍。

<Aside>
  `collideConnected` 默认关闭,而且它把两个刚体并进**同一个装配**而不是只对这一对生效:
  一串关节所能连通到的所有刚体,彼此之间都不再碰撞。门需要这个(它不能和自己的门框打架),
  布娃娃也需要。确实应该互相碰的时候再把它打开。

  **一个实体只有一个关节**——世界按「声明它的实体」给约束建索引。
  需要两个关节的实体就挂一个子实体给第二个,这也正好让场景说清楚哪个是哪个。
</Aside>

## 问世界「那里有什么」

`Physics3D` 资源用世界单位回答空间问题。

```typescript
const q = app.getResource(Physics3D);

// 这条线上有东西吗?
const hit = q.raycast(muzzle, { x: 0, y: 0, z: -2000 }, ENEMIES);

// 这个东西「过得去」吗?射线是无限细的,会从一个运动刚体根本挤不过去的缝里穿过——
// 这正是扫掠形状回答的那个不同的问题。
const blocked = q.sphereCast(from, 30, travel, WORLD);

// 在往这里放东西之前,这里已经有什么了?
const occupants = q.overlapSphere(spawnPoint, 50);
```

| 查询 | 回答 |
|---|---|
| `raycast(origin, direction, layerMask?)` | 一条线上最近的刚体,形如 `{ entity, fraction, x, y, z, normalX, normalY, normalZ }`,没有则为 `null`。`direction` 自带射线长度。 |
| `sphereCast(origin, radius, direction, layerMask?)` | 一个运动的球最先撞上的刚体,形状同上,没有则为 `null`。 |
| `overlapSphere(centre, radius, layerMask?)` / `overlapBox(centre, halfExtents, layerMask?)` | 已经在某个体积里的所有刚体,形如 `{ entity, x, y, z }[]`。 |

物理模块加载完成之前 `Physics3D` 是 `null`,所以在最初几帧里询问的系统要先判断。

<Aside>
  层掩码为 `0` 表示**所有层**,不是「一个都不要」:没有要求过滤的调用者是在要全部,
  而另一种读法会让最常见的调用悄悄返回空。命中法线**不做单位换算**——它是方向,
  乘上 `pixelsPerUnit` 只会得到一个长度 100 的单位向量。
</Aside>

## 碰撞层

每个刚体属于十六层中的一层,由项目声明哪些层之间能互相听见。**两边都得同意**——
其中一边拒绝就足以让两个刚体互不相碰,所以一条规则只需要写一次就成立。

```typescript
app.addPlugin(physics3dPlugin(url, {
  layerMasks: [
    0xFFFF,             // 0: 全部
    0xFFFF,             // 1: 世界
    ~(1 << 3),          // 2: 子弹 —— 不打自己人
    0xFFFF,             // 3: 那支队伍
  ],
}));
```

<Aside>
  一个刚体**只属于一层**,不像 2D 世界那样用一组类别位:Jolt 用单个 id 给刚体分类。
  另外,刚体的层在它进入世界的那一刻就固定了,所以矩阵必须在任何刚体注册之前就位——
  插件在建世界时装它。
</Aside>

## 碰撞事件

每一步都会把「谁碰到了谁」发布到 `Physics3DEvents` 资源里。它按固定步长排空,
所以读它的系统必须跑在固定步里——从 `Update` 里读只会看到上一步碰巧留下的东西。

```typescript
const events = app.getResource(Physics3DEvents);
for (const hit of events.contactEnters) {
  // 两个实体,以及它们相遇的位置
  spawnSparks(hit.pointX, hit.pointY, hit.pointZ);
}
for (const { sensorEntity, visitorEntity } of events.sensorEnters) {
  if (sensorEntity === goalZone) score(visitorEntity);
}
```

| 通道 | 带着什么 |
|---|---|
| `contactEnters` | 两个实体、接触法线和接触点,接触点与 `Transform` 同单位;以及 `speed`:接触时第一个物体沿法线靠近第二个物体的速度,同单位每秒,在求解器处理之前读取(从一米高落下的球约以 4.4 m/s 着地);`mass`:两者相撞时的有效质量(千克),1 / (1/a + 1/b),不动的物体视为逆质量为 0,所以石头落在地上时就是石头自己的质量;`impulse`:`speed` 乘 `mass`,即撞击力度。 |
| `contactExits` | 只有这一对——原因见下。 |
| `sensorEnters` / `sensorExits` | **传感器在前**,然后是访客。 |

<Aside>
  结束的接触不带几何:在那一刻求解器锁着两个刚体,其中一个甚至可能已经被销毁,
  所以除了「这一对是谁」之外什么都报不出来。另外,接触也会在刚体**睡着**时结束,
  而不只是在它移开时——请把 exit 理解成「这一对不再接触了」,而不是「有东西动了」。
</Aside>

带 `isSensor` 的碰撞体报告重叠但不拦任何东西:访客直接穿过去,并且出现在
`sensorEnters` 而不是 `contactEnters` 里。

## 一个场景在哪个世界里

没有东西阻止一个实体同时带两套组件,但也没有东西会把它们合并:两个世界互相看不见,
一个 2D 碰撞体永远拦不住一个 3D 刚体。**一个场景选一套。**

### SwingTwist 与六自由度关节

`SwingTwistJoint3D` 锁定平移，用椭圆摆动锥和独立扭转区间限制旋转。
`axis` 是局部约束 X（扭转轴），`normalAxis` 是局部 Y 参考方向。
方向会归一化并正交化；零向量或平行方向无效。

`SixDOFJoint3D` 的 `translationMotion` / `rotationMotion` 每轴分别选择
`JointMotion3D.Locked`（0）、`Limited`（1）或 `Free`（2）。锁定轴保持创建姿态；
限制轴读取对应 Lower / Upper 向量，下限必须小于上限；自由轴忽略数值边界。
角度限位必须在 −π 到 π 内，Y/Z 旋转使用 Jolt 的金字塔限位。

Inspector 以度显示角度，文件和脚本仍存弧度。平移限位、线速度分别使用世界单位、
世界单位/秒；角速度为 rad/s，力和扭矩为 N、N·m，不随 `pixelsPerUnit` 缩放。

马达默认关闭。运行时修改 `enableMotor`、`linearVelocity`（仅 SixDOF）、
`angularVelocity`、`maxMotorForce`、`maxMotorTorque` 不会重建关节。
目标速度表示约束坐标系中**连接体 B 相对于声明体 A** 的速度；B 静止时，A 朝相反方向运动。
每个马达轴共享填写的力或扭矩上限。这是速度控制，不是姿态伺服或主动布娃娃。

修改参考坐标系、碰撞设置或限位会重建关节，当前姿态成为新的零点。
禁用、移除组件会在刚体移除前释放约束。
`joint3DSettingsError(settings)` 返回无效设置的原因；无效关节不会进入物理解算。

现有 **3D Physics** 示例包含肩/上臂和受限滑块。按 **J** 反转马达，**F1** 切换碰撞体调试绘制。
在编辑器选中关节即可检查限位；视口提供只读显示，通过细节面板改数值。
两种组件仍为实验性接口。无窗口 Jolt 检查覆盖限位和马达，目标设备验收另行记录。

## 导入的复合碰撞体

`CompoundCollider3D` 将多个盒体、球体和胶囊体组成一个原生刚体，与
`RigidBody3D` 放在同一实体上。`parts` 的每项包含局部 `position`、`rotation`，
以及 `halfExtents`、`radius` 或胶囊圆柱段的 `halfHeight`。这些尺寸和偏移采用
模型单位：先应用实体合成后的世界缩放，再换算为物理单位。Jolt 与 PhysX
共享同一组件和数据包格式。

放置缩放必须为有限正数。非均匀缩放下带旋转的盒体或胶囊需要预先烘焙碰撞几何；
组件会明确拒绝该情况。网格和凸包碰撞体也会将模型的合成缩放应用到源顶点。

## 会碎的东西

东西碎的那一刻并没有发生切割。模型是事先切成互相贴合、没有缝隙的碎块的（模型的
`fracture` 步骤会把它们写成一个预制体，每块是一个带刚体和凸包的网格），`Breakable`
在标志置真时把整体换成这些碎块。

```typescript
world.insert(pot, Breakable, { pieces: 'assets/models/pot_pieces.esprefab', burst: 300 });
// 被击中时：
world.update(pot, Breakable, (b) => { b.origin = hitPointInItsOwnSpace; b.broken = true; });
```

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `pieces` | prefab | `''` | 碎块的预制体。 |
| `broken` | boolean | `false` | 置真即碎；置假恢复完整。 |
| `burst` | number | `300` | 碎块从 `origin` 向外飞出的速度，世界单位每秒。0 表示原地落下。 |
| `origin` | vec3 | `0,0,0` | 受击的位置，相对它自己的原点。 |
| `lifetime` | number | `0` | 碎块保留的秒数，之后被移除。0 表示一直保留。 |
| `breakImpulse` | number | `0` | 撞击力度达到它就碎：速度乘质量，千克·世界单位每秒。0 表示只在 `broken` 置真时碎。 |

整体只是隐藏，不是删除：它的渲染器、刚体和碰撞体被关掉，`broken` 置假时恢复。
没有 3D 物理世界时，碎块会原地出现并留在那里。

要让它被撞碎，给它设 `breakImpulse`，并给它一个自己的碰撞体（编辑器对碎裂模型的回复里会以
`hull` 给出一个同形状的 `ConvexCollider3D`）。撞击力度达到这个值就会碎，碎块从被击中的位置
飞出；同一步里有多次撞击时取最重的一次。力度是两者相撞的接近速度乘以相撞时的有效质量，所以在
100 单位一米的场景里，1 kg 的石头以 10 m/s 落下是 1000，同样速度的 50 g 石子是 50。只有碰撞体
时它是静止的，石头撞上来按石头自己的质量算；再加一个动态 `RigidBody3D`，它就能被撞倒，摔下时
按它自己的质量算。石头和罐子的质量用 `RigidBody3D.mass` 设定。

把碎块抛出去用的是 `Physics3D.setLinearVelocity(entity, velocity)`，其他需要把刚体
送出去的场合（爆炸、踢击）也可以用它。实体还没有刚体时它返回 false，实体刚生成的
那一帧就是这样。
