每个场景都通过一个相机渲染:一个带 `Camera` 组件的实体。相机控制缩放、投影,以及世界里
哪一片会到达屏幕。本指南涵盖配置相机、跟随目标、在屏幕与世界空间之间转换、震屏与混合视图,
以及同时运行多个相机。

## 工作原理

你可以有很多相机实体,但同一时刻只有一个是**活动**的。引擎按 `isActive` + `priority`
选出活动相机(优先级最高的活动相机胜出),并把世界渲染到它的 `viewport`(一个屏幕矩形)里。
2D 游戏用**正交(Orthographic)**投影,此时 `orthoSize`——可见半高(世界单位)——*就是缩放*:
越小越放大。

<Aside type="note">
  相机只是一个带 `Camera` 组件的实体——无需安装。下面的跟随、混合、震屏系统会在编辑器和
  标准运行时里自动运行。
</Aside>

## 快速上手

生成一个正交相机并设为活动:

```typescript
import { defineSystem, Commands, Transform, Camera, ProjectionType } from 'esengine';

const spawnCamera = defineSystem([Commands()], (cmds) => {
  cmds.spawn()
    .insert(Transform, { position: { x: 0, y: 0, z: 0 } })
    .insert(Camera, {
      projectionType: ProjectionType.Orthographic,
      orthoSize: 540,        // half-height in world units → zoom
      isActive: true,
    });
});
```

### 从创建菜单放相机组合

编辑器的**创建**菜单（以及 agent 的 `create` 操作加 `template`）提供常用的相机组合，和 Cinemachine 的创建菜单一样。每一项都是已经装好流水线阶段的 `Camera`，目标在 Details 里选。

| 菜单项 | 模板 | 内容 |
|---|---|---|
| Follow Camera 2D | `camera:follow-2d` | 用 `PositionComposer` 构图的正交相机：目标可在死区内移动，永远不会离开软区。 |
| Tracking Camera | `camera:tracking` | 透视相机，站在目标后上方（`FollowTarget`）、构图（`LookAtTarget`）并保持目标可见（`CameraDeoccluder`）。 |
| Look-At Camera | `camera:look-at` | 放在哪就在哪，转头看目标。 |
| Handheld Camera | `camera:handheld` | 带轻微 `CameraNoise` 的相机，像手持拍摄。 |
| Dolly Camera with Track | `camera:dolly` | 一条 `Spline` 轨道和轨道上的相机（`CameraDolly`，Track Target），并看向目标。 |
| Target Group Camera 2D | `camera:group-2d` | 一个 `CameraTargetGroup` 和框住它的正交相机（`PositionComposer`、`GroupFraming` 缩放）。 |
| Target Group Camera | `camera:group-3d` | 一个 `CameraTargetGroup` 和跟随、注视并框住它的透视相机（`GroupFraming` 先推拉再缩放）。 |
| Camera Brain | `camera:brain` | 场景的 `CameraBrain`，换相机时混合而不是硬切。 |

## `Camera` 组件

SDK 默认值为 2D 调好(正交、活动、`orthoSize` 540)。移动相机就是移动它实体的 `Transform`。

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `projectionType` | `ProjectionType` | `Orthographic` | `Orthographic`(2D)或 `Perspective`。 |
| `orthoSize` | number | `540` | 可见半高(世界单位,正交)——你的**缩放**。可动画。 |
| `fov` | number | `60` | 视场角(度,仅透视;1–179)。 |
| `nearPlane` | number | `0.1` | 近裁剪距离（仅透视）。 |
| `farPlane` | number | `1000` | 远裁剪距离。正交相机没有近裁剪面,渲染的是一个对称的 `±farPlane` 盒子,所以这个值是它两个方向上的范围。 |
| `aspectRatio` | number | `1.77` | 宽 / 高。`0` = 从视口自动推算。 |
| `isActive` | boolean | `true` | 该相机是否有资格成为活动相机。 |
| `priority` | number | `0` | 活动相机之间的优先级(高者胜)。 |
| `viewport` | Vec4 | `{0,0,1,1}` | 屏幕矩形 `x, y, w, h`(0–1,分屏/画中画)。 |
| `clearFlags` | `ClearFlags` | `ColorAndDepth` | 渲染前清什么:`Nothing` / `Color` / `Depth` / `ColorAndDepth`。 |
| `pixelPerfect` | boolean | `false` | 吸附到世界像素网格,让像素画清晰(正交)。 |
| `cullingMask` | number | 全部层 | 这台相机渲染的排序层位掩码(第 *i* 位 = 第 *i* 层)。 |
| `renderTarget` | number | `0` | 这台相机绘制到的 `RenderTexture` 句柄,而不是屏幕(`0` = 屏幕)——小地图、镜子;运行时由脚本设置。 |
| `showFrustum` | boolean | `false` | 仅编辑器：画出这台相机的整个视锥体(近面到远面)。关闭时 gizmo 只勾出它在内容平面上取景的范围——相机朝向别处时那里是空的。 |

## 缩放与投影

`orthoSize` 是缩放控制——减半即让屏上尺寸翻倍。因为它是 `animatable` 的,最平滑的缩放方式
是用一个 [tween](/docs/zh-cn/animation/overview/):

```typescript
import { defineSystem, Res, Tween, TweenTarget } from 'esengine';

const zoomIn = defineSystem([Res(Tween)], (tween) => {
  tween.to(cameraEntity, TweenTarget.CameraOrthoSize, 270, 0.5);   // zoom to 2×
});
```

`Perspective` 只用于伪 3D 的分层场景;2D 游戏保持 `Orthographic`,尺寸才不随深度变化。

## 设计分辨率适配

发布的游戏会跑在各种宽高比的屏幕上。引擎每帧解析一个*适配源*,当其生效时,把主相机适配到
实际屏幕的宽高比:`orthoSize` 是相机**在设计宽高比下**的半高,缩放模式决定屏幕更宽或更窄时
怎么处理(保持高度、保持宽度、扩展、收缩或按比例混合)。适配源按此顺序:

1. **`ScreenScaling`** 资源(设置 → 项目 → 游戏 → 显示 → 相机适配),当其 `scaleMode` 是真实模式
   (`≥ 0`)时;
2. 否则,场景的 **`Canvas`** 组件(若存在);
3. 否则无——相机按原始 `orthoSize` 渲染。

有适配时 `orthoSize` 仍然是缩放——场景里有 `Canvas` 时上面的 tween 同样生效。UI 不跟随缩放:
UI 的布局框是适配到屏幕的设计分辨率,缩放相机不会让 UI 重新排版,屏幕空间 UI 也走自己的投影。

想正好显示设计画面,就把 `orthoSize` 设为 `designResolution.y / 2`(默认的 `540` 对应默认 1080
高的设计分辨率)。0.97 及之前,适配会忽略 `orthoSize`、固定使用 `designResolution.y / 2`;在适配下
写了其它值的场景,现在会按那个值显示。缩放模式、letterbox 实例与 `ScreenScaling` 字段详见
[屏幕与设计分辨率](/docs/zh-cn/core-concepts/screen/)。

## 跟随目标

给相机加一个 `FollowTarget` 并指向一个实体。跟随是帧率无关的阻尼移动,带一个死区,所以相机
平滑漂移并忽略细小移动:

![相机把目标保持在离视图中心固定的 offset;目标在死区圆内自由漫游,一旦离开相机就阻尼跟上](@/assets/guides/camera-follow.svg)

```typescript
import { defineSystem, Query, Commands, Camera, FollowTarget } from 'esengine';

const follow = defineSystem([Query(Camera), Commands()], (cameras, cmds) => {
  for (const [cameraEntity] of cameras) {
    cmds.entity(cameraEntity).insert(FollowTarget, {
      target: playerEntity,   // the Entity to follow
      offsetY: 40,
      deadzone: 24,
      damping: 0.25,
    });
  }
});
```

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `target` | Entity | `0` | 要跟随的实体(`0` = 无;旧场景里的 `-1` 也当作无)。 |
| `offsetX` | number | `0` | 相对目标的世界空间 X 偏移。 |
| `offsetY` | number | `0` | 相对目标的世界空间 Y 偏移。 |
| `offsetZ` | number | `0` | 相对目标的世界空间 Z 偏移(3D 跟随使用)。 |
| `followZ` | boolean | `false` | 同时跟随目标的深度。平面场景保持关闭,因为那里相机的 z 是它退后的距离。 |
| `deadzone` | number | `0` | 目标可漫游而相机不动的半径(世界单位,3D 中为球体)。 |
| `damping` | number | `0.25` | 平滑时间常数(秒,越大越慢;`0` = 立即吸附)。 |

数据形状导出为 `FollowTargetData` 类型。跟随系统直接写相机的 `Transform`(所以 director
混合的是已跟随的视图),且**只在 play 模式运行**——编辑器的导航视图永远不会被它拖走。

## 移动相机来构图

`PositionComposer` 和 `LookAtTarget` 一样在屏幕上构图，但它移动相机而不是转动相机：对应 Cinemachine 的 Position Composer，也是常用的 2D 相机。目标被保持在一个屏幕点上；在死区内目标可以随意移动、相机不动；超出死区后相机按 `damping` 平滑追上；软区是目标能到的最远处：越过软区边缘，相机立刻移动。3D 相机还会沿视线方向与目标保持 `cameraDistance` 的距离。

```typescript
import { PositionComposer } from 'esengine';

cmds.entity(cameraEntity).insert(PositionComposer, {
  target: player,
  screenX: 0.4, screenY: 0.4,              // 稍偏左下：给前方留出视野
  deadzoneWidth: 0.1, deadzoneHeight: 0.2, // 走动不会带动相机
  softzoneWidth: 0.6, softzoneHeight: 0.6, // 冲刺也不会让玩家越过这里
  damping: 0.25,
});
```

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `target` | Entity | `0` | 构图的目标（`0` = 无）。 |
| `offsetX` / `offsetY` / `offsetZ` | number | `0` | 构图点，相对目标的世界空间偏移。 |
| `screenX` / `screenY` | number | `0.5` | 目标被保持的位置：`0` 为左/下边缘，`1` 为右/上边缘。 |
| `deadzoneWidth` / `deadzoneHeight` | number | `0` | 目标可以移动而相机不动的屏幕占比。 |
| `softzoneWidth` / `softzoneHeight` | number | `0.8` | 目标被限制在内的屏幕占比；越过边缘相机立刻移动。 |
| `damping` | number | `0.3` | 在屏幕方向上追上大部分距离所需秒数（`0` = 立刻）。 |
| `cameraDistance` | number | `0` | 3D：目标在相机前方保持的距离。`0` 保持当前距离。 |
| `depthDamping` | number | `0.3` | 3D：追上该距离所需秒数。 |

相机沿自身屏幕平面（右和上）滑动，所以转过角度的相机像轨道车一样移动。正交相机在任何深度下屏幕高度都是 `orthoSize`。它是相机流水线的位置阶段：一台相机用它、`FollowTarget` 或 `CameraDolly` 之一。视口里的相机预览会画出它的死区和软区，Follow Camera 2D 预设就是它。

## 看向目标

`FollowTarget` 决定相机站在哪,`LookAtTarget` 决定它看向哪。把它加到透视相机上并指向一个实体,相机就会转动,
让目标停在画面上指定的位置,就像 Unity Cinemachine 的 Rotation Composer 构图那样。目标在这个位置周围的死区里移动时,
相机不转;移出死区后,相机只转到让目标回到死区边缘为止,转动的快慢由 `damping` 控制。

```typescript
import { LookAtTarget } from 'esengine';

cmds.entity(cameraEntity).insert(LookAtTarget, {
  target: hero,
  offsetY: 160,          // 看头部,而不是脚下
  screenX: 0.5,          // 水平居中……
  screenY: 0.6,          // ……略高于画面中心
  deadzoneWidth: 0.1,    // 在画面宽度的十分之一内自由移动
  deadzoneHeight: 0.1,
  damping: 0.2,
});
```

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `target` | Entity | `0` | 要看向的实体(`0` = 无)。 |
| `offsetX` / `offsetY` / `offsetZ` | number | `0` | 看向的点,即相对目标的世界空间偏移。 |
| `screenX` | number | `0.5` | 目标在画面上的水平位置:`0` 左边缘,`0.5` 中心,`1` 右边缘。 |
| `screenY` | number | `0.5` | 目标在画面上的竖直位置:`0` 下边缘,`0.5` 中心,`1` 上边缘。 |
| `deadzoneWidth` / `deadzoneHeight` | number | `0` | 目标可以移动而相机不转的范围,占画面的比例。 |
| `damping` | number | `0.1` | 转到目标大部分路程所需的秒数(`0` = 立即)。在任何帧率下结果相同。 |

相机只绕世界的上方向和自身的右方向转动,所以不会发生翻滚。挂在父节点下的相机按世界朝向转动,
再通过父节点换算成自己的本地旋转。正交相机不受影响:它画的是一个平面,转动它只会看到平面的边缘。
画面位置按相机实际绘制的视口(它的 `viewport` 占屏幕的部分)来量,所以同一个构图在手机和宽屏上都一样。

### 构图参考线

选中带 `LookAtTarget` 的相机，视口里的相机预览会在画面上画出构图：目标被保持的屏幕点和它周围的死区，和 Cinemachine 的 Game Window Guides 一样。拖动那个点改 `screenX`/`screenY`，拖死区的边以点为中心调整大小；每次拖动是一步撤销。

## 相机流水线

每个 `Camera` 都是一台虚拟相机:场景描述的一个视角。每一帧,在选出要显示的视角之前,每台相机都按它带的组件
依次被移动,顺序固定为:

| 阶段 | 组件 | Cinemachine | Unreal |
|---|---|---|---|
| 1. 位置:站在哪 | `FollowTarget`、`CameraDolly` 或 `PositionComposer` | Position Control(Follow、Spline Dolly、Position Composer) | 相机 rig 的位置节点 |
| 2. 朝向:看向哪 | `LookAtTarget` | Rotation Control(Rotation Composer) | 相机 rig 的注视节点 |
| 3. 收尾:对结果的限制 | `GroupFraming`、`CameraDeoccluder`、`CameraBounds` | Extensions(Group Framing、Deoccluder、Confiner) | 弹簧臂探测、相机修改器 |
| 4. 噪声:画面上的漂移 | `CameraNoise` | Noise(Basic Multi-Channel Perlin) | 相机震动 |

流水线在游戏自己的 Update 系统之后运行（和 Cinemachine Brain 在 LateUpdate 运行一样），读取的是目标这一帧的位置。每个阶段都按世界坐标决策,再经由相机的父节点写回;后面的阶段读取前面阶段这一帧写下的结果,所以一台既跟随又注视
同一个角色的相机,是从它这一帧所站的位置去瞄准的。噪声只移动最终画面,逐相机施加,在混合之前。
之后相机导演(下文)从中选出一台活动相机并混合过去,相当于 Cinemachine 的 Brain 和 Unreal 的 `PlayerCameraManager`。示例 `camera-shots` 把所有阶段放在一起：
轨道上的跟拍、环形轨道上的摇臂和一个远景，不写一行相机代码。
震屏在那之后施加,只作用于最终画面,从不改相机的 `Transform`,和 Cinemachine 的 Impulse、Unreal 的相机震动一样。
流水线**只在播放模式下**运行。

## 沿轨道移动

`CameraDolly` 把相机放到一条轨道上:场景里的一个 `Spline` 实体,就像架在导轨上的摄影车。它是决定相机站在哪的另一种
方式(另一种是 `FollowTarget`),一台相机用其中一种。`mode` 决定相机在轨道上的位置:

- **固定**(`DollyMode.Fixed`):在 `position` 处,由脚本或动画来移动。
- **追踪目标**(`DollyMode.TrackTarget`):在轨道上离 `target` 最近的点,再沿轨道挪 `offset`:一台跟着拍摄对象跑的相机。
- **匀速**(`DollyMode.Speed`):以 `speed` 前进,闭合轨道上一圈圈绕,开放轨道上走到头为止。

```typescript
import { CameraDolly, DollyMode, LookAtTarget } from 'esengine';

cmds.entity(cameraEntity)
  .insert(CameraDolly, { spline: railEntity, mode: DollyMode.TrackTarget, target: runner, offset: -150, damping: 0.4 })
  .insert(LookAtTarget, { target: runner });
```

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `spline` | Entity | `0` | 作为轨道的 `Spline` 所在的实体。 |
| `mode` | number | `Fixed` | 如何选择轨道上的位置(`DollyMode`)。 |
| `position` | number | `0` | 相机在轨道上的位置,从起点算起的世界单位。每一帧、每种模式下都会写回。 |
| `target` | Entity | `0` | 追踪目标模式下相机要对齐的对象。 |
| `offset` | number | `0` | 在离目标最近的点之前(负数为之后)多少世界单位。 |
| `speed` | number | `0` | 匀速模式下每秒沿轨道前进的世界单位;负数为倒退。 |
| `damping` | number | `0.3` | 追踪目标模式下追上大部分距离所需的秒数;`0` 为立即。 |

距离是沿曲线量的世界单位,所以缩放过的样条更长。在闭合轨道上,追踪目标的相机走较短的那一边,目标跨过接缝时
相机不会绕整圈跑回去。轨道和 `PathFollower` 用的是同一条曲线。

## 手持噪声

`CameraNoise` 让相机像手持拍摄那样轻微漂移和点头,或者像在船上那样摇晃:六个通道的平滑 Perlin 噪声,三个让画面
沿自身的左右、上下、前后漂移,三个让画面绕这三根轴转动,和 Cinemachine 的 Basic Multi-Channel Perlin 一样。

```typescript
import { CameraNoise } from 'esengine';

cmds.entity(cameraEntity).insert(CameraNoise, { rotation: 0.5, frequency: 0.3 });   // 手持
cmds.entity(carCamera).insert(CameraNoise, { amplitude: 4, rotation: 1.5, frequency: 2 });   // 车载
```

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `amplitude` | number | `0` | 画面漂移的距离,世界单位。 |
| `rotation` | number | `0.5` | 画面转动的角度。手持相机大约 `0.5`。 |
| `frequency` | number | `0.3` | 漂移改变方向的频率(Hz):手持约 `0.3`,车载约 `2`。 |
| `seed` | number | `0` | 选哪一种漂移;`0` 由实体决定,所以任意两台相机都不会同步晃动。 |

噪声只移动最终画面,从不改相机的 `Transform`,所以不会累积,跟随、轨道和注视也都按相机真实的位置计算。
它在导演混合之前逐相机施加,所以从一台晃动的相机混合到一台稳定的相机时,晃动会逐渐平息。2D 相机在屏幕上漂移并翻滚。
噪声跟随游戏时钟:游戏暂停时它也停止。

## 同时框住多个目标

两名玩家同屏、Boss 和主角同框：`CameraTargetGroup` 把多个实体当成一个目标，和 Cinemachine 的 Target Group 一样。每一帧它所在的实体会被放到成员的中心，所以任何接受目标的阶段（`FollowTarget`、`LookAtTarget`、`PositionComposer`、`CameraDolly`）只要把目标设成这个组实体，就能框住整组。相机上的 `GroupFraming` 再决定画面大小：把包住所有成员（每个成员是半径为组 `radius` 的球）的盒子撑满屏幕的 `framingSize`，方式是缩放镜头或推拉相机。

```typescript
import { CameraTargetGroup, GroupFraming, PositionComposer, FramingAdjustment } from 'esengine';

const players = cmds.spawn()
  .insert(Transform, {})
  .insert(CameraTargetGroup, { members: [p1, p2], weights: [1, 1], radius: 40 })
  .id();

cmds.entity(cameraEntity)
  .insert(PositionComposer, { target: players })
  .insert(GroupFraming, { framingSize: 0.7, adjustment: FramingAdjustment.Zoom });
```

| `CameraTargetGroup` | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `members` | Entity[] | `[]` | 一起被框住的实体。 |
| `weights` | number[] | `[]` | 按顺序对应每个成员的权重；缺省为 `1`，`0` 表示排除该成员。 |
| `radius` | number | `50` | 每个成员的大小（以原点为中心的球）：取景时保留在画面内的部分。 |
| `center` | number | `Bounds` | 组所在的位置：`GroupCenter.Bounds`（盒子中心）或 `GroupCenter.Average`（加权平均）。 |

| `GroupFraming` | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `group` | Entity | `0` | 被框住的组。`0` 取相机的构图、注视或跟随目标所指的组。 |
| `framingSize` | number | `0.8` | 组占据的屏幕比例。 |
| `mode` | number | `Both` | 按宽 `FramingMode.Horizontal`、按高 `Vertical`，或取需要更大空间的那个（`Both`）。 |
| `adjustment` | number | `Zoom` | `FramingAdjustment.Zoom` 改镜头（orthoSize 或视野角）；`DollyThenZoom` 先沿视线推拉相机，超出范围的部分再缩放。 |
| `damping` | number | `0.5` | 追上大部分所需秒数（`0` = 立刻）。 |
| `minFov` / `maxFov` | number | `10` / `80` | 视野角范围（度）。 |
| `minOrthoSize` / `maxOrthoSize` | number | `1` / `5000` | 正交相机的范围。 |
| `minDistance` / `maxDistance` | number | `100` / `5000` | 推拉时离组中心最近和最远的距离。 |

推拉量和相机组合放置的位置分开保存，所以同时跟随该组的相机会平滑后退，而不是每帧被推一步。创建菜单的 Target Group Camera 2D 和 Target Group Camera 会同时创建一个组和一台框住它的相机。

## 保持目标可见

3D 相机和它拍摄的目标之间出现墙时，画面就被挡住了。`CameraDeoccluder` 让目标保持可见，和 Cinemachine 的 Deoccluder（Pull Camera Forward）以及 UE 的弹簧臂一样：从目标向相机的位置扫一个球，碰到东西时，相机沿这条线被拉近到它跟前。沿这条线移动，目标在画面中的构图位置不变。墙移开后，相机平滑退回到相机组合原本要放的位置；相机组合自己的各个阶段永远看不到被拉近的位置。

```typescript
import { CameraDeoccluder } from 'esengine';

cmds.entity(cameraEntity).insert(CameraDeoccluder, {
  radius: 15,               // 在墙前这么远处停下
  minimumDistance: 30,      // 离目标不会比这更近
  dampingWhenOccluded: 0,   // 立刻拉近，永远不会看穿墙
  damping: 0.4,             // 约 0.4 秒退回
});
```

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `target` | Entity | `0` | 必须保持可见的对象。`0` 取 `LookAtTarget` 的目标（含偏移），否则取 `FollowTarget` 的。 |
| `radius` | number | `15` | 扫掠球的半径：相机在墙前停下的距离。 |
| `layers` | number | `0` | 会挡住目标的物理层；`0` 为全部。 |
| `minimumDistance` | number | `30` | 相机离目标不会比这更近。 |
| `dampingWhenOccluded` | number | `0` | 目标被挡住时拉近所需秒数；`0` 为立刻。 |
| `damping` | number | `0.4` | 遮挡消失后退回所需秒数。 |

扫掠查询的是 3D 物理世界，所以只有带 3D 碰撞体的物体会挡住目标；没有 3D 物理的场景里相机保持原位。Tracking Camera 预设自带它。

## 把相机限制在关卡内

给相机加一个 `CameraBounds`,视野就再也不会离开这个矩形——关卡的边缘停在屏幕边缘,
而不是露出外面的虚空:

```typescript
import { Camera, CameraBounds } from 'esengine';

cmds.entity(cameraEntity).insert(CameraBounds, {
  minX: -1280, maxX: 1280,   // 关卡的世界矩形
  minY: -768,  maxY: 768,
});
```

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `minX` / `maxX` | number | `0` | 视野保持在其中的水平区间。 |
| `minY` / `maxY` | number | `0` | 视野保持在其中的垂直区间。 |

每个轴通过给出一个真实区间来启用,所以留在 `0`/`0`(或任何 `max ≤ min`)的轴不受约束——
一个横向无限滚动的关卡只约束水平轴即可。当区间比视野还窄时,整个区间会居中显示,
而不是贴住某一面墙。

这个钳制跑在所有移动相机的东西之后,包括 `FollowTarget`:它约束的是相机结束这一帧时在
哪里,而不是谁把它放到那里的。只对正交相机生效——透视相机的半尺寸取决于被拍摄物有多远,
没有任何相机属性描述它。和跟随一样,**只在 play 模式运行**。

## 屏幕 ↔ 世界坐标

读 `CameraView` 资源在两个空间之间转换——用于把实体放到光标下,或检测什么可见。无活动相机
时每个方法返回 `null`:

```typescript
import { defineSystem, Res, CameraView, Input } from 'esengine';

const pick = defineSystem([Res(CameraView), Res(Input)], (view, input) => {
  const world  = view.screenToWorld(input.mouseX, input.mouseY);  // { x, y } | null
  const screen = view.worldToScreen(x, y);                        // { x, y } | null
  const mouse  = view.getWorldMousePosition();                    // { x, y } | null
  const bounds = view.getWorldBounds();  // { left, right, bottom, top } | null
});
```

| 方法 | 返回 | 说明 |
|---|---|---|
| `screenToWorld(sx, sy, planeZ = 0)` | `{x, y} \| null` | 屏幕像素 → `planeZ` 平面上的世界位置。正交相机忽略该平面;透视相机下请传目标所在的 z。 |
| `worldToScreen(wx, wy, wz = 0)` | `{x, y} \| null` | 世界位置 → 屏幕像素。没有相机或点在眼睛处/身后时为 `null`;在视口之外仍返回坐标。 |
| `getWorldMousePosition()` | `{x, y} \| null` | 世界空间里的光标。 |
| `getWorldBounds()` | `{left, right, bottom, top} \| null` | 可见的世界矩形。 |

## 震屏

`shakeCamera` 只给**渲染的**视图加一个衰减扰动——绝不碰 Transform,所以相机总会恢复,场景
保持干净:

```typescript
import { shakeCamera } from 'esengine';

shakeCamera(app, { amplitude: 12, rotation: 0, frequency: 22, duration: 0.4 });
```

`shakeCamera` 与 `setViewTarget` 的第一个参数既可以是 `App`(宿主代码),也可以是
`CameraDirector` 资源状态——在系统里直接传 `Res(CameraDirector)` 给你的值:

```typescript
import { defineSystem, Res, Input, CameraDirector, shakeCamera } from 'esengine';

const shakeOnHit = defineSystem([Res(Input), Res(CameraDirector)], (input, director) => {
  if (input.isKeyPressed('Space')) shakeCamera(director, { amplitude: 16 });
});
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `amplitude` | `12` | 峰值位置偏移(世界单位)。 |
| `rotation` | `0` | 峰值旋转震动(弧度)。 |
| `frequency` | `22` | 每秒振荡次数。 |
| `duration` | `0.4` | 衰减到零的秒数。 |

## 冲击：来自某处的震动

`shakeCamera` 不论画面在哪都同样震动。爆炸则取决于发生的位置：旁边的相机剧烈一震，关卡另一头的相机几乎感觉不到。`CameraImpulseSource` 发出这样的冲击，每台带 `CameraImpulseListener` 的相机按距离感受它，对应 Cinemachine 的 Impulse Source 和 Impulse Listener。和噪声一样，它只移动最终画面，从不改动相机的 `Transform`。

```typescript
import { CameraImpulseSource, CameraImpulseListener, fireImpulse } from 'esengine';

cmds.entity(barrel).insert(CameraImpulseSource, { amplitude: 30, frequency: 8, decay: 0.6, radius: 300, dissipation: 2000 });
cmds.entity(cameraEntity).insert(CameraImpulseListener, { gain: 1 });

// 爆炸时：
fireImpulse(world, barrel, 1.5);   // 比设定强一半
```

| `CameraImpulseSource` | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `amplitude` | number | `20` | 满强度时画面被甩出的距离（世界单位）。 |
| `rotation` | number | `1` | 被转动的角度（度）。 |
| `frequency` | number | `8` | 抖动频率（Hz）。 |
| `attack` / `sustain` / `decay` | number | `0.02` / `0.1` / `0.6` | 达到满强度、保持、衰减各需的秒数。 |
| `radius` | number | `300` | 在此距离内以满强度感受到。 |
| `dissipation` | number | `2000` | 超出半径后衰减到零的距离。 |
| `propagationSpeed` | number | `0` | 传播速度（单位/秒），远处的相机稍后才感受到；`0` 为同时到达。 |
| `channels` | bitmask | `1` | 哪些监听者能感受到。 |
| `fire` | boolean | `false` | 设为 true 即从这里发出（时间轴、可视化脚本、运行时的 Inspector）；发出后自动清除。 |

| `CameraImpulseListener` | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `channels` | bitmask | `1` | 这台相机感受哪些冲击。 |
| `gain` | number | `1` | 感受的强度。 |
| `use2DDistance` | boolean | `false` | 只在 X/Y 平面上量距离，适合离开所拍平面的 2D 相机。 |

创建菜单里的 Impulse Source 会创建一个冲击源；Follow Camera 2D、Tracking Camera 和组相机预设都带监听者。

## 相机间混合

`setViewTarget` 把活动视图切到另一个相机实体,可选地在 `time` 秒里**混合**而非硬切——用于
电影化的镜头交接:

```typescript
import { setViewTarget, BlendCurve } from 'esengine';

// Cut instantly:
setViewTarget(app, cutsceneCamera);
// Or ease over 1.5s:
setViewTarget(app, cutsceneCamera, { time: 1.5, curve: BlendCurve.EaseInOut });
```

`BlendCurve` 取值为 `Linear`、`EaseIn`、`EaseOut`、`EaseInOut`。`time <= 0`(或没有先前视图)
即硬切。位置、缩放、旋转会插值;3D 相机的朝向沿较短的路径从一台转到另一台;离散字段(投影、视口)在中点翻转。

## 按优先级切换相机

在铺满屏幕的激活相机里,`priority` 最高的那台是活动相机;优先级相同时取最近打开的那台(和 Cinemachine Brain 一样;场景加载时就在的相机取第一台)。提高某台相机的优先级,或者打开、
关闭某台相机,活动相机就会换成另一台。默认是直接切过去。在场景里任意实体上加一个 `CameraBrain`,就会改为平滑混合,
相当于 Cinemachine Brain 的 Default Blend:

```typescript
import { CameraBrain, BlendCurve } from 'esengine';

cmds.spawn().insert(CameraBrain, { defaultBlend: 1.2, blendCurve: BlendCurve.EaseInOut });

// 之后:这台相机成为活动相机,画面在 1.2 秒内平滑过渡过去。
cmds.entity(bossCamera).insert(Camera, { ...bossCameraData, priority: 10 });
```

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `defaultBlend` | number | `1` | 没有显式指定、活动相机自己变了时,画面过渡所用的秒数。`0` 为硬切。 |
| `blendCurve` | number | `EaseInOut` | 过渡的缓动:`BlendCurve.Linear`、`EaseIn`、`EaseOut` 或 `EaseInOut`。 |
| `customBlends` | records | `[]` | 针对特定相机切换的混合,按相机名(`from`、`to`;留空表示任意相机),各自带 `time` 和 `curve`。 |

自定义混合对应 Cinemachine 的 Custom Blends:从全景硬切到特写、再慢慢退回。同时写明两台相机的条目优先,其次是写明目标相机的,再次是写明来源相机的;其余切换用默认混合。`time` 为 `0` 时硬切。Details 里以表格编辑:

```typescript
cmds.spawn().insert(CameraBrain, {
  defaultBlend: 1,
  customBlends: [
    { from: 'Wide', to: 'Close', time: 0, curve: BlendCurve.Linear },   // 硬切进去
    { from: '', to: 'Wide', time: 2.5, curve: BlendCurve.EaseInOut },  // 从任意相机慢慢退回
  ],
});
```

如果在混合途中活动相机又变了,新的混合从画面当前所在的位置开始,不会跳变。`setViewTarget` 自带混合时长,
不受大脑影响。每个场景一个大脑;没有大脑的场景照旧硬切。

## 相机 director

`setViewTarget` 与 `shakeCamera` 是**相机 director** 的 API——一个 per-app 资源
(`CameraDirector`),每帧从全屏相机候选中解析出*一个*主视点:已提交的视图目标(或活动/
最高优先级相机),过渡进行中则向新目标混合,震屏只叠加在渲染视图之上。其状态
(`CameraDirectorState`)可读;把它当**只读**,用 `setViewTarget` / `shakeCamera` 去改:

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `target` | number | `-1` | 已提交的视图目标实体;`-1` = 回退到 `isActive` / 最高 `priority` 的选择。 |
| `blending` | boolean | `false` | 视图目标混合正在进行。 |
| `duration` / `curve` | number | `0` / `EaseInOut` | 当前混合的时长(秒)与缓动。 |
| `currentMain` | `CameraPOV \| null` | `null` | 最后解析出的主 POV,**未加震屏**——也是屏幕↔世界转换所用的视图。 |
| `shakes` | `ActiveShake[]` | `[]` | 活动的瞬时震屏(由 `shakeCamera` 压入,衰减完即丢弃)。 |

其余字段(`timelineShot`、`timelineOwner`(由播放中的时间线相机轨道写入)、`hasPending`、`pendingTarget`、`pendingTime`、`pendingCurve`、`from`、
`startTime`、`shakeSeq`)是 `setViewTarget` 写入的 director 内部请求/混合簿记。

```typescript
import { defineSystem, Res, CameraDirector } from 'esengine';

const watchDirector = defineSystem([Res(CameraDirector)], (director) => {
  if (director.blending) { /* e.g. suppress player input during the hand-off */ }
  const pov = director.currentMain;   // CameraPOV | null — the view being rendered
  if (pov) { /* pov.x, pov.y, pov.orthoSize, ... */ }
});
```

`cameraDirectorReport(app)` 把 director 的状态汇总给工具或测试用：当前相机、进行中的混合（从哪台相机、进度 0 到 1）以及参与选择的相机。

```typescript
import { cameraDirectorReport } from 'esengine';

const { live, blend } = cameraDirectorReport(app);
if (blend) console.log(`混合 ${blend.from} → ${blend.to}：${Math.round(blend.progress * 100)}%`);
```

在编辑器里运行游戏时，大纲视图会把当前相机标为**当前**（混合中显示进度），把混合正在离开的相机标为**淡出**，对应 Cinemachine Brain 的 Live Camera 和 Live Blend；在 Inspect 模式下游戏画面上也会显示。

### 相机事件

画面切换相机时，导演会通知游戏，对应 Cinemachine 的 Camera Activated 和 Blend Finished 事件：在系统里读取 `CameraEvent`，可以在某个镜头的相机成为活动相机时显示它的 HUD，或在混合结束后把控制权交回玩家。事件在绘制这一帧时发出，所以系统在下一帧读到。

```typescript
import { defineSystem, EventReader, CameraEvent, CameraEventKind } from 'esengine';

const onCameraChange = defineSystem([EventReader(CameraEvent)], (events) => {
  for (const e of events) {
    if (e.kind === CameraEventKind.Activated) console.log(`当前相机：${e.camera}（来自 ${e.previous}，${e.blendTime} 秒）`);
    if (e.kind === CameraEventKind.BlendFinished) console.log(`已停在 ${e.camera}`);
  }
});
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | number | 相机成为活动相机（硬切或混合进入）时为 `CameraEventKind.Activated`，混合进入结束时为 `BlendFinished`。 |
| `camera` | Entity | 画面当前所在或将要到达的相机。 |
| `previous` | Entity | 离开的相机；没有，或画面正处于两台相机之间时为 `0`。 |
| `blendTime` | number | 混合进入它所需秒数；硬切为 `0`。 |

### `CameraPOV`

`CameraPOV` 是相机*被作者的视图参数*的一个纯快照——director 混合的单位,也是
`currentMain` 存的形状:

| 字段 | 类型 | 说明 |
|---|---|---|
| `entity` | number | 来源相机实体,`-1` 表示合成 POV(编辑器视图)。 |
| `isActive` | boolean | 权威的"这就是主相机"标志。 |
| `x` / `y` / `z` | number | 相机位置(世界单位)。 |
| `rotation` | number | Z 旋转,弧度。 |
| `projection` | number | 一个 `ProjectionType` 值。 |
| `orthoSize` | number | 作者写的正交半高(世界单位)。 |
| `fov` | number | 视场角,度(透视)。 |
| `near` / `far` | number | 裁剪距离。 |
| `viewport` | `{x, y, z, w}` | 屏幕矩形,0–1(`z`/`w` 是宽/高)。 |
| `clearFlags` | number | 一个 `ClearFlags` 值。 |
| `priority` | number | 活动相机间的优先级。 |
| `pixelPerfect` | boolean | 像素网格吸附标志。 |

混合期间,连续字段(位置、按最短角路径的 `rotation`、`orthoSize`、`fov`、`near`/`far`)
插值;离散字段(`projection`、`pixelPerfect`)在中点翻转,`viewport` / `clearFlags` /
`priority` 取目标值。

## 匹配画布宽高比

`updateCameraAspectRatio(world, aspect)` 把 `aspectRatio` 写到世界里**每个** `Camera`
组件上。各发布运行时启动时用真实画布的 `width / height` 调用它,让作者字段与实际表面保持
同步(渲染本身每帧从活动视口推导宽高比):

```typescript
import { updateCameraAspectRatio } from 'esengine';

updateCameraAspectRatio(app.world, canvas.width / canvas.height);
```

## 多相机与分屏

有多个 `Camera` 实体时,激活的相机里 `priority` 最高的那台是活动相机(见[按优先级切换相机](#按优先级切换相机))。用 `viewport` 给每个相机一个
子矩形来共享屏幕——例如双人分屏,左右各半:

```typescript
.insert(Camera, { viewport: { x: 0,   y: 0, w: 0.5, h: 1 }, isActive: true }); // left
.insert(Camera, { viewport: { x: 0.5, y: 0, w: 0.5, h: 1 }, isActive: true }); // right
```

## 最佳实践

- **用 `orthoSize` 驱动缩放**,别用 Transform 缩放——缩放相机实体会扭曲渲染。
- **跟随带死区**,相机才不会因细小移动抖动;调大 `damping` 得到更慵懒、电影化的感觉。
- **震屏而非移动**:冲击用 `shakeCamera`,视图总能恢复。
- **像素画开 `pixelPerfect`** 消除亚像素抖动。
- 场景与过场切换**优先用混合**(带 `time` 的 `setViewTarget`),而不是瞬移相机。

## 大世界

一个单精度浮点只在零点附近精确：离零点 50 公里时一步是 4 毫米，那里的网格会随相机移动而抖动。`setRenderOriginStep(step)` 改为相对相机附近的一个点来绘制世界：

```ts
import { setRenderOriginStep } from 'esengine';

setRenderOriginStep(1024); // 单位米；0（默认）是相对世界自己的零点绘制
```

原点取相机位置按 `step` 取整，相机离开它超过 `step` 才会移动，所以阴影图、光照网格这些按世界网格布置的缓存只在它移动时才变。渲染器在交给 GPU 之前，把每个网格、光、探针、粒子、拖尾、瓦片图和世界空间 UI 都从原点算起，相机的视图投影也为同一个原点构造，所以画面一样，里面的数字却很小。地形、星球、水、植被、高度雾和天空的云按世界位置铺设，会从原点把世界位置读回来，原点移动时不会滑动。

仍用世界自己坐标、不受影响的有：变换、物理、网络、`screenToWorld` 和拾取。绘制回调和调试绘制拿到的是世界的视图投影，按世界坐标画，所以在远离零点处保持的是单精度浮点原有的精度。一帧只有一个原点：多个相机时它跟随屏幕自己的相机，远离它的相机以单精度浮点的精度绘制。原点移动时，上一帧的视图和网格会被带到新原点，运动矢量和时间性效果照常继续；全局光照的体素缓一帧。
