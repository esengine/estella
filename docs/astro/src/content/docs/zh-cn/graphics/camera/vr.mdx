Web 包可以在 VR 头显里玩：用头显自带的浏览器，或者用接了头显的桌面浏览器。两只眼睛按头显自己的镜片参数和头部追踪分别绘制，帧率跟随头显。

## 打开 VR

打开**项目设置 > 渲染 > VR 头显（WebXR）**（它会把 `features.rendering.vr` 写进 `project.esproject`），再导出 Web 包。只要浏览器能进入 VR，页面就会显示 **Enter VR** 按钮；玩家点它进入头显，点 **Exit VR** 退出。

```json
{ "features": { "rendering": { "vr": true } } }
```

开发时这样试用：

- **浏览器预览**会在本机的浏览器里打开游戏，这个浏览器能使用接在本机上的头显（通过 Link 连接的 Quest，或任何装了 OpenXR 运行时的头显）。
- **播放**时，如果编辑器本身能进入 VR，游戏面板里也会显示同样的按钮，否则不显示。
- 头显自带的浏览器只能通过 HTTPS 或 `localhost`（用 `adb reverse` 转发端口）打开预览。`http://192.168.1.20` 这样的局域网地址不算安全上下文，那里不会提供 WebXR。

游戏也可以从自己的界面进入。`enterVR` 必须在点击或按键事件里调用，这是浏览器的要求。

```typescript
import { enterVR, exitVR, inVR, vrSupported } from 'esengine';

if (await vrSupported()) showButton(() => (inVR(app) ? exitVR(app) : enterVR(app)));
```

VR 使用页面自身线程上的 WebGL2 绘制，因为头显从这个上下文取画面。项目设成 WebGPU 或多线程渲染时，打开 VR 后这两项都不会启用。

## 玩家站在哪里

第一台画到屏幕上的相机就是玩家站的位置。进入 VR 时，玩家的眼睛就在这台相机所在的地方，朝向它的朝向。转头会转动视野；移动相机（行走、载具、传送）会带着玩家一起移动。只取相机的偏航角：俯视目标的第三人称相机不会让玩家的地平线倾斜。

头显以米为单位，按项目的"世界单位/米"换算，所以按 100 单位一米做的游戏，两只眼睛相距 6.4 个单位。

## 手柄与头部

带 `XRController` 的实体每帧都会被摆到手柄所在的位置。给它加一个网格就能画出手或手柄，也可以把玩家拿着的东西挂在它下面。`pose` 选择跟随手柄的哪个位姿：**Grip** 是手握住的位置，**Aim** 是它指向的方向（前方是 -Z），用来发射指向射线。带 `XRHead` 的实体跟随玩家的头部。

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `hand` | Left / Right | Right | 实体跟随哪只手的手柄。 |
| `pose` | Grip / Aim | Grip | 手握手柄的位置，或手柄指向的位置。 |

不在头显里、或者手柄没有被追踪时，实体停在原来的位置。所以在相机旁边摆一只手的场景，在编辑器和普通屏幕上看起来也是对的。

手柄的按键和摇杆按左右手区分，用法和普通手柄一样，按键布局是所有头显浏览器都遵循的那一套：

```typescript
import { Input, XRButton, XRAxis } from 'esengine';

if (input.isXRButtonPressed(XRButton.Trigger, 'right')) fire();
const forward = -input.getXRAxis(XRAxis.ThumbstickY, 'left');
```

`XRButton` 包括 `Trigger`（扳机）、`Squeeze`（握把）、`Touchpad`（触摸板）、`Thumbstick`（摇杆按下）、`Primary`（A 或 X）和 `Secondary`（B 或 Y）。手柄同时也是普通手柄，左手是 1000 号，右手是 1001 号（`xrPadIndex(hand)`），所以任何手柄查询和绑定都能读到它们。动作可以用 `XrButton(button, hand)` 和 `XrStick(hand)` 绑定到它们上面，监听改键时也能识别这些按键。`xrPresentation(app)` 报告每只手柄的位姿、浏览器给出的设备型号，以及头部的位姿。

## 两只眼睛的开销

场景每帧只按一个覆盖两只眼睛的视野剔除和收集一次，第二只眼睛从自己的视角重画这份列表，所以只有绘制做两遍，这是 VR 的主要开销。阴影也按同一个视野只规划一次，两只眼睛读同一张阴影图集，场景静止时还会跨帧保留。时间性效果（抗锯齿、运动模糊）和按相机缓存的 GI 每只眼睛各保留一份历史，所以一只眼睛的画面不会混进另一只；为此 GI 缓存要占两倍内存。

## 头显里不显示的内容

头显没有自己的屏幕，所以这些内容不会画进头显：其他画到屏幕上的相机、屏幕空间的 HUD（世界空间的 UI 会画）以及编辑器的叠加层。渲染到纹理的相机照常绘制。

只有在头显等待的那段时间里画完的帧才会显示。如果某个系统在等待很慢的东西（比如网络请求），那一帧就会迟到，头显会继续显示上一帧；退出 VR 时日志会报告迟到了多少帧。
