Estella 通过 ping-pong 帧缓冲运行全屏后处理。加一个 `PostProcessVolume` 组件,启用你要的
效果,并调节它们的参数——在编辑器里或用代码。效果共享 ping-pong 缓冲,所以多个可以在一帧里
叠加,除各遍(pass)本身外没有额外的目标开销。

### 链路之前的抗锯齿

几何边缘由**场景本身的 MSAA** 抹平,不是某个效果做的:默认 4×,WebGL2 与 WebGPU 都有——
所有原生包(iOS、Android、桌面、Steam)跑的都是 WebGPU。用
`createWebApp({ msaaSamples })` 调它的大小,`msaaSamples: 1` 在填充率比边缘更要紧的设备上关掉它。
`fxaa` 是更便宜也更糊的替代品,留给连多一个采样都吃不下的设备。

### 运动模糊与镜头

`motionBlur` 无需配置:加上它,相机的移动由深度缓冲得出,运动网格的移动由时间性抗锯齿用的同一个运动 pass 得出,所以自己在动的网格会沿着它自己的轨迹被抹开,而不是相机的轨迹。`intensity` 是快门——0.5 是 180° 快门的半帧曝光,1 是整帧——`maxBlur` 把拖影长度限制在画面的一个比例内,切镜头或瞬移只会抹开一点点,不会抹开整个画面。相机没动时它画出原图,并且不像时间性效果那样对画面做亚像素偏移,所以可以不带 `taa` 单独使用。

`filmGrain` 和 `lensFlare` 是普通的后处理效果。镜头光斑读取的是画面本身,所以只有画面里存在高于 `threshold` 的值(明亮的太阳圆盘、灯、HDR 下的自发光表面)时它才有东西可投。

### 天空与细小几何体

`skyAtmosphere` 在场景之后、在场景下面绘制天空。为了让比一个像素还细的电线或栏杆保持完整,只要这个效果在链里,场景就被清为全透明,它的 alpha 表示几何体覆盖了每个像素的多少,于是天空按这个比例垫在边缘下面,而不是整个替换这个像素。下游看不到这一点:效果交回的 alpha 是 1。把**保留背景**调高,场景就恢复成清为相机颜色,这正是保留背景的含义。

### 云

`skyAtmosphere` 在空气中步进绘制云，太阳从云的内部照亮它们：每一步都会询问这一点和太阳之间隔着多少云，所以厚云的背光面是暗的，薄边是亮的。**Silver Lining** 控制靠近太阳时云边有多亮。

| 设置 | 作用 |
|---|---|
| **Cloud Coverage**、**Cloud Base**、**Cloud Thickness** | 主云层的覆盖率和所在高度，单位是千米。 |
| **Cloud Scale**、**Cloud Softness** | 云的大小（2 表示宽度减半）和边缘的柔和程度。 |
| **Cloud Change** | 云形随时间变化的速度。0 表示每朵云保持原样。 |
| **Wind Speed**、**Wind Direction** | 漂移速度（千米每秒）和方向。 |
| **Upper Layer Coverage** | 第二层云。0（默认）没有任何开销。 |
| **Upper Layer Base**、**Thickness**、**Scale**、**Wind** | 第二层自己的高度、颗粒和受风比例。通常又高又薄、移动更快；设在主云层之下时，它会挡在主云层前面。它也会投下云影。 |

**云遵循游戏时钟。** 云的位置是风到目前为止累积的结果，逐帧相加，所以风变强或转向时，云从当前位置继续走；[天气](/docs/zh-cn/graphics/weather/)在过渡途中给云加速也不会跳变。游戏暂停时天空静止，相同的步进得到相同的天空。雾的光柱读取同一个位置。要从存档恢复天空，保存 `skyClockState()`，再传给 `setSkyClockState()`。

### 云的限制

- **云只能从下方看。** 相机在云层之上时看不到云，所以飞越云海时没有云顶可看。
- **颗粒。** 步进抖动在放大回全分辨率时已经过滤，但地平线附近或 **Cloud Scale** 很大时仍可能有淡淡的纹理。
- **雾的光柱只跟随主云层。** 第二层云不产生光束。
- **云的位置不改变主光。** 云影是在天空通道里叠到表面上的；光源本身的强度跟随天气，不跟随挡在太阳前面的云。
- **没有在真机上测过。** 第二层云对它覆盖的每个半分辨率像素增加 12 次密度采样，主云层是 64 次；覆盖率为 0 时没有开销。

### 云影

把**云影**调到 0 以上,从每个表面朝太阳发出的光线会穿过天空绘制的云层逐步前进,用的是同一份密度,所以云下的地面更暗、更斑驳,天空开阔处则被照亮。被挡掉的是太阳直射光;环境光不受影响。开启云影也会把云固定在世界里而不是跟着相机走,所以人可以走进云影再走出来。天空以千米为单位,场景用自己的单位:**每千米世界单位**说明场景里多少个单位是一千米。为 0(默认值)时效果与之前完全一样。阴影只落在表面上;云仍然只画在有天空的地方。

### 分离色调与抬高的黑位

胶片感大半来自颜色在阴影和高光里的去向,颜色分级为此有三项控制。它们作用在显示器所见的画面上,所以要把分级放在**色调映射之后**;在它之前,0 到 1 只是场景光的一部分。

- **阴影染色**和**高光染色**分别乘在暗处和亮处,按亮度在**色调下限**和**色调上限**(默认 0.03 和 0.55)之间过渡。白色表示不变;它们是乘数,不做色彩管理,
  阴影里的 `(0.80, 1.01, 1.13)` 和高光里的 `(1.07, 1.0, 0.90)` 就是偏青和偏暖,数值可以大于 1。
- **S 曲线**混入围绕画面范围的平滑阶梯曲线:阴影略沉,高光略提。0 为关闭。
- **抬升**是带色相的黑位,按其颜色的十分之一加在所有色调上,`(0.06, 0.085, 0.11)` 会把黑位朝青色抬高约 `(0.006, 0.0085, 0.011)`,让没有纯黑的场景像空气而不是墨。

默认值是白、白、黑和 0,所以现有的分级不会变。

### 雨、潮湿的地面与水坑

`rain` 是由两部分组成的暴雨。**落下的雨**是三层在屏幕上向下滚动的细斜线,每层站在自己的距离上:比该层更近的表面会挡住
雨丝,更远的表面则被雨丝盖住,天空算作无限远。**潮湿的表面**是雨落到的一切,按 `wetness`
压暗,因为孔隙里的水吞掉了干燥表面会散射的光。朝向天空的地面压暗到满值,背向天空的表面稍弱一些(最低到满值的 0.6),
取自表面自己的法线(G-buffer 里有就用它,例如树叶),否则取自深度缓冲,所以暴雨中的山坡和植物会和旁边的平地一起变暗,
而不是浅浅地突出来。需要**平地**——朝上、平得能存水的表面——的是积水和落在上面的雨滴,它们留下**涟漪**(扩散并消退的圆环)和**水花**(落在非水面上的
小而快的冠状溅起),它们排布在世界里的网格上,所以相机移动时仍留在地面上。涟漪需要雨滴:`intensity` 为 0 时地面潮湿但静止。

**水坑**是积水:`puddles` 是多少平地被水覆盖,`puddleScale` 是水坑多大(世界长度)。水坑更暗,涟漪更密更清晰,没有水花。
水坑在哪里取决于世界位置和周围的地面:噪声决定水坑的位置,深度缓冲说明哪些地方低——比一个水坑范围内的周围地面更低的点积水更多,在隆起上的点积水更少,平地保持给定的覆盖率。所以水坑会聚在路缘旁、凹处和坡脚,而且不会随相机移动。水坑同时是一面**镜子**,这是反射效果的部分:给 `ssr` 同样的 `puddles` 与
`puddleScale`,雨压暗的水坑就是会反射的水坑——不管下面是什么地面都是平的,反射比干燥表面强得多,且清晰,而干燥表面的反射是模糊的。
潮湿的地面整体比干燥的更亮泽:下雨时提高 `ssr` 的 `intensity`。

**遮蔽。** 雨不会穿过屋顶。链路里有 `rain` 效果时,这一帧会把场景从正上方画一遍,只画深度,画在相机周围一个 1024² 的方块里
(每边 `shelterRange` 世界单位)——一张每处最高表面的地图——效果拿一个点去问它头顶有没有东西。遮阳篷下的地面保持干燥和静止
(没有潮湿、没有水坑、没有涟漪),站在屋顶下的那一层的雨线不会画出来,本来会落在那里的雨滴落在了遮阳篷上——它对着天空,于是轮到它变湿。
代价是范围内常驻网格的只写深度绘制,所以把 `shelterRange` 留在你需要的范围;地图之外的地面按露天处理。

时钟是游戏的。要在每次运行都相同的截图,把 `timeScale` 设为 0,`phase` 设为想要的时间。它不是什么:地面的形状是从相机看到的东西里读出来的(墙后面的凹处它不知道),
雨是屏幕空间的一层,不是会与世界碰撞的粒子。

### 次表面散射

皮肤、蜡、大理石和树叶会让受光的画面沿表面变柔,每种颜色柔的程度不同:红色传得远,蓝色几乎不传。`subsurface` 就是这个模糊,作为作用在完成画面上的 x 和 y 两个 pass。哪些表面参与由材质决定——`u_subsurface` 大于 0 的 Model 材质会标记自己的像素(以 alpha 0.996 绘制,屏幕上看不出来,效果会把它还原成 1)——传多远由效果决定:`width` 是最宽那个颜色的世界长度,`color` 是各通道之间的比例(最亮的传满整个宽度),`strength` 是混入多少模糊。被标记的像素只从同一表面上被标记的邻居那里采样,所以耳朵不会渗到身后的墙上。

它模糊的是原样的受光颜色,包括高光,所以散射表面上锐利的高光会被一并变软;宽度属于效果,视野里所有散射材质共用同一个宽度。和环境光遮蔽一样,它需要场景深度,低质量档位不包含它。

### 环境光遮蔽

两种估计器共用一套模糊和合成。`ssao` 数的是周围一圈点里有多少高于表面;它更便宜,需要 `bias` 来避免平坦的地面给自己上阴影。`gtao` 沿每个像素的几个切片平面在深度缓冲里步进,找出两侧地平线升到多高,再对剩下的开阔弧段按表面自身法线积分——所以没有要调的 bias,平坦的地面保持白色,夹角处的暗度就是它实际有多封闭。两者的 `radius` 都是世界长度。`thickness`(GTAO)让栏杆这类很薄的遮挡物可以被看穿。两者都读场景深度、以半分辨率运行,并且模糊时不会跨过深度边缘。质量档位用同一个环境光遮蔽开关管理两者,低档位不包含 GTAO。

### 接触阴影与弹射光

`contactShadows` 从每个像素朝太阳(场景自己的方向光,和雾一样)在深度缓冲里步进一条长 `length` 世界单位的短射线,射线刚好经过深度缓冲所示表面
后面的地方就把像素压暗 `intensity`(`thickness` 说一个东西多厚还算数)。它用来补阴影贴图太粗放不下的东西——灯的脚、衣褶、门下的缝——
盖在完成的画面上,所以它是接触处的一次修正,不是第二套阴影。

`ssgi` 是相机看得见的东西带来的**漫反射光**的一次弹射。它需要 [G-buffer](#g-buffer):每个表面绕存下的法线向半球发出八条射线,
每条在深度缓冲里走六步、最远 `radius`,落到的东西给出它的颜色(用场景的颜色,所以弹射光会在帧与帧之间自己喂自己)。收集在半尺寸的浮点目标上进行;
第二遍把同一个表面上的邻居平均起来,再把光乘以接收者自己的颜色加上去,所以红墙把旁边的白地面染红,灰墙弹出的是灰。它是屏幕空间的估计——
只看得到屏幕上有的东西,而移动的光会带着周围一起被照亮,这是烘焙光做不到的——一帧里它比看起来更吵:剩下的由 `taa` 平均掉。

### 自动曝光

`autoExposure` 就是眼睛:它测量画面有多亮,并稳定到把画面放在中灰的曝光上。测量的是亮度**对数**的平均,
因为亮度是按比例判断的,而原始平均会被画面里的某盏灯决定;暗于 2^-8 的像素不计入,因为黑色背景不等于暗场景。
结果从上一帧的位置随时间趋近目标——变亮比变暗快(`speedUp` / `speedDown`,按秒计,与帧率无关)——
`minEV` / `maxEV` 限定范围,`bias` 给结果加几档,用于想比中灰更暗或更亮的场景。`metering` 选择在画面哪里测量:0 整个画面,
1 偏向中间(半径为 `meterSize` 的柔和衰减),2 点测光——中间一个这么大的圆盘,其余都不算,这样明亮的窗户就不再决定窗前暗处人脸的曝光。
测量值和稳定下来的曝光只要设备能渲染到浮点目标就存在各自的浮点目标里,所以 8 位链路里表现相同(被曝光的画面仍然是被截断的)。
放在输出变换之前、`bloom` 之前,让辉光看到眼睛稳定后的曝光。

### 景深

`depthOfField` 模糊不在焦点上的东西,`focusRange` 深的一片保持清晰。它分三遍:第一遍定下镜头对焦在哪里,第二遍量出每个像素
有多模糊(和颜色存在一起,在浮点目标里),第三遍做模糊的收集。

**对焦**是 `focusDistance`(到相机的世界长度);开了 `autoFocus` 则是 `focusX`、`focusY`(屏幕宽度从左、高度从上的比例)那一点下的表面距离,
周围取九个点,不让某一个像素说了算。它以 `focusSpeed` 向那个距离靠拢,在距离的对数上走,所以拉焦是一次滑动;
那一点下只有天空时镜头留在原处。

**模糊**半径(像素)随表面离焦点的距离占其自身距离的比例增长,封顶 `maxBlur`;`aperture` 是无限远处东西的半径,天空算作这样。
每个像素在自己的圆里收集邻居,只在邻居自己的模糊够得着这里时才计入:清晰的前景物体不会渗进模糊的背景,而模糊的前景会铺到它后面的东西上。
六十四个采样沿螺旋按像素不同的小数偏移,留下一层细颗粒,由 `taa` 平均掉。

**散景**就是镜头的形状:`blades` 为 3 或更大时光圈是那么多边的多边形(0 为圆形),按 `bokehRotation` 转动,失焦的亮点就成了那个形状。
`highlight` 让亮的采样权重更大,所以失焦的灯是一个明亮的形状而不是暗淡的一团。

### G-buffer

有些效果必须知道表面**是什么**,而不只是它看起来怎样。着色器里写了 `#pragma gbuffer` 的效果会让这一帧在场景的颜色旁多画一个颜色附件,
同一个 pass、同样的着色器:**八面体法线在 `r`、`g`,粗糙度在 `b`,金属度在 `a`**(没写的地方 `a` 为 0,写了的地方是
`0.75 + 0.25 × 金属度`,所以被多重采样与未写入像素平均过的边缘(最多 0.5)能和真正的表面区分开),每通道 8 位。效果在 `u_gbuffer`(GLSL)或 `t6`(WGSL,用 `textureLoad` 读)处找到它。

它多花一个 RGBA8 目标和每像素一次额外写入,而且只在有已启用的效果要它时才有:没有这种效果的帧没有附件,也不编译变体。
目前写它的是内置的 **Model** 着色器——导入的 glTF 材质变成的就是它,粗糙度、金属度和法线贴图都按材质所说——以及引擎自带的普通受光网格,它如实记录自己是什么:粗糙的电介质。
精灵、混合表面、不受光网格和自定义着色器都留 0,效果必须把它当"未知"并保持像素不变,`ssr` 就是这样做的。你自己的着色器也可以写它:当 pass 有这个附件时,
编译会定义 `ES_GBUFFER`,然后声明第二个输出(`layout(location = 1) out vec4`,WGSL 里是返回结构体)并按同样的编码写入。

在 WebGL2 和 WebGPU 上,附件都与场景一起多重采样、一起解析。混合绘制从不写它——与背后那个平均过的法线谁也不是——场景自己的背景把它清成 0。

### 体素 GI

`voxelGI` 是基于**世界空间体素缓存**的漫反射全局光照。一个围绕相机的体素网格(128 × 64 × 128,每个 `voxelSize` 世界单位)记住相机见过的东西:
每一帧,被照亮的画面被写进它可见表面所在的体素——它们的平均辐射度和朝向——原有的内容按 `decay` 衰减。然后像路径追踪那样收集光,只是穿过网格:
从每个可见表面发出几条余弦加权的光线(`rays`),逐格前进,遇到一个朝向它的体素,那个体素的辐射度就是它带来的光。收集在画面尺寸的一部分上进行
(`divisor`),跨帧混合(`blend`),并用深度上采样,所以不会越过边缘渗色。

因为缓存属于世界而不是屏幕,一面已经离开画面的亮墙仍会给旁边的地面染色,只被另一个表面照亮的表面也能被照亮,移动的光会照亮周围——这三件事屏幕空间的弹射(`ssgi`)都做不到。

默认值是按以像素为单位的世界调的。在一个世界单位等于一米的 3D 场景里,请把这些长度按比例改小:拍一个角色时,`voxelGI` 的 `voxelSize` 取 0.03(缓存约四米见方)、`range` 取 48 格;`ssgi` 的 `radius` 取 0.4、`thickness` 取 0.15。两者都接受小到一厘米的值。

它**不是对场景几何体的追踪**,并且如实说明:

- 缓存里只有相机*见过*的表面,精度是体素大小——没见过的表面不发光,薄的东西和一格一样厚;
- 一次弹射,只有漫反射(没有光泽传输),注入用的画面带着上一帧的光,所以很亮的表面会稍微自己给自己供光;
- 在 WebGPU 上它是计算 pass。**WebGL2** 没有计算阶段,同样的缓存由三个片元 pass 写进一张半精度浮点图集(2048 × 1024,32 MB):图集的每个纹素向画面询问自己的体素里有什么,所以结果与 WebGPU 版一致,但收集固定在半尺寸(`divisor` 被忽略),掠射角看到的表面在缓存里更薄,开销也更高。WebGL2 上 `low` 画质档会跳过它;
- 它要一块网格内存(约 32 MB)、每帧若干 pass、每个相机一份缓存。

它不是虚幻的 Lumen:没有距离场或硬件光追,也没有场景网格的表面缓存——这正是 Lumen 能照亮从未出现在屏幕上的东西的原因。体素 GI 是这个思路中只需要画面的那一版。

### 计算特效(WebGPU)

一个特效可以是**计算着色器**而不是绘制:在整张画面上运行的 WGSL,适合需要读取很多相邻像素、或要保留自己结果的特效,不必每一步都开一个渲染 pass。
`sharpen` 就是一个:每个像素被推离邻居的均值,再被限制在邻居所张成的范围内,所以边缘变陡却不会出光晕。

计算特效需要有计算阶段的设备,也就是 **WebGPU**。在 WebGL2 里,带 `fallback`(同样算术的片元 pass,`sharpen` 就是这样,两者画出完全相同的画面)的特效会改跑它;没有的会被从链路中拿掉,画面原样通过,所以没有 fallback 的计算特效是用来精修一张已经完整的画面的:请按这个思路写。游戏需要知道时,可以问 `postprocess_supportsCompute`(或检查后端)。

像注册其他特效一样注册你自己的,用 `compute` 代替 `factory`:

```ts
import { registerEffect } from 'esengine';

registerEffect({
  type: 'myInvert',
  label: 'Invert',
  compute: { source: INVERT_WGSL, workgroupSize: [8, 8] },
  // 参数块:这些,按这个顺序,作为 f32。
  uniforms: [{ name: 'u_amount', label: 'Amount', min: 0, max: 1, step: 0.01, defaultValue: 1 }],
});
```

着色器在 group 0 里拿到下面这些,声明它用到的即可,入口函数叫 `main`:

| 绑定 | 内容 | 声明为 |
|---|---|---|
| 0 | 到目前为止的画面 | `texture_2d<f32>` |
| 1 | 它要写入的画面,同样大小 | `texture_storage_2d<rgba16float, write>` |
| 2 | 特效的 `uniforms`,按列出的顺序作为 f32 | 以它们开头的结构体的 `var<uniform>` |
| 3 | 尺寸,`vec4f(w, h, 1/w, 1/h)` | `var<uniform>` |
| 4 | 场景深度 | `texture_depth_2d` |
| 5 | 线性夹取采样器 | `sampler` |

它按 `workgroupSize` 为一组铺满整张画面,所以要自己检查像素是否在图像内。

### 雾与大气

`heightFog` 是随高度变薄的雾:山谷被填满,山顶是清朗的。它的密度按指数下降,所以射线穿过多少雾有
闭式解——不用步进——而同一个公式让**地平线朦胧、天顶清澈**:贴着地面的射线一直待在浓处,朝上的射线
立刻离开。天空像素没有可测量的表面,所以它们用一条很长的射线代入公式;`skyFog` 决定天空保留多少这样的
雾。朝向太阳看时雾带上 `sunColor`:用 `sunAzimuth`(从 +Z 向 +X 的角度)和 `sunElevation`(地平线以上的
角度)给出太阳方向。`followSun` 开着(默认)时效果忽略这两个角度,从场景里取太阳:第一盏有光的方向光,
它的方向和颜色,所以太阳转动,雾霾跟着转;两个角度只是场景没有方向光时的退路。

`volumetric` 让雾霾带上太阳的阴影。相机到每个表面之间的空气被分成 24 步,对着太阳的阴影贴图走一遍,
每一步站在光里的就把一部分光散射向眼睛——所以一栋楼的影子是暗的雾,两栋楼之间的缝是一道光束。它需要
一盏投射阴影的方向光(效果读的是网格接收阴影用的同一张图集),`volumeRange` 说空气从相机起走多远;
超出之后雾仍然让画面变暗,但不再有光束。

`cloudShade` 让这些光束跟着天空的云走:云的缺口就是一道光束,站在空气里,不管相机朝哪边看,不只是朝着太阳。
雾把太阳的光线向上穿过 `cloudShadow` 大于 0 的 `skyAtmosphere` 的云层(云此时固定在世界里,随风漂移),
用的是和天空画出来的同一份密度;云盖住的地方是暗的空气。光束的长度是 `volumeRange`(世界单位),穿过几公里
高的云需要同样高的空气:`heightFalloff` 取小,`volumeRange` 取几公里。天空的覆盖、高度、厚度和风每帧
复制到雾上,不是雾自己的设置。

云的形状可以由一张图决定。`skyAtmosphere` 带上**云遮罩**(`u_cloudMask`,一张可平铺的覆盖率纹理:线性数据、单通道、重复寻址,0 通透、1 浓密)和它的 `cloudMaskTile`(一次重复覆盖云层多少公里),云就画在遮罩说有的地方,噪声只负责侵蚀边缘;第二张更柔、更高的遮罩(`u_cloudMask2` 与 `cloudMask2Tile`)按三分之一并入。云投在场景上的影子、雾里被照亮的光束都是同一份云,雾从天空读取遮罩。遮罩是数据:不要 sRGB,不要压缩。它不含高度信息,所以云层的 `cloudThickness` 要薄(不到一公里):低角度看过去,太厚的云层会沿视线被涂抹成条纹。

`lightShafts` 在屏幕空间里找出太阳光穿过前方遮挡物的样子:每个像素朝太阳在屏幕上的位置步进,数这一路有
多少是开阔天空。太阳需要在屏幕上或刚好在屏幕外,而且只有深度缓冲里有的东西才能投出光束。两者配合出
低角度太阳的"雾加光束"的样子;`lightShafts` 仍是屏幕空间的,带阴影的体积光是 `heightFog` 的 `volumetric`。

雾的颜色按 **sRGB** 书写,线性项目里会被转换,和清屏色、灯光色一样,所以你选的颜色就是完全被雾吞没的表面
显示的颜色。

### 屏幕空间反射

`ssr` 把屏幕上已有的东西反射到朝上的表面里:湿街道、抛光地板、湖岸。反射射线在世界里步进、每一步投影回屏幕,落在深度缓冲所示表面
刚好后面的一步算命中。找到的颜色按 Schlick 菲涅尔项混到像素上:正对时很弱,掠射时很强,所以地面
越靠近地平线越亮。命中越远越模糊,这代替了粗糙度。

表面是什么来自 [G-buffer](#g-buffer):场景写了记录的地方,反射用表面自己的法线(法线贴图的细节,深度看不到)、粗糙度和金属度。
粗糙的表面反射暗而模糊,比 `maxRoughness` 更粗糙的表面在步进射线之前就被跳过,这是大头开销;金属几乎全部反射
所得的光,而电介质正对时只反射 4%。`wetness` 让地面变光滑(水膜填满了孔隙),所以越湿越反光,水坑是镜子。没有写记录的地方——精灵、混合或不受光表面、自定义着色器——不做猜测:像素保持原样。`floorBias`(默认 0)可以进一步收窄谁反射:为 1 时只有朝上的表面反射。
射线离开画面或射向天空的地方,表面仍然反射网格所反射的**环境**,清晰度由粗糙度决定;`skyReflection` 控制多少(0 关闭)。所以水坑映出天空和画面边缘之外的东西,而不只是屏幕上的道具。`maxDistance` 是世界长度;步数固定,所以距离越长
步进越粗,而用来藏起条带的逐像素起始偏移要靠 `taa` 平均掉——两者配合使用。

### 时间性抗锯齿

**把 `taa` 放在所有它该平均掉噪点的效果之后**——环境光遮蔽、接触阴影、全局光照、反射、雾。时间性 pass 只能处理排在它前面的东西;排在它后面的效果带来的噪点会原样到达屏幕。在 Bistro 示例里,把 `taa` 从第二位挪到雾之后,平坦墙面上的颗粒少了四分之一。如果 `taa` 后面还有这类效果,编辑器会给它一个警告标记。

`taa` 抹平 MSAA 够不到的东西——着色锯齿和细几何——办法是跨帧累积。效果在链路里时,引擎每帧把画面
偏移一个不同的亚像素量(八个位置循环),保留这个效果上一帧的输出,再把两者混合。像素上一帧在哪,
由深度缓冲得出:把像素反投影到世界,再用上一帧的相机投影回去,所以相机移动时历史还在。`blend`
是每帧里新画面的占比:越低越平滑、对变化跟得越慢,1 就是不累积。

把它放在链路**最前**,后面的效果看到的就是稳定后的画面,同时保留 `msaaSamples`——两者叠加。
每个相机有自己的历史。

相机的运动能说明所有静止物体的历史在哪。自己在动的物体是另一回事,所以效果在链路里时,这一帧会把
**移动的网格再画一遍**到它自己的目标里,写下每个像素自上一帧走了多远;在那里就是场景所显示的表面时,
效果改用这个位移。所以又细又快的移动物体会保住对比度,而不是淡进身后的地面。它只多画一遍真正动了的
东西(一帧里没有物体动就什么都不画),外加一个和场景同尺寸的 RGBA32F 目标,因此需要浮点渲染目标,
没有的设备会跳过。`objectMotion` 设为 0 就关掉它,只剩相机的答案。蒙皮网格按骨骼跟随:这一帧会记住每个
骨骼上一次画时的姿态。不跟随的有混合表面,以及材质顶点钩子加上的运动——它们退回相机的答案,并被夹进像素周围
的颜色里。TAA 和 SSAO 一样要读场景深度,因此在 WebGPU 上,没有深度解析的多重采样场景里无法运行。

上面是友好标签;**在代码里它们带 `u_` 前缀**(`u_intensity`、`u_exposure`……)。少数效果
在默认值下是恒等(`colorGrade`、`lensDistortion`、没绑定查找表的 `lutGrade`),加进去不调参不改画面。
多数一加就可见——`grayscale`(完全去色)、`vignette`、`bloom`、`blur`(强度 2)、
`chromaticAberration`(3)、`pixelate`(4)、`outline`、`tonemap`(ACES 曲线恒生效)——这些只在你需要时才启用。

## HDR(线性色彩空间)

当项目以**线性色彩空间**渲染时(见[光照](/docs/zh-cn/graphics/lighting/)),只要浮点渲染目标
可用——WebGPU 恒可用,WebGL2 上是几乎无处不在的 `EXT_color_buffer_float`——效果链就跑在
**半浮点 HDR** 上。超过 `1.0` 的光照累积(`intensity` 大于 1 的 `Light`)会*存活*进效果链,
而不是在 8 位存储处被压平:

- **`threshold` 大于 1 的 `bloom`** 只让超范围能量泛光——亮光发辉光,普通 LDR 美术保持锐利。
  这就是经典的"自发光辉光"配方:拉高灯的 `intensity`,把 `threshold` 设在约 1.2–1.5。
  辉光建在从 1/2 到 1/64 尺寸的图像金字塔上(和 Unreal、使命召唤的做法一样):衰减圆润柔和,
  带一条很淡的长尾,`radius` 让整体变宽。亮天空要压在 `threshold` 以下,否则每条贴着天空的暗边都会被天空的辉光冲淡。
- **`tonemap`** 收到真正的 HDR 输入,ACES 曲线得以收卷高光,而不是对已压平的值做整形。**Fitted ACES**(`u_curve` 为 1)把引擎的曲线换成另一条
  常用的 ACES 拟合,也就是 three.js 所说的 ACES Filmic:它在过曲线之前先混合通道,所以亮的颜色会走向白色(引擎的曲线保持色相),暗部也压得更深。
  按那条曲线做出来的画面要用它;three.js 还会先把曝光乘以 1/0.6,在这里就是 `u_exposure` 0.74。
- 不加 tonemap 时,超范围值在最终的线性→sRGB 编码处直接截断——轻微辉光没问题,大面积过曝会显得生硬。

伽马模式(或无浮点目标能力)下效果链仍是 LDR,行为与从前一致;此时 `threshold` 超过约 0.75
就永远不会触发。

## 输出变换

在线性空间里打光的场景,亮度可以超出显示器能显示的范围。**输出变换**是成品帧在送往屏幕前经过的唯一一条曲线——
**在所有效果之后、只作用一次**——它是项目设置,不是效果:**设置 → 项目 → 渲染 → 输出变换**。

| 变换 | 作用 | 适用 |
| --- | --- | --- |
| **无** | 只做编码。大于 1 的值被截断。 | 平面 2D 美术、UI,以及必须原样往返的内容。 |
| **ACES** | 电影式高光肩部:高光收卷、暗部加深。它会一路去饱和,所以很亮的红色会偏向奶白。 | 想要电影质感的 3D 光照场景。 |
| **中性** | Khronos PBR Neutral:同样收卷高光,但色相和饱和度保留。阳光下的红色仍是红色。 | 产品展示、风格化美术,以及颜色本身就是重点的内容。 |

它对编辑器视口、运行预览和所有导出都生效,改动无需重新加载。代码里是 `outputTransform: 'none' | 'aces' | 'neutral'`。

对着成品画面做的调色(调色师给的暖色 LUT、胶片模拟)应该排在曲线之后,而效果链里的任何效果都做不到:它们都跑在
场景值上,在曲线之前。**显示 LUT**(`displayLut`)是最后一个通道自己的阶段:画面先过曲线,再为显示器编码,然后按它将要
显示的颜色从一张 1024x32 的表里取值:沿 x 排 32 片,蓝是片号,红沿片内 x 增大,绿沿图像向上增大(图像从最下面一行读起)。它是在本来就要跑的那个通道里多读一次纹理,不是多一个通道,
和输出变换是哪个无关。表的纹理是数据:不压缩、不要 mip、不要 sRGB。符合这个形状的图(N 片 N×N,32 片就是 1024×32)被加入项目时会自动按这些设置建立,编辑器里和命令行里都一样。代码里是 `stack.setDisplayLut(textureHandle, amount)`。

<Aside>
上面列表里的 `tonemap` *效果*是效果链里一个单独的、可选的 ACES 通道。设了输出变换之后,通常既不需要它,也不需要第二条曲线:
选输出变换,把这个效果关掉。
</Aside>

## 使用 `PostProcessVolume`

在编辑器里,体积的效果按执行顺序列出,每个都有开关和参数(包括颜色参数)、一个用来收起参数的折叠,以及说明它用途的标签(镜头、色彩、光照、大气、抗锯齿、风格化);需要计算着色器的效果会标出**仅 WebGPU**。添加菜单按同样的方式分组。

加一个 `PostProcessVolume`,启用效果,设置参数。体积**在重叠处混合**,所以你可以按区域驱动
效果(比如一个"水下"体积),或在过渡中淡入。

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `effects` | list | `[]` | 每个效果的 `{ type, enabled, uniforms, textures?, colors? }`——`textures` 放纹理引用(查找表、遮罩),`colors` 放颜色参数。 |
| `isGlobal` | boolean | `true` | 全局应用 vs 仅在体积形状内。 |
| `shape` | `'box' \| 'sphere'` | `'box'` | 局部体积的边界形状。 |
| `size` | Vec2 | `{5, 5}` | 局部体积的半尺寸(球体用 `x` 当半径)。可选的 `z` 是盒体的半深度;`0` 或省略表示深度上不设限。 |
| `priority` | number | `0` | 重叠处优先级高者胜。 |
| `weight` | number | `1` | 混合权重,0..1(淡化整个体积)。 |
| `blendDistance` | number | `0` | 体积边缘的衰减距离。 |

## 程序化控制

固定的相机管线用 `PostProcess` 资源。栈初始为空——每个效果加一个 **pass**。用
`getEffectDef(type).factory()` 从注册表拿到效果的着色器,再设它带 `u_` 前缀的 uniform,
把栈绑到相机:

```typescript
import { defineSystem, Query, Res, Camera, PostProcess, getEffectDef } from 'esengine';

const setup = defineSystem([Query(Camera), Res(PostProcess)], (q, pp) => {
  const grade = getEffectDef('colorGrade')!;
  for (const [camera] of q) {
    const stack = pp.createStack();
    stack.addPass('colorGrade', grade.factory())
         .setUniform('colorGrade', 'u_saturation', 1.3)
         .setUniform('colorGrade', 'u_contrast', 1.1);
    pp.bind(camera, stack);   // pp.unbind(camera) to remove
  }
});
```

**多 pass** 的效果(如 `bloom`)带 `def.multiPass`;逐个 sub-pass 加进去
(`for (const p of grade.multiPass!) stack.addPass(p.name, p.factory())`)。固定管线之外,
`PostProcessVolume` 更省事——它会替你解析多 pass 与纹理参数。

sub-pass 不只能读上一个 pass,还能读同一效果里更早的 pass:声明一个名为 `u_pass_<名字>` 的纹理参数
(`#pragma param u_pass_bloom_down_2 texture default(black)`),链就会绑定名为 `<名字>` 的 pass 的输出,
并让它一直保留到这个 pass 跑完。bloom 的上采样就是这样把同尺寸的下采样加回来的;`scale` 小于 1 的 sub-pass
以链尺寸的这个比例绘制。

### 自己写的天空

`defineSkyEffect` 把你写的一个函数——天空在某个方向上的辐亮度——变成一个效果,PostProcessVolume 像放别的效果一样放它。
它画在场景后面;打开 **Light the Scene** 后,引擎大约每秒读回一张它的小全景图,作为场景的环境(漫反射光和反射),
和 Sky Atmosphere 的做法一样:风格化的天空用它看起来的光照亮世界。

```typescript
import { defineSkyEffect } from 'esengine';

defineSkyEffect({
    type: 'duskSky',
    label: 'Dusk Sky',
    colors: [{ name: 'u_horizon', label: 'Horizon', defaultValue: { r: 0.95, g: 0.55, b: 0.28, a: 1 } }],
    glsl: `vec3 skyRadiance(vec3 dir, vec3 sun, vec3 sunColor, float env) {
        return mix(u_horizon.rgb, vec3(0.05, 0.09, 0.14), smoothstep(0.0, 0.4, dir.y));
    }`,
    wgsl: `fn skyRadiance(dir : vec3f, sun : vec3f, sunColor : vec3f, env : f32) -> vec3f {
        return mix(mc.u_horizon.rgb, vec3f(0.05, 0.09, 0.14), smoothstep(0.0, 0.4, dir.y));
    }`,
});
```

`sun` 是第一盏方向光的方向,`sunColor` 是它的颜色乘强度;画全景图时 `env` 为 1(这时别画太阳圆盘:
方向光就是太阳的直射光)。返回线性辐亮度。参数是 uniform(WGSL 里写 `mc.`),时间是 `u_time.x`,
`textures` 用来带上天空需要的贴图(噪声用 `wrap: 'repeat'`)。

有云的天空可以给云下的地面投影。设 `groundShadow: true`,并在第一个函数旁边再写一个
`float skyShadow(vec3 world, vec3 sun)`(WGSL 为 `fn skyShadow(world : vec3f, sun : vec3f) -> f32`):某个世界位置上
还剩多少光,1 为全部。画面里的每个表面都乘上它,和 Sky Atmosphere 的 **Cloud Shadows** 对自己的云做的一样,
所以它压暗的是表面的全部光照,不只是太阳的;下限要明显高于 0。

| 方法 | 说明 |
|---|---|
| `PostProcess.createStack()` | 创建一个空效果栈。 |
| `stack.addPass(name, shader)` | 加一个效果 pass;`shader` 来自 `getEffectDef(type).factory()`(可链式)。 |
| `stack.setUniform(pass, uniform, value)` | 设一个带 `u_` 前缀的参数(可链式)。 |
| `stack.setTexture(pass, uniform, handle)` | 绑定一个纹理参数,比如 LUT(可链式)。 |
| `stack.setEnabled(name, on)` | 开关一个已加入的 pass(可链式)。 |
| `PostProcess.bind(camera, stack)` / `unbind(camera)` | 附加 / 移除相机的栈。 |
| `getEffectDef(type)` / `getAllEffectDefs()` / `getEffectTypes()` | 查效果定义(着色器工厂 + uniform)。 |

### 纹理参数(LUT 与遮罩)

有些效果吃的是纹理而不只是标量。`lutGrade` 采样一张**颜色查找表**——一张 2D 打包的
`1024×32` PNG(32³ 色立方切成 32 片)——于是你可以在图像编辑器里做好整套调色再丢进来。
先加 pass,再用 `setTexture` 绑定纹理(或在 `PostProcessVolume` 上,把它列在该效果的
`textures: { u_lut: <ref> }` 下):

```typescript
stack.addPass('lutGrade', getEffectDef('lutGrade')!.factory())
     .setTexture('lutGrade', 'u_lut', lutHandle)
     .setUniform('lutGrade', 'u_intensity', 1);
```

## 在包里

效果的定义(名字和参数)每个包都带;它的着色器才是大头,所以分成四组,包里只带内容用到的那几组:

| 组 | 子路径 | 效果 |
|---|---|---|
| 基础 | `esengine/fx-basic` | blur、bloom、vignette、grayscale、colorGrade、lutGrade、chromaticAberration、tonemap、fxaa、sharpen、lensDistortion、pixelate、palette、outline、depthOutline、edgeOutline、filmGrain、motionBlur、lensFlare |
| 大气 | `esengine/fx-atmosphere` | mist2d、rain2d、fog2d、skyAtmosphere、heightFog、distanceFog、rain |
| 光照 | `esengine/fx-lighting` | ssao、gtao、ssr、ssgi、voxelGI、contactShadows、lightShafts、autoExposure、depthOfField、subsurface、taa |
| AgX | `esengine/fx-agx` | agx(带 Blender 的 AgX 表,约 80 KB,所以只用泛光、暗角而不用 AgX 的包不必为它们付出体积) |

导出会读 `PostProcessVolume` 里写了哪些效果(以及驱动大气组的 `Weather`、`TimeOfDay` 组件),并导入它们需要的组。**从脚本里**加的效果——
`getEffectDef('bloom')!.factory()`——在内容里没有痕迹,所以要自己导入对应的组(`import 'esengine/fx-basic'`),或在项目设置里把该模块设为**包含**;否则这个效果第一次
被用到时会告诉你它需要哪一组。编辑器和任何非精简入口四组都带。

## 最佳实践

- **顺序有讲究**——pass 按你加入的顺序运行(或在体积上按其 `effects[]` 的顺序)并共享缓冲,
  合理的链是 bloom → tonemap → 调色 → vignette。
- **用体积做局部**(某区域的氛围),用 `PostProcess` API 做固定的相机管线。
- 过渡时**用 `weight` 淡化**体积,而不是硬开关。
- 低端/移动端**让栈保持简短**——每一遍都是一次全屏绘制。

<Aside type="note">
  效果是纯 GLSL、由注册表数据驱动的,所以编辑器和运行时共用一份列表——没有会漂移的硬编码效果集。
</Aside>
