一块一百单位外的石头和一块两千单位外的石头,现在用同样多的三角形绘制;而在两千单位外,
它们几乎全部落进同一个像素里。**`LODGroup`** 让一个物体在小到没人分辨得出来时,交给
更便宜的网格去画 —— 这是道具密集的场景里最大的一笔节省。

在 Estella 自带的第三人称示例里,一片 35 块石头的场地就用上了它;在一万个道具的规模上,
三角形从 191 万降到 4.2 万,GPU 时间从 3.5 ms 降到 0.27 ms([数字在下面](#这笔交易换来了什么))。

## LODGroup 组件

`LODGroup` 挂在**和 `MeshRenderer` 同一个实体**上。渲染器说这个物体**是什么** ——
那个网格就是 level 0,即最精细的一级;组件说的是它变小之后谁可以顶替它:

```typescript
world.insert(rock, MeshRenderer, { mesh: 'assets/models/rock-lod0.esmesh', lit: true });
world.insert(rock, LODGroup, {
    lod1: 'assets/models/rock-lod1.esmesh',
    lod2: 'assets/models/rock-lod2.esmesh',
    lod1Size: 0.25,   // 小于屏幕高度的四分之一 → 换 lod1
    lod2Size: 0.11,   // 小于八分之一 → 换 lod2
    cullSize: 0.02,   // 小于五十分之一 → 干脆不画
    hysteresis: 0.1,
});
```

把这个组件去掉,最精细的网格就回来了 —— 渲染器的其他部分一点没变。

## 烘焙静态区域的代理几何

Node 创作工具可以调用 `@estella/pipeline` 的 `bakeStaticProxy`。输入是已经分好区域的静态表面,
包含解码后的网格、世界矩阵、绘制状态,以及明确的运动和混合分类。它复用静态合批的几何合并与绘制分组规则。

```typescript
import { bakeStaticProxy } from '@estella/pipeline';

const proxy = await bakeStaticProxy(sources, {
    origin: [1000, 0, 2000],
    ratio: 0.25,
    maxWorldError: 0.05,
});
```

结果包含区域局部坐标下的网格、原绘制状态、来源 id、简化前后的三角形和字节数、实际误差及输入指纹。
将代理放在 `proxy.origin`。材质、纹理、颜色、层、照明和投影设置不同的表面会保留为不同绘制组。
调用方负责写入网格资源,并将采集的绘制标识转换为资源引用;这个接口不会直接修改场景。

`maxWorldError` 使用世界单位,不会因为区域里增加了一栋远处的建筑而放宽精度。`ratio` 是目标,
误差限制可能让结果保留更多三角形。顶点颜色和两套 UV 都参与误差计算。
发光或其他敏感表面应设置 `preserveGeometry: true`:兼容组里只要有受保护的表面,整组就保留几何,仍可合并绘制。
`pruneDisconnected: true` 允许删除小的独立构件,默认关闭,启用后需要对照画面验收。

会运动、变形、朝向相机、透明混合、带光照贴图、骨骼或形态目标的表面会列入 `refused`,由原有逻辑继续管理。
这目前是 HLOD 的几何制作环节;纹理和发光烘焙、自动生成格子代理、距离选择以及精细场景与代理之间的流送交接尚未接通。

## 这些尺寸是屏幕占比,不是距离

`lod1Size` 和它的兄弟们,是物体包围体覆盖**视口高度**的比例。`1.0` 表示物体正好一屏高,
`0.02` 表示五十分之一屏高。

它刻意不是距离,因为距离在不同尺度、不同镜头下给的是同一个答案:

- 一百米外的高塔和一颗石子,在屏幕上不是一个大小;
- 同一个位置,30° 视场看到的物体是 60° 的两倍大;
- 正交相机的答案根本不随距离改变。

屏幕占比同时覆盖这三件事,而且与分辨率无关 —— 同一个数字在手机上和桌面上都对。

<Aside type="tip">
挑阈值的方法:把相机放在关卡里真正发生动作的位置,看着那个物体。你要的数字大致就是
「它占窗口高度的几分之几」;低于 5% 左右的,就是最粗一级网格的候选。
</Aside>

## 迟滞 —— 为什么级别不会闪

一条只用一个数字划的边界,会因为相机的轻微呼吸而来回翻转;而每帧都在换网格,远比换本身
更显眼。`hysteresis` 让每条边界变得不对称:物体在阈值处**往下**交给更粗的网格,但要长回
到超出阈值那么一个比例之后,才会换回精细的一级。

默认 `0.1` 时,`lod1Size = 0.20` 的含义是:

- 缩小穿过 **0.20** → level 1 接手;
- 重新长过 **0.22** → level 0 才回来。

把它设成 `0` 就是一条裸阈值,会闪。它同样作用于 `cullSize`,所以在可见边缘的物体不会眨眼。

## 这个选择是什么、不是什么

**它属于相机,不属于实体。** 同一帧里的两个相机 —— 主视角和小地图,或者分屏 ——
看到的是同一个物体的两个尺寸,可以画成两个不同的级别。实体上没有 `currentLOD`
可读、也没有可写。

**它是在整组的包围体上量的。** 用来做判断的包围体是所有级别的并集,所以它不随当前
画的是哪一级而改变。若按当前网格取包围体,就会反过来影响挑出它的那个判断,进而振荡。

**剔除先跑。** 视锥已经拒绝掉的物体根本不会被测量,所以这份开销只花在可能被看见的东西上。

**实例化不受影响。** 选级只改变一次 draw 引用哪份几何,别的都不变,所以同一级的道具照旧
合并成一次 instanced draw。三个级别的一片场地到达 GPU 时大约是三次 draw,而不是每个道具一次。

## 编辑规则

- **槽位按顺序填** —— 先 `lod1`,再 `lod2`,再 `lod3`。留空的槽位就是梯子的终点,它后面的
  一律到不了(引擎会告警)。
- **尺寸必须递减。** `lod2Size` 小于 `lod1Size`,依此类推。
- **默认值。** `lod1Size` 0.5、`lod2Size` 0.25、`lod3Size` 0.1、`cullSize` 0.02、`hysteresis` 0.1(取值 0 到 1);组件的 `enabled` 关闭时始终画渲染器自己的网格。
- **`cullSize: 0`** 完全关掉剔除,于是这一组永远不会消失。
- **各级可以在导入时生成。** 在模型的导入设置里把 **Generate LODs** 设为 1–3 级(或给 `import-model` 传 `--lods <n>`):每个网格会被塌缩成约 50%、20%、7% 三角形的副本,写成 `<mesh>_lod<n>.esmesh`,并在实体上加一个 `LODGroup`。蒙皮和变形网格,以及三角形少于 **LOD Minimum Triangles**(256)的网格,只保留一级。
- **蒙皮的一组必须共用一副骨架。** 蒙皮网格的每一级都要有相同的关节数;对不上的那一级会
  画成绑定姿势,引擎会说出来。

## 这笔交易换来了什么

在一片纵深排布的道具场地上实测,512×512,WebGL2:

| 道具数 | 三角形 | GPU |
|---|---|---|
| 1 000,始终最高精度 | 195 776 | 0.505 ms |
| 1 000,带 `LODGroup` | 4 248 | 0.116 ms |
| 10 000,始终最高精度 | 1 912 960 | 3.595 ms |
| 10 000,带 `LODGroup` | 42 392 | 0.27 ms |

每一万个道具的选级大约花掉 0.2–0.3 ms 的 CPU,这就是那笔交易:花 CPU 去挑,省 GPU 去画。
数量越大,汇率越划算 —— 这正是重点,它决定了一万个道具的场地到底能不能发出去。

## Impostor:用一张图代替远处的网格

MeshRenderer 旁边的 `Impostor` 会在物体占视图高度小于 `screenSize` 时,用一张卡片代替网格。卡片上是从视图所在方向拍下的网格图像,所以远远看过去还是那个物体,只要两个三角形。

```typescript
world.insert(tree, Impostor, { screenSize: 0.06, frames: 8, resolution: 1024 });
```

- **拍图**在游戏运行时进行,每种只拍一次:`frames` x `frames` 台引擎自己的正交相机,从上半球的各个方向看一个网格副本,各自画进同一张图集(边长 `resolution` 像素)里属于自己的格子。它们就是普通相机,所以图里有网格的材质、贴图和场景的光照,所有后端都一样。网格、材质、贴图和颜色都相同的实体共用一张图集;不同种类依次拍,每种一两帧。
- **卡片**由渲染器在每个视图里画:取离这个视图方向最近的那张图,画在一个朝向它的正方形上。所有卡片都走精灵批处理,图集能放进一次 draw 的贴图槽时,这些卡片就是一次 draw。在 `impostor` 编辑器检查里,五种物体各一个,画成卡片是 1 次 draw,画成网格(按形状实例化)是 2 次。
- **它做不到的。** 图保留拍摄时的光照,而且是在物体自己的坐标系里:在世界里转过的物体,光照就像太阳也跟着转了,所以 Impostor 适合光线柔和或者没有旋转的物体。视角绕着转时图像是一级一级变的(`frames` 越多,每级越小);卡片不投影,不能从下方看;拍图在 Play 和打包后的游戏里进行,编辑器自己的视口里不拍。

## 它不做什么

`LODGroup` 讲的是**同一个物体在不同尺寸下**的事。它不是流式加载:每一级的网格都常驻,
不会加载也不会卸载;小到 `cullSize` 以下的物体只是不画,并没有从世界里移走。
把远处的物体合并成一个代理(HLOD),以及把世界分块加载,都是另外的题目;引擎里没有把任意场景物体烘成代理的通用 HLOD。
现有的是针对具体内容的:植物的远景版本(`Foliage`、`PlacedFoliage`,见[植被](/docs/zh-cn/graphics/foliage/))、
地形自己按距离切分的四叉树([地形](/docs/zh-cn/graphics/terrain/)),以及[静态合批](/docs/zh-cn/performance/static-batching/)
(把不同网格合并以省绘制调用,但不会让它们在远处变便宜)。
