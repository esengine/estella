## 性能剖析器面板

编辑器的 **Profiler** 面板显示实时帧时间曲线，并按阶段与系统细分；单击某一帧可查看该帧。**Render** 模块按通道拆分本帧的 GPU draw，并与当前画质档位的 draw call 预算比较（[按通道统计 draw](#按通道统计-draw)）。视口还有一个显示 FPS 的性能浮层。

![运行中的 third-person-3d 示例与停靠的性能分析器：模块列表，以及带百分位统计的 CPU / GPU 帧时间图](@/assets/guides/zh/perf-profiler-panel.png)
- 单击开销树或系统列表的列标题按名称或时间排序；再次单击反转顺序。该选择会被记住。
- 按时间排序时，两个系统交换位置就会重排行，在实时窗口中每隔几帧就会发生；要跟踪某个系统，请按名称排序。
- 系统列表显示十二个系统。
- 开销树按**领域**归组系统：取注册它们的插件的 `profileDomain`，否则取插件的 `name`。项目脚本中的系统归入 `scripts`，
  不属于任何插件注册的系统归入 `unattributed`。单个系统可以用注册选项 `profileDomain` 指定自己的领域
  （[系统](/docs/zh-cn/core-concepts/systems/#排序边)）。
- **Profiler ▸ Open…** 打开录制的 `.esprof` 采集（[设备端采集](/docs/zh-cn/performance/profiling/recording/)）。

在游戏构建中，`statsPlugin` 提供相应的数据。

## `statsPlugin`

`statsPlugin` 每帧在 `Last` 调度中把数据收集到 `Stats` 资源：

```typescript
import { statsPlugin } from 'esengine';

app.addPlugin(statsPlugin);
```

`statsPlugin` 是使用默认选项的实例。需要其他选项时构造 `StatsPlugin`：

```typescript
import { StatsPlugin } from 'esengine';

app.addPlugin(new StatsPlugin({ overlay: true, position: 'top-right' }));
```

| `StatsPluginOptions` | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `overlay` | boolean | `true` | 显示 DOM 浮层；没有 `document` 的环境中跳过。 |
| `position` | `StatsPosition` | `'bottom-left'` | 浮层所在角：`'top-left'`、`'top-right'`、`'bottom-left'`、`'bottom-right'`。 |
| `container` | HTMLElement | `document.body` | 浮层挂载的元素。 |

该插件还会调用 `app.enableStats()`，开启按系统与按阶段的计时。否则计时处于关闭状态，未安装插件的游戏无需为此付出开销。

### 读取 `Stats`

```typescript
import { defineSystem, addSystem, Res, Stats } from 'esengine';

const watchPerf = defineSystem([Res(Stats)], (stats) => {
  if (stats.fps > 0 && stats.fps < 30) {
    console.warn(`slow frame: ${stats.frameTimeMs.toFixed(1)}ms, ${stats.drawCalls} draw calls`);
  }
});
addSystem(watchPerf);
```

`fps` 与 `frameTimeMs` 是 60 帧滑动窗口的平均值；渲染计数为当前帧的值。

| `FrameStats` 字段 | 类型 | 说明 |
|---|---|---|
| `fps` | number | 最近 60 帧的每秒帧数。 |
| `frameTimeMs` | number | 同一窗口的平均帧时间（毫秒）。 |
| `entityCount` | number | 存活实体数。 |
| `systemTimings` | `Map<string, number>` | 本帧每个系统的 CPU 毫秒数，以系统名为键。 |
| `phaseTimings` | `Map<string, number>` | 本帧每个调度阶段的 CPU 毫秒数。 |
| `drawCalls` | number | 合批后场景列表与浮层列表的 draw 数，即帧捕获所列的数量。 |
| `gpuDraws` | number | 本帧向 GPU 发出的所有 draw，包括所有通道：阴影贴图、深度预通道、反射、运动向量与后处理，以及场景本身。 |
| `drawCallBudget` | number | 当前画质档位的 draw call 预算；没有画质档位时为 `0`。 |
| `triangles` | number | 提交的三角形数。 |
| `sprites` | number | 渲染的精灵数。 |
| `text` | number | 渲染的文本实体数。 |
| `skeletal` | number | 骨骼动画运行时摆姿的三角形数（Spine 与 DragonBones）。 |
| `meshes` | number | 渲染的网格数。 |
| `culled` | number | 被剔除（未提交）的实体数。 |

## 统计浮层

`overlay: true` 时，插件渲染一个固定位置的面板，显示 FPS 与帧时间；draw call、三角形、精灵与剔除数；实体数；以及按最差帧排名的**前 5 个系统**，各以 `avg / max ms` 显示。面板最多每 500 ms 刷新一次，期间累计系统计时，因此单帧尖峰会出现在 `max` 列。**GPU** 项显示 `gpuDraws` 与画质档位 draw call 预算的对比，超出预算时变为红色。

也可以直接驱动 `StatsOverlay`，例如绑定到调试按键：

```typescript
import { StatsOverlay, defineSystem, addSystem, Res, Stats } from 'esengine';

const overlay = new StatsOverlay(document.body, 'top-right');

const feedOverlay = defineSystem([Res(Stats)], (stats) => {
  overlay.update(stats);
});
addSystem(feedOverlay);

// overlay.hide() / overlay.show() 切换显示；overlay.dispose() 移除。
```

<Aside type="note">
  浮层基于 DOM：在 Web 与桌面构建中可用，`statsPlugin` 在没有 DOM 的环境中会跳过它。`Stats` 资源在所有环境中都可用。
</Aside>

## 渲染器计数

`Renderer.getStats()` 无需统计插件，以 `RenderStats`（`drawCalls`、`gpuDraws`、`triangles`、`sprites`、`text`、`skeletal`、`meshes`、`culled`）返回 `FrameStats` 中的渲染计数：

```typescript
import { Renderer } from 'esengine';

const rs = Renderer.getStats();
console.log(`${rs.drawCalls} draw calls, ${rs.triangles} triangles`);
```

### 按通道统计 draw

`drawCalls` 统计绘制列表；`gpuDraws` 统计所有 GPU draw，包括列表看不到的通道。draw call 预算针对 `gpuDraws`。

`drawBudgetReport` 根据帧统计报告中的引擎计数器按通道拆分 `gpuDraws`：

| 通道 | 计数器 |
|---|---|
| `lists` | `batch.draws` |
| `shadow` | `render.shadow.draws` |
| `prepass` | `render.prepass.draws` |
| `reflection` | `render.planar.draws` |
| `motion` | `render.motion.draws` |
| `cover` | `render.cover.draws` |
| `other` | 其余部分，因此各份额之和总等于 `gpuDraws`。 |

各通道计数器仅在帧剖析器开启时发布；否则列表之外的所有 draw 都计为 `other`。

```typescript
import { drawBudgetReport } from 'esengine';

const r = drawBudgetReport(gpuDraws, budget, counters);
for (const p of r.passes) console.log(`${p.pass}: ${p.draws}`);
if (r.over > 0) console.warn(`${r.over} draws over the budget of ${r.budget}`);
```

预算是每个[画质档位](/docs/zh-cn/performance/quality-levels/settings/#视距与绘制)的设置。

## 帧历史工具

插件背后的两个工具导出供自定义工具使用：

- **`StatsCollector`**：`fps` 与 `frameTimeMs` 背后的 60 帧滑动窗口。`pushFrame(deltaSeconds)` 加入一帧；`getFps()` 与 `getFrameTimeMs()` 读取平均值；`reset()` 清空窗口。
- **`FrameHistory`**：`FrameSnapshot` 的环形缓冲（默认容量 300 帧），用于帧时间曲线。`push(frameTimeMs, phaseTimings, systemTimings?)` 会复制映射，使快照保持有效；`getLatest()` 返回最新快照，`getAll()` 按从旧到新返回整个窗口；`count` 与 `reset()` 用于查询与清空。

| `FrameSnapshot` 字段 | 说明 |
|---|---|
| `frameTimeMs` | 该帧的总 CPU 时间。 |
| `phaseTimings` | 各阶段毫秒数，push 时复制。 |
| `systemTimings` | 各系统毫秒数，push 时复制。 |

## 资源统计

`getResourceStats()` 报告 GPU 资源驻留情况：纹理字节数与纹理预算、可淘汰纹理、存活的着色器、纹理与缓冲、缓存命中与未命中，以及为上下文丢失保留的 CPU 副本。字段、`setTextureBudget`、`trimTextureCache` 与温缓存模型见[生命周期与内存](/docs/zh-cn/assets/memory/#纹理预算与统计)。

## 子系统健康

每个 `App` 在 `app.subsystems` 上有一个 `SubsystemRegistry`，跟踪每个引擎子系统的生命周期阶段（`registered` → `initializing` → `ready`，`error` 为终止状态）以及派生的活动状态（`stepping`、`idle`、`inactive`）：

```typescript
for (const s of app.subsystems.getStatuses()) {
  console.log(`${s.displayName}: ${s.phase} (${s.activity})`, s.lastError ?? '');
}
```

`recentEvents()` 返回最近的生命周期转换，`subscribe(fn)` 在阶段变化时通知。见 [App 与生命周期](/docs/zh-cn/core-concepts/app/overview/)。

## 使用建议

- 发布时不包含 `statsPlugin`，或放在调试开关之后；计时收集默认关闭。
- 优化之前先读取 `systemTimings` 与 `phaseTimings` 找出慢的系统；浮层的 `max` 列显示被平均值掩盖的单帧尖峰。
- 与 draw call 预算比较的应是 `gpuDraws`，而不只是 `drawCalls`。
