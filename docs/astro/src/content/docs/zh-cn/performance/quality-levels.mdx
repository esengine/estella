同一个项目要能在旗舰手机和六年前的手机上都跑起来。**画质档位**就是做这件事的办法：**低、中、高**三份配置，每份说明渲染器在
该档位下花多少。项目选一个（或交给设备选），而对档位来说太慢的游戏会自己把分辨率降下来。

## 选择档位

**设置 → 项目 → 渲染 → 设备画质 → 画质档位：**

| 模式 | 含义 |
|---|---|
| 关闭 | 不做画质管理，项目按原样渲染（默认）。 |
| 低 / 中 / 高 | 所有设备都用该档位。 |
| 自动 | 档位由设备决定：第一条匹配的[设备规则](#设备规则)，否则看内存和核心数。 |

**动态分辨率**在 GPU 吃紧时降低场景分辨率，最低降到该档位的*最小渲染比例*，有余量时再升回来；UI 保持显示分辨率。低于屏幕大小绘制的场景会用一个被周围纹素夹取的 Catmull-Rom 重采样器拉伸回来,边缘比双线性拷贝更陡,又不会画出光晕;整数倍的拉伸则是精确拷贝。
**目标帧率**是它要维持的帧时间。

## 一个档位里有什么

**画质档位设置 → 正在编辑的档位**决定下面各行显示并修改哪个档位。它们按花在哪里分组：

| 分组 | 设置 |
|---|---|
| 渲染 | 渲染比例、最小渲染比例、抗锯齿方式(MSAA 或时间性)、MSAA、深度预通道、细节距离、Draw call 预算、贴图流式加载及其预算、2D 雨遮罩尺寸 |
| 阴影 | 图集尺寸、单元尺寸、级联数、距离、2D 软阴影采样数 |
| 反射与粒子 | 平面反射的比例、最大尺寸和每秒更新次数，粒子上限 |
| 水体 | 水体波数(1 到 4)、水体涟漪格数，以及位移、镜面、焦散三个开关。档位不是关闭、且构建里带水体模块时才显示 |
| 后处理 | 总开关，以及在这个档位运行的每个效果的勾选框 |

每个档位从引擎自己的值起步，**只有你改过的才会保存**到 `project.esproject` 的
`features.rendering.quality.profiles.<档位>` 下。引擎以后改进的默认值会传给从没碰过它的项目；改回该档位默认值的行也不再算差异。

**抗锯齿方式**可选 MSAA 或时间性(TAA)。时间性按 1 个采样绘制,由 TAA 通道用之前的帧来平滑:1080p 下便宜得多,画面略软,需要相机上有后处理体积;选它时 MSAA 一行会隐藏。**深度预通道**把不透明场景画两遍,先只画深度,让每个像素只为最前面的表面着色一次。表面大量重叠(树林、成片植被)且 GPU 对光栅化出的像素立即着色时划算;对把着色推迟到分块末尾的 GPU,等于几何多付一遍。低档默认关,中、高档默认开。默认抗锯齿方式：低档 MSAA(1 个采样)、高档 MSAA(4 个采样)、中档时间性。预通道和颜色通道在 WebGL2 与 WebGPU 上都把顶点位置声明为 invariant,所以表面的颜色总能通过与自己深度的等深测试,Metal 上也一样;Mac 上开着预通道时地形出现暗色三角形,只需更新到新的构建。

<Aside type="note">
一行的"默认值"是它正显示的那个档位的默认值，所以同一个数字在低档可能是改动，在中档却是默认。
</Aside>

**细节距离**是一档里放置的植物保留多少比例的距离：0.5 时，原本 60 米换成更省网格、150 米外不再画本体的树，会在 30 米和 75 米处这样做，远景卡片也更早接手。低档保留 0.5、中档 0.8、高档全部，所以同一个世界在手机上画的三角形只有一小部分。

**Draw call 预算**是这一档每帧最多应向 GPU 发出的 draw 数:低档 150、中档 400、高档 1500。所有 pass 都算,不只是场景自己的绘制列表:每个阴影级联都要把投影物再画一次,深度预通道要把不透明场景再画一次,后处理每个 pass 也要一次 draw。不会为了达标而少画什么。Profiler 的**渲染**模块显示这一帧的 GPU draw 数和预算,并按 pass 拆开;统计浮层在超出时把数字标红。一次 draw 花在 CPU 和驱动上的比花在 GPU 上的多,在手机和小游戏里,3D 场景最先用完的就是它。要降下来,不同网格很多时看[静态合并](/docs/zh-cn/performance/static-batching/),阴影那部分则减少级联数。

**贴图流式加载**把只被网格使用的贴图按视图实际需要的尺寸常驻。被 MeshRenderer 用到的贴图(它的贴图、法线贴图,或者经过它的材质)第一次加载时边长最多 256 纹素,所以场景刚出来时只占一小部分显存;之后,渲染器对视图里画的每个网格,根据网格自身的 UV 密度、尺寸和距离,算出它的贴图需要多少纹素宽才能做到一个纹素约等于一个像素,每秒四次把尺寸不对的贴图从文件按刚好够用的 2 的幂重新解码,放回同一个句柄后面。需要变大时立刻变大;需要变小时,要持续三秒才会缩;五秒没有被任何视图画到的贴图缩到 64 纹素。低档和中档默认开、高档默认关;**贴图流式预算**限制被流式管理的贴图合计占用(低档 128 MB,中档 256 MB,0 表示不设上限),超出时整体降一级清晰度。

在编辑器 Play 里用低档实测(`texture-streaming` 编辑器检查,数字是引擎自己的显存估计):

| 示例 | 关流式 | 开:首帧 | 开:十秒后 | 稳定后两次画面 |
|---|---|---|---|---|
| `dusk-fort` | 285.6 MB | 33.6 MB | 31.0 MB | 平均差 0.28/255 |
| `bistro` | 1293.5 MB | 321.1 MB | 449.6 MB(228 张贴图,149 次缩放) | 平均差 1.1/255;0.04% 的像素有明显变化 |

它做不到的:省的是显存,不是下载。文件第一次仍然完整读取,每换一次尺寸还要再读一次。在视图要求更大之前,贴图按起始尺寸绘制:场景开头的一两秒可能比之后模糊;一次缩放要在它落地的那一帧付出解码和上传,场景稳定之前会有一两帧几十毫秒。同时被精灵、UI、瓦片地图、粒子或拖尾使用的贴图会恢复原尺寸并保持不变。KTX2 文件直接从某一级截取,不用重新解码;宿主自己转码 KTX2 的平台(原生打包)做不到这一点,这类贴图保持原尺寸。

## 去掉一些效果

引擎有的每个后处理效果都在列表里，该档位运行的打勾。没勾选的效果在这个档位被跳过，不管相机的体积是否要求它——而且是整个跳过：
有多个 pass 的效果，比如环境光遮蔽或自动曝光，会被整体移除。清单里按类型保存被去掉的效果：

```json
"quality": { "mode": "auto", "profiles": { "low": { "skipEffects": ["ssr", "taa", "depthOfField"] } } }
```

默认情况下，低档去掉反射、时间性抗锯齿、景深、光束、运动模糊、镜头光斑、GTAO、次表面散射和体素 GI；中档去掉反射和景深；高档什么都不去掉。这些默认值依据每个效果每像素的工作量，
**不是**在弱设备上量出来的。编辑器的 `fx-cost` 检查能量出每个效果在当前机器上的开销，可以在决定某个档位跳过什么之前先看看你的机器上它们要多少。

## 设备规则

模式为自动时显示。每行写一个档位和设备必须满足的条件：**型号包含**、**GPU 包含**、**内存上限**、**核心上限**，全部成立才算。
第一条匹配的规则决定档位。没有任何条件的规则会匹配所有设备，所以必须至少有一个条件。

## 着色器编译与按需渲染

同一页还有两组设置,管的是游戏*如何交付*,而不是它跑在哪个档位。它们与画质档位无关,模式为**关闭**时同样生效,保存在 `features.rendering.quality` 下。

![项目设置的渲染页:着色器编译、按需渲染、省电和抗锯齿四个分组](@/assets/guides/zh/settings-shader-compilation.png)

**着色器编译**

| 设置 | 作用 |
|---|---|
| **后台编译着色器**(`asyncShaderCompile`) | 浏览器还在编译着色器的绘制会先跳过,游戏立刻打开,画面随着色器就绪逐步补全。关闭时,第一次用到某个着色器的绘制会等它编完:每一帧都完整,但首次访问可能卡住数秒。需要 `KHR_parallel_shader_compile`,没有该扩展时仍按原方式编译。 |
| **在启动页后面预热**(`prewarmShaders`) | 在启动页后面把第一个场景画到没有着色器在编译为止,再打开成完整画面。开启后台编译后才显示。 |
| **预热超时** | 启动页最多等多久(秒,默认 30);超时后不管有没有编完都直接打开。开启预热后才显示。 |

**按需渲染**

| 设置 | 作用 |
|---|---|
| **只绘制会变化的帧**(`renderOnDemand`) | 静止的画面只花游戏逻辑的开销。有人请求绘制、玩家有操作、画面尺寸变化、实体被创建或销毁、或仍有着色器在编译时,才会画一帧。 |
| **变化后继续绘制的帧数**(`renderOnDemandTail`) | 最后一次绘制原因之后继续画的帧数,让淡出或收尾动作能走完。默认 30。 |

引擎看不到脚本自己改了什么(颜色、动画):用 `RenderDemand.request()` 请求画一帧,或用 `RenderDemand.hold()`(返回释放它的函数)声明某样东西在自己运动,否则这类变化要等别的原因唤醒画面才会画出来。所以这个开关默认关闭。

## 省电与降温

手机上玩得久,就是发热和耗电,而这两样都花在画面这一帧上。打开 **电量低或设备发烫时降低开销**(`QualityConfig.power`)后,引擎每隔几秒看一眼设备:处于省电状态时,降低帧率上限并给画质档位设一个上限,设备恢复后再放回。关闭(默认)时不监测设备,什么都不变。

| 设置 | 作用 |
|---|---|
| **电量低于**(`lowBattery`) | 电量低于该比例且没在充电时省电。默认 20%;0 表示不因电量省电。 |
| **发热压力**(`thermal`) | 平台报告压力达到该级别或更高时省电:严重(默认)、危急、不因发热。 |
| **省电时的帧率上限**(`fps`) | 省电时每秒最多画多少帧,默认 30。游戏已设得更低的上限保持不变。 |
| **省电时的画质上限**(`ceiling`) | 省电时画质不超过该档;本来更低的档位不动。默认中。 |

发热压力达到危急时更进一步:帧率上限减半(不低于 15),画质固定为低(`severe: 'never'` 可关闭这一步)。平台没报告的项不会触发任何事:没有电池接口的浏览器不会因电量省电,多数浏览器完全不报告温度(Chromium 报告电量和处理器压力;微信小游戏平台报告电量)。`Device.power()` 把同样的数字给游戏(`level`、`charging`、`thermal`,平台没说的为 `null`),`Quality` 的报告在压低档位期间会在限制里列出 `power-saver`。帧率上限只在游戏自己没有改动过它的情况下才放回。

静止的画面(菜单、牌桌)更好的省法是什么都不画:见编辑器同一页设置里的"按需渲染"。

## 在代码里

同样的设置就是 `QualityConfig`——`QualityController`、`parseQualityConfig`、`resolveQualityProfile` 和 `defaultQualityProfile`
构建并读取它——运行中的档位是 `Quality` 资源。
