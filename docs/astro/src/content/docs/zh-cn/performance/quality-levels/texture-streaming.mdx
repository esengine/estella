**纹理流式加载**把只由网格绘制的纹理保持在其视图所需的尺寸。它是档位设置：Low 与 Medium 开启，High 关闭。

## 行为

- `MeshRenderer` 绘制的纹理（作为其纹理、法线贴图或经由其材质）首次加载时最长边不超过**起始尺寸**，因此场景启动时只占一小部分内存。
- 对于视图绘制的每个网格，渲染器根据网格的 UV 密度、尺寸与距离，计算其纹理横向需要多少纹素才能使一个纹素约覆盖一个像素。
- 每个**间隔**，尺寸不合适的纹理会从其文件重新解码为高于所需值的下一个 2 的幂，并替换到同一句柄之后。最多同时进行**同时处理纹理数**个调整。
- 纹理需要变大时立即变大；只有在持续需要更小达到**缩小延迟**之后才缩小。在**未见保持时间**内没有被任何视图绘制的纹理降到**最小尺寸**。
- 以多个放置实例绘制的网格（`MeshInstances`：`PlacedFoliage` 与世界植物放置的树木与岩石）按其最近的已绘制实例的需要请求尺寸。世界生成的植物的材质与纹理与场景中的一样从小尺寸开始。
- **Texture streaming budget** 限制所有流式纹理的总内存；超出后纹理保持在小一级的尺寸。
- 对于流式加载的 PNG、JPEG 或图像配方，起始尺寸限制 GPU 上传的最长边：起始为 64 纹素时，240 × 120 的图像以 64 × 32 开始，之后可以在同一句柄上恢复到 240 × 120。

## 设置

| 设置 | 键 | Low / Medium / High | 说明 |
|---|---|---|---|
| Texture streaming | `textureStreaming` | 开 / 开 / 关 | 启用流式加载。 |
| Texture streaming budget (MB) | `textureStreamingBudget` | 128 / 256 / 0 | 所有流式纹理的总上限；`0` 表示不限。 |
| Streaming smallest size | `textureStreamingMinEdge` | 32 / 64 / 64 | 无视图绘制的纹理的尺寸。 |
| Streaming shrink delay (ms) | `textureStreamingShrinkMs` | 2,000 / 3,000 / 3,000 | 纹理需持续需要更小多久才缩小。 |
| Streaming unseen hold (ms) | `textureStreamingUnseenMs` | 3,000 / 5,000 / 5,000 | 纹理无视图多久后降到最小尺寸。 |
| Streaming interval (ms) | `textureStreamingIntervalMs` | 500 / 250 / 250 | 两次调整之间的时间。 |
| Streaming textures at once | `textureStreamingInFlight` | 2 / 4 / 4 | 同时进行的调整数。 |
| Streaming starting size | `textureStreamingStartEdge` | 128 / 256 / 256 | 流式纹理首次加载时的最长边。 |

这些参数只在该档位开启流式加载时读取。

## Web 构建中的缩小副本

Web 构建会为网格作为表面绘制、且每边大于 512 纹素的纹理附带一份缩小副本。副本每边最多 256 纹素，格式相同（KTX2 以其自身模式重新编码；PNG 或 JPEG 按原格式写出），用烘焙生成 mip 链时所用的盒式滤波从发布文件缩小得到。

流式加载从副本开始，只有当视图需要的细节超过副本时才下载完整文件，因此从未被近距离观察的纹理永远不会完整下载。副本会给包体增加其自身的大小。小游戏整体下载其包，因此不为小游戏生成副本，也不为网格以外的对象绘制的纹理生成副本。

## 限制

- 在视图请求更多细节之前，纹理以其起始尺寸绘制，因此场景最初的一两秒可能较模糊。
- 一次调整在完成的那一帧需要一次解码与一次上传，场景稳定过程中可能表现为一两帧数十毫秒的耗时。
- 同时被精灵、UI 元素、瓦片地图、粒子或拖尾绘制的纹理会恢复到其导入尺寸并保持不变。只被精灵使用的纹理按导入尺寸加载。
- KTX2 文件在某个 mip 级别处截取，无需解码。在宿主自行转码 KTX2 的平台（原生构建）上无法截取，纹理保持原尺寸。
- 无法原地替换纹理内容的旧宿主会立即加载完整图像。
