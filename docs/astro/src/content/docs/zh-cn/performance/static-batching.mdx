渲染器已经把**同一网格的多个副本**绘制为一次实例化 draw。**不同的网格**位于不同的 GPU 内存区段，每个材质各需一次 draw。`StaticBatch` 把绘制状态相同的不同静态网格按区域合并为一个网格；`CompositeBatch` 对整体移动的模型做同样的事。

| 内容 | 使用 |
|---|---|
| 同一网格的大量副本 | 实例化（自动） |
| 大量不移动的不同网格 | `StaticBatch` |
| 由多个部件组成、整体移动的模型（船、载具、平台） | `CompositeBatch` |

## `StaticBatch`

给不会移动的网格添加 `StaticBatch`。游戏运行时，材质、纹理、颜色与层都相同的已标记网格按区域合并为一个网格。

```typescript
world.insert(wall, MeshRenderer, { mesh: 'builtin:cube', material });
world.insert(wall, StaticBatch, {});
```

在编辑器中，选中网格后从大纲视图的菜单中选择 **Static Batch**。

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `group` | string | `''` | 网格只与同组的网格合并，因此可以把两个房间分开。空字符串为默认组。 |
| `state` | `StaticBatchState` | Waiting | 只读：上一次处理对该网格的结果（已合并，或未合并的原因）。 |
| `batched` | number | `0` | 只读：与该网格一起绘制的网格数（含自身）；未合并时为 `0`。 |

`StaticBatch` 标记为 `@experimental`。

## 合并规则

- 网格按一次 draw 所拥有的全部状态分组（材质、纹理、法线贴图、颜色、层、剔除、光照与投射阴影标志），并按 `group` 分组。
- 每组再划分为世界单元，使每个批次覆盖一片邻近区域并仍可剔除。单元边长为 1,600 世界单位，最多容纳 262,144 个顶点。
- 被标记的实体保持原样：脚本可以找到它们，碰撞体照常碰撞，编辑器可以拾取。只有它们的绘制转移到合并后的网格，后者是一个单独的实体。
- 已合并的网格**不得移动**。销毁是支持的（其批次会在去掉它后重建）；移动则不受支持，也不会被检测到。
- 批次每隔画质档位的 **Batch scan interval** 帧重新扫描一次（Low 为 60，Medium 与 High 为 30；[视距与绘制](/docs/zh-cn/performance/quality-levels/settings/#视距与绘制)）。

## 不参与合并的网格

无法合并的网格继续自行绘制，并在 `state` 以及性能剖析器的 **Static batch** 部分报告原因。

| 原因 | 说明 |
|---|---|
| Skinned（蒙皮） | 一次 draw 只有一个姿势。 |
| Morphing（变形） | 一次 draw 只有一个形状。 |
| Level of detail（LOD） | 渲染器在运行时选择级别。 |
| Billboard（公告板） | 它面向每个视图；合并的网格固定在烘焙时的位置。 |
| Blended（混合） | 结果取决于绘制顺序，而合并会丢弃顺序。 |
| Moves（移动） | 动态刚体或角色控制器。 |
| Baked light（烘焙光照） | 场景有光照探针或烘焙；合并的网格无法保留各部件自身的烘焙光照。 |
| No mesh yet（尚无网格） | 网格仍在加载或加载失败。 |
| Switched off（已关闭） | 不绘制任何内容。 |
| Vertex layout（顶点布局） | 位置或法线不是 32 位浮点数，合并无法对其变换。 |
| Alone in its group（组内只有一个） | 合并单个网格没有收益，还占用内存。 |

## 内存开销

合并会把每个部件的顶点复制到合并后的网格中：它**以内存换取 draw 数**。原本代表一百个实例的网格会变成一百份副本。性能剖析器为每个合并网格显示其包含的部件数、这些部件合并前的 draw 数以及副本占用的内存。

合并后的顶点在 CPU 上以 32 位浮点数变换，因此几何边缘处的像素可能与未合并的帧略有差异。

## `CompositeBatch`：移动模型

`StaticBatch` 把每个部件烘焙在其世界位置上，因此由部件组成的移动模型无法使用它。应在模型的**根节点**上添加 **`CompositeBatch`**；部件不需要任何组件。

```typescript
const ship = world.spawn('Ship');
world.insert(ship, Transform, {});
world.insert(ship, CompositeBatch, {});
// 木板、立柱与道具挂在 `ship` 之下，各自带有 MeshRenderer。
```

| 字段 | 默认值 | 说明 |
|---|---|---|
| **Instance at**（`instanceMin`） | `4` | 同一网格的部件数达到该值时作为一组实例绘制，不复制顶点；少于该值则合并。最小为 2。 |
| **Chunk size**（`cellSize`） | `0` | 根节点空间中合并分块的边长；`0` 根据模型大小自动选择。分块越小，编辑时重新合并的范围越小，剔除效果越好。 |
| **Batched parts**（`parts`） | — | 只读：根节点下由该处理绘制的网格数。 |
| **Instanced parts**（`instanced`） | — | 只读：以实例组绘制的部件数。 |
| **Draws**（`draws`） | — | 只读：模型当前的 draw 数。 |
| **Draws before**（`drawsBefore`） | — | 只读：相同部件在合批之前的 draw 数。 |
| **Moving parts**（`moving`） | — | 只读：持续移动、已交还给自身绘制的部件数。 |

游戏运行时，部件在**根节点自身的空间**中合并，绘制它们的网格是根节点的子节点：

- 移动、旋转或缩放根节点会移动整个模型，无需重新合并。
- 重复次数达到 **Instance at** 的网格（甲板木板、栏杆立柱）保持为一个常驻网格，作为一组实例绘制。
- 其他部件按绘制状态合并到根节点空间的分块中。添加、移除、更换网格或移动部件只会在下一次扫描（**Batch scan interval**）时重新合并其所在分块。`app.getResource(CompositeBatchingRes).refresh(root)` 立即重新扫描。
- 修改部件的 `MeshRenderer.castShadows` 会在下一次扫描时重新分组。投射阴影与不投射阴影的部件即使材质相同，也分在不同的实例组与分块中。
- 在模型内部持续移动的部件（门、车轮）在连续三次扫描都发生变化后被交还给自身绘制，因此不会导致每帧重新合并。
- `StaticBatch` 的排除规则同样适用：蒙皮、变形、LOD、公告板与混合部件以及动态刚体自行绘制。位于组合合批之下的部件永远不会同时被静态合并。

`CompositeBatch` 节省的主要是 CPU 开销（每帧收集、剔除与排序每个部件），因为重复网格本来就已实例化。部件越多收益越大；部件较少的模型，周期性扫描的开销可能与节省相当。

`CompositeBatch` 标记为 `@experimental`。

## 实例包围盒

原生实例组（植被也使用）对每个放置实例的包围盒同时考虑网格的各级 LOD 与材质声明的 `vertexbounds`，包括放置的旋转、缩放与切变。移动顶点的材质必须声明其完整的局部位移，否则可见表面可能在视图边缘被剔除。

阴影贴图的覆盖范围使用相同的 LOD 几何与声明的位移，并经每个放置实例及其父节点变换。空的实例组不增加包围盒。接收者、投射者与头发焦点包围盒在一次遍历中收集，因此实例化不会使阴影贴图偏离其必须覆盖的几何。
