`Ads`、`Share`、`Recorder`、`Leaderboard`、`Identity` 和 `Payment` 服务封装了小游戏宿主 API。每个服务在所有平台上都存在，并通过 `available` 报告当前平台的支持情况，因此玩法代码检查能力即可，无需按平台分支。

| 服务 | 包 | 运行模式中的模拟 |
|---|---|---|
| `Ads` | `esengine` | 有 |
| `Identity` | `esengine` | 无 |
| `Share`、`Recorder`、`Leaderboard`、`Payment` | `estella-plugin-minigame-services` | `Recorder` 实际录制；`Leaderboard` 在本地渲染；`Share` 和 `Payment` 报告不可用 |

## 激励视频

`Ads.showRewarded(adUnitId)` 展示激励视频，在广告关闭且游戏恢复运行后 resolve，结果说明是否获得奖励：

```typescript
import { defineSystem, Res, GetWorld, Ads } from 'esengine';

const reviveSystem = defineSystem([Res(Ads), GetWorld()], (ads, world) => {
  if (!reviveClicked(world)) return;
  ads.showRewarded('adunit-xxxx').then(({ completed }) => {
    if (completed) revivePlayer(world);   // watched to the end → grant the reward
    else showToast(world, 'Watch the whole ad to revive');
  }).catch(() => {
    showToast(world, 'No ad available right now');
  });
}, { name: 'ReviveSystem' });
```

广告展示期间，该服务会：

- 暂停游戏时钟；
- 挂起音频设备，不改变用户设置的任何音量；
- 无论广告如何结束（包括所有错误路径）都恢复二者。广告前已暂停的游戏在广告后仍保持暂停。

宿主的加载/展示流程（无填充的广告会加载并重试一次）在内部处理。对于发放奖励却不报告 `isEnded` 的运行时，没有关闭记录视为已完成。

| 方法 | 说明 |
|---|---|
| `Ads.showRewarded(adUnitId)` | 展示激励广告；以 `{ completed }` resolve。 |
| `Ads.showInterstitial(adUnitId)` | 约定相同，但没有奖励。 |
| `Ads.preloadRewarded(adUnitId)` | 预先加载广告位，使下一次展示立即开始。 |

<Aside type="tip">
`adUnitId` 来自宿主的广告后台（微信：MP 后台的 流量主 → 广告位）。只有在后台开通流量主的游戏才会投放广告；开发者工具模拟器显示测试广告。
</Aside>

### 可用性

存在广告来源（平台自身或已安装的提供方）时，`Ads.available` 为 `true`：

| 平台 | 广告来源 |
|---|---|
| 小游戏（微信、抖音及其他同族宿主） | 宿主的激励视频和插屏广告。宿主没有广告 API 的厂商报告 `false`。 |
| 设置了平台渠道的 Web | Poki、CrazyGames 和 YouTube Playables 安装各自的提供方（[Web 游戏平台](/docs/zh-cn/publishing/web-portals/)）。 |
| 编辑器运行模式 | 模拟提供方：`showRewarded` 片刻后以 `completed: true` resolve，暂停与音频处理与真实情况一致。 |
| Android、iOS | 项目自己的原生广告 SDK，在其代码响应 `ads.show` 之后（[原生代码](/docs/zh-cn/publishing/native-code/#广告)）。 |
| 独立发行的 Web、桌面 | 无；`false`。 |

## 分享

分享、录屏、排行榜和游戏内购买由 `estella-plugin-minigame-services` 包提供。编辑器自带该包，因此在运行模式和所有导出中都可直接导入，无需安装；项目自身 `node_modules` 中安装的副本优先。

```typescript title="src/main.ts"
import { addPlugin } from 'esengine';
import { miniGameServicesPlugin } from 'estella-plugin-minigame-services';

addPlugin(miniGameServicesPlugin);
```

小游戏宿主有两个分享入口，两者都应配置：

```typescript
import { defineSystem, addStartupSystem, Res } from 'esengine';
import { Share } from 'estella-plugin-minigame-services';

addStartupSystem(defineSystem([Res(Share)], (share) => {
  // The DEFAULT card: what the host's own share menu (top-right on WeChat)
  // shows, and what share() without arguments uses. A function is asked at
  // share time, so the card can carry live state — a score, a room code.
  share.setShareCard(() => ({
    title: `I scored ${currentScore()} — beat me!`,
    query: `room=${currentRoomCode()}`,
  }));
}, { name: 'SetupShare' }));

// In the game's own share button handler (share is Res(Share) as above):
share.share();                          // the default card
share.share({ title: 'Join my game' }); // or a one-off card
```

| 入口 | 配置方式 |
|---|---|
| 宿主自带的分享菜单 | `setShareCard(card \| () => card)`；也是 `share()` 的默认卡片。 |
| 游戏内的分享按钮 | `share(card?)`。 |

打开分享卡片的玩家会在宿主的启动参数中收到 `query`；邀请链接和房间号通过这种方式传递。

分享是“发出即不管”的：小游戏宿主不报告玩家是否完成分享。在平台之外（Web、原生、编辑器），`Share.available` 为 `false`，`share()` 返回 `false`；此时应隐藏按钮。

## 录屏

`Recorder`（同一个包）录制游戏画布以供分享：

```typescript
import { Recorder } from 'estella-plugin-minigame-services';

// When the run starts (recorder is Res(Recorder)):
if (recorder.available) await recorder.start();

// When something worth keeping just happened — a kill, a near miss:
recorder.highlight(3, 2);   // keep 3s before now and 2s after

// When the run ends:
await recorder.stop();

// In the "share my run" button's tap handler — both hosts refuse a share
// the player did not tap for:
if (recorder.canShare) await recorder.share({ title: 'Look at this run' });
```

有高光片段时，分享的视频按顺序由高光片段组成；没有时为完整录制。每个调用在宿主确认后 resolve，并以宿主给出的原因（及 `code`，若有）reject。宿主因错误结束的录制通过 `recorder.onFailure(...)` 报告，`state` 回到 `'idle'`。

| | 微信 | 抖音 | 编辑器 / Web |
|---|---|---|---|
| 时长（`maxSeconds`） | 5–7200 秒 | 4–300 秒 | 任意 |
| `stop()` 的结果 | 时长；视频由微信保存 | 临时文件（`path`） | WebM 预览（`blob`） |
| 分享的视频 | 最多 60 秒高光，至少 2 秒 | 合并后的高光片段 | 无法分享 |

`maxSeconds` 默认为 300，并限制在宿主的范围内。只录制游戏画布；覆盖在其上的广告和宿主对话框不会被录入。

<Aside type="caution">
抖音开发者工具不支持录屏（“开发者工具不支持录屏调试，请在真机上调试录屏相关功能”）。微信在 Android 8.0.28、iOS 8.0.30 起支持分享录屏；宿主没有分享接口时 `canShare` 为 `false`。
</Aside>

运行模式中的录制是真实的：`stop()` 以 WebM 返回画布内容。`canShare` 为 `false`，因此分享按钮会像在不支持分享的宿主上一样隐藏。`record-share` 示例演示了完整流程。

## 好友排行榜

在小游戏宿主上，好友数据只能在**开放数据域**中读取：这是宿主在游戏旁启动的第二个 JavaScript 运行时，没有引擎、WebGL 和 wasm，也没有回到游戏的通道。排行榜在那里绘制，以纹理形式传回游戏。

```typescript
import { UIVisual } from 'esengine';
import { miniGameServicesPlugin, Leaderboard } from 'estella-plugin-minigame-services';

addPlugin(miniGameServicesPlugin);
const leaderboard = app.getResource(Leaderboard);

// Your half: write your own row. It is the one cloud operation the game
// itself may do — reading anyone's, including your own, belongs to the context.
leaderboard.submit(score);

// Ask the context to draw. This is a request, not a question: no rows come
// back, no count, no "did it work".
leaderboard.show({ limit: 10, order: 'desc' });

// What it drew, as a texture handle any UIVisual can wear.
world.get(panel, UIVisual).texture = leaderboard.texture;

leaderboard.hide();   // clears the board and stops sampling
```

| 成员 | 说明 |
|---|---|
| `submit(score)` | 写入玩家自己的记录——游戏自身唯一可执行的云端操作。 |
| `show(options)` | 请求绘制。不返回任何记录或状态。选项：`limit`、`order`、`style`（颜色、行高、字号、头像）。 |
| `texture` | 绘制出的排行榜，作为任意 `UIVisual` 可用的纹理句柄。 |
| `hide()` | 清除排行榜并停止采样。 |
| `available` | 没有开放数据域时为 `false`：Web、原生，以及未声明开放数据域的包。 |

排行榜对记录排序、突出显示玩家自己的一行，并省略从未玩过的好友。画布尺寸固定且**不能滚动**——开放数据域收不到任何指针或按键事件——因此 `limit` 是能容纳的行数。

### 开放数据域文件

开放数据域目录归项目所有，内容由包提供：

```typescript title="open-data/index.ts"
import 'estella-plugin-minigame-services/open-data';
```

导出器单独打包 `open-data/` 并在 `game.json` 中声明。没有该目录的项目不发布开放数据域，`available` 报告 `false`。

要绘制自定义排行榜，可不导入包而自行编写该文件。它运行在开放数据域中，因此**不得导入 `esengine`**；若导入，导出和进入运行模式都会失败。开放数据域提供 `wx.getSharedCanvas()` 得到的 2D 画布、`wx.getFriendCloudStorage()`，以及携带 `show()` 所传选项的 `wx.onMessage()`。

### 运行模式

运行模式会在离屏画布上运行项目的 `open-data/index.ts`，使用生成的占位好友数据，并通过与设备相同的能力响应 `Leaderboard`。`submit()` 会作用于它，因此玩家自己的那一行会变化。真实好友和宿主沙箱只能在设备上检查。

## 登录

小游戏宿主为玩家登录并返回一个**一次性登录码**。将登录码换成身份需要 app secret，而 app secret 必须保存在游戏的服务端；引擎的职责止于登录码。

```typescript
import { defineSystem, Res, Identity } from 'esengine';

if (!identity.available) return;             // web, native, the editor

// Skip the round trip when the session your server holds is still good.
if (await identity.sessionValid()) return;

const { code } = await identity.login();     // a CODE, not a session
const session = await postToYourServer('/session', { code });
```

| 成员 | 说明 |
|---|---|
| `available` | 平台是否支持登录。 |
| `sessionValid()` | 宿主会话是否仍然有效。 |
| `login()` | 以 `{ code }` resolve。登录失败时以宿主消息 reject；平台不支持登录时立即 reject。 |

登录码有效期短且只能使用一次：缓存服务端返回的会话，而不要缓存登录码。运行模式不模拟登录，因为任何服务端都无法换取占位登录码；在平台之外 `available` 为 `false`。

## 游戏内购买

游戏内购买是一项设备权限。微信上仅 Android 支持：iOS 上该接口存在但会被平台拒绝。因此 `Payment.available` 针对的是**设备**；打开商店前应先检查。

```typescript
import { defineSystem, Res } from 'esengine';
import { Payment } from 'estella-plugin-minigame-services';

if (!payment.available) return;   // iOS, web, native — do not open the shop

try {
  await payment.request({ offerId: 'your-offer-id', quantity: 10 });
  // The HOST says the purchase completed. Now ask YOUR server what the player
  // owns — do not add the coins here.
  await refreshInventoryFromYourServer();
} catch (err) {
  // The host's own message and code, including "the player changed their mind".
  // Those are different UI, and only the host can tell them apart.
  if ((err as { code?: number }).code === /* your host's cancel code */ 2) return;
  showPurchaseFailed(err);
}
```

`request()` 的选项：`offerId`、`quantity`，开发流程期间使用 `sandbox: true`，多区服的游戏使用 `zoneId`。

- 该服务**不解释宿主的错误码**；各厂商的错误码不同，原样传出。
- 该服务**不发放任何物品**。宿主通知游戏服务端，由服务端发放货币；`request()` resolve 后应向服务端查询。
- 运行模式不模拟购买。
