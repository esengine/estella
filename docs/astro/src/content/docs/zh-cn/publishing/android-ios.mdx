**Android** 与 **iOS** 目标将项目打包为原生应用：引擎的 C++ 核心编译为 arm64，通过内嵌的 [Dawn](https://dawn.googlesource.com/dawn) 渲染（Android 上为基于 **Vulkan** 的 WebGPU，iOS 上为基于 **Metal** 的 WebGPU）。游戏脚本运行在内嵌的 JavaScript 引擎上——Android 上为带 JIT 的 [V8](https://v8.dev/)，iOS 上为 [QuickJS-ng](https://github.com/quickjs-ng/quickjs)（iOS 不允许 JIT）。应用中不包含 WebView 或浏览器。

场景、组件和 TypeScript 与其他所有目标相同；项目不需要任何移动端专属内容。

## 目标

Android 和 iOS 是两个独立目标，因为二者的产物和装配宿主不同。它们共享同一个运行时和同一份导出内容：引擎、SDK 和游戏运行时位于应用二进制中，导出写出的是应用**内容**——场景、脚本和烘焙后的资产。

| | Android | iOS |
|---|---|---|
| 图形 | Vulkan（经 Dawn） | Metal（经 Dawn） |
| 导出目录 | `dist-android/` | `dist-ios/` |
| 装配者 | 编辑器（无需 Android SDK） | 编辑器，然后 Xcode |
| 装配宿主操作系统 | 任意桌面系统 | 仅 macOS |
| 结果 | 签名的 `.apk`（可选附带 `.aab`），或 Android Studio 工程 | Xcode 工程 |

## 设备要求

| | Android | iOS |
|---|---|---|
| 最低系统 | **Android 10**（API 29） | **iOS 17.0** |
| 目标 API | 33 | — |
| CPU | `arm64-v8a`；`x86_64`（模拟器）仅在要求时包含 | arm64 真机与模拟器切片 |
| GPU | **Vulkan 1.0.3**，声明为 `required="true"` | Metal |

- Android 最低为 API 29，因为字体路径调用的 `AFontMatcher_create` 需要 API 29。
- Vulkan 要求来自 Dawn 的 Android 后端；没有 GLES 回退。由于在 manifest 中声明，Google Play 不会向不支持 Vulkan 的设备提供该应用。
- Android 包只携带手机 ABI。在 Android 目标设置中勾选 **包含模拟器（x86_64）**，或在命令行使用 `--emulator-abi`，可加入模拟器库；发布构建应关闭。

## 前置条件

<Steps>

1. **安装运行时模板。** 模板是该目标预编译好的引擎，随每个版本发布。打包项目中该目标的行提供 **下载**，或对单独获取的归档文件使用 **从文件安装…**。模板必须与编辑器版本完全一致，因为 SDK 编译在应用二进制中。

   :::tip[下载来源]
   发布文件镜像在 `dl.estella.games`，编辑器优先尝试该镜像。每个归档都会按发布索引中给出的大小和 SHA-256 校验；缺失、过期或不匹配的副本回退到 GitHub。`ESTELLA_RELEASE_MIRROR` 可设置其他镜像（逗号分隔，按顺序尝试）；每个镜像须按发布的结构在 `v<version>/` 下存放对应版本。
   :::

2. **安装平台工具链（仅 iOS）。**
   - *Android*：无需安装。APK 由编辑器在任意操作系统上编译、对齐和签名；不需要 Android SDK、NDK 或 JDK。
   - *iOS*：**装有 Xcode 的 macOS**。不需要 CMake、Ninja、xcodegen 或 Dawn 源码。在其他操作系统上，导出仍会写出一个完整的工程，可在 Mac 上打开。

3. **检查对话框。** 前置条件满足之前，目标所在行显示警告，面板中列出缺少的内容。

</Steps>

含 `@compiled` 系统的项目在导出 Android 时，导出机器上还需要 **Android NDK**（[脚本执行](#脚本执行)）。

## 导出

<Steps>

1. **构建 → 打包项目…**，在 **移动** 下选择 **Android** 或 **iOS**。
2. 选择配置和输出目录（默认 `dist-android` / `dist-ios`）。不提供源码映射。
3. 检查 **构建包含的场景**。
4. 点击 **打包**。导出会烘焙资产、打包脚本、写出内容和包含应用标识的 `app.config.json`，并围绕这些内容装配应用。

</Steps>

| 产物 | 内容 |
|---|---|
| **Android**，*打包为：安装包（.apk）* | 签名的 `.apk`，可直接 `adb install -r`。勾选 **Google Play App Bundle（.aab）** 时会在其旁写出 `.aab`；Bundle 是 Google Play 的上传格式，不能直接安装到设备上。 |
| **Android**，*打包为：Android Studio 工程* | 一个 Gradle 工程：内容位于 `app/src/main/assets`，引擎位于 `app/src/main/jniLibs`，宿主的 Java 适配层以源码形式提供，`app/build.gradle.kts` 包含应用标识。用 Android Studio 打开并运行。重新导出会重写游戏内容而保留构建脚本，因此加入 `build.gradle.kts` 的 SDK 会保留下来。 |
| **iOS** | 一个 Xcode 工程：`.xcframework`、应用外壳以及围绕内容生成的 `.pbxproj`。打开后在 *Signing & Capabilities* 中选择签名团队并运行。 |

所有游戏的应用二进制相同，导出只是内容，因此装配只涉及复制文件和写出工程文件，不需要编译器。

### Android 签名

| 构建 | 签名密钥 |
|---|---|
| 开发 | 编辑器首次使用时生成的开发密钥。设备可安装，商店不接受。 |
| 发行 | 设置后使用项目的发布密钥：Android 目标签名分组中的 **发布私钥** 和 **发布证书**（PEM，项目相对路径或绝对路径）。签名前会核对二者是否匹配。**发布私钥密码** 保存在本机钥匙串中；CLI 读取 `ESTELLA_ANDROID_KEY_PASSPHRASE`。 |

不要将发布密钥放入项目仓库。也可以用 `node build-tools/cli.js native --package --content dist-android` 从导出内容装配应用，通过 `--key` / `--cert`（及 `--passphrase`）指定签名密钥，用 `--aab` 写出 Bundle。

### 原生库

**压缩原生库**（Android 目标设置，默认开启）在 APK 中以 deflate 压缩原生库：空项目的下载体积约为 20 MB 而非 54 MB，Android 在安装时解压一次。关闭后原生库以存储方式放置，供系统直接映射：安装体积约减半，下载体积接近三倍。App Bundle 始终以存储方式放置原生库；Google Play 会压缩其分发内容。

## 应用标识

以下设置写入内容旁的 `app.config.json`，而不是运行时读取的 `game.config.json`：

| 设置 | 位置 | 作用 |
|---|---|---|
| **应用图标** | 设置 → 项目 → 构建与模块 → 打包 | 一张项目相对路径下的方形 PNG（建议 1024×1024）。Android 用作启动器 mipmap，iOS 用作资源目录，由 Xcode 派生全部尺寸。留空时使用 Estella 标志。 |
| **应用 ID** | 同上 | Android manifest 包名和 iOS bundle id（反向域名）。留空时由项目名派生。 |
| **Android 版本号** | Android 目标设置 | Google Play 用来排序构建的整数，每次上传都必须递增。用户可见的版本号来自项目版本。 |
| **屏幕方向** | 设置 → 项目 → 游戏 → 显示 | 项目级设置；未设置时按设计分辨率的宽高比决定。 |

## 设备上的引擎子系统

移动目标编译完整的引擎源码列表。在 Web 上作为独立侧模块的子系统（Box2D、Spine 运行时、MPEG-1 视频解码器）编译进应用二进制。`app.sideModules` 仍会报告它们，因此运行时的功能检查与浏览器中一致。

| 子系统 | 设备上 |
|---|---|
| 精灵、瓦片地图、粒子、后处理 | 原生（Dawn） |
| 文本、位图文本、富文本 | 与 Web 相同的图集和排版；字形由系统字体光栅化 |
| 物理（Box2D） | 编译在内；在多个工作线程上求解 |
| Spine | 编译在内，包含所有版本；见 [Spine 运行时](#spine-运行时) |
| DragonBones | 编译在内，一个运行时 |
| 视频 | 编译在内（构建时烘焙，设备上解码） |
| 音频 | 原生混音器（[miniaudio](https://miniaud.io/)），基于 CoreAudio / AAudio |
| 文本输入 | 平台**软键盘**作为输入框的编辑界面 |
| 网络 | 系统网络栈（`NSURLSession` / `HttpURLConnection`） |
| 地形与流式世界 | 支持。地形图层纹理以字节形式传给设备；分块世界的生成器使用自身的取消句柄，因为原生运行时没有 `AbortController`。 |
| 压缩纹理 | KTX2 转码为设备格式（ASTC、ETC2、BC），保留 mip 链 |
| 生命周期 | `onShow` / `onHide` 和系统内存警告可传达到应用 |

若将来的构建缺少某个子系统，导出会指明该子系统及使用它的场景。

### Spine 运行时

原生应用可读取 Spine 2.1、3.8、4.1、4.2 和 4.3。每个骨架由其导出版本对应的运行时读取，因此项目可以混用多个版本；项目设置中的 Spine 版本只是一项偏好。各运行时定义了相同的 C 名称，因此宿主以各自的前缀分别编译它们。Android 上每个版本是一个独立的库（每个 ABI 0.2–1 MB），导出只包含打包的骨架所需的库。iOS 和桌面上所有版本都链接进应用（约 1 MB）。

Web、Playable、小游戏和 Android 包携带哪些运行时，按同一规则决定。项目设置 → Spine 中每个运行时一行：

| 值 | 行为 |
|---|---|
| **Auto**（默认） | 包中有骨架由该版本导出时携带。 |
| **Include** | 始终携带。用于只由代码加载的骨架（运行时拼出的路径、之后获取的内容）。 |
| **Exclude** | 从不携带。若打包的骨架需要它，导出失败并指明该骨架。 |

导出结果列出每个运行时及其被携带或排除的原因。旧版本的运行时模板只携带一个 Spine 版本；用它打包时，会列出模板无法播放的每个骨架。安装与当前编辑器版本对应的模板即可解决。

## 设备上的资产

- **只被代码引用的资产会被剔除。** 构建只打包从构建场景可达的资产。在内容浏览器中将只被代码引用的文件夹标记为 **交付方式 → 总是打进构建（即使无人引用）**，这会在 `.esengine/asset-groups.json` 中写入 `alwaysInclude`：

  ```json
  {
    "version": "1.0",
    "groups": {
      "markup-images": {
        "folder": "assets/textures",
        "mode": "local",
        "alwaysInclude": true
      }
    }
  }
  ```

  默认关闭。见[资产](/docs/zh-cn/assets/overview/#只有代码点名的资产)。
- **按平台的纹理设置。** 导入设置按平台分页，包括移动目标，因此可以在不修改源文件的情况下为手机设置更强的压缩。

## 脚本执行

| | Android | iOS |
|---|---|---|
| 引擎 | 带 JIT 的 V8（每个 ABI 一个 `libv8android.so`） | QuickJS-ng 解释器 |
| 语言支持 | 提供 `Intl` 和 Unicode 正则表达式（`/\p{L}/u`）所需的 ICU 数据；`TextEncoder` / `TextDecoder` 由宿主提供 | — |
| `@compiled` 系统 | 用 Android NDK 为包内每个 64 位 ABI 交叉编译，放在 `lib/<abi>/` 中 | 解释执行 |
| 首次启动时的 SDK 包 | 启动时编译，并缓存在应用缓存目录 | 预编译字节码随应用发布 |

- **Android 的 `@compiled` 系统** 从第一帧起即以机器码运行。导出机器上必须安装 NDK（Android Studio 的 SDK Manager，或设置 `ANDROID_NDK_HOME`）；项目含编译系统而缺少 NDK 时，打包对话框会给出提示。宿主无法绑定的系统在该帧以解释方式运行。
- **iOS** 以解释方式执行所有脚本。用 TypeScript 编写的逐实体循环比在浏览器中开销更大；热路径中应优先使用引擎系统和批量 API。
- **iOS 首次启动。** SDK 字节码随应用一同构建，因此全新安装后无需解析脚本包即可到达第一帧。构建机器没有 C 编译器时无法生成字节码，应用会在首次运行时编译，该次启动约需十秒，之后不再发生。

启动记录（[启动诊断](#启动诊断)）会说明实际情况——`SDK bundle: loaded from the cache shipped with the app` 或 `bundle: no compile cache`——其开头几行给出引擎名称（`engine: V8 …` 或 `engine: QuickJS-ng …`）。

## 启动诊断

每次启动都会写出启动记录：

```
Android   Android/data/<your.package.id>/files/estella-boot.log
iOS       the app's Documents directory
```

上一次运行的记录保存为 `estella-boot.prev.log`。

```
estella boot record — 2026-07-29 19:07:38
device: 24129PN74C, Android 16, arm64-v8a
phase: gpu device
gpu: qualcomm Adreno (TM) 830 (adreno-8xx) — Adreno Vulkan Driver 512.800.71
phase: surface
phase: engine context
phase: js runtime
  SDK bundle: loaded from bytecode shipped with the app
phase: game script
ready in 105 ms
```

未完成的启动中，最后一行 `phase:` 即停止的位置；完成的启动以 `ready in` 结尾。原生崩溃会追加信号、所处阶段和返回地址：

```
FATAL SIGSEGV (bad memory access) during phase: js runtime
backtrace (symbolize against this version's unstripped libestella_js_host.so):
  0x7b41e2632c  /data/app/.../libestella_js_host.so+0x1e32c
```

这些地址需用同一引擎版本**未剥离符号**的 `libestella_js_host.so` 解析（`llvm-addr2line -e libestella_js_host.so 0x1e32c`）；APK 中的副本已剥离符号。

从 Android 设备读取记录：

```bash
adb shell cat /sdcard/Android/data/<your.package.id>/files/estella-boot.log
adb pull /sdcard/Android/data/<your.package.id>/files/estella-boot.log
```

<Aside type="caution">
  自 Android 11 起，文件管理器和系统“文件”应用无法访问应用的 `Android/data` 目录。`adb shell` 能够读取，是因为其用户属于 `ext_data_rw` 组。
</Aside>

发生崩溃后，下一次启动会将记录复制到文件管理器可访问的 `Android/media/<your.package.id>/`（回退到 `Download/`），文件名为 `estella-crash-<date>.log`。新运行的记录会给出该路径：

```
previous run CRASHED; its record was copied to
  /storage/emulated/0/Android/media/com.example.game/estella-crash-20260729-190738.log
```

向玩家收集崩溃报告的方式：再打开一次游戏，然后发送该目录中最新的 `estella-crash-*.log`。只有崩溃会被复制。

设备连接期间，同样的内容也会出现在 `logcat` 中：

```bash
adb logcat --pid=$(adb shell pidof <your.package.id>)
```
