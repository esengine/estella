**热更新** 用 **CDN** 上的新版本替换已发布游戏的资产——纹理、音频、预制体。运行中的客户端只下载改动过的资产；不重新下载整包，也不需要重新提交商店审核。

热更新具备**内容寻址**、**原子性**（全部成功或全部不生效，可回滚）、**完整性校验**（与哈希不符的字节会被拒绝）以及**对游戏代码透明**（内置的重新绑定器将新资产换入运行中的组件）。同一机制运行在 Web、桌面、小游戏和原生应用上。

<Aside type="tip">
  [`hot-update-demo`](https://github.com/esengine/estella/tree/master/examples/hot-update-demo) 示例在单个精灵上演示了完整流程，不含任何游戏代码。
</Aside>

## 工作原理

每个烘焙后的资产以 `<contentHash>.<ext>` 形式发布，这是一个不可变、可永久缓存的 URL。修改文件内容会改变哈希和 URL。只调整纹理采样或九宫格边距时，图片沿用原来的 URL。

<Steps>

1. 从 CDN **获取**远端清单（`asset-manifest.json`）。
2. 与运行中的清单**比对**文件哈希、交付位置和运行时设置。
3. **下载并校验** `downloadFiles` 列出的文件。
4. **切换**到新清单。场景中正在使用的纹理随即采用新图片或新设置。

</Steps>

只更新设置时，`hasUpdate` 为 `true`，`totalBytes` 为 `0`。调用 `applyUpdate` 会应用设置，开启持久化后下次启动也会沿用。

## 交付组

资产随包发布还是由 CDN 提供，按文件夹由其**交付组**决定。每个文件夹解析为三种模式之一：

| 模式 | 打包方式 | 徽标 | 发布位置 | 用途 |
| --- | --- | --- | --- | --- |
| **本地** | eager | — | 在包内，启动时加载 | 游戏核心资产 |
| **分包** | lazy | `PKG`（紫色） | 在包内，按需加载 | 较大的可选内容、[微信分包](/docs/zh-cn/publishing/wechat/#分包) |
| **远端** | remote | `CDN`（蓝色） | 由 CDN 提供；**可热更新** | 发布后需要修改的内容 |

只有 **远端** 分组会被热更新。本地和分包资产属于构建的一部分；分包在包内按需加载（[资产 → 寻址组](/docs/zh-cn/assets/overview/#寻址组懒加载)）。

### 将文件夹标记为 CDN 交付

在 **内容浏览器** 中右键文件夹，选择 **交付方式 → 远端（CDN / 热更）**。该文件夹中（递归）的所有资产随后由 CDN 提供。

![在内容浏览器右键文件夹并选择 交付方式 → 远端（CDN / 热更）](@/assets/guides/zh/hot-update-delivery-menu.png)

*内容浏览器 → 右键文件夹 → **交付方式** → **本地 / 分包 / 远端（CDN / 热更）**。选择结果写入 `.esengine/asset-groups.json`。*

同一子菜单中还有 **总是打进构建（即使无人引用）**，这是一个独立开关，即使文件夹中没有任何内容可从场景到达，也会将其保留在构建中（[资产](/docs/zh-cn/assets/overview/#只有代码点名的资产)）。

分配到分包或远端分组的文件夹会显示角标：远端为 `CDN`（蓝色），分包为 `PKG`（紫色）。

![内容浏览器中一个文件夹图块，带蓝色 CDN 交付徽标](@/assets/guides/zh/hot-update-cdn-badge.png)

*`cdn` 文件夹带有蓝色 **CDN** 徽标：其资产远端交付，可热更新。*

交付方式与文件夹名称无关。项目没有 `asset-groups.json` 时，名为 `remote/<name>/` 或 `subpackages/<name>/` 的文件夹仍隐含对应的交付模式。

### CDN 地址

远端分组的资产从 CDN 上的**根地址**获取。根地址是项目的打包设置（`project.esproject` 中的 `packaging.remoteRoot`），**导出配置档**可以覆盖它，因此测试构建和正式构建可以使用不同的 CDN。导出会将解析得到的根地址写入发布的游戏。在 **构建 → 打包项目… → 高级 → CDN 地址** 中设置：

![打包对话框的「高级」分组——CDN 地址、源码映射与完成后打开输出文件夹](@/assets/guides/zh/hot-update-build-cdn.png)

***CDN 地址** 字段写入项目的 `remoteRoot`，选中配置档时写入该配置档的值。留空时从游戏自身的源加载远端资产（例如用于本地测试）。*

```json
{
  "packaging": {
    "remoteRoot": "",
    "profiles": {
      "prod-web": { "platform": "web", "config": "shipping", "remoteRoot": "https://cdn.example.com/my-game" }
    }
  }
}
```

`estella export --profile prod-web`（或在对话框中选择 **prod-web**）使用正式环境的根地址构建；其他构建使用项目的根地址。

### `.esengine/asset-groups.json`

交付组和图集组保存在同一个手写文件中。烘焙和编辑器的运行环境通过同一个解析器读取它。

```json
{
  "version": "1.0",
  "groups": {
    "cdn": { "folder": "assets/cdn", "mode": "remote" }
  },
  "atlases": {
    "ui": { "folder": "assets/art/ui" }
  },
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | `string` | 配置版本（`"1.0"`）。 |
| `groups` | `Record<name, {folder, mode}>` | 文件夹到交付方式的分配。 |
| `groups.<name>.folder` | `string` | 项目相对的文件夹；其下（递归）所有资产加入该分组。文件夹嵌套时，最长匹配前缀优先。 |
| `groups.<name>.mode` | `'local' \| 'subpackage' \| 'remote'` | 交付模式。 |
| `groups.<name>.alwaysInclude` | `boolean` | 即使构建中没有任何内容到达该分组也打包——用于只在代码中引用的资产（URL、路径、富文本标记）。默认 `false`。见[资产](/docs/zh-cn/assets/overview/#只有代码点名的资产)。 |
| `atlases` | `Record<name, {folder}>` | 其中纹理打包到同一图集页的文件夹（需勾选 **打包图集**）。与 `groups` 相互独立：一个图集可以跨两个交付组，一个分组也可以包含两个图集。未设置时沿用 `<name>.atlas/` 文件夹约定。 |
| `atlases.<name>.folder` | `string` | 项目相对的文件夹；其中符合条件的 PNG 打包进该图集，网格使用的纹理单独导出。最长匹配前缀优先。 |
| `activeProfile`、`profiles` | — | CDN 根地址的旧存放位置，仅在项目未设置 `packaging.remoteRoot` 时读取。 |

## 随包发布的文件

每个 Web、桌面、小游戏和原生导出都会在游戏旁写出 **`asset-manifest.json`**（可寻址清单），客户端以它为基准比对。构建设置了 CDN 地址时，导出还会在 `game.config.json` 中写入 `hotUpdate` 块：

```json
{
  "hotUpdate": {
    "remoteRoot": "https://cdn.example.com/my-game",
    "persistUpdateKey": "esengine:hotupdate"
  }
}
```

启动时运行时读取该块并：

- 应用 `remoteRoot`，使远端分组的 `@uuid` 引用解析到 CDN；
- 根据 `persistUpdateKey`（设置了根地址时默认为 `esengine:hotupdate`）恢复之前已应用的更新，使再次进入的玩家直接从更新后的内容开始，离线时也是如此；
- 安装内置的重新绑定器，使已应用的更新无需游戏代码即可作用到运行中的组件。

发布更新时，将新烘焙的资产和新的 `asset-manifest.json` 上传到 CDN。上传是增量的：旧文件对尚未更新的客户端仍然有效。

## 检查并应用更新

游戏通过一次调用发起检查——在启动时、在 **检查更新** 按钮中，或定时进行。

```ts
import { defineSystem, Res, Schedule, Assets } from 'esengine';

async function pullUpdate(assets: Assets): Promise<void> {
  // 1. Fetch the CDN manifest and diff it against the running one (downloads nothing).
  const plan = await assets.checkForUpdate({
    manifestUrl: 'https://cdn.example.com/my-game/asset-manifest.json',
    remoteRoot:  'https://cdn.example.com/my-game',
  });
  if (!plan.hasUpdate) return;
  console.log(`Update available: ${plan.downloadFiles.length} files, ${(plan.totalBytes / 1024) | 0} KB`);

  // 2. 校验更新所需的文件，全部通过后切换清单。
  const result = await assets.applyUpdate((loaded, total) => {
    console.log(`Downloading ${loaded}/${total}`);
  });
  if (result.ok) console.log(`Applied — ${result.updated} assets updated`);
  else console.warn('Update failed, rolled back:', result.failed);
}

// Run it once at startup (guarded so the async check fires a single time).
let checked = false;
const checkForUpdates = defineSystem([Res(Assets)], (assets) => {
  if (checked) return;
  checked = true;
  void pullUpdate(assets);
});
// app.addSystems(Schedule.Update, checkForUpdates)
```

`checkForUpdate` 获取候选清单并返回 [`UpdatePlan`](#api-参考)，不下载任何资产，因此游戏可以在确认前显示大小（`N files, K KB`）。`applyUpdate` 负责下载和切换。

### 自动重新绑定

当场景通过 `@uuid` 引用远端分组的资产时，`applyUpdate` 下载新字节、切换清单，内置的重新绑定器会在所有声明了纹理的运行中字段里替换旧纹理：内置字段（`Sprite.texture`、`MeshRenderer.texture` / `.normalMap`、`UIVisual.texture`、`TilemapLayer.tileset`、`ParticleEmitter.texture`、`TrailRenderer.texture`）以及在 `assetFields` 中声明的项目组件字段。

如果组件也在 `discoverAssets` 返回的列表中声明了同一张纹理，`Sprite.texture` 或
`MeshRenderer.texture` 等运行中字段会切换到更新后的图像，列表则继续持有加载时的版本。
预制体实例和离开原场景的实体会在最后一个相应字段清空时释放字段持有的引用。
持有列表的场景或实体会将旧版本保留到自身生命周期结束。

材质文件改名后，`Sprite.material` 和 `MeshRenderer.material` 也会跟随清单中的同一条记录。
更新移除纹理或材质时，已有字段继续使用当前句柄。后续更新恢复同一个 UUID 后，运行中的字段会切换到恢复的资产。

替换资产按持有它的每个场景各获取一次，每个场景作为整体切换——该场景的绑定要么全部切换，要么全部不变。卸载一个场景不会从仍在使用它的另一个场景中释放更新后的纹理，卸载的场景也只释放自己持有的部分，无论它经历过多少次更新。

重新绑定器未覆盖的内容——手动绑定的纹理、音频、自定义系统——可订阅 `onInvalidate` 自行重新绑定：

```ts
const unsub = assets.onInvalidate((event) => {
  // `event.ref` was just invalidated by an update. `event.type` says what kind of
  // asset it was ('texture', 'audio', 'material', …) and `event.oldValue` what live
  // holders were bound to before the drop (a texture's handle).
  if (event.type !== 'texture') return;
  void assets.loadTexture(event.ref).then((tex) => { /* assign tex.handle */ });
});
```

## API 参考

热更新 API 位于 `Assets` 资源（`Res(Assets)`）上：

| 方法 | 返回值 | 说明 |
| --- | --- | --- |
| `checkForUpdate(options)` | `Promise<UpdatePlan>` | 获取候选清单，与当前清单比对并暂存。不下载资产。 |
| `applyUpdate(onProgress?)` | `Promise<ApplyUpdateResult>` | 校验 `downloadFiles` 中的文件，成功后切换清单、重新绑定运行中的句柄并持久化。`onProgress(loaded, total)` 报告下载进度。 |
| `restorePersistedUpdate(key)` | `boolean` | 启动时恢复之前 `applyUpdate` 以 `key` 持久化的清单。设置了 `persistUpdateKey` 时由运行时调用。 |
| `updateStatus()` | `UpdateStatus` | `{ revision, persistedRevision, staged, applying }`，用于诊断界面。 |
| `setRemoteRoot(url?)` | `void` | 设置远端分组的 CDN 根地址（`undefined` 清除，即同源）。运行时根据构建的 `remoteRoot` 设置。 |
| `remoteRoot` | `string \| undefined` | 当前的 CDN 根地址（getter）。 |
| `onInvalidate(listener)` | `() => void` | 订阅失效事件。监听函数接收 `{ ref, type, oldValue }`；返回取消订阅函数。 |
| `loadGroup(name, onProgress?)` | `Promise<AssetBundle>` | 按需加载整个分组（[按需分组](#按需分组)）。 |
| `releaseGroup(name)` | `void` | 释放 `loadGroup(name)` 获取的、仍待释放的最早一批资源。 |

**`CheckForUpdateOptions`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `manifestUrl` | `string` | 候选（远端）清单的 URL。 |
| `remoteRoot` | `string`（可选） | 候选清单中远端资产的 CDN 根地址，默认沿用当前地址。更换根地址时，即使清单相同，也会校验实际 URL 发生变化的文件。 |

**`UpdatePlan`**（`checkForUpdate` 的返回值）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `hasUpdate` | `boolean` | 资产、分组设置或构建修订号发生变化时为 `true`。 |
| `changedAssets` | `AssetChange[]` | 新增资产，以及主文件或交付位置发生变化的资产。 |
| `reconfiguredAssets` | `AssetChange[]` | 可以沿用主文件、以新设置或新预览生效的资产。 |
| `removedAssets` | `AssetChange[]` | 从清单移除的记录。移除无需下载文件，已有字段继续使用持有的版本。 |
| `changedGroups` | `string[]` | 成员、设置或资产发生变化的分组。 |
| `downloadFiles` | `UpdateFile[]` | 需要校验的实际文件。流式纹理可以同时包含原图和预览。同一交付位置的共享文件只计一次。 |
| `totalBytes` | `number` | `downloadFiles` 的大小总和，即下载量估计。 |
| `fromRevision` / `toRevision` | `string \| null` | 旧、新清单的修订号。 |

**`ApplyUpdateResult`**（`applyUpdate` 的返回值）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | `boolean` | 所需文件全部通过校验、候选清单已生效时为 `true`。 |
| `updated` | `number` | 已应用的资产数量（失败时为 `0`）。 |
| `failed` | `AssetDownloadFailure[]` | 校验未通过的文件路径及原因，包括下载失败（`fetch`）、完整性不符（`integrity`）或资源包发生变化（`packed`）。 |
| `stages` | `UpdateStages` | 应用进行到哪一步（见下）。仅凭 `ok` 无法判断下次启动是否保留该更新。 |
| `revision` | `string \| null` | 本次会话此后运行的修订号。 |
| `uncached` | `string[]` | 磁盘缓存拒绝写入的改动资产（按 URL）；下次启动会重新获取。 |
| `reason` | `'nothing-staged'`（可选） | 未做任何尝试：没有暂存的更新，或已被另一次 `applyUpdate` 取走。 |

**`UpdateStages`**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `verified` | `boolean` | 下载计划中的文件均已通过校验。 |
| `applied` | `boolean` | 本次会话运行在新清单上，其资产已切换完成。 |
| `persisted` | `boolean \| null` | 下次启动从新清单开始（已存储并回读确认）。存储被拒绝（配额已满）时为 `false`；没有持久化键时为 `null`。 |
| `cached` | `boolean \| null` | 所有改动的远端资产都在磁盘缓存中，下次启动无需网络即可读取。平台没有磁盘缓存（Web）时为 `null`。 |

`updateStatus()` 随时报告相同的信息：当前运行的修订号、下次启动的修订号、暂存的内容及其下载量，以及是否正在应用。

## 按需分组

远端分组也可以作为可下载内容加载：玩家到达相应内容时加载整个分组，离开后释放。

```ts
// Player enters "world 2" — pull its remote group from the CDN.
const bundle = await assets.loadGroup('world2', (loaded, total) => {
  showProgress(loaded / total);
});
// ...later, player leaves:
assets.releaseGroup('world2');
```

`loadGroup` 与其他资产使用相同的类型化加载器，`releaseGroup` 按引用计数释放：仍被其他场景持有的资产会保留。见[资产 → 寻址组](/docs/zh-cn/assets/overview/#寻址组懒加载)。

## 完整性、原子性与回滚

`applyUpdate` 分两个阶段运行：

<Steps>

1. **下载并校验。** 获取 `downloadFiles` 中的文件，计算哈希并与清单中的 `contentHash` 比较。下载失败或哈希不符（响应损坏或被篡改）记为失败。此阶段不修改当前清单。
2. **提交。** 仅当所有资产都成功时：切换清单和根地址、重新绑定运行中的句柄，并持久化新清单。

</Steps>

若第 1 阶段出现任何失败，则不应用任何内容：原清单保持生效，`applyUpdate` 返回 `{ ok: false, failed }`。

<Aside type="caution">
  烘焙后的 Web 构建默认启用**同源 CSP**。从其他源（不同主机或端口）获取清单或资产会被拦截，除非 CDN 返回所需的 CORS 头。请从游戏允许访问的源提供清单和资产。
</Aside>

## 持久化与离线启动

设置了 `persistUpdateKey`（导出会设置）时，`applyUpdate` 将已应用的清单保存到平台存储。下次启动时运行时调用 `restorePersistedUpdate(key)`，游戏从更新后的内容开始。在有磁盘缓存的目标上，校验过的字节也会写入缓存，因此更新后的资产无需网络即可加载；`stages.cached` 报告是否全部写入。见[设备磁盘缓存](/docs/zh-cn/publishing/content-cache/)。

已存储的更新属于应用它时所在的包。安装了更新的构建（新的 Web 部署、应用商店更新）后，已存储的更新比随包内容旧，会被丢弃。

更新一次只应用一个。另一个正在下载时发现的更新保持暂存；应用它时只下载前一次未带来的内容。

## 平台支持

| 目标 | 清单与比对 | CDN 获取 | 持久化 | 磁盘缓存 |
| --- | --- | --- | --- | --- |
| **Web** | 支持 | 支持（受 CORS 和 CSP 约束） | `localStorage` | 无；下次启动从 CDN 重新获取 |
| **桌面** | 支持 | 支持 | 支持 | 支持（内容寻址） |
| **小游戏**（微信、抖音等） | 支持 | 支持 | 支持 | 支持（宿主的用户数据目录） |
| **原生（iOS、Android）** | 支持 | 支持 | 支持 | 支持 |

比对与平台无关；只有获取、存储和磁盘缓存原语因平台而异。

## 建议

- 将可热更新的内容放在专门的远端文件夹中，游戏核心保持本地，使包在无网络时也能启动。
- 只在启动时或通过按钮检查一次，不要每帧检查。
- 在移动网络下进行大量下载之前，显示 `totalBytes` 和文件数量。
- 处理 `ok: false`：更新已回滚，可稍后重试。
- 使用导出配置档：项目根地址指向测试存储桶（或留空使用同源），正式 CDN 放在正式配置档中。
- 在同一 CDN 上通过不同的 `manifestUrl` 实现分阶段发布或 A/B 渠道。
