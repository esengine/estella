小游戏宿主（微信的 `wx`、抖音的 `tt` 等）提供几乎一致的 API：没有 DOM、打包的文件系统、分包、触摸输入和键值存储。Estella 将这一模型实现为一个平台**家族**，并把每个厂商描述为一份**配置**（profile）。微信是该家族中的一份配置。

本页说明如何接入 Estella 未内置的厂商。微信本身见[微信小游戏](/docs/zh-cn/publishing/wechat/)；SUD OpenPaaS 见 [SUD OpenPaaS](/docs/zh-cn/publishing/openpaas/)。

<Aside type="caution">
  **1.0 之前。** 配置约定为 `@beta`，随着更多厂商接入可能增加字段。
</Aside>

## 运行时配置

运行时配置由 id、名称和宿主全局对象组成，另可包含若干可选覆盖：

```ts
import { installMiniGamePlatform } from 'esengine/minigame';

declare const myHost: any;   // the host global, e.g. `tt`

installMiniGamePlatform({
  id: 'myvendor',
  hostLabel: 'MyVendor',
  get global() { return myHost; },
});
```

这已是一个完整的平台。文件系统、`fetch`、画布、图片解码、触摸与按键输入、存储、分包、内存压力信号、设备像素比和语言都来自规范化后的宿主全局对象，**音频**（`createInnerAudioContext`）和**套接字**（`connectSocket`）也是如此。视频使用引擎自带的 wasm MPEG-1 解码器。

通过 getter 读取 `global`：宿主全局对象只在运行时存在，getter 使配置可以在打包工具或测试中被导入。

### WebAssembly 实例化

唯一需要专门方法的宿主差异是 WASM 实例化。微信通过 `WXWebAssembly.instantiate(path)` 而不是标准的 `WebAssembly` 实例化，因此其配置覆盖了 `instantiateWasm`：

```ts
{
  id: 'wechat',
  hostLabel: 'WeChat',
  get global() { return wx as unknown as MiniGameGlobal; },
  instantiateWasm(pathOrBuffer, imports) { /* WXWebAssembly */ },
}
```

使用标准 `WebAssembly` 的宿主无需提供该方法；平台家族会通过打包文件系统读取二进制并实例化。

### 可替换的后端

`createAudioBackend`、`createVideoBackend` 和 `createSocket` 是可选覆盖。默认实现为 `MiniGameAudioBackend`、wasm 视频解码器和 `MiniGameSocket`，均从 `esengine/minigame` 导出，可供包装。覆盖也可用于替换项目不需要的实现，例如视频解码：

```ts
import type { MiniGameProfile, PlatformVideoBackend, VideoBackendContext } from 'esengine/minigame';

class SoftwareVideoBackend implements PlatformVideoBackend {
  readonly name = 'my-software-decoder';
  constructor(private ctx: VideoBackendContext) {}
  createStream(url: string, options) { /* your decode → VideoStreamHandle */ }
  dispose() {}
}

export default {
  id: 'myvendor',
  hostLabel: 'MyVendor',
  get global() { return myHost; },
  createVideoBackend: (ctx) => new SoftwareVideoBackend(ctx),
} satisfies MiniGameProfile;
```

`VideoPlugin` 在构建时向平台请求一次后端；游戏中所有 `VideoPlayer` 都使用它。约定为 `PlatformVideoBackend`：`createStream(url, options)` 返回一个 `VideoStreamHandle`，其 `pump(module)` 每帧将当前帧上传到 `textureHandle`。音频（`PlatformAudioBackend`）和套接字（`PlatformSocket`）遵循相同模式。

要保留某个宿主的配置只改一项能力，可展开该配置：

```ts
import { wechatProfile } from 'esengine/wechat';

export default { ...wechatProfile, createVideoBackend: (ctx) => new SoftwareVideoBackend(ctx) };
```

<Aside type="note">
  **内置目标不可覆盖。** 内置目标在导入时安装自己的配置，因此在打包项目中选择 *微信小游戏* 始终使用默认后端。要替换某项能力，应定义一个项目平台（[项目平台](#项目平台)），在其 `runtimeProfile` 中展开宿主配置并覆盖该能力，然后选择该目标。

  展开不会包含微信的 `WXWebAssembly` polyfill（由 `initWeChatPlatform()` 安装）；这种情况下需自行调用 `esengine/wechat` 中的 `polyfillWebAssembly()`。
</Aside>

## 宿主 API

`global` 必须满足 `MiniGameGlobal`。必需成员：

| 成员 | 用途 |
| --- | --- |
| `createCanvas()` | 显示表面（首次调用）和离屏 2D |
| `createImage()` | 图片解码 |
| `getFileSystemManager()` | `readFileSync` / `readFile` / `access` / `accessSync` / `writeFile` |
| `request(opts)` | `fetch` polyfill |
| `createInnerAudioContext()` | 音频播放 |
| `connectSocket(opts)` | `GameSocket` 和同步复制 |
| `getSystemInfoSync()` | 视口尺寸、像素比、语言 |
| `onTouchStart/Move/End` 及 `off*` | 指针输入 |
| `getStorageSync` / `setStorageSync` / `removeStorageSync` / `getStorageInfoSync` | 存档数据、热更新记录 |

可选成员，由适配层探测（缺失时相关功能降级）：`onTouchCancel` / `offTouchCancel`、`onKeyDown` / `onKeyUp`（及 `off*`）、`loadSubpackage`、`onMemoryWarning` / `offMemoryWarning`、`onShow` / `onHide`。

<Aside type="note">
  `isMiniGame()` 检查的是适配层声明的家族，而不是厂商名称列表，因此已安装的平台会走所有小游戏代码路径（打包读取、分包分组、无 DOM 分支）。`isWeChat()` 仍是厂商检查，返回 `false`。
</Aside>

## 启动

包的入口调用平台家族的运行时：

```js
// game.js — the host runs this
const engineFactory = require('./wasm/esengine.js');
const bundle = require('./game-bundle.js');
bundle.boot(engineFactory, { /* side module factories */ });
```

```ts
// bundled with the game
import { installMiniGamePlatform, initMiniGameRuntime } from 'esengine/minigame';
import { myProfile } from './myProfile';

export function boot(engineFactory, sideModuleFactories) {
  installMiniGamePlatform(myProfile);
  return initMiniGameRuntime({
    engineFactory,
    engineWasmPath: 'wasm/esengine.wasm',
    sceneNames: ['Main'],
    firstScene: 'Main',
    sideModuleFactories,
  });
}
```

`initMiniGameRuntime` 从适配层获取显示画布，将其 GL 上下文注册到引擎模块，加载可寻址清单并运行应用。`initWeChatRuntime` 是同一函数，只是填入了微信的 wasm 文件名。

<Aside type="note">
  必须在调用 `initMiniGameRuntime` **之前**安装平台，否则它会抛出错误，并在消息中给出修正方法。在所有小游戏宿主上，进程中第一次 `createCanvas()` 得到的是显示表面，因此在运行时之前不得创建任何画布。
</Aside>

## 项目平台

在 **打包项目** 中，将鼠标悬停在目标列表的 *项目自定义* 分组上并点击 **+**（或 **新建平台**）。选择类型 *小游戏宿主*，填写标识和名称后，编辑器会写出厂商的两个部分（已相互关联），并选中新目标。
打包部分是一个普通的项目文件：

```js
// .esengine/platforms/acme-play.mjs
export default {
  id: 'acme-play',
  label: 'ACME Play',
  blurb: 'ACME mini-game package.',
  defaultOut: 'dist-acme',

  emitConfigFiles(ctx) {
    return [{
      file: 'game.json',
      content: JSON.stringify({
        orientation: ctx.orientation,
        appName: ctx.title,
        ...(ctx.subPackages.length > 0 ? { subPackages: ctx.subPackages } : {}),
      }, null, 2) + '\n',
    }];
  },
};
```

未声明的部分均采用标准小游戏宿主的默认值：与厂商无关的 SDK 入口（`index.minigame.js`）、`initMiniGameRuntime`、标准 `WebAssembly` 引擎 glue 以及通用 CommonJS `game.js`。烘焙、清单、场景转换、侧模块扫描、打包和运行时复制使用微信的同一条流水线。

### 关联运行时配置

运行时部分即上文所述的 `MiniGameProfile`。`runtimeProfile` 指向它，生成的入口会在启动前安装它：

```js
// .esengine/platforms/acme-play.mjs
export default {
  id: 'acme-play',
  label: 'ACME Play',
  runtimeProfile: 'src/acme-runtime.ts',   // ← the other half
  emitConfigFiles(ctx) { /* … */ },
};
```

```ts
// src/acme-runtime.ts — default-exports the runtime MiniGameProfile
export default {
  id: 'acme-play',
  hostLabel: 'ACME Play',
  get global() { return acme; },
  createVideoBackend: (ctx) => new SoftwareVideoBackend(ctx),
};
```

在游戏指定宿主之前，`esengine/minigame` 不会安装任何平台；缺少 `runtimeProfile` 时包能正常构建，但在设备上会抛出错误。只有游戏自行调用 `installMiniGamePlatform` 时才可省略 `runtimeProfile`。编辑器会在将平台标记为就绪前检查该路径是否存在。

`id` 只能由小写字母、数字和连字符组成，且不能与内置目标重名。它同时是烘焙使用的**导入设置键**，因此可按平台名称为单张纹理设置覆盖。

<Aside type="note">
  加载失败的配置会连同错误一起列出。编辑器会探测平台所需的引擎运行时（`wasmDir`，默认为编辑器的 Web 运行时），以便在构建开始前在对话框中报告缺失的运行时。配置模块运行在编辑器主进程中，加载前需要批准（[编辑器插件](/docs/zh-cn/extending/editor-plugins/#项目平台配置)）。
</Aside>

### 配置字段

| 字段 | 说明 |
| --- | --- |
| `id` | 厂商标识；也是烘焙按纹理读取的导入设置键。 |
| `label`、`blurb`、`defaultOut` | 目标列表中的名称和描述；默认输出目录。 |
| `sdkEntryFile` | `esengine` 被映射到的 SDK dist 入口。 |
| `runtimeInit` | 生成的入口所导入的启动函数。 |
| `engineGlueCandidates` | 按优先顺序查找的引擎 glue 文件名。 |
| `esTarget` | 打包产物和降级后 glue 的语法级别。 |
| `wasmBuildHint` / `sideModuleBuildTargets` | 错误提示中使用的 `build -t …` 名称。 |
| `nativeSuffixes` / `binRestageExts` | 打包器的文件后缀策略。 |
| `subpackageDir` | 懒加载分组的存放位置。 |
| `emitConfigFiles` / `emitEntry` | 厂商的配置文件和 `game.js`。 |
| `wasmDir` | 项目相对的引擎运行时目录（默认为编辑器的 Web 运行时）。 |
| `runtimeProfile` | 项目相对的模块，默认导出运行时 `MiniGameProfile`。 |

配置模块运行在编辑器**主进程**而不是渲染进程中：其 emitter 是函数，无法跨越 IPC 边界，因此该文件是带默认导出的纯 `.mjs`。

## 宿主专属的引擎构建

只有无法加载 Web 引擎 wasm 的宿主才需要专属的引擎构建。微信需要（`-t wechat`，`ES_BUILD_WXGAME`），因为它使用 `WXWebAssembly` 且不支持 WebGPU。支持标准 `WebAssembly` 和 WebGL2 的宿主可以使用 Web 构建的 glue；`engineGlueCandidates` 会为此回退到 `esengine.js`。

不支持 WASM SIMD 的宿主使用不带 SIMD 的小游戏构建（`-t quickgame`，`ES_MAIN_DISABLE_SIMD`），侧模块也取同一套（`physics-quickgame`、`spine-quickgame` 等，都输出到 `build/wasm/quickgame`）。快游戏、支付宝和华为使用这套构建；抖音也使用，因为它的 iOS 宿主不支持 SIMD，而同一个包要同时在两种手机上运行。不带 SIMD 的构建在优化时也不开启 SIMD，产物里残留一条 SIMD 指令就会让构建失败。
