Estella 项目从编辑器导出到 **Web**、**桌面**、**微信小游戏**及其他小游戏宿主（抖音、快手、B 站、快游戏、支付宝、华为）、单文件 **Playable** 试玩广告，以及原生 **Android** 与 **iOS** 应用。所有导出都运行在与编辑器“运行”模式相同的运行时上。

## 打包项目对话框

![打包项目对话框——目标列表、构建配置、输出目录与构建场景](@/assets/guides/zh/build-dialog.png)

*左侧：分组的目标列表。右侧：所选目标的设置、配置档、配置、压缩、输出目录、构建包含的场景与“高级”选项。*

<Steps>

1. 打开 **构建 → 打包项目…**。
2. 选择**目标**。目标分为 *通用*（网页、桌面、Playable）、*小游戏*（微信、抖音、快手、B 站、快游戏、支付宝、华为快游戏，见[小游戏平台](/docs/zh-cn/publishing/minigame-platforms/)）、*移动*（Android、iOS）和 *项目自定义*（项目定义的平台）。有多个发行去向的目标在其下列出各去向：桌面分为 *独立发行* 和 *[Steam](/docs/zh-cn/publishing/steam/)*。
3. 填写目标自身的设置（*\<目标\>设置*）：应用标识及商店相关的值。
4. 选择 **配置档**（*项目设置*，或已保存的导出配置档）、**配置**（*开发* 或 *发行*）、**压缩** 复选框（[压缩](#压缩)）和 **输出** 目录。**高级** 中包含 CDN 地址、体积预算、源码映射和 *完成后打开输出文件夹*。
5. 检查 **构建包含的场景**（[构建包含的场景](#构建包含的场景)）。
6. 点击 **打包**。构建日志实时显示在对话框中。构建完成后打开输出目录（除非关闭了 *完成后打开输出文件夹*），Web 与 Playable 构建提供 **通过 http 预览**。

</Steps>

对话框中的选择保存在 `project.esproject` 中，下次打开时恢复。

### 导出配置档

导出配置档是针对单个目标的一组具名覆盖值，保存在 `project.esproject` 的 `packaging.profiles` 中：配置、源码映射、压缩复选框、CDN 地址、排除的场景以及目标专属设置。选中配置档时，对话框中的控件编辑的是该配置档；每个被覆盖的值旁有重置按钮，可将该设置交还给项目。*为这个平台新建配置档* 用于创建配置档。CLI 通过 `--profile <name>` 选择配置档。

## 导出目标

| 目标 | 产物 | 默认目录 | 后续步骤 |
|---|---|---|---|
| **网页** | 静态、自包含的 Web 构建。 | `dist-web/` | **通过 http 预览**，或将目录上传到静态托管。 |
| **桌面** | 每个已安装桌面运行时模板对应一个原生应用：macOS 上为 `.app`，Windows 上为包含 `<Name>.exe` 的 `<Name>/` 目录，Linux 上为 `<Name>`。不含 Chromium，也不是 npm 工程。 | `dist-desktop/` | 直接运行。**Steam** 渠道还会写出 depot 脚本和 `STEAM.md`，见 [Steam](/docs/zh-cn/publishing/steam/)。 |
| **微信小游戏** | 微信小游戏包。 | `dist-wechat/` | 用微信开发者工具打开该目录，见[微信小游戏](/docs/zh-cn/publishing/wechat/)。 |
| **抖音**、**快手**、**B 站**、**快游戏**、**支付宝**、**华为快游戏** | 对应宿主的小游戏包（快游戏和华为为签名的 `.rpk`），与微信使用同一条流水线构建。 | `dist-douyin/`、`dist-kuaishou/`、`dist-bilibili/`、`dist-quickgame/`、`dist-alipay/`、`dist-huawei/` | 用该平台的开发者工具打开。抖音和 B 站的 AppID 在目标设置中填写；快手和支付宝的 AppID 在开发者工具中填写；华为需要在 AppGallery Connect 注册应用。 |
| **Playable** | 一个内联全部资源的自包含 `index.html`。 | `dist-playable/<network>/` | **通过 http 预览**，然后上传到所选广告平台，见[试玩广告](/docs/zh-cn/publishing/playable-ads/)。 |
| **Android** | 通过 Vulkan 渲染的原生 arm64 应用：签名 APK、Android Studio 工程，或 APK 加 App Bundle。 | `dist-android/` | 安装 APK，或用 Android Studio 打开工程，见 [Android 与 iOS](/docs/zh-cn/publishing/android-ios/)。 |
| **iOS** | 通过 Metal 渲染的原生 arm64 应用，以 Xcode 工程形式写出。 | `dist-ios/` | 用 Xcode 打开工程，选择签名团队后运行。 |

桌面、Android 和 iOS 导出的是应用**内容**；引擎、SDK 和游戏运行时位于应用二进制中，该二进制由编辑器安装的运行时模板装配而成（[运行时前置条件](#运行时前置条件)）。

## 构建包含的场景

项目场景文件夹中的每个场景都会导出，并可作为 `SceneManager.switchTo` 的目标（[场景](/docs/zh-cn/world/scenes/)）。**构建包含的场景** 列表控制该集合：

- **启动场景** 固定在首位并带运行标记，始终打包。点击其他场景的运行按钮可移动该标记，也可在内容浏览器中场景的右键菜单里选择 **设为启动场景**。
- 取消勾选的场景不进入构建（记录在 `project.esproject` 的 `packaging.excludeScenes` 中）。被排除的场景在编辑器中仍可编辑和运行；只被排除场景引用的资产不会被烘焙。
- **Playable** 只导出启动场景。CLI 选项 `--all-scenes` 可内联全部场景。

## 构建配置

| 配置 | 行为 |
|---|---|
| **开发** | 脚本不压缩。可配合源码映射调试。支持的目标的开发构建可连接编辑器的帧调试器（“高级”中的 *帧调试器连接*）。 |
| **发行** | 脚本经过压缩（项目打包设置中的 *压缩脚本*，默认开启）。用于正式发布。 |

**包含源码映射**（高级）将运行中的包映射回 TypeScript 源码。仅对支持的目标（Web 和桌面）提供；发布构建应关闭。

## 压缩

每种压缩在 **压缩** 一行中各有一个复选框。所有复选框默认关闭；未勾选时资源原样输出，体积预算也不会自动勾选任何一项。各项所用的参数（纹理的格式和 Max Size、音频的码率）位于检视器中每个资产的 **导入设置**，按平台分页。

![选中 Web 目标的打包项目对话框，构建分组：配置、三个压缩复选框及其下方提示](@/assets/guides/zh/publish-compression.png)
| 复选框 | 目标 | 作用 |
|---|---|---|
| **纹理按导入设置压缩** | 全部 | 应用每张纹理的导入设置：目标支持时转为 GPU 格式（KTX2），并按 Max Size 缩小。Playable 只发布图片，因此只应用 Max Size。勾选期间，视口按本次构建的发布结果显示纹理。 |
| **打包图集** | 全部 | 将每个 `<name>.atlas/` 文件夹，或 `.esengine/asset-groups.json` 中的每个 [`atlases` 条目](/docs/zh-cn/publishing/hot-update/#esengineasset-groupsjson)，打包为图集页。 网格采样的纹理会单独导出。 |
| **音频转 MP3** | 全部 | 按各音频导入设置中的码率将 WAV 转为 MP3；导入设置中关闭压缩的音频保持 WAV。 |
| **压缩引擎二进制** | 小游戏 | 在宿主能够加载时，以 Brotli 压缩发布引擎 `.wasm`（及侧模块）。与微信目标页的 *压缩 wasm 二进制* 为同一设置。 |
| **图片转 WebP**（不转 / 无损 / 质量 90 / 质量 80） | Playable | 将 PNG 编码为 WebP，见[试玩广告](/docs/zh-cn/publishing/playable-ads/#图片编码)。 |

### 压缩纹理

运行时将 KTX2 纹理转码为设备支持的最佳格式（依次为 ASTC、ETC2、S3TC，最终回退到 RGBA8），并保留 mip 链。

<Aside type="caution" title="块压缩纹理的尺寸必须是 4 的倍数">
KTX2 可转码到的格式均为块压缩格式，而 WebGPU 拒绝宽或高不是 4 的倍数的压缩纹理。构建会将此类纹理以未压缩形式发布，并在警告中列出：

```
assets/textures/platform.png: shipped raw — 70x70 is not a multiple of 4,
which a block-compressed texture must be
```

将纹理缩放或填充到 4 的倍数，或将其打包进图集（图集页总是整块尺寸）。
</Aside>

### 内容寻址与资产包

- **内容寻址** 在 Web、桌面和小游戏目标上默认开启：每个文件以其字节的哈希命名，因此 URL 不可变，相同文件只存一份。
- **资产包**（Web）：导出将小型本地资产（网格、材质、KTX2 纹理、时间轴、动画资产）打包为少量 `packs/*.pack` 文件，每个文件一次请求加载；清单记录每个资产所在的位置。配置了[热更新](/docs/zh-cn/publishing/hot-update/) CDN 地址的导出保持每个资产一个文件，因为更新按资产逐个下载。

<Aside type="caution" title="只被代码引用的资产会被剔除">
  烘焙只打包从构建场景可达的资产。只在代码中引用的资产——富文本标记中的纹理、按 URL 播放的音频、按路径生成的预制体——会被剔除。编辑器直接从磁盘读取项目，因此这一遗漏只在导出的构建中可见。在内容浏览器中将这类文件夹标记为 **交付方式 → 总是打进构建（即使无人引用）**（[资产](/docs/zh-cn/assets/overview/#只有代码点名的资产)）。
</Aside>

## 打包设置

单个目标专属的设置在 **打包项目** 中该目标的页面上编辑（在设置对话框中搜索会链接到这些设置）：

| 目标 | 设置 |
|---|---|
| **网页** | Web 发行渠道（独立发行、Poki、CrazyGames、YouTube Playables，见 [Web 游戏平台](/docs/zh-cn/publishing/web-portals/)）、无 WebAssembly 时运行、方向不对时提示旋转设备。 |
| **微信小游戏** | AppID、压缩 wasm 二进制、引擎放入分包、通过 EmscriptenGLX 渲染。 |
| **桌面** | 桌面 App ID（覆盖值）、产品名称（决定应用名称）、发行渠道（独立发行或 Steam）。 |
| **Android** | Android 版本号、打包为（安装包或 Android Studio 工程）、包含模拟器（x86_64）、压缩原生库、Google Play App Bundle（.aab）、发布签名密钥。 |

项目级设置位于 **设置 → 项目 → 构建与模块 → 打包**，随项目保存：

| 设置 | 说明 |
|---|---|
| **应用 ID** | 已安装应用的反向域名标识：Android manifest 的包名、iOS 的 bundle id、桌面安装程序的 id。留空时由项目名派生。发布前应设置，商店会永久保留该值。 |
| **应用图标** | 一张方形 PNG，供所有可安装目标使用。 |
| **成就 ID** | 游戏会解锁的成就 id。与平台无关；供 [Steam](/docs/zh-cn/publishing/steam/#成就) 等商店使用。 |
| **压缩脚本** | 在发行构建中压缩游戏与引擎的 JavaScript。默认开启。 |
| **编译所有系统** | 发行构建将编译器能处理的所有系统编译为机器码；关闭时只编译标记了 `@compiled` 的系统。默认开启。 |

![设置 → 项目 → 构建与模块的“打包”分节](@/assets/guides/zh/publish-packaging-settings.png)
### 屏幕方向

屏幕方向是唯一的项目级设置：**设置 → 项目 → 游戏 → 显示 → 屏幕方向**（竖屏或横屏）。未设置时由设计分辨率推导（宽 ≥ 高为横屏，否则为竖屏）。各目标的应用方式：

| 目标 | 应用方式 |
|---|---|
| 微信及其他小游戏 | `game.json` 中的 `deviceOrientation` |
| 网页 | 尽力调用 `screen.orientation.lock` |
| 桌面 | 窗口宽高比 |
| Android、iOS | 原生应用的 `app.config.json` |
| Playable | 仅在广告平台要求时向平台声明；不锁定页面方向（[试玩广告](/docs/zh-cn/publishing/playable-ads/#屏幕方向)） |

在 Web 上，以另一方向握持手机时游戏以加黑边方式显示。开启 **方向不对时提示旋转设备**（网页目标设置）后，触屏设备方向不对时画布被“请旋转设备”提示遮住，直到转正为止；桌面浏览器始终显示游戏。清单写法如下，默认关闭：

```json
"packaging": { "platforms": { "web": { "rotateHint": true } } }
```

## 预览导出结果

**网页** 或 **Playable** 构建完成后，**通过 http 预览** 在回环地址（`http://127.0.0.1:<port>/`）上提供输出目录并在浏览器中打开。

<Aside type="caution">
  Web 构建需要 **http 源**。直接从磁盘打开 `index.html`（`file://`）无法流式加载 WebAssembly。请使用预览按钮或静态托管。
</Aside>

## 运行时前置条件

| 目标 | 运行时 | 准备工作 |
|---|---|---|
| 网页、Playable | 随编辑器提供的引擎运行时。Playable 将其内联（glue 作为 blob 模块，wasm 作为 base64）。 | 无。 |
| 微信及使用微信运行时的小游戏 | 由于 WebAssembly 加载方式不同而单独构建的运行时，以及微信侧模块。随编辑器安装包提供。 | 已安装的编辑器无需准备。在源码检出中需构建一次（见下）。 |
| 桌面、Android、iOS | 每个编辑器版本一个**运行时模板**。安装前，打包项目中该目标的行会提供 **下载** 和 **从文件安装…**。 | iOS 另需装有 Xcode 的 macOS。含 `@compiled` 系统的项目，桌面需要 C 编译器（clang 或 gcc），Android 需要 Android NDK。 |

```bash
# source checkout only, before the first WeChat export
node build-tools/cli.js build -t wechat
```

对话框区分两类缺失的前置条件：

- 缺少**引擎运行时**（网页、Playable、微信）会阻止导出。微信导出会给出需要运行的构建命令。微信小游戏使用 `physics-wechat` 构建 Box2D。使用 3D 物理时，按项目选择构建 `physics3d-wechat`（Jolt）或 `physics3d-physx-wechat`（PhysX）。抖音的 iOS 宿主不支持 WASM SIMD，所以抖音包使用不带 SIMD 的运行时：同样的模块，名字后缀为 `-quickgame`（`physics-quickgame`、`physics3d-quickgame` 等）。其他可选模块见[微信小游戏](/docs/zh-cn/publishing/wechat/)。
- 缺少**原生工具链**（iOS）不会阻止导出。应用内容照常写出；只有装配为可安装应用的最后一步需要工具链，且这一步可以在另一台机器上完成。

<Aside type="caution" title="原生目标需要运行时模板">
  桌面、Android 和 iOS 的运行时模板不包含在编辑器安装包中。每个编辑器版本需从打包项目中目标所在的行安装一次对应模板，且模板版本必须与编辑器完全一致。Android 不需要引擎源码、SDK 或 JDK；iOS 另需装有 Xcode 的 macOS。见 [Android 与 iOS](/docs/zh-cn/publishing/android-ios/#前置条件) 和 [Steam](/docs/zh-cn/publishing/steam/)。
</Aside>

## 侧模块

可选的引擎功能以 WebAssembly **侧模块**形式发布——一个 emscripten `<file>.js` glue 加一个 `<file>.wasm`——按需加载：

| 模块 | 产物 | 加载时机 |
|---|---|---|
| 物理（Box2D） | `physics.js` / `physics.wasm` | 项目声明了物理，或场景使用 2D 物理组件。 |
| 3D 物理（Jolt） | `physics3d.js` / `physics3d.wasm` | 场景使用 `RigidBody3D`。与 2D 模块同时加载，而非替代。 |
| 3D 物理（PhysX） | `physics3d-physx.js` / `physics3d-physx.wasm` | 同上，用于 3D 求解器为 PhysX 的项目。一个包只携带两个 3D 模块中的一个。 |
| Spine | `spine21`、`spine38`、`spine41`、`spine42`、`spine43`（`.js` / `.wasm`） | 场景使用对应格式版本的 Spine 骨架。 |
| DragonBones | `dragonbones.js` / `dragonbones.wasm` | 场景使用 DragonBones 骨架。一个模块读取所有版本。 |
| Basis 转码器 | `basis.js` / `basis.wasm` | 构建发布了 KTX2 纹理。 |
| 视频解码器 | `videodec.js` / `videodec.wasm` | wasm 视频路径解码视频。 |

| 目标 | 侧模块的交付方式 |
|---|---|
| 网页、桌面 | 作为独立文件放在 `esengine.wasm` 旁，从 `wasmBaseUrl`（引擎加载所在的目录）获取。 |
| Playable | 以 base64 内联到 HTML 中；`initPlayableRuntime` 接收一个内嵌的侧模块宿主。 |
| 微信 | 微信预编译的模块工厂，因此每个功能需要一个 `*-wechat` 运行时构建。 |
| Android、iOS、桌面应用 | 编译进应用二进制。 |

编辑器的运行模式通过同一运行时（`initPlayRealmRuntime`）启动，从编辑器源获取侧模块。运行时 API 见[应用初始化与生命周期](/docs/zh-cn/core-concepts/app/overview/#侧模块)。

## 目标无法渲染的内容

如果某个目标没有编译项目所用的子系统，导出会报告该子系统（瓦片地图、粒子、后处理、物理、Spine、视频、文本）以及使用它的场景或文件，而不会写出缺少该部分的包。当前所有目标都不存在这种缺口：原生应用编译了完整的引擎源码列表，包括在 Web 上作为独立侧模块的部分。

## 无 WebAssembly 的浏览器

**无 WebAssembly 时运行**（网页目标设置）会在 `wasm/esengine.wasm` 旁增加编译为纯 JavaScript 的引擎 `wasm/esengine.asm.js`。页面在启动时选择：存在 `WebAssembly` 时加载 wasm 引擎，且不会下载 JavaScript 版本；不存在时（部分受限的 WebView 和内嵌浏览器）加载 `esengine.asm.js`，运行相同的场景和脚本。清单写法：

```json
"packaging": { "platforms": { "web": { "engineJs": true } } }
```

该设置默认关闭。它使包体增加约 4 MB，计入宿主的上传上限。关闭时，没有 WebAssembly 的浏览器会显示一条指明该设置的错误。小游戏目标从不包含该文件。要在普通浏览器中测试 JavaScript 引擎，可在开启该设置后导出，并在 URL 后加上 `?engine=js`。

| `hello-world` 示例，无头 Chromium | WebAssembly 引擎 | JavaScript 引擎 |
|---|---|---|
| 引擎文件 | 2.1 MB（gzip 0.67 MB） | 4.3 MB（gzip 0.98 MB） |
| 每帧主线程耗时 | 9.3 ms | ~11.5 ms |

JavaScript 引擎不支持：

- **WebGPU**——始终通过 WebGL2 渲染。
- **侧模块**（2D 与 3D 物理、Spine、DragonBones、Basis、视频）——每个模块记录一条指明模块的错误，其功能不运行。
- **已编译（`@compiled`）系统**——以解释方式运行，与未启用 AOT 的导出相同。

## 构建 CLI

编辑器负责打包游戏。`build-tools/cli.js` 用于构建**引擎和 SDK**；在源码检出中构建微信运行时、开发引擎以及装配原生应用时需要它：

```bash
node build-tools/cli.js build -t web        # build the engine (web target)
node build-tools/cli.js build -t wechat     # the WeChat runtime
node build-tools/cli.js sdk                 # build the SDK only
node build-tools/cli.js watch               # rebuild on change (engine development)
node build-tools/cli.js native --target ios # the native mobile host
```

不经编辑器打包项目使用 `pipeline/bin/estella.mjs export <projectDir>`；`--help` 列出其选项（`--platform`、`--profile`、`--out`、`--json`、`--enforce-budget` 等）。CI 示例见[包体体积](/docs/zh-cn/publishing/package-size/#按体积拦截构建)。
