每次导出都会测量包体，结果显示在打包项目对话框的构建日志下方，并以 `result.size` 随导出结果一同给出。报告包括包体各项数字、按类别的构成、最大的文件及其被打包的原因、与上次构建相比的变化，以及对每个生效上限的判定。

## 体积数字

| 数字 | 内容 |
|---|---|
| **首包** | 游戏可玩之前需要下载的字节：宿主页面、引擎运行时、脚本，以及 `local` 交付组中的资产。 |
| **按需分包** | 分包，在游戏加载对应分组时获取。 |
| **CDN（不进包）** | `remote` 交付组中的资产。由 CDN 提供，不计入包体。见[热更新](/docs/zh-cn/publishing/hot-update/#交付组)。 |

这一划分读取自运行时加载的同一份资产清单。将内容移入分包或远端分组后，它就不再计入首包。

## 包内的引擎子系统

包只携带项目用到的引擎子系统，其余部分不打包。是否用到依据导出已有的证据判断：场景和预制体中的组件、资产扩展名（`.esgraph`、`.esfsm`、`.esbt`）、扫描到的侧模块，以及项目脚本导入的 `esengine/*` 子路径。

只在代码中使用的子系统——手动构建的瓦片地图、脚本打开的套接字——在脚本导入其子路径后即被包含：

```ts
import { Tilemap } from 'esengine/tilemap';
```

使用 **视频** 的项目携带完整引擎及全部可选子系统，因为视频没有子路径。两种情况下 API 完全相同。

### 微信运行时目标上的精简引擎

在微信、抖音、快手和 B 站上，若没有任何场景或预制体包含粒子发射器、后处理体积或瓦片地图，且没有脚本提及它们，包会携带**精简引擎**——去掉粒子、后处理和瓦片地图的引擎，小约 200 KB。脚本中出现一次（`ParticleEmitter`、`PostProcess…`、`Tilemap…`），或在项目设置中将 `esengine/tilemap` 设为 **Include**，即选用完整引擎。无法确定时选用完整引擎。

## 平台上限

平台公布了上限时，构建会据此判定。报告会给出所用上限并引用其出处。

| 目标 | 上限 |
|---|---|
| 微信 | 主包 4 MB（按打包字节计）；全部包合计 30 MB |
| 抖音 | 主包 4 MB；全部包合计 20 MB（开通虚拟支付的账号为 30 MB——需设置体积预算才会按此判定） |
| 快手 | 主包 6 MB；全部包合计 30 MB |
| B 站 | 主包 4 MB；每个分包 4 MB；全部包合计 30 MB |
| 快游戏（vivo、OPPO、小米、荣耀） | 主包 4 MB；全部包合计 20 MB |
| 支付宝 | 主包 4 MB；全部包合计 20 MB |
| 华为快游戏 | 主包 4 MB；全部包合计 20 MB |
| Playable | 所选广告平台的上限，见[试玩广告](/docs/zh-cn/publishing/playable-ads/#广告平台) |
| 网页、桌面、Android、iOS | 无公布上限；可设置[体积预算](#体积预算) |

超出上限的构建只报告，不阻止。达到上限 90% 以上时指示条变为琥珀色。

## 体积预算

**打包项目 → 高级 → 体积预算** 为所选目标设置以 MB 为单位的上限，按平台以字节保存在 `packaging.sizeBudget` 中。留空则使用平台自身的上限。

预算**替换目标的主要上限**（微信为 4 MB 主包），并标注为项目设定而非平台规则。其他上限仍然有效：微信的 30 MB 总量依旧适用。没有公布上限的目标按首包判定。

## 按体积拦截构建

无头导出器报告相同的判定结果，并可据此失败：

```bash
node pipeline/bin/estella.mjs export ./my-game \
  --platform wechat --json report.json --enforce-budget
```

使用 `--enforce-budget` 时，超出任一生效上限的包以状态码 1 退出，并在 stderr 中指明该上限。不加该选项时仍生成报告，构建照常成功。`--json` 将导出结果（包括 `result.size`）写入指定文件。
