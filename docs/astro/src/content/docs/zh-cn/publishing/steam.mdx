Steam 是**桌面目标的一个发行渠道**。它不增加运行时、渲染器或资产格式：Steam 构建就是桌面构建加上 SteamPipe 所需的文件。

桌面构建是原生应用：引擎的 C++ 核心配合内嵌的 [Dawn](https://dawn.googlesource.com/dawn)（macOS 上为 Metal，Windows 上为 D3D12，Linux 上为 Vulkan），运行于 SDL3 之上，并带有 JavaScript 引擎——Windows 上为带 JIT 的 [V8](https://v8.dev/)，macOS 和 Linux 上为 [QuickJS-ng](https://github.com/quickjs-ng/quickjs)。进程中没有浏览器，因此 Steam 覆盖层、Steam 输入和独占全屏的表现与其他原生游戏相同。

<Aside type="note" title="运行时模板">
  桌面运行时是一个**运行时模板**，每个编辑器版本从打包项目的桌面行安装一次，每个操作系统一个。装配器是纯 Node 程序，因此在 Mac 上安装 Windows 模板后，同一份导出也能生成 Windows 构建。
</Aside>

## 前置条件

<Steps>

1. **一个 Steamworks 应用。** 从 Steamworks 合作伙伴后台获得 App ID。depot、启动选项和成就均在后台配置，构建不会写入这些内容。

2. **Steamworks SDK**，从合作伙伴网站下载。Estella 不附带该 SDK：其再分发权仅授予 Steamworks 合作伙伴，而运行时模板是所有游戏共用的同一个预编译二进制。

3. **`steamcmd`**，Valve 的上传工具。先在终端中登录一次，使 Steam 令牌验证通过并缓存；Estella 不保存任何密码。

</Steps>

## 渠道设置

在 **构建 → 打包项目…** 中，选择目标列表里桌面下的 **Steam**。选择它会将桌面目标的 **发行渠道** 设为 Steam。

![打包项目对话框的 桌面 → Steam 页：发行渠道选中 Steam，以及 Steam 分组里的 App ID、Steamworks SDK 和各 OS 的 depot id](@/assets/guides/zh/steam-channel.png)

| 设置 | 说明 |
|---|---|
| **发行渠道** | `Steam` 会在构建旁写出 depot 脚本。与在目标列表中选择 Steam 是同一个值。 |
| **Steam App ID** | 来自合作伙伴后台。未填写时不写出脚本。 |
| **Steamworks SDK** | 下载的 SDK。其 `redistributable_bin/<os>/` 中的库会打包进应用。 |
| **Depot ID** | 为 0 时依次使用 `App ID + 1` 等。depot id 由 Valve 分配；`STEAM.md` 列出所用的 id 以供核对。 |

成就 id 是项目级设置：**设置 → 项目 → 构建与模块 → 打包 → 成就 ID**（[成就](#成就)）。

对应的 CLI 选项为 `pipeline/bin/estella.mjs export --platform desktop` 的 `--steam-sdk <dir>` 和 `--steam-appid <id>`。

## 产物

```
dist-desktop/
  MyGame.app/            ← macOS, and/or
  MyGame/                ← Windows: MyGame.exe + Content/
                         ← Linux:   MyGame     + Content/
  steam/
    app_build_<appid>.vdf
    depot_<id>_<os>.vdf
  STEAM.md               ← this build's own values
```

`STEAM.md` 列出本次构建需要在合作伙伴后台填写的值：各操作系统的启动可执行文件、所用的 depot id、游戏实际写入的 Auto-Cloud 路径，以及需要创建的成就 id。构建结果中的 **打开 STEAM.md** 可直接打开它。

<Aside type="caution" title="从不写出 steam_appid.txt">
  `steam_appid.txt` 允许构建在 Steam 之外运行，而将它放进 depot 会关闭 Steam 的启动检查。导出从不写出该文件。
</Aside>

## 上传

```bash
steamcmd +login <your-account> +run_app_build "…/steam/app_build_<appid>.vdf" +quit
```

生成的构建脚本包含 `Preview "1"`，因此首次运行不会上传任何内容，只报告将要执行的操作。删除该行后才会真正上传。`SetLive` 为空：将分支设为上线需在合作伙伴后台操作。

## 成就

`Achievements` 与 `Ads`、`Leaderboard` 一样是引擎服务，因此无论是否接入商店，游戏代码都相同：

```ts
import { Achievements } from 'esengine';

const achievements = world.getResource(Achievements);
achievements.setStat('enemies_defeated', count);
await achievements.unlock('FIRST_BLOOD');
await achievements.store();      // pushes to Steam; stores batch behind this
```

解锁总会记录在本地，即游戏内成就界面读取的同一份数据。`available` 表示商店是否也会收到解锁，UI 据此选择使用平台通知还是自行绘制。

| 失效情形 | 处理方式 |
|---|---|
| 后台未定义的 id | id 在 **成就 ID** 中声明；不在列表中的解锁在调用处被拒绝，并列出已声明的 id。 |
| 构建中缺少 Steam 库 | SDK 设置缺失时导出给出警告，`STEAM.md` 在开头注明。 |

## 云存档

`Storage` 写入操作系统规定的用户目录，Steam Auto-Cloud 无需代码即可同步。在合作伙伴后台的 **Steam Cloud → Auto-Cloud** 中，使用 `STEAM.md` 列出的根目录：

| 操作系统 | 根目录 | 子目录 |
|---|---|---|
| Windows | `WinAppDataRoaming` | `Estella/<Name>` |
| macOS | `MacHome` | `Library/Application Support/Estella/<Name>` |
| Linux | `LinuxHome` | `.local/share/Estella/<Name>` |

## 限制

- **macOS 构建使用 ad-hoc 签名**，且只在 Mac 上构建时签名。公开发布前需使用 Developer ID 进行公证。
- **编辑器不运行 `steamcmd`。** `STEAM.md` 给出确切命令。
- **不支持：** 创意工坊、DLC、微交易和 Steam 输入操作集。
