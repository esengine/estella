Estella 能把同一个项目导出为**微信小游戏**。你从编辑器导出游戏，
再用微信开发者工具打开结果。

## 为微信构建引擎

编辑器下载包已经自带微信引擎和它的侧模块，装好的编辑器不需要做这一步。在引擎源码检出里，
需要先构建一次。微信目标用微信的 `WXWebAssembly` 垫片编译 C++ 内核：

```bash
node build-tools/cli.js build -t wechat
# 侧模块，仅当你的游戏用到时：
node build-tools/cli.js build -t physics-wechat   # 物理
node build-tools/cli.js build -t spine-wechat     # Spine（一次构建 2.1 + 3.8 + 4.1 + 4.2 + 4.3）
node build-tools/cli.js build -t dragonbones-wechat # DragonBones
node build-tools/cli.js build -t basis-wechat     # KTX2 / 压缩纹理
node build-tools/cli.js build -t videodec-wechat  # 视频（MPEG-1 wasm 解码器）
```

<Aside type="note">
  **缺失运行时是导出硬错误，不是警告。** 如果某个场景用了物理或 Spine，或构建里
  带 KTX2 纹理，而对应的 `*-wechat` 模块没构建，导出会直接停下，并给出要运行的
  确切构建命令。导出器只暂存场景实际需要的侧模块，未用到的不会增加包体。
</Aside>

## 从编辑器导出

<Steps>

1. 在**设置 → 项目 → 构建与模块 → 打包 → 微信**中，填写 AppID。屏幕方向是项目级设置——在**设置 → 项目 → 游戏 → 显示 → 屏幕方向**里设一次即可(它驱动下面 `game.json` 的 `deviceOrientation`)。

2. 打开**构建 → 打包项目…**，在 Package Project 对话框里选 **WeChat** 平台，
   检查**构建场景**列表，点击 **Package**。Estella 会烘焙资源，把 SDK 与你的
   脚本打包（用 esbuild 打成 CommonJS），转换场景，并写出一个独立的小游戏包。

3. 用**微信开发者工具**打开输出目录，编译、测试、提交。如果 AppID 留空了，
   在开发者工具里填进 `project.config.json` 即可。

</Steps>

输出目录包含 `game.js`（入口，负责引导 `game-bundle.js` —— SDK + 你的脚本）、
`game.json` / `project.config.json`（微信配置）、`asset-manifest.json`、以
`scenes/<名字>.json` 存放的场景，以及 `wasm/` 目录 —— 引擎加上场景实际需要的
侧模块。构建里的每个场景都是 `SceneManager.switchTo` 的切换目标——非启动场景在
首次切换时才加载（见[场景](/docs/zh-cn/world/scenes/)）。

<Aside type="caution">
  不要手改 `game.js` 或移动 `wasm/` 下的文件——引导序列按暂存时的确切文件名
  实例化，改名会让游戏在开发者工具里直接挂掉。
</Aside>

## 压缩纹理

打包对话框的**资源压缩**选**按导入设置**时，纹理按各自导入设置里的**压缩**
（自动、GPU 压缩或原图）烘焙为 KTX2 —— 包更小、首屏更快。两个微信
特有的细节，都已自动处理：

- Basis 转码器以 `basis-wechat` 侧模块的形式随包发布——构建一次（见上），否则
  导出会失败并给出确切命令。
- 微信的代码包只接受白名单后缀，`ktx2` 不在其中——所以导出器把每个 `.ktx2` 暂存为
  `.ktx2.bin`，运行时两种拼写都能解析。导出器还会在 `project.config.json` 里为每个
  暂存的自定义扩展名（`.skel`、`.atlas`、`.bin` 等）生成 `packOptions.include`
  规则，让开发者工具打包并读取它们。

## EmscriptenGLX

微信的 EmscriptenGLX 让引擎的 GL 调用在 wasm 内执行、批量交给宿主，而不必每一次都跨到
JavaScript。在约一千次 draw call 的场景里，它在 Android 手机上让渲染耗时少了约 12%。

在 **打包项目** 的微信页打开 **通过 EmscriptenGLX 渲染**，并构建一次它需要的引擎：

```bash
node build-tools/cli.js build -t wechat-glx
```

构建会下载固定版本的微信库并校验哈希，并使用 emsdk 4.0.10（首次安装到 `tools/emsdk-glx`）——
那个库只为这个版本发布。wasm 多约 310 KB。

它在基础库 3.8.12 及以上的 Android、以及开启高性能+模式的 iOS 上生效。其他宿主（包括开发者工具）
照旧走 WebGL2；日志里的 `rendering through …` 一行会说明设备用的是哪一条。

## 分包（subpackages）

惰性资源分组会成为 `game.json` 里的微信 **subPackages**。运行时，
`assets.loadGroup('level2')` 底层会触发 `wx.loadSubpackage`，于是关卡按需下载，而不会
撑大初始包：

```json
{
  "deviceOrientation": "landscape",
  "subPackages": [
    { "name": "level2", "root": "subpackages/level2" }
  ]
}
```

## 最佳实践

- **保持在 4 MB 主包限制以内**：把按需内容移到 `subpackages/<name>/`——见
  [资源](/docs/zh-cn/assets/overview/)。导出会设置 `bigPackageSizeSupport`，超限的包
  在开发者工具里仍可*预览*——但上传照样卡限制。
- **压缩纹理** —— 见上文（让**资源压缩**保持**按导入设置**）；这是包体最大的一笔节省。
- **在微信开发者工具里测试**，而不只是浏览器——文件系统、存储与套接字后端都与 Web 不同。
- **在游玩中预加载下一关的分组**（`loadGroup`），让分包下载不卡过渡。

## 参见

启动器的 **WeChat Mini Game** 模板包含 CC0 选船小关卡、登录码/服务器交换
扩展点、分享请求、配置后启用的激励视频和设备本地积分。按复制后的
`README.md` 完成创建、改造、导出与提交。`wechat` 导出档启用引擎分包与
压缩 WASM；`web` 导出档可在本地游玩，并禁用不可用的宿主按钮。
在 `src/config.ts` 配置自己的广告单元与服务器交换，不把 AppSecret 放进项目。
取得登录码不等于认证，分享请求不证明完成，本地积分也不是云备份；
真实账号、后端、广告和设备仍需分别验收。

- [视频](/docs/zh-cn/graphics/video/) —— 为微信随包发布的 MPEG-1 wasm 解码路径。
