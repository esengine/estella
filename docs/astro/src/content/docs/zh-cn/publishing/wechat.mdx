**微信小游戏** 目标将项目导出为微信小游戏包，在微信开发者工具中打开、测试和提交。

## 微信运行时

微信通过 `WXWebAssembly` 加载 WebAssembly，因此使用带微信适配的独立引擎构建，以及微信版的侧模块。编辑器安装包已包含这些内容。在引擎源码检出中需构建一次：

```bash
node build-tools/cli.js build -t wechat
# side modules, only if the game uses them:
node build-tools/cli.js build -t physics-wechat     # physics
node build-tools/cli.js build -t spine-wechat       # Spine (builds 2.1 + 3.8 + 4.1 + 4.2 + 4.3)
node build-tools/cli.js build -t dragonbones-wechat # DragonBones
node build-tools/cli.js build -t basis-wechat       # KTX2 / compressed textures
node build-tools/cli.js build -t videodec-wechat    # video (MPEG-1 wasm decoder)
```

<Aside type="note">
  **缺少运行时是导出错误。** 若场景使用了物理或 Spine，或构建发布了 KTX2 纹理，而对应的 `*-wechat` 模块尚未构建，导出会停止并给出构建命令。包中只放入场景需要的侧模块。
</Aside>

## 导出

<Steps>

1. 打开 **构建 → 打包项目…**，在 **小游戏** 下选择 **微信小游戏**。
2. 在微信目标设置中填写 **AppID**。屏幕方向是项目级设置 **设置 → 项目 → 游戏 → 显示 → 屏幕方向**，写入 `game.json` 的 `deviceOrientation`。
3. 检查 **构建包含的场景** 后点击 **打包**。导出会烘焙资产，用 esbuild 将 SDK 和脚本打包为 CommonJS，转换场景并写出小游戏包。
4. 用 **微信开发者工具** 打开输出目录进行编译、测试和提交。如果 AppID 留空，可在开发者工具中于 `project.config.json` 里填写。

</Steps>

### 目标设置

| 设置 | 默认值 | 说明 |
|---|---|---|
| **AppID** | 空 | 写入 `project.config.json`。 |
| **压缩 wasm 二进制** | 关 | 引擎与每个侧模块以 `.wasm.br` 形式发布。见[引擎二进制](#引擎二进制)。 |
| **引擎放入分包** | 关 | 将引擎二进制移入启动时加载的分包。 |
| **通过 EmscriptenGLX 渲染** | 关 | 将引擎与微信的 EmscriptenGLX 链接。见 [EmscriptenGLX](#emscriptenglx)。 |

### 包结构

| 路径 | 内容 |
|---|---|
| `game.js` | 入口；启动 `game-bundle.js`。 |
| `game-bundle.js` | SDK 和项目脚本。 |
| `game.json`、`project.config.json` | 微信配置。 |
| `asset-manifest.json` | 可寻址资产清单。 |
| `scenes/<name>.json` | 构建中的每个场景；非启动场景在首次 `SceneManager.switchTo` 时加载（[场景](/docs/zh-cn/world/scenes/)）。 |
| `wasm/` | 引擎及场景所需的侧模块。 |

<Aside type="caution">
  不要编辑 `game.js`，也不要重命名 `wasm/` 下的文件。启动流程按原样实例化这些文件。
</Aside>

## 压缩纹理

勾选“压缩”中的 **纹理按导入设置压缩** 后，纹理按其 **Compression** 导入设置（Auto、GPU compressed 或 Original image）烘焙为 KTX2。微信专属的处理：

- Basis 转码器以 `basis-wechat` 侧模块形式发布；缺少时导出失败并给出构建命令。
- 微信代码包只接受白名单中的文件后缀，而 `ktx2` 不在其中。导出器将每个 `.ktx2` 存为 `.ktx2.bin`，运行时两种写法都能解析。导出器还会在 `project.config.json` 中为每个自定义扩展名（`.skel`、`.atlas`、`.bin` 等）写入 `packOptions.include` 规则，使开发者工具将它们打包。

## 引擎二进制

引擎 `.wasm` 是小游戏中最大的单个文件。以下两项设置可使其不占用 4 MB 主包：

- **压缩 wasm 二进制**（与“压缩”中的 **压缩引擎二进制** 为同一设置）将引擎和每个侧模块以 `.wasm.br` 形式发布，约为原大小的三分之一，由微信在加载时解压。需要**基础库 2.14.0** 或更高版本。包中只有压缩后的文件，运行时不检查版本，因此开启后需在微信后台将小游戏的最低基础库设为 2.14.0。
- **引擎放入分包** 将二进制移入启动时加载的分包，不再计入主包；启动需等待其下载完成，加载条显示下载进度。

## EmscriptenGLX

微信的 EmscriptenGLX 在 wasm 内部执行引擎的 GL 调用，并分批交给宿主，而不是每次调用都进入 JavaScript；在绘制密集的场景中渲染耗时约降低 12%。开启 **通过 EmscriptenGLX 渲染**，并构建一次所需的引擎：

```bash
node build-tools/cli.js build -t wechat-glx
```

构建会下载固定版本的微信库并校验其哈希，使用 emsdk 4.0.10（首次使用时安装到 `tools/emsdk-glx`），即该库发布时所对应的版本。wasm 增加约 310 KB。

它在基础库 3.8.12 及以上的 Android 上生效，在 iOS 上需开启高性能+模式。其他宿主（包括开发者工具）通过 WebGL2 渲染。日志中的 `rendering through …` 一行说明设备实际使用的路径。

## 分包

懒加载的资产分组会成为 `game.json` 中的微信 `subPackages`。首次读取 `level2` 中的文件时，运行时会等待 `wx.loadSubpackage` 成功。也可以调用 `assets.loadGroup('level2')` 提前加载整个组。

```json
{
  "deviceOrientation": "landscape",
  "subPackages": [
    { "name": "level2", "root": "subpackages/level2" }
  ]
}
```

## 建议

- **将主包控制在 4 MB 以内**，把按需内容移入分包（[资产](/docs/zh-cn/assets/overview/)）。导出会设置 `bigPackageSizeSupport`，因此超限的包仍可在开发者工具中预览，但上传时会强制执行上限。见[包体体积](/docs/zh-cn/publishing/package-size/)。
- **压缩纹理**：勾选 **纹理按导入设置压缩**。
- **在微信开发者工具和真机上测试**；文件系统、存储和套接字后端与 Web 不同。
- **在游玩过程中预加载下一关的分组**（`loadGroup`），避免分包下载拖慢关卡切换。

## 起始项目

启动器中的 **WeChat Mini Game** 模板会创建一个 CC0 舰队游戏，包含登录码/服务端换取钩子、分享请求、已配置的激励视频以及保存在设备本地的积分。其 `README.md` 涵盖创建、定制、导出和提交。`wechat` 导出配置档启用引擎分包；`web` 配置档在本地运行游戏，并禁用仅宿主可用的按钮。广告位和服务端集成在 `src/config.ts` 中设置。项目不包含 AppSecret 或示例账号。登录码不是已认证的身份，分享请求不代表分享已完成，本地积分也不是云端备份。
