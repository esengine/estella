一根**连线（wire）**规定：当本实体收到此事件时，在那个实体上运行此动作。连线是发出事件的实体上的数据行，存储在 `EventBinding` 组件中；无需回调或脚本文件。

```
click ─▶ ui.setPage(tabs, settings)      on "This entity"
click ─▶ ui.setPage(badge, on)           on "Card"
```

一行中没有分支，也没有表达式。逻辑通过 `fsm.fire` 等动作委托给[状态机](/docs/zh-cn/gameplay/ai/overview/)，或写成[脚本图](/docs/zh-cn/gameplay/script-graphs/)，其 **On event** 节点监听相同的具名实体事件。

## 事件区域

![细节检视器中的事件区域](@/assets/guides/zh/events-section.png)

*按钮上的两根连线。两者都在 `click` 时触发；一根切换按钮祖先链上的控制器，另一根按名称指向 `Card` 实体。*

选中能够发出事件的实体——UI 节点、`Interactable`、碰撞体——其连线显示在细节面板的**事件**区域中。每一行从左到右为：

| 部分 | 说明 |
|---|---|
| ☑ | 行是否启用。未勾选的行保留在数据中，但从不触发。 |
| 事件 | 要监听的事件类型（`click`、`change`、`trigger_enter`……）。 |
| ↳ 目标 | 动作运行所在的实体：默认为*本实体*，也可**按名称**指定其他实体。 |
| 动作 | 已注册的动作名，与状态机及行为树编辑器使用同一候选列表。 |
| 参数 | 动作声明的参数。未声明参数的动作接受一个自由文本参数。 |
| ⚙ | 显示**条件**（必须通过的已注册条件）与**仅一次**。 |

## `EventBinding` 组件

连线存储在 `EventBinding` 组件中，因此与其他组件一样序列化进场景，并随[预制体](/docs/zh-cn/world/prefabs/)一起携带：

```typescript
import { EventBinding, UIEventType } from 'esengine';

world.insert(button, EventBinding, {
  rows: [
    { event: UIEventType.Click, action: 'ui.setPage', params: { controller: 'tabs', page: 'settings' } },
    { event: 'trigger_enter', target: 'Door', action: 'ui.setVisible', params: { visible: true }, once: true },
  ],
});
```

| `EventBindingRow` 字段 | 类型 | 说明 |
|---|---|---|
| `event` | `string` | 要监听的事件类型。可为任意字符串；内置类型为预定义集合。 |
| `target` | `string?` | 动作运行所在实体的名称。省略时为携带该行的实体。 |
| `action` | `string` | 已注册的动作名。 |
| `params` | `Record<string, …>?` | 按名称给出的动作声明参数。优先于 `arg`。 |
| `arg` | `string?` | 同一输入的规范字符串形式（`"tabs:settings"`）。 |
| `guard` | `string?` | 行运行前必须通过的已注册条件。 |
| `once` | `boolean?` | 最多运行一次，此后保持失效，直到场景重新加载。 |
| `enabled` | `boolean?` | `false` 使该行失效而不删除。 |

连线仅在运行期间触发；编辑器在创作时不运行动作。

### 目标解析

`target` 是实体**名称**，从该行所在实体向外查找：实体自身，然后是其子树，然后是各级祖先的子树，最后是整个场景。使用最近的匹配项，因此同一预制体的两个实例不会互相解析：对话框 A 中的 `Close` 按钮找到的是对话框 A 的 `Panel`，而不是对话框 B 的。

未匹配任何实体的名称在细节面板中以红色显示，并在运行时记录警告。

## 动作

动作是共享动作注册表中的具名函数，`.esfsm` 状态钩子与 `.esbt` 叶子也在同一注册表中解析。已注册的名称出现在全部三个候选列表中。

![按命名空间分组的动作候选列表](@/assets/guides/zh/events-palette.png)

*候选列表按 `namespace.` 前缀对动作分组；引擎的动作附带一行说明。*

内置动作：

| 动作 | 作用 |
|---|---|
| `ui.setPage` | 将 [UI 控制器](/docs/zh-cn/ui/controllers/)切换到某一页。 |
| `ui.setVisible` | 显示或隐藏一棵 UI 子树（`UINode.display`）。 |
| `property.set` | 写入任意组件字段，以 `Component.dot.path` 寻址。可选的 `entity` 参数写入另一个实体。 |
| `fsm.fire` | 在目标的状态机上触发一个触发器。 |
| `blackboard.set` | 设置黑板值（`key=value`；值为有效 JSON 时按 JSON 解析）。 |
| `scene.load` · `scene.reload` | 切换到指定场景，或重启当前场景，可选以秒计的淡入淡出。 |
| `audio.play` · `audio.stop` | 驱动目标的 `AudioSource`；`audio.play` 可指定另一个音频剪辑。 |
| `soundEvent.trigger` · `soundEvent.stop` | 驱动目标的声音事件源。 |
| `timeline.play` · `timeline.pause` | 驱动目标上的[时间轴](/docs/zh-cn/animation/timeline/playback/)。 |
| `spriteAnim.play` · `spriteAnim.restart` · `spriteAnim.stop` | 驱动精灵序列帧。 |

导入 `esengine/logic`（脚本图）时还会注册 `entity.despawn` 与 `debug.log`。

### 自定义动作

`registerAction(name, spec)` 使一个名称在所有候选列表中可用：

```typescript
import { registerAction } from 'esengine';

registerAction('game.award', {
  params: [
    { name: 'kind', type: 'enum', options: [{ label: 'Coin', value: 'coin' }, { label: 'Star', value: 'star' }] },
    { name: 'amount', type: 'number' },
  ],
  run: (ctx, bb, arg, params) => {
    grantReward(ctx.entity, params!.kind as string, params!.amount as number);
  },
});
```

声明的 `params` 以类型化控件（此处为下拉框与数字框）取代自由文本框。`ctx` 与状态机动作接收的上下文相同——`entity`、`world`、`commands`——外加黑板。

<Aside type="tip" title="在何处注册">
  编辑器不执行玩法代码；它从项目的[声明入口](/docs/zh-cn/scripting/script-modules/#声明入口)（默认 `src/components.ts`）读取动作名。在此注册的动作出现在所有候选列表中。在其他位置注册的动作仍可运行，但其名称必须手动输入。
</Aside>

## 事件

### UI 事件

控件发出标准事件集（`UIEventType`）。事件会**冒泡**，因此面板上的行能收到其按钮的事件：

`click` · `press` · `release` · `hover_enter` · `hover_exit` · `focus` · `blur` · `change` · `submit` ·
`drag_start` · `drag_move` · `drag_end` · `scroll` · `select` · `deselect` · `pointer_move` · `press_cancel` ·
`shown` · `hidden`

指针事件（`press`、`release`、`click`、`pointer_move`、`press_cancel`）携带 `UiPointerEventData`：

| 字段 | 说明 |
|---|---|
| `pointer` | 指针 id；鼠标为 `-1`。 |
| `worldX`、`worldY` | 世界中的位置。 |
| `screenX`、`screenY` | 表面上的位置，以像素计，从左下角向上测量。 |
| `layoutX`、`layoutY` | UI 布局空间中的位置。 |

被按下的实体在指针按住期间持续收到 `pointer_move`，无论指针移动到何处。`UIControlPointers.cancelHold(pointer, to?)` 释放按住：按住者收到 `press_cancel`，不产生点击；指定 `to` 时由另一个实体接管手势的剩余部分。仅由 `ContentRect` 与 `Interactable` 组成的实体也可被按下。

`shown` 与 `hidden` 在节点出现在屏幕上或离开屏幕时发出，通常因为某个**祖先**被显示或隐藏，导航、标签页与对话框均是如此。受影响子树中的每个节点都会收到，因此针对某个屏幕出现的动作就是该屏幕上的一行：

```
shown ─▶ fsm.fire(enter)  on "MissionPanel"   →   Hidden ──enter──▶ Entering
```

在没有行监听 `shown` 或 `hidden` 之前，可见性跟踪没有开销；在没有 UI 变化的帧中同样没有开销。

### 物理事件

[物理](/docs/zh-cn/gameplay/physics-2d/overview/)接触通过同一通道投递（`Physics2DEventType`），因此[触发区域](/docs/zh-cn/gameplay/markers/)的连接方式与按钮相同。两个参与者都会收到事件，各自以对方为对端：

`collision_enter` · `collision_exit` · `collision_hit` · `trigger_enter` · `trigger_exit`

### 自定义事件

事件词汇是开放的。通过 `EntityEvents` 发出的任何名称都可被行监听：

```typescript
import { EntityEvents } from 'esengine';

app.getResource(EntityEvents).emit(chest, 'looted', { gold: 12 });
```

## 交给状态机处理

一行只运行一个动作，除守卫外没有条件，也没有顺序编排。`fsm.fire` 将事件传给实体的[状态机](/docs/zh-cn/gameplay/ai/overview/)，由状态机决定其含义：

```
click ─▶ fsm.fire(start)  on "Hint"   →   Idle ──start──▶ Running
                                                          onEnter: property.set(…)
```

![状态机编辑器中状态钩子的声明参数](@/assets/guides/zh/events-fsm.png)

*状态机编辑器中的相同参数控件：`property.set` 声明了 `path` 与 `value`，因此钩子显示两个字段，而非一个字符串。*

动作只需声明一次参数，所有创作界面——事件行、状态钩子、行为树叶子——都会显示它们。

## 参数形式

每个动作都有规范字符串形式。`{ controller: 'tabs', page: 'settings' }` 与 `"tabs:settings"` 等价，注册表负责二者之间的转换：

- 在动作声明参数之前创作的数据继续照常运行；
- 只读取 `arg` 的动作在行存储参数时也能收到 `arg`；
- 对于存储纯字符串的行，细节面板显示类型化控件。

细节面板写入 `params`；手写数据可使用任一形式。

<Aside type="caution" title="不支持资源与实体参数">
  参数不能是资源引用或实体句柄。烘焙的资源发现与场景的实体重映射都不检查行参数，因此这类参数会导致构建缺失资源。其他实体通过 `target` 名称指定；资源通过烘焙能够发现的组件引用。
</Aside>
