`defineBehavior` 声明每实体的游戏逻辑。一次调用生成：

1. 一个**组件**，持有该 behavior 的每实体 `state`。可挂到任意实体，并在细节面板中编辑。
2. 一个已注册的**系统**，为每个携带该组件的实体运行 `start` / `update` / `destroy` 生命周期。

一个 behavior 恰好等于 [ECS](/docs/zh-cn/core-concepts/ecs/) 上的一个 `defineComponent` 加一个 `defineSystem`；不存在独立的脚本运行时。

## 定义 behavior

`defineBehavior(name, def)` 返回其背后的组件，该组件与其他组件一样通过 spawn 或 insert 使用。`state` 对象成为该组件的每实体数据：

```typescript
import { defineBehavior, Transform } from 'esengine';

export const Patrol = defineBehavior('Patrol', {
  state: { speed: 60 },   // per-entity data, editable in the Details panel
  update(ctx, dt) {
    const t = ctx.get(Transform);
    t.position.x += ctx.self.speed * dt;
    ctx.set(Transform, t);
  },
});
```

| `BehaviorDef` 字段 | 类型 | 说明 |
|---|---|---|
| `state` | object | 每实体数据及其默认值；成为组件的字段。 |
| `metadata` | `ComponentMetadata` | 字段呈现与组件元数据，转交给组件（[可编辑状态](#可编辑状态)）。 |
| `schedule` | `Schedule` | 生命周期系统运行的阶段。默认 `Schedule.Update`（[调度](#调度)）。 |
| `touches` | `SystemTouches` | 通过 `ctx.get` / `ctx.set` 访问的组件（[声明访问的组件](#声明访问的组件)）。 |
| `start` / `update` / `destroy` | 函数 | 生命周期钩子（[生命周期](#生命周期)）。 |

插入 behavior 的组件即将其挂到实体上，可同时覆盖初始 `state`：

```typescript
import { defineSystem, Commands, Transform } from 'esengine';

const spawn = defineSystem([Commands()], (cmds) => {
  cmds.spawn()
    .insert(Transform, { position: { x: 0, y: 0, z: 0 } })
    .insert(Patrol, { speed: 120 });   // per-instance override
});
```

在编辑器中，behavior 通过 **细节面板 → 添加组件**（类别 **Scripts**）添加到实体，其 `state` 字段也在此编辑。只有可从项目声明入口到达的 behavior 才会出现在编辑器中（[脚本模块](/docs/zh-cn/scripting/script-modules/#声明入口)）。

## 生命周期

每个钩子均为可选。

| 钩子 | 运行时机 |
|---|---|
| `start(ctx)` | 一次，在 behavior 的组件首次出现在实体上的那一帧。 |
| `update(ctx, dt)` | 每帧，对每个携带该 behavior 的实体运行。`dt` 为以秒计的帧间隔（等于 `ctx.time.delta`）。 |
| `destroy(ctx)` | 一次，在组件被移除**或**实体被销毁时。 |

```typescript
export const Enemy = defineBehavior('Enemy', {
  state: { hp: 100 },
  start(ctx) {
    // one-time setup: initialize state, cache lookups, spawn a health bar
  },
  update(ctx, dt) {
    if (ctx.self.hp <= 0) ctx.commands.despawn(ctx.entity);
  },
  destroy(ctx) {
    // runs whether the entity was despawned or the component was removed
  },
});
```

`destroy` 由实体在 behavior 查询中的**存在性**驱动：实体离开查询的那一帧即运行，与由哪个系统、以何种顺序移除无关。

## 上下文

每个钩子都会收到其所运行实体的 `BehaviorContext`：

| 成员 | 类型 | 说明 |
|---|---|---|
| `ctx.self` | `S` | behavior 自身的 `state`。修改会保留。 |
| `ctx.entity` | `Entity` | 该实例所挂载的实体。 |
| `ctx.time` | `TimeData` | 帧计时：`delta`、`elapsed`、`frameCount`、`fixedDelta`。 |
| `ctx.input` | `InputState` | 键盘、鼠标、触摸与手柄（[输入](/docs/zh-cn/scripting/input/overview/)）。 |
| `ctx.commands` | `Commands` | 延迟执行的 spawn、despawn 与 insert；遍历期间可安全使用。 |
| `ctx.world` | `World` | 世界，用于访问其他实体。 |
| `ctx.get(Comp)` | `ComponentData` | 读取**本**实体上的另一个组件。 |
| `ctx.set(Comp, data)` | `void` | 写入**本**实体上的组件。 |
| `ctx.has(Comp)` | `boolean` | 本实体是否拥有 `Comp`。 |

<Aside type="caution">
  **引擎组件以拷贝形式返回。** 对脚本组件（`defineComponent` 定义的组件，以及 `ctx.self`），`ctx.get` 返回存储的对象本身，修改会保留。`Transform`、`Sprite`、`RigidBody2D` 以及其他所有 C++ 支撑的组件在每次读取时从 WebAssembly 堆中解码；修改返回值不产生任何效果。应读取值、修改后再用 `ctx.set` 写回。
</Aside>

```typescript
import { defineBehavior, Transform } from 'esengine';

export const PlayerController = defineBehavior('PlayerController', {
  state: { speed: 200, facing: 1 },
  update(ctx, dt) {
    const move = (ctx.input.isKeyDown('KeyD') ? 1 : 0) - (ctx.input.isKeyDown('KeyA') ? 1 : 0);
    if (move !== 0) ctx.self.facing = move;        // mutating self persists
    if (move !== 0) {
      const t = ctx.get(Transform);                // a copy — Transform is C++-backed
      t.position.x += move * ctx.self.speed * dt;
      ctx.set(Transform, t);                       // written back
    }
  },
});
```

<Aside type="caution">
  `ctx` 对象在不同实体与不同帧之间**复用**，仅在钩子调用期间有效。将它或其 `self`、`time`、`input` 存入闭包或集合供之后使用，读到的将是其他实体的数据。应改为复制所需的值。
</Aside>

## 可编辑状态

`state` 对象定义组件的字段与默认值。`metadata` 控制它们在细节面板中的呈现——范围、步长、单位、枚举、类别——使用与任何[组件](/docs/zh-cn/core-concepts/components/#字段元数据)相同的字段元数据：

```typescript
export const Turret = defineBehavior('Turret', {
  state: { range: 300, fireRate: 2, target: 0 },
  metadata: {
    fields: {
      range: { min: 0, unit: 'px', category: 'Targeting' },
      fireRate: { min: 0, unit: '/s', category: 'Targeting', tooltip: 'Shots per second.' },
    },
  },
  update(ctx, dt) { /* … */ },
});
```

state 是一个序列化组件：每实体的值随场景保存，并在细节面板中实时编辑。

## 调度

生命周期系统默认在 `Schedule.Update` 中运行，每帧一次。`schedule` 可选择其他阶段，例如用 `Schedule.FixedUpdate` 与物理同步步进：

```typescript
import { defineBehavior, Schedule } from 'esengine';

export const Thruster = defineBehavior('Thruster', {
  schedule: Schedule.FixedUpdate,
  state: { force: 500 },
  update(ctx) {
    // fixed cadence; ctx.time.fixedDelta is the fixed step
  },
});
```

可用阶段：`Startup`、`First`、`PreUpdate`、`Update`、`PostUpdate`、`Last`，以及 `FixedPreUpdate` / `FixedUpdate` / `FixedPostUpdate`（[调度](/docs/zh-cn/core-concepts/systems/#调度)）。

### 声明访问的组件

通过 `ctx.get` / `ctx.set` 访问的组件对调度器不可见。没有声明时，behavior 被视为不透明，与其他所有系统冲突。`touches` 列出这些组件，使 behavior 能够参与排序并与其他系统并行运行（[声明访问](/docs/zh-cn/core-concepts/systems/#声明访问)）；behavior 自身的 state 组件已自动声明：

```typescript
export const Drifter = defineBehavior('Drifter', {
  state: { speed: 60 },
  touches: { reads: ['Transform'], writes: ['Transform'] },
  update(ctx, dt) { /* … */ },
});
```

## behavior 与系统

`defineBehavior` 适合天然以**实体**为单位的逻辑：巡逻、投射物、拾取物。普通[系统](/docs/zh-cn/core-concepts/systems/)适合一次处理整个查询，或协调多个实体。

钩子上下文——`entity`、`world`、`commands` 与 `self`——与[游戏 AI](/docs/zh-cn/gameplay/ai/overview/) 的动作及行为树叶子使用同一编程模型，因此逻辑可在 behavior 与 AI 动作之间迁移而无需重构。
