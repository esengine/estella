`SaveManager` 以带版本的封装（`{ version, data, savedAt }`）存储具名存档槽。每次存档都记录写入时的 schema `version`，因此游戏可以更改存档格式，同时仍能读取旧存档：读档时，旧数据会被前向迁移。

## 存档槽

游戏使用当前 schema `version` 创建一个管理器，并按名称读写存档槽：

```typescript
import { SaveManager } from 'esengine';

const saves = new SaveManager({ version: 1 });

saves.save('slot1', { level: 3, score: 1200, hp: 80 });

const data = saves.load<{ level: number; score: number; hp: number }>('slot1');
// -> { level: 3, score: 1200, hp: 80 }   (null if the slot is empty)

saves.has('slot1');       // true
saves.savedAt('slot1');   // epoch ms when the slot was written, or null
saves.remove('slot1');    // deletes the slot
```

| 方法 | 说明 |
|---|---|
| `save(slot, data)` | 以当前版本与时间写入 `data`。 |
| `saveAsync(slot, data)` | 同 `save`，并在写入刷新后兑现（[异步写入](#异步写入)）。 |
| `load(slot)` | 返回迁移到当前版本的存档槽数据；存档槽为空或不可读时返回 `null`。 |
| `has(slot)` | 存档槽是否存在。 |
| `remove(slot)` | 删除存档槽。 |
| `savedAt(slot)` | 存档槽的写入时间（epoch 毫秒），或 `null`。 |

| `SaveManagerOptions` | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `version` | `number` | — | 当前 schema 版本。必填。 |
| `migrations` | `Record<number, SaveMigration>` | — | 迁移步骤（[Schema 迁移](#schema-迁移)）。 |
| `keyPrefix` | `string` | `'save:'` | 管理器的存档槽在存储中的命名空间。 |
| `storage` | `SaveStorage` | 平台 `Storage` | 注入的存储，用于测试。 |
| `now` | `() => number` | `Date.now` | `savedAt` 使用的时钟，用于确定性测试。 |

## Schema 迁移

存档格式变更时，递增 `version`，并为每一步添加一个迁移。`migrations[n]` 将版本 `n` 写入的存档升级到 `n + 1`；读档时，从存档版本到当前版本的每一步依次运行：

```typescript
const saves = new SaveManager({
  version: 2,
  migrations: {
    // v1 stored a flat score; v2 nests it under `stats`.
    1: (old) => {
      const s = old as { level: number; score: number };
      return { level: s.level, stats: { score: s.score, deaths: 0 } };
    },
  },
});

// A v1 save is upgraded to the v2 format on load.
const data = saves.load('slot1');
```

迁移**只能向前**。读取比当前版本更新的存档会抛出异常，迁移链中缺少某一步同样会抛出异常。

`migrateSaveData(version, data, currentVersion, migrations)` 以纯函数形式提供迁移链，用于在 `SaveManager` 之外迁移数据（单元测试、一次性导入）。

## 键值存储

`Storage` 是按平台实现、带类型化辅助方法的键值存储，用于无需版本管理的标志与偏好设置：

```typescript
import { Storage } from 'esengine';

Storage.setBoolean('muted', true);
Storage.setNumber('volume', 0.8);
Storage.setJSON('keybinds', { jump: 'Space', fire: 'KeyJ' });

Storage.getBoolean('muted', false);   // true
Storage.getNumber('volume', 1);       // 0.8
Storage.has('keybinds');              // true
```

| 分组 | 成员 |
|---|---|
| 类型化访问 | `getString` / `setString`、`getNumber` / `setNumber`、`getBoolean` / `setBoolean`、`getJSON` / `setJSON` |
| 键 | `has(key)`、`remove(key)`、`clear()` |
| 刷新 | `flush()` |

`SaveManager` 构建于 `Storage` 之上，因此二者使用同一底层存储。

<Aside>
  读取与暂存写入均为同步操作。异步宿主可能在其存储服务确认之前保持写入为待定状态。存档保存的是游戏状态而非大块资源，且必须控制在目标平台的存储上限之内。
</Aside>

## 异步写入

需要确认进度已保存时，等待写入完成：

```typescript
await saves.saveAsync('slot1', { level: 4, score: 1500, hp: 80 });
// Or after several Storage writes:
Storage.setNumber('completedLevels', 4);
await Storage.flush();
```

- 暂存写入或宿主刷新失败时，二者均会拒绝。云端请求失败后，最新的内存数据可能仍可读取；在重试的 `Storage.flush()` 成功之前，它并未保存。
- `SaveManager.saveAsync` 写入相同的带版本封装，并遵循与 `save` 相同的迁移规则。
- 异步平台适配器实现 `PlatformAdapter.flushStorage()`，且必须在接受写入之前加载已有数据。将数据存为单个云端数据块的适配器会串行化请求，并在较早的存档仍在进行时保留较新的更改。加载失败或不受支持时，不得视为空存档。
- 在同步适配器上，等待 `flush()` 仅完成已有的写入；它不会增加云存储，也不会确认服务商的云端备份。例如 CrazyGames SDK Data 的备份调度独立于 `setItem`。

## 底层存储

`Storage` 不提供文件系统路径；Web 与小游戏平台没有路径命名空间。各平台使用其持久化存储：

| 平台 | 底层存储 |
| --- | --- |
| Web | `localStorage` |
| 微信及其他小游戏 | `wx.setStorageSync` 及相关 API |
| iOS | `Application Support/estella-storage.json` |
| Android | `files/estella-storage.json`（应用内部数据目录） |
| Node | 仅内存；不会在进程结束后保留 |

iOS 上文件保存在 Application Support 中，因为系统可能清空 Caches 以回收空间。两个移动端位置均为应用私有，并包含在设备备份中。

Estella 0.41 之前的构建将文件保存在缓存目录中。新版本构建首次启动时，会将该处已有的文件移到当前位置。

`platformReadFile()` 不访问这些存储。它读取打包进构建的文件（APK 的 `assets/`、iOS 应用包），且为只读。
