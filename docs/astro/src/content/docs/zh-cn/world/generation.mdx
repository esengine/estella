`esengine/worldgen` 在世界被探索时按规则布置世界：连续的群落、美术组合好的成组物件、留出的空地和道路、先放大物件再放小物件。
布置是确定性的：在每台机器上相同，与各区块被请求的顺序无关。

职责划分如下：

| 参与方 | 提供 |
|---|---|
| 引擎 | 采样环境场、计算群落权重、逐层放置成组物件、让区域留空、为每个放置物分配稳定 ID，并按区块流送结果。 |
| 游戏 | 规则：有哪些群落、群落里有什么、哪里留给家园或道路。 |
| 美术 | 配方：一片树林、一组岩石、一条沿岸的芦苇带。 |

## WorldGen 组件

| 字段 | 默认 | 说明 |
|---|---|---|
| `rules` | `''` | 布置世界所用的规则：一个 `.esworld` 文件，或通过 `registerWorldRules` 注册的规则 ID。 |
| `version` | `1` | 生成该世界时使用的规则版本。存档会保留它；规则中已没有该版本时，世界失败（状态中给出原因），而不是布置出另一个世界。 |
| `world` | `''` | 游戏为该世界（星球、关卡）起的名称。 |
| `seed` | `1` | 世界的种子。换一个种子即按同一套规则布置出另一个世界。 |
| `paintGround` | `true` | 群落是否为地形上色。 |
| `surface` | `Plane` | `Plane` 把世界铺在 `Terrain` 上；`Planet` 表示该实体同时是 `Planet`，世界铺在其六个面上。 |
| `seaLevel` | `0` | `Planet` 时显示：海面高出星球半径的高度。低于它的地面位于水下。 |
| `groundStep` | `1.5` | `Planet` 时显示：在放置物下方读取地面的间距，以星球的单位计。值越大布置越快，贴合地面越粗略；布置开销随该值的平方下降。 |

规则放置的内容作为该实体的子实体，围绕[流送源](/docs/zh-cn/world/streaming/#流送源)（或相机）以[程序化区块](/docs/zh-cn/world/streaming/#程序化区块)的形式发布。

## 规则

规则是数据：群落、群落中的配方，以及它们所在的布置层。规则保存在 **`.esworld` 文件**中（编辑器中 **新建 → 新建世界规则**，
或在内容浏览器中打开已有文件），并在 WorldGen 的 `rules` 字段中引用。

- 世界规则编辑器列出文件中的群落、配方和布置层，用表单编辑每一项（网格和材质像其他资源一样选取），并在下方说明引擎是否接受当前规则。
- 保存文件后，打开的世界会重新布置，编辑器中和运行中的游戏均如此。
- 文件内容即 `registerWorldRules` 接受的 JSON，加载时会校验。引用了文件中未定义的配方或布置层、或缺少必需内容时，WorldGen 失败并指出出错位置。

![在 worldgen 示例中打开 wilds.esworld 的世界规则编辑器：左侧为群落、配方与布置层，右侧为 grove 配方的表单](@/assets/guides/zh/world-generation-rules-editor.png)
规则也可以从代码注册，游戏自定义的环境场即通过这种方式加入（函数不是数据）：

```ts
import { registerWorldRules } from 'esengine/worldgen';

registerWorldRules({
    id: 'mygame:wilds',
    versions: [1],
    biomes: [
        { id: 'forest', conditions: [{ field: 'moisture', min: 0.52, blend: 0.08 }, { field: 'up', min: 0.82, blend: 0.05 }],
          transition: 120, paint: [0.55, 0.45, 0, 0], paintStrength: 0.5,
          recipes: [{ recipe: 'grove', layer: 'groups', density: 0.75 }] },
        // …
    ],
    recipes: [
        { id: 'grove', version: 1, tags: ['tree'],
          anchor: { id: 'elder', mesh: 'assets/models/pine.esmesh', material: 'assets/materials/pine.esmaterial', scale: [1.4, 1.8], footprint: 10, canopy: 35 },
          members: [
              { id: 'pine', mesh: 'assets/models/pine.esmesh', count: [3, 6], ring: [45, 110], scale: [0.9, 1.3], footprint: 8 },
              { id: 'sapling', mesh: 'assets/models/pine.esmesh', count: [2, 5], ring: [110, 170], scale: [0.35, 0.6], footprint: 4, chance: 0.8 },
          ] },
    ],
    layers: [
        { id: 'groups', spacing: 260, drawDistance: 4200, chunkSize: 512 },
        { id: 'detail', spacing: 90, drawDistance: 2400 },
    ],
});
```

### 环境场

每个决定都基于**环境场**：可在任意世界位置读取的数值。

| 环境场 | 来源 |
|---|---|
| `height`、`up`、`slope` | 地形表面。`up` 表示地面朝上的程度。 |
| `paint.<层名>` | 该处地面属于此地形层的程度，按层文件命名：`grass.esterrainlayer` 对应 `paint.grass`。没有层文件时为 `paint.grass`、`paint.dirt`、`paint.snow` 和 `paint.rock`。 |
| `waterDepth`、`shoreDistance` | 水体。`shoreDistance` 是干燥处到水边的距离，在水面上为负值。 |
| `moisture`、`temperature`、`rock` | 带种子的噪声，在世界尺度上缓慢变化；尺度由规则的 `noise` 设定。 |

游戏可用 `fields: { name: (x, z, at) => number }` 加入自己的环境场，并从 `at` 读取内置环境场。规则文件可在 `noise` 中声明额外的
噪声场（`{ "turf": { "scale": 1400, "octaves": 2 } }`），任何条件都可按名称读取。区域可以在其范围内设置任意环境场的值。环境场按需求值：
没有条件读取的环境场不会被计算。

### 群落

群落是环境场上的权重。每个条件是某个环境场的一段区间（`min`、`max`），边缘在 `blend` 范围内衰减；各条件相乘。

- 多个群落同时成立时权重混合：候选点按所在位置的权重选择群落，因此两个群落相接处是一条混合带而不是一条线。`transition` 让边缘按这么多
  世界单位的噪声摆动。
- `paint`（草、土、雪、岩）按群落权重和 `paintStrength` 把地形原有的上色拉向群落的上色。
- 群落列出其配方，每个配方带有所在的布置层和 `density`：占该层候选点的比例。

候选点**先按权重选定一个群落，再取该群落在当前布置层中的配方**。因此群落必须在它要出现的每个布置层中都列出配方；某层没有配方的群落，
选中它的候选点为空。群落权重在重叠处混合群落，但不会让群落变稀；密度由配方的 `density` 和布置层的 `spacing` 决定。

### 配方

配方是一个组：一个**锚点**和围绕它放置的**成员**。`version` 是每个放置物 ID 的一部分；配方放置的内容改变时应将其加一。

| 成员字段 | 说明 |
|---|---|
| `mesh`、`material` | 资源路径或已加载的句柄。也可以用 `plant` 指定规则 `plants` 中的一项。 |
| `count` | 放置数量。 |
| `ring`、`arc` | 离锚点的距离范围，以及允许的角度。 |
| `scale` | 缩放范围。 |
| `footprint` | 它在地面上占据的范围（树干）。 |
| `canopy` | 它在头顶伸展的范围（树冠），与 `footprint` 分开记录。 |
| `attach` | 直立，还是顺着地面倾斜。指定了 `plant` 的成员也遵循它：石头顺着坡面躺放。 |
| `minUp` | 可站立地面的最大陡度。 |
| `waterDepth` | 可站立的最大水深。 |
| `chance` | 被放置的概率。 |
| `tags` | 区域的 `excludes` 可以引用的标签。 |
| `far` | 远景版本：两张十字交叉卡片（针叶树可用帐篷形）所显示的贴图矩形，在所在层的 `lodDistance` 之外绘制。 |
| `interactive` | 使成员成为独立实体（[可交互的放置物](#可交互的放置物与变化)）。 |
| `grounding`、`scaleFootprint` | 建筑的底面贴合（[建筑底面](#建筑底面)）。 |

站不住的成员（没有地面、太陡、在水下、被区域排除、压在先放置的物件上）被省略；组的其余部分照常成立。

### 植物

成员可以是网格加材质，也可以是**植物**：规则 `plants` 中的一项，用于表达网格和材质无法表达的内容。

- `parts`：树干和树冠是两个部件，各有 `mesh`、更省的 `lod1Mesh`、`material`、`texture`、`tint`、是否 `opaque`、`soft`
  （用于代表树冠的卡片：法线朝上偏转的比例，使其像圆润的树冠那样受光，而不是像一块平板），以及 `castShadows`
  （对小到不值得一次阴影图绘制的地被设为 `false`）。
- `lodDistance`：超过该距离换用更省的网格。`drawDistance`：超过该距离不再以本体绘制。
- `far`：远景版本（树的交叉卡片，烘焙到自己的图集上），从 `drawDistance` 绘制到 `farDistance`。

可选的植物字段：

| 字段 | 说明 |
|---|---|
| `tints`、`tintScale` | 植物的几种着色（乘在颜色上的线性系数），以及一片林子跨越的世界单位。每个位置按慢噪声取其中一种，林子里有偏暖和偏冷的片区，而不会出现杂点。 |
| `farKeep` | 远景版本绘制的植物比例（大于 0 到 1，默认 1）。其余的不绘制，保留的放大以维持覆盖。没有卡片的植物可以把更省的网格作为 `far` 并以此稀疏化。远景版本按格子铺设，格子宽度取所有远景版本中最短显示距离所允许的值（最多八个区块），因此远处的地被每格只需几次绘制，而不是每个区块几次。 |
| `sink` | 沉入地面的深度，世界单位（石头埋在土里的底面）。 |
| `unit` | 每个网格单位对应的世界单位：按米建模的植物放在以厘米为单位的世界中为 100。此时配方的 `scale` 是相对于模型的大小。 |

植物由与[手摆植物](/docs/zh-cn/graphics/foliage/#手摆植物)相同的机制按格子生长：区块立即出现，在随后几帧中逐步填满，每个网格占用帧预算中的
几毫秒。远景版本自成一层，铺设到其中最远者所及之处，在超出各自种类本体绘制距离时显示。因此布置层的 `drawDistance` 是其植物以本体绘制的距离，
而不是世界的可见距离。建在有限面积地形上的世界在地形边缘结束。

### 布置层

布置层按顺序逐遍执行，先放大物件。

- 每层在间距为 `spacing` 的网格中每格取一个抖动后的候选点，并赋予随机优先级。
- 两个候选点的组会重叠时，优先级高的成立。
- 每个候选点都避开前面各层的占地，因此蕨类不会长穿树干，石头不会嵌进巨石。
- 布置层以 `chunkSize` 大小的区块发布，直到 `drawDistance`。
- `occupies: false` 使后续布置层可以与之重叠（地被）。
- `farSpacing`（默认 1）让该层植物的远景版本按更大的间距规划。远景只保留四分之一植物的地被设为 2，只需计算四分之一的候选点。

## 区域

区域（`WorldZone` 组件）是手工规划的一块地方：家园、道路、着陆点、建筑占地、保留的视野。它跟随所在实体的位置和绕竖直轴的旋转。

| 字段 | 默认 | 说明 |
|---|---|---|
| `kind` | `reserve` | 区域的用途，用游戏自己的术语（家园、道路、着陆点、建筑、资源、视野）。 |
| `shape` | `Circle` | `Circle` 或 `Box`。编辑器绘制其轮廓。 |
| `radius` | `10` | 圆的半径，世界单位。 |
| `sizeX`、`sizeZ` | `20`、`20` | 盒体沿自身 x、z 的尺寸；盒体随实体绕竖直轴旋转。 |
| `falloff` | `4` | 轮廓外逐渐消失的范围，世界单位：被排除的内容在此范围内变稀，而不是停在一条线上。 |
| `priority` | `0` | 区域重叠时，优先级高的决定群落。 |
| `excludes` | `*` | 排除内容的标签，逗号分隔：布置层、配方、配方或成员的标签、`decor`、`interactive`。`*` 表示全部；留空则不排除任何内容。 |
| `biome` | `''` | 在区域范围内强制的群落；留空则不强制。 |
| `flatten` | `false` | 把区域下方的地形压平到中心处的地面高度，在 `falloff` 内平滑过渡：一块可供建造的地基。代码中 `flatten` 为世界高度或 `'ground'`。 |

![World Zone 的 Details：类型、形状、半径、衰减、优先级、排除、群落和压平](@/assets/guides/zh/details-worldzone.png)

*一个 **World Zone**：一个圆，告诉生成器在其中生长哪种群落。*

游戏在规划时和玩家建造时添加区域：

```ts
const gens = app.getResource(WorldGenRes);
gens.zones().set({ id: 'house 1', kind: 'building', shape: { type: 'rect', x, z, halfX: 40, halfZ: 30, yaw },
    falloff: 12, priority: 20, excludes: ['*'] });
```

只有区域触及的区块会重新生成，每个区块的旧版本保留到新版本替换为止。

- **身份。** 场景中编排的区域以场景名称和文档实体 ID 作为身份，因此以相同种子重新加载同一场景时，衰减分布保持一致。插件会在场景加载前
  启用场景来源记录。游戏代码创建的实体使用运行时身份；需要跨重载保持区域时，使用 `gens.zones(world).set()` 并提供稳定的 `id`。
- **共享。** 同名世界的生成器共享区域，并各自接收变化。实体消失或该世界的最后一个生成器退出时，编排区域的投影被移除。代码添加的区域和
  `PlacementDiffs` 保留给后续生成器使用；地形压平和群落上色随最后一个活动使用者释放。
- **监听。** `zones.subscribe(listener)` 和 `diffs.subscribe(listener)` 用于监听变化而不替换其他使用者；调用返回的函数即停止监听。

## 建筑底面

直立的配方成员可以设置 `grounding: { size: [宽, 深], samples: 5, mode: 'highest', maxRelief: 2 }`。

- `size` 以模型单位计。先应用旋转和缩放，再对角点、边缘和内部采样。`samples`（网格边长）可取 3、5、7 或 9。
- 每个采样点都必须有地面并满足 `minUp` 和 `waterDepth`。`maxRelief` 以世界单位拒绝过大的高差。
- `mode` 选择底面高度：`highest`（默认）、`lowest`、`mean` 或 `center`；之后加上以缩放后模型单位计的 `offset`。
- `Placement.grounding` 给出高度范围、支撑深度和埋入深度。

这是有限网格的支撑检测，不会压平地形：应使用足以覆盖允许高差的地基，或对编排的场地使用带压平的 `WorldZone`。

避让范围始终包含整个贴合后的底面。`scaleFootprint: true` 把 `footprint` 和 `canopy` 也视为模型单位半径；不设置时它们以世界单位计。
规划器在确定缩放和底面高度后再解决重叠。`stats` 和 `explain` 在坡度、水、区域和重叠之外报告 `relief` 拒绝。世界规则编辑器提供这些设置。

## 道路

```ts
import { setRoad } from 'esengine/worldgen';
setRoad(gens.zones('valley'), {
  id: 'camp-trail', points: [[0, 0], [40, -20], [80, -10]],
  width: 6, clearance: 2, falloff: 3, excludes: ['tree', 'grass', 'building'],
});
```

- `roadZones(options)` 返回可序列化的矩形和圆形区域，转弯连续，端点为圆头。
- `setRoad(zones, options)` 替换一条道路的预留并移除过时的段；`removeRoad(zones, id)` 释放它们。
- `points` 为世界 `[x, z]` 坐标对（2D 世界中为 `[x, y]`）。重复第一个点即闭合成环。`width` 为路面宽度；`clearance` 在两侧、
  柔和的 `falloff` 边缘之前额外留出空间。

这些函数只预留空间；道路网格和整地另行处理。把建筑层放在森林层之前，树木即会避开建筑占地；为 `Foliage` 编排的建筑地面和入口用 `WorldZone` 预留。

## 可交互的放置物与变化

带 `interactive`（`'ore'`、`'tree'`）的成员成为独立实体，带有记录放置 ID 和类型的 `PlacedObject`。其他成员为装饰。
`gens.objectOf(id)` 返回某个放置物的实体。

ID 由布置层、网格单元、配方和成员及其版本组成（`groups@1:12,-3/grove@1/pine.2`），从不使用列表中的序号。它不随区块生成的顺序变化，
之后新增布置层或配方时也不变。

玩家的改动与生成的世界分开保存，并在显示任何内容之前叠加上去：

```ts
gens.diffs().remove(id);                  // 砍倒、开采：永久消失
gens.diffs().change(id, { yaw: 1.2 });    // 移动、旋转、缩放
save(gens.diffs().toJSON());              // 存档保存的内容
gens.diffs().load(saved);                 // 以及读回
```

砍倒的树在其区块被释放并重新生成后、以及存档读回后都保持砍倒。玩家建造的建筑属于游戏自身；建筑预留的区域使生成避开其地面。

## 规划查询

`gens.plan()` 可回答任意位置，无论是否已加载，结果与发布的内容一致。服务器、小地图和放置检查读取的就是它。

| 方法 | 返回 |
|---|---|
| `placementsIn(x0, z0, x1, z1, layers?)` | 组锚点位于该矩形内的所有放置物。 |
| `biomeAt(x, z)` | 该位置的群落。 |
| `biomeWeights(x, z)` | 该位置每个群落的权重。 |
| `explain(x, z)` | 决定该处内容的全部因素：环境场、群落、区域，以及每层在该格的候选点及其被拒绝的原因（`noBiome`、`density`、`noGround`、`slope`、`water`、`relief`、`zone`、`occupied`、`conflict`）。 |
| `stats(layer, x0, z0, x1, z1)` | 成立的候选点数，以及按原因统计的被拒绝数。 |

## 打包

`.esworld` 文件像材质一样被跟踪：它引用的网格和材质随引用它的场景一起打包。从代码注册的规则所引用的资源不被任何场景引用，打包时会被省略；
应在 `.esengine/asset-groups.json` 中把它们所在的文件夹声明为始终包含：

```json
{ "version": "1.0", "groups": { "recipes": { "folder": "assets/models", "mode": "local", "alwaysInclude": true } } }
```

## 2D 世界

同一套规则可以布置 2D 世界：没有地形，规划按 **x 和 y** 平面读取，结果以区块形式围绕相机发布。引擎不绘制任何内容；游戏的 `publish`
回调决定放置物的外观（精灵、预制体）以及地面的绘制方式（瓦片层、着色器）。

```typescript
import { registerWorldRules, createWorld2D } from 'esengine/worldgen';

registerWorldRules(rules);                        // 群落、配方和布置层，与上文相同
const world = createWorld2D(app, 'island', {
    rules: rules.id, seed: 11, chunkSize: 512, cellSize: 32,
    publish(chunk) {
        // chunk.placements：这里有什么（id、recipe、member、biome、x、y、scale、interactive、footprint……）
        // chunk.biomeGrid：地面每个格子的群落，是 chunk.biomes 的下标
        const spawned = spawnTilesAndSprites(chunk);
        return () => despawn(spawned);            // 撤掉这个区块
    },
});

world.diffs.remove(tree.id);                      // 砍倒：只重新生成那个区块，并保持砍倒
```

- **区块跟随相机**（或流送源），在帧预算内由近到远生成，超出 `unloadRadius` 后释放。该世界是 `'xy'` 平面上的 `ProceduralChunks` 层，
  因此任意大小的世界同时存在的区块数都有上限。
- **与顺序无关。** 区块只取决于种子、规则和位置，因此早生成或晚生成的相邻区块结果一致，服务器与客户端一致，放置物 ID 在多次加载间稳定。
  一个组（锚点及其成员）属于其锚点所在的区块。
- **玩家改动**是一个 `PlacementDiffs`，在区块显示前叠加到规划上；`diffs.toJSON()` 和 `diffs.load()` 即为存档。
- **区域**：`z` 为世界 y 的 `ZoneDef` 让一片区域保持空旷或固定为某个群落（玩家搭建的营地）。
- 配方的 `ring` 以世界单位计，`arc` 为从 +x 转向 +y 的角度。`mesh`、`material`、`attach` 和 `minUp` 是 3D 属性，不被读取。

## 限制

- **装饰不按放置物实例化。** 植物部件使用共享几何和逐实例的细节层级。指定网格和材质的成员在每个区块中按网格和材质合并：渲染器的实例记录
  每帧重写，成千上万个物件每帧要上传数兆字节，而合并的静态网格不上传任何内容，内存由区块限定。
- **游戏自定义的环境场是代码。** 规则文件使用内置环境场和区域设置的环境场；由游戏计算的环境场需随规则从代码注册。

参见 **Generated World** 示例（`examples/worldgen`）。
