项目由场景组织。所有已加载的场景共享同一个 ECS 世界。**`SceneManager`** 资源负责加载、切换与卸载场景，记录每个实体归属的场景，并且只在场景处于活动状态时运行该场景的系统。

`sceneManagerPlugin` 提供 `SceneManager` 与 `SceneStreaming` 资源，在启动时加载初始场景，并在每帧推进过渡与流送。默认的应用引导流程已注册该插件；由单个插件自行组装的 `App` 需显式添加。

## 切换场景

`switchTo` 替换当前活动场景。该调用为异步，在切换（含过渡）完成后兑现。

```typescript
import { defineSystem, Res, SceneManager } from 'esengine';

const goToLevel2 = defineSystem([Res(SceneManager)], async (scenes) => {
  await scenes.switchTo('level2');
});
```

`reload(options?)` 从文件重新切换到当前活动场景。以正在运行的场景名调用 `switchTo` 不执行任何操作；重新开始、重试等场合应使用 `reload`。

## 过渡

`switchTo`、`reload` 与 `unload` 接受 `TransitionOptions`。

| 选项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `transition` | `'none' \| 'fade'` | `'none'` | 直接切换，或经 `color` 淡入淡出。 |
| `duration` | number | `0.3` | 淡入淡出总时长（秒）：一半淡出、一半淡入（`RuntimeConfig.sceneTransitionDuration`）。 |
| `color` | `Color` | 不透明黑色 | 遮罩颜色（`RuntimeConfig.sceneTransitionColor`；构建配置中为十六进制字符串）。 |
| `onStart` / `onComplete` | 回调 | — | 淡出开始时 / 淡入结束后调用。 |
| `keepPersistent` | boolean | `true` | 卸载时保留[持久化实体](#持久化实体)。设为 `false` 时它们随场景其余部分一并销毁。 |
| `staggered` | boolean | `false` | 经场景的退役流程分多帧卸载：立即隐藏，在帧预算内销毁，随后释放资源。同名场景的加载会等待其完成。 |

淡入淡出分三个阶段：

1. 遮罩在 `duration` 的前一半内渐变至不透明。
2. 旧场景卸载、新场景加载期间遮罩保持不透明。加载较慢时该阶段相应延长。
3. 遮罩在 `duration` 的后一半内渐变回透明。

返回的 Promise 在淡入完成后兑现，加载失败时拒绝。切换进行中再次调用 `switchTo` 会被忽略并输出警告；`isTransitioning()` 返回是否有过渡正在进行。

加载在提交前被取代时——被 `unload` 或同一场景的另一次加载抢先——Promise 以 **`SceneLoadCancelled`** 拒绝，而不会提交只加载了一部分的场景。它表示竞争，而非失败；在 `catch` 中应与加载错误分开处理。

### `transitionTo`

`transitionTo(host, scene, config)` 以 `TransitionConfig`（`type: 'fade'`、`duration`、可选 `color`）描述的淡入淡出执行一次 `switchTo`。`host` 为 `App`（引导代码、菜单处理函数），或系统内通过 `Res(SceneManager)` 获得的 `SceneManager` 资源状态。

```typescript
import { transitionTo, type TransitionConfig } from 'esengine';

const fadeToBlack: TransitionConfig = {
  type: 'fade',
  duration: 0.5,
  color: { r: 0, g: 0, b: 0, a: 1 },
};

async function onPlayClicked() {
  await transitionTo(app, 'levels/level1', fadeToBlack);
}
```

`examples/scene-flow` 通过 `SceneManager` 在一个菜单与两个关卡之间循环切换，每次切换使用不同的淡入淡出。

## 叠加场景

`loadAdditive` 在已加载场景之上加载一个场景，不卸载已有场景——HUD、暂停菜单、流送区域等。它接受可选的进度回调，兑现为该场景的 `SceneContext`。

```typescript
await scenes.loadAdditive('pause-menu', (loaded, total) => { /* progress */ });
// …
await scenes.unload('pause-menu');
```

## 归属与系统门控

场景拥有的每个实体都带有记录该场景名的 `SceneOwner` 组件。实体从场景文件加载、通过 `ctx.spawn()` 生成或通过 `ctx.adopt(entity)` 收养时即归该场景所有。卸载场景会销毁其拥有的实体。

- 在任何场景上下文之外创建的实体没有归属，任何卸载都不会移除它。`ctx.adopt(entity)` 将其交给一个场景。
- 运行时实例化的预制体默认由当前活动场景收养（[预制体](/docs/zh-cn/world/prefabs/#instantiate-参考)）。
- 场景声明的系统只在该场景处于活动状态时运行，因此叠加的 HUD 与游戏场景各自独立更新。

代码定义的场景在 `setup(ctx)` 中获得其上下文。其他位置可通过 `getScene(name)` 获取已加载场景的上下文。

场景管理器为每个实例提供独立的 `ctx.signal`。把它传给 `fetch(url, { signal: ctx.signal })` 等异步操作，场景卸载、初始化失败或世界重置时即可取消这些操作。场景暂停或休眠期间，信号保持有效。

预加载场景可以提前读取 2D 或 3D 物理模块。第一个实际加入世界并需要该求解器的场景负责安装，也由它决定重力等世界设置。丢弃预加载会立即释放它已取得的场景资源，其他等待同一模块的场景可以继续共用这次读取。

## 持久化实体

切换会销毁旧场景拥有的实体。`setPersistent` 将实体标记为在其场景卸载时保留——玩家、音乐源、相机等：

```typescript
import { defineSystem, Res, SceneManager } from 'esengine';

const keepPlayer = defineSystem([Res(SceneManager)], (scenes) => {
  const ctx = scenes.getScene(scenes.getActive()!);
  ctx?.setPersistent(player, true);
});
```

该标记存储在 `SceneOwner` 上，因此只对场景拥有的实体生效。`SceneOwner` 是引擎内部组件，不在项目组件 schema 中；检视器中没有对应字段，编辑器中放置的实体需在运行时由代码标记为持久化。

卸载时，持久化实体被保留并**提升为全局**：`SceneOwner.scene` 被设为 `''`，即"始终活动"的值。受场景门控的使用方——相机渲染过滤、系统门控与绘制回调门控——因此继续将其视为活动。在 `switchTo` 或 `unload` 上传入 `keepPersistent: false` 会连同持久化实体一并销毁。

提升后的实体保留：

- **其资源。** 提升会拆分场景的资源引用；实体持有其绘制所用的资源，并在被销毁时（包括作为父级子树的一部分被销毁时）释放。纹理、材质、字体、网格或环境保持为实体所绑定的那个实例，即使热更新已替换了文件。动画片段、时间线、状态机、行为树或动画控制器以名称引用并在每帧查找，因此实体跟随该条目的更新。
- **其屏幕位置。** 与未保留的父级脱离的实体保持其世界位置。

不随之保留的：

- **场景的系统。** 场景声明的所有系统在卸载时注销。持久化实体的行为必须来自注册在 `App` 上的系统。
- **未声明的资源。** 提升读取组件声明的 `assetFields`。手动加载且未经声明字段赋值的资源不会被追踪；需持有生命周期长于场景的引用（在引导时 `Assets.preload`，或使用永不卸载的叠加场景）。
- **非持久化的子实体。** 持久化作用于实体本身，而非其子树。未标记的子实体随场景销毁；非持久化父级下的持久化子实体被脱离并单独保留。

不需要实体存活的游戏状态（分数、背包、任务标记）应使用[存档](/docs/zh-cn/scripting/save/)。

## 场景流送

**`SceneStreaming`** 资源围绕焦点加载与卸载**单元**——放置在世界空间中的叠加场景：

```typescript
import { defineSystem, Res, SceneStreaming } from 'esengine';

const setupStreaming = defineSystem([Res(SceneStreaming)], (streaming) => {
  streaming.configure({ loadRadius: 1200, unloadRadius: 1600 });
  streaming.register({ scene: 'cells/forest',  x: 0,    y: 0, radius: 800 });
  streaming.register({ scene: 'cells/village', x: 1500, y: 0, radius: 800 });
  streaming.setFocusEntity(player);          // or setFocus(x, y) each frame
});
```

- 每帧，距焦点在 `loadRadius` 以内的单元以叠加方式加载，超出 `unloadRadius` 的单元卸载。两个半径之间的间隔构成迟滞，避免在边界处反复加载。
- 距离以**单元边缘**计算（中心距离减去 `radius`），因此大单元在其中心仍很远时就开始加载。
- `policy: 'sleep'` 时，超出范围的单元进入休眠而不卸载：其实体保留在内存中，被禁用并隐藏；重新进入时立即恢复，代价是内存占用。
- 加载或卸载正在进行的单元不会被重复发起。加载完成时焦点已离开的单元会被再次释放。
- 单元场景是按名称引用的普通项目场景（[构建中的场景](#构建中的场景)）。

该资源是一个 `SceneStreamingController`，它编排 `SceneManager` 的基本操作（`loadAdditive`、`unload`、`sleep`、`wake`），自身不执行加载。未注册任何单元时，`update()` 不执行任何操作。

| `SceneStreamingController` | 说明 |
|---|---|
| `configure({ loadRadius, unloadRadius, policy? })` | 设置半径（`unloadRadius` 至少取 `loadRadius`）与超出范围时的策略：`'unload'`（默认）或 `'sleep'`。 |
| `register(cell)` / `unregister(scene)` / `clear()` | 管理单元集合；单元为 `{ scene, x, y, z?, radius }`。 |
| `setFocus(x, y, z?)` | 设置焦点（每帧调用）。距离按三维计算；`z` 与单元的 `z` 默认为 0。 |
| `setFocusEntity(entity)` / `getFocusEntity()` | 跟随实体；流送系统每帧读取其 `Transform`（仅播放模式）。 |
| `getActive()` | 当前处于范围内的场景名。 |
| `update()` | 根据焦点协调驻留单元。`sceneManagerPlugin` 每帧调用。 |

阈值计算以纯函数 `computeStreaming(cells, focusX, focusY, loadRadius, unloadRadius, active)` 导出，用于测试与自定义调度。由流送单元构建的大型世界见[世界流送](/docs/zh-cn/world/streaming/)。

## 构建中的场景

项目场景文件夹中的每个场景都会被导出，并注册为 `switchTo` 目标。场景的**名称**是其相对场景文件夹的路径，不含 `.esscene` 扩展名：`assets/scenes/levels/boss.esscene` 对应 `switchTo('levels/boss')`。启动场景预先加载；其他场景在首次加载时才获取，不增加初始下载量。编辑器中的播放注册同一组场景：入口场景，以及按路径延迟加载的其余所有场景文件。

在打包对话框的**构建场景**列表中取消勾选的场景不会被导出，但仍可在编辑器中编辑与播放。试玩广告构建只包含启动场景。见[构建与导出](/docs/zh-cn/publishing/overview/)。
## `SceneManager` 参考

| 方法 | 说明 |
|---|---|
| `switchTo(name, options?)` | 替换活动场景（异步；可选过渡）。 |
| `reload(options?)` | 从文件重新切换到活动场景（异步；可选过渡）。 |
| `loadAdditive(name, onProgress?)` | 在已加载场景之上加载一个场景；兑现为其上下文（异步）。 |
| `unload(name, options?)` | 卸载场景（异步；可选过渡）。 |
| `getScene(name)` | 已加载场景的 `SceneContext`（`spawn` / `adopt` / `despawn` / `setPersistent` / 绘制回调 / 后处理绑定），或 `null`。 |
| `getActive()` | 活动场景名，或 `null`。 |
| `getActiveScenes()` | 所有活动场景名，包括叠加场景。 |
| `pause(name)` / `resume(name)` | 暂停 / 恢复已加载场景的更新。 |
| `sleep(name)` / `wake(name)` | 暂停**并隐藏**场景的实体；实体保留在内存中，唤醒时立即恢复。 |
| `isLoaded(name)` / `isActive(name)` | 场景是否已加载 / 是否活动。 |
| `isPaused(name)` / `isSleeping(name)` | 上述暂停状态。 |
| `isTransitioning()` | 过渡进行中时为 `true`。 |

## 序列化与迁移

`SceneData` 是纯 JSON，编辑器与运行时读写它所用的函数均已导出。典型用途：保存实时世界的快照（比[存档 API](/docs/zh-cn/scripting/save/) 包含更多内容的检查点）、加载玩家生成或下载的场景，以及序列化状态无法放入普通字段的组件。

| 函数 | 说明 |
|---|---|
| `serializeScene(world, name?)` | 从实时世界生成 `SceneData`。层级写入每条实体记录的 `parent` / `children` 字段。由系统重新派生的仅运行时投影实体（瓦片碰撞体等）不包含在内。 |
| `loadSceneWithAssets(world, data, options?)` | 预加载所有引用的资源后生成实体（异步）。 |
| `loadSceneData(world, data)` | 同步生成实体，不解析资源。 |
| `findEntityByName(world, name)` | 按名称查找已生成的实体。 |

两个加载函数都返回从序列化实体 id 到实时实体的映射。

```typescript
import { defineSystem, GetWorld, Res, Assets, serializeScene,
         loadSceneWithAssets, findEntityByName, MissingAssetsError } from 'esengine';

const checkpoint = defineSystem([GetWorld(), Res(Assets)], async (world, assets) => {
  // Save: snapshot the live world as scene JSON.
  const data = serializeScene(world, 'checkpoint');
  localStorage.setItem('checkpoint', JSON.stringify(data));

  // Load: preload assets, then spawn. Older formats are migrated automatically.
  try {
    await loadSceneWithAssets(world, JSON.parse(localStorage.getItem('checkpoint')!), {
      assets,
      abortOnMissingAssets: true,        // throw instead of spawning with missing assets
      onMissingAssets: (missing) => {    // called once per load (the list may be empty)
        for (const m of missing) console.warn(`${m.ref}: ${m.reason}`);
      },
    });
  } catch (e) {
    if (e instanceof MissingAssetsError) { /* e.missing lists the missing assets */ }
  }

  const player = findEntityByName(world, 'Player');
});
```

### `SceneLoadOptions`

| 选项 | 说明 |
|---|---|
| `assets` | `Assets` 资源。启用生成前的资源预加载与预制体实例展开。 |
| `assetBaseUrl` | 解析资源路径所用的基础 URL。 |
| `onProgress` | `(loaded, total)` 预加载进度回调。 |
| `onMissingAssets` | 以所有解析或加载失败的引用调用一次（`MissingAsset[]`：`ref`、可选 `type`、`reason: 'unresolved' \| 'load-failed'`）。列表为空时同样调用。 |
| `abortOnMissingAssets` | 默认 `false`：缺失的资源句柄为 `0`，场景照常加载。`true` 时在预加载后、生成任何实体前抛出 `MissingAssetsError`。 |
| `collectAssets` | 加载过程将所获取的资源键加入的集合，供调用方（通常是场景管理器）在卸载时释放。 |

### 格式版本

场景文件带有 `version`；当前格式为 `SCENE_FORMAT_VERSION = 4`。`migrateSceneData(raw)` 将旧数据升级到当前格式：

- 返回迁移后的深拷贝，从不修改输入。
- 幂等。
- 删除引擎升级中已退役的组件类型。
- 拒绝比引擎更新的数据。

所有加载函数都在内部调用它。仅在需要检查 `migrated` / `fromVersion` 时直接调用，例如提示重新保存已升级的文件：

```typescript
import { migrateSceneData } from 'esengine';

const { data, migrated, fromVersion } = migrateSceneData(raw);
if (migrated) console.log(`upgraded scene from format ${fromVersion}`);
```

### 带外组件状态

完整状态无法放入普通字段记录的组件可注册 **`SceneComponentCodec`**，使通用序列化器无需组件专用代码即可携带额外状态。`TilemapLayer` 用它保存位于 C++ 内核中的瓦片分块。

```typescript
import { registerSceneComponentCodec } from 'esengine';

registerSceneComponentCodec('MyVoxelChunk', {
  exportData(entity, data) { data.chunks = myStore.serialize(entity); },
  outOfBandFields: ['chunks'],          // stripped before the component is inserted
  importData(entity, outOfBand) { myStore.restore(entity, outOfBand.chunks); },
});
```

| 编解码器成员 | 作用 |
|---|---|
| `exportData(entity, data)` | 保存时将额外状态写入组件记录。 |
| `outOfBandFields` | 加载时在插入组件前从记录中移除的键。 |
| `importData(entity, outOfBand)` | 加载时在插入组件后接收被移除的字段。 |

注册是幂等的；插件在启动时注册其编解码器。

## `NodeVisibility`

`NodeVisibility.visible` 是作用于子树的可动画可见性开关。设为 `false` 时，实体及其子孙上每个已注册渲染组件的渲染标志被屏蔽；恢复为 `true` 时还原创作时的值。开关关闭期间，场景序列化写入的是创作时的值。子树中的相机、物理刚体与玩法实体保持活动。

粒子发射器被屏蔽的标志是 `enabled`，因此隐藏子树也会停止其中的发射器。需要持续运行的发射器应放在被隐藏的子树之外。
