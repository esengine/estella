世界流送在 cook 时把编排好的世界切成方形格子。运行时，有流送源靠近时格子存在，没有流送源靠近时格子被销毁。卸载的格子不是被隐藏：
它的实体、物理刚体、导航代理和资源引用全部释放，因此未加载的地方不占内存、不参与碰撞，也不运行任何逻辑。

没有 `StreamedWorld` 的场景不是流送世界，整体加载。

## 声明一个流送世界

流送世界由两个组件声明，均在场景中编排：

```typescript
// 挂在世界设置实体上：这个场景按 1000 单位的格子切分。
world.insert(settings, StreamedWorld, { cellSize: 1000 });

// 挂在任何绝不允许被流送掉的东西上。
world.insert(player, WorldPersistent, {});
world.insert(camera, WorldPersistent, {});
world.insert(sun, WorldPersistent, {});
```

其他实体按其顶层实体的位置归入某个格子。`WorldPersistent` 把实体的整棵子树留在持久世界中，持久世界从不流送。`StreamedWorld`
所在的实体本身就是持久的。

### `StreamedWorld` 字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `cellSize` | `1000` | 一个方形格子的边长，世界单位，位于下方所选平面上。 |
| `plane` | `Ground` | `StreamPlane.Ground` 沿世界 x、z 切分格子（3D 世界）；`StreamPlane.Screen` 沿世界 x、y 切分（2D 世界）。见[格子平面](#格子平面)。 |
| `farProxies` | `false` | 构建时为每个格子烘焙远景代理（[远景代理](#远景代理)）。 |
| `farDistance` | `8000` | 不常驻的格子在距流送源多远以内显示远景代理。 |
| `proxyError` | `1` | 远景代理表面相对原始表面的最大偏移，世界单位。 |
| `proxyRatio` | `0.01` | 远景代理力求保留的最少三角形数，占格子三角形数的比例，取值 (0, 1]。`proxyError` 需要时会保留更多。 |

在编辑器中，**世界设置 → 启用流送**会把 `StreamedWorld` 组件添加到世界设置实体上。

![world-streaming-3d 示例中流送世界的细节面板：Streamed World 卡片](@/assets/guides/zh/world-streaming-settings.png)
<Aside type="note">
`WorldPersistent` 不是场景持久化。`SceneContext.setPersistent` 决定实体能否在场景切换后保留；`WorldPersistent`
决定实体被写入哪一个 cook 后的场景，因而决定常驻系统能否移除它。
</Aside>

## 流送源

有 `WorldStreamingSource` 靠近时，格子存在：

```typescript
world.insert(player, WorldStreamingSource, {
    prefetchRadius: 3000, // 距离在此以内的格子被准备好，但不进入世界
    loadRadius: 2000,     // 距离在此以内的格子被带进世界
    unloadRadius: 3000,   // 已常驻的格子在越过这个距离前一直保留
});
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `prefetchRadius` | `3000` | 最近边缘在此距离以内的格子被准备，但不发布。取值不会小于 `loadRadius`。 |
| `loadRadius` | `2000` | 最近边缘在此距离以内的格子被带进世界。 |
| `unloadRadius` | `3000` | 常驻格子的最近边缘超出此距离后被释放。必须大于 `loadRadius`。 |
| `enabled` | `true` | `false` 把该源从并集中移除，而不移除组件。 |

半径以世界单位计。可以同时存在多个源，它们请求的格子取**并集**，任一源需要的格子都保持常驻。分屏、观战相机、过场相机和
编辑器预览都是同一类源。距离量到格子的包围盒而不是中心点，因此靠近格子角落的源也被视为靠近该格子。

### 预取

位于 `prefetchRadius` 以内的格子会被**准备**：取回文档、展开预制体、获取资源，但不创建任何实体。查询不会返回它，渲染器不绘制它，
刚体不与它碰撞。实体由发布创建，而发布只在某个源进入 `loadRadius` 时发生。在引擎的测试场景中，发布一个已准备的格子耗时 0.6 ms；
未准备的格子还要加上取回和解码的时间。

准备是推测性的。为掉头离开的源准备好的格子会被丢弃并释放资源，不会因为已经准备好而被发布。准备完成时，流送器会再次检查该格子是否仍被需要。

`prefetchRadius` 与 `unloadRadius` 相互独立：前者决定多早开始准备，后者决定常驻格子多晚才释放。

### 加载与卸载带

格子在 `loadRadius` 处发布，越过 `unloadRadius` 后才释放。两者之间的带防止位于格子边界上的源每帧反复加载和卸载该格子。
可以从 `unloadRadius` 为 `loadRadius` 的 1.5 倍开始设置。

### 发布预算

格子分多帧发布。它的实体分批生成、组件分批写入、层级分批连接，使用与烘焙作业、地形分页和程序化区块共用的每帧预算
（`Bakes.budgetMs`，8 ms）。格子到达期间其根实体处于 `Disabled` 状态，因此任何系统、查询、刚体或绘制都看不到不完整的格子；
最后一步整体启用，所有 `Added` 过滤器在该帧看到它的组件。卸载过程相反：格子在被释放的那一帧禁用，在预算内销毁，随后释放资源。

格子的**准备**也按轮次（`Bakes.turn`）分段进行。取回文档和资源不占用帧时间；它们返回后要做的工作（解析文档、展开预制体、
解析资源、准备着色器程序）需等待轮次。每帧按剩余预算能容纳的数量放行轮次，至少一个。紧急的格子，或因清空世界而被加速的格子，
不等待轮次。资源本身的解码（网格、纹理）不做拆分。

清空世界时（`clear()`、停止 Play），正在处理的格子会立即完成并移除。

### 流送策略

流送器的并发数以及跟不上时的处理方式是它的**策略**，通过 `streamer.setPolicy({...})` 设置。帧预算本身属于 `Bakes` 资源，
由所有分帧工作共用。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `Bakes.budgetMs` | 8 | 每帧分给所有分帧工作的毫秒数。 |
| `Bakes.priorityExtraMs` | 12 | 紧急工作（例如流送源所在的格子）尚未到齐时，每帧额外增加的毫秒数。 |
| `maxLoadingCells` | 4 | 同时准备的格子数；其余按距离由近到远排队。紧急格子从不排队。 |
| `maxPublishingCells` | 1 | 同时发布的格子数。紧急格子从不排队。 |
| `slowStreamingRatio` | 0.25 | 流送源与某个需要的格子的距离小于其 `loadRadius` 的这一比例时，该格子为**紧急**格子。 |
| `slowStreaming` | `'wait'` | 紧急格子的处理方式（见下表）。 |

`slowStreaming` 的取值：

| 取值 | 行为 | 取舍 |
|---|---|---|
| `'wait'` | 紧急格子在变为紧急的那一帧完成，并**挂起**游戏（暂停，流送继续进行），直到所有紧急格子到齐。 | 出现卡顿和停顿，但不会露出空洞。 |
| `'publish'` | 紧急格子立即完成，从不挂起游戏。 | 仍在取回的格子在到达前缺失。 |
| `'budget'` | 任何工作都不超出预算；紧急格子只额外获得 `priorityExtraMs`。 | 帧率最平稳；流送跟不上时会露出空洞。 |

挂起是流送器自己持有的暂停。游戏请求的暂停（如菜单）照常停止流送，挂起也不会结束游戏的暂停。准备或发布失败的格子不会挂起游戏。

`maxLoadingCells` 限制同时准备的格子数；超出时先准备最近的格子。值越大，快速移动的视野远端越早到达，轮次之间可分配的工作也越多。

## cook 产物

切分在 cook 时进行：

```
main.esscene ──cook──▶ main.esscene          持久世界
                       world/main.world.json 清单
                       world/main.cell_0_0.json
                       world/main.cell_1_0.json ...
```

每个流送场景在自己的场景文档中保留持久实体。游戏代码指定地图，由常驻系统加载其格子。

- 在编辑器 Play、Web 和原生导出包中，`SceneManager.switchTo(name)` 先释放旧地图的格子和远景代理，再开始流送新地图。切换到菜单时同样会释放。
- `loadAdditive` 叠加一个场景（如 HUD），当前地图继续流送。
- `load(name)` 激活一个已加载的地图。属于该地图的流送源在其激活时开始生效。
- `WorldMemory.toJSON()` 保存当前世界记住的实体；回到之前的世界时恢复该世界自己的记录（[记住的状态](#记住的状态)）。

### 格子平面

格子在一个平面上切分。默认（`StreamPlane.Ground`）为地面，即世界 x 与 z：一个格子是一根竖直柱体，因此一座塔的各层属于同一个地方。
2D 世界位于屏幕平面，所有实体的 z 相同；把 `plane` 设为 **Screen (x, y)**（`StreamPlane.Screen`）后，格子沿世界 x 与 y 切分，
流送源也按 x、y 读取。不设置时，2D 世界会落入沿 x 的一行格子。cook 后的清单以 `WorldManifest.plane: 'xy'` 记录同一选择，
此时格子的 `z` 即世界 y。

## 远景代理

不常驻的格子不在世界中，因此默认情况下加载半径以外不绘制任何内容。在 `StreamedWorld` 上开启 **Far proxies** 后，构建时为每个格子
烘焙一个替身：把格子中静态、不透明的网格按材质合并为每种材质一次绘制并加以简化，在格子不在时显示。

```typescript
world.insert(settings, StreamedWorld, {
    cellSize: 1000,
    farProxies: true,
    farDistance: 8000,   // 离某个流送源这么近、又不常驻的格子显示代理
    proxyError: 1,       // 简化后的表面最多偏离原来多少世界单位
    proxyRatio: 0.01,    // 最少保留的三角形比例；proxyError 需要时会多留
});
```

- cook 在格子旁写出 `world/<cell>.far.json` 及其网格，并在清单中登记（`WorldCell.proxy`，以及 `WorldManifest.farDistance`）。
- 预制体实例会被展开，因此以预制体放置的建筑也会贡献网格。
- 以下表面不进入代理：禁用的、混合的、蒙皮的、公告板，以及自身或父节点会自行移动的表面（角色控制器、非静态刚体、动画器）。
  由游戏代码移动但不带上述组件的网格会按其当前位置烘焙：给它或其上层实体添加 `ExcludeFromFarProxy`，该子树即不进入代理。
  格子常驻时该子树照常绘制。
- `proxyError` 决定格子的简化程度。应使其小于代理开始显示的距离（流送源加载半径以外）上一个像素的大小。
- 只有颜色不同的表面共用一次绘制，颜色存于顶点。代理不带光照贴图 UV。

两个方向的交接都没有空档：接近格子时，代理保留到格子常驻；离开时，格子保留到代理加载完成。代理加载失败不会阻止格子释放。
`WorldStreamerStatus.proxyCells` 和常驻报告列出当前由代理绘制的格子。

Play 用与构建相同的格子和相同的简化代码生成同样的代理，并保存在内存中。每个代理在流送器首次请求时生成。

在 `far-proxy-town` 示例中（144 个格子，静态网格共 310 万个三角形，`proxyError` 为 0.5）的测量结果：

| 测量项 | 数值 |
|---|---|
| 代理保留的三角形 | 2% |
| 沿示例飞行路线的一帧 | 12.2 万个三角形，354 次绘制 |
| 城镇全部加载 | 86.6 万个三角形，620 次绘制 |
| 明显不同的像素 | 0.3% |
| Play 启动（标出哪些格子有代理） | 172 ms |
| Play 中生成一个代理 | 约 30 ms，最多 190 ms |

编辑器**世界**面板在**地图**和**列表**之外还有 **HLOD** 视图，列出每个格子的代理及其原始面数、减面后面数和构建状态。
## 流送内容的规则

**子树是常驻的单位。** 只有顶层实体参与定位，因此即使门的世界坐标落在相邻格子中，门也不会与其所属的房屋分开。格子的包围盒会扩展以
覆盖其内容，悬出边缘的道具不会在边界处突然出现。

**硬实体引用不能跨越常驻边界。** 同一格子中的两个实体可以相互引用，持久世界中的实体之间也可以；格子可以引用比它存活更久的持久世界。
从一个格子指向另一个格子、或从持久世界指向格子内部的引用会导致构建失败，因为它指向常驻系统可能删除的实体。

**常驻系统决定存在，延续需要显式声明。** 卸载的格子会丢失运行时状态，重新加载时按编排内容重建：受伤的敌人回来时是满血的。

### 记住的状态

`RememberState` 让实体在其格子卸载时保持离开时的状态：

```typescript
world.insert(enemy, RememberState, {});                     // 记住血量和位置
world.insert(chest, RememberState, { keepTransform: false }); // 开过的宝箱保持打开
```

- 被记住的实体随格子卸载时，其游戏组件（项目自己定义的组件，如 `Health` 或宝箱的 `opened` 标记）和 `Transform` 按其编排 id 记录。
  `keepTransform: false` 时不记录 `Transform`。
- 格子再次加载时，在生成任何内容之前先修改其文档，因此实体以离开时的状态出现，不会有一帧以编排状态出现。
- 格子常驻期间被销毁的被记住实体（被击败的首领、被采完的矿、被拆除的建筑）连同其子树记录为已消失，格子不会再把它带回。
- 引擎自身的组件不保留：它们持有资源句柄和格子会自行重建的状态。
- 运行时生成的实体没有编排 id，不会被记住。

记忆保存在 `WorldMemoryRes` 资源中。通过[存档槽](/docs/zh-cn/scripting/save/)带入存档：

```typescript
const saves = new SaveManager({ version: 1 });
const memory = app.getResource(WorldMemoryRes);
saves.save('slot1', { player, world: memory.toJSON() });   // 存档时
const loaded = saves.load<{ world: WorldMemoryData }>('slot1');
if (loaded) memory.read(loaded.world);                     // 读档时，在世界流入之前
```

`read` 替换存档中所指世界的记忆，每个格子在下次加载时读取。`clear()` 清空所有已访问世界的记忆，用于开始新游戏。

## 程序化区块

游戏在运行时生成的内容（运动物体周围的地面碰撞、视点周围的植物、游戏自行生成的内容）不是 cook 出来的格子，而是某个**层**的区块。
`ProceduralChunks` 管理区块的生命周期，如同流送器管理格子。层定义自身的切分方式、在其源周围多远内需要，以及单个区块如何生成、发布和释放：

```typescript
import { chunksOf } from 'esengine';

chunksOf(app).set('ruins', {
    label: 'Placing ruins',
    originX: 0, originZ: 0, sizeX: 64, sizeZ: 64, extent: null,
    loadRadius: 256, unloadRadius: 320,
    generation: `${planet}:${generatorVersion}`,     // 区块由什么生成
    make: (cx, cz, signal) => generateRuins(cx, cz, signal), // 一个值、表示"还不行"的 null，或一个 Promise
    publish: (cx, cz, ruins) => spawnRuins(ruins),
    release: (cx, cz, ruins) => despawnRuins(ruins),
});
```

- **源。** 层围绕流送器读取的同一组 `WorldStreamingSource`（没有时为视点）被需要，除非它提供自己的 `sources()`。例如地形碰撞跟随每个
  运动的 3D 刚体和角色。
- **平面。** 层默认在地面（世界 x 与 z）上切分。设置 `plane: 'xy'` 后沿世界 x 与 y 切分，源也按此读取；层中所有称为 "z" 的量
  （`originZ`、`sizeZ`、区块的 `cz`、`stateAt` 的第二个坐标）此时表示世界 y。层自己的 `sources()` 本就按层所在平面返回。
- **预算。** 每帧按由近到远的顺序生成所有层需要的区块：源所在的区块立即生成，其余在本帧预算内生成。预算为 `Bakes.budgetMs`，
  与烘焙作业和地形分页共用。
- **上限。** 超出所有源 `unloadRadius` 的区块连同其发布的内容一起释放，因此存活区块数有上限；在带内来回移动不会重新生成区块。
- **代次。** `generation` 标识层的输入。它变化时所有区块重新生成，旧版本保持发布直到被新版本替换，站在上面的东西不会掉落。
  属于旧代次的结果被丢弃，该区块的 `AbortSignal` 被中止。
- **状态。** `status(id)` 统计层的区块（`ready`、`stale`、`pending`、`making`、`failed`，以及第一个失败的原因），`stateAt(id, x, z)`
  返回某点所在区块的状态。仍在生成区块的层会与烘焙作业一起，带进度显示在编辑器状态栏中。

## 常驻报告

```typescript
const report = worldResidencyReport(app);
report.residentCells;        // ['main.cell_1_0', 'main.cell_2_0']
report.cellEntityCounts;     // 每个常驻格子当前拥有的实体数
report.loadCount;            // 启动以来带进来过多少个地方
```

报告给出计数而不是画面，因为未绘制的格子与不存在的格子从相机看是一样的。除格子列表（`desiredCells`、`prefetchCells`、
`residentCells`、`preparedCells`、`loadingCells`、`unloadingCells`、`proxyCells`）外，它还报告策略的活动：`urgentCells`、
`queuedCells`、`holding`、`holdCount`、`holdMs` 和 `rushCount`（在预算之外完成的发布次数）。

## 在编辑器中

编辑视图下，地形细节、植被、生成世界和体素围绕视口生成，2D 和 3D 均如此；场景中的 `WorldStreamingSource` 只在游戏运行时生效。

带 `StreamedWorld` 的场景打开时，视图中只有 `WorldPersistent` 实体，其格子的贴图和网格不加载。**世界**面板以地图或列表显示格子，
可逐个或全部加载、卸载；视口标出已加载的格子，下次会话打开时保持相同的加载状态。Play 期间面板显示每个格子的运行时状态（已驻留、
已备好、加载中、卸载中、未加载）。场景文档始终包含全部实体：未加载的格子照常保存，Play 和导出看到的是完整世界。
## 清空或替换世界

先禁用或移除流送源，再等待 `streamer.clear()`。它释放已准备的资源，并等待尚未完成的准备、发布和卸载结束。注册信息保留可用：
之后更新流送源时可以再次请求这些格子。

替换世界时等待 `streamer.loadManifest(manifest, sceneConfig)`。它先清理旧格子再注册新清单，两个清单使用相同格子名称时也如此。
并发替换以最后一次请求为准；显式调用 `clear()` 会取消尚未完成的替换请求。卸载失败时操作被拒绝，防止新世界接管仍有内容存活的名称。
`await streamer.loadManifest(null)` 卸载当前世界并释放其格子和代理的注册信息。

## 限制

- **单个组件的写入不拆分。** 仅组件写入就超出预算的单个实体仍会占用该帧。
- **远景代理只包含静态网格。** 会移动的、混合的或不是网格的内容（精灵、粒子、灯光）在格子不在时不绘制；代理只有一级，没有逐级变粗的多级代理。
- **自带远景表示的内容：** 地面（[地形](/docs/zh-cn/graphics/terrain/overview/)是按距离划分的四叉树，绘制到 `drawDistance`；
  分块地面的远处由常驻内存的概览绘制，只在视野附近读入全精度分块；星球一直绘制到地平线），以及植物（[植被](/docs/zh-cn/graphics/foliage/)
  和 `PlacedFoliage` 的远景卡片，以及生成世界中植物的远景版本），它们一次覆盖整片区域。网格纹理按视图需要的尺寸保留
  （[纹理流送](/docs/zh-cn/performance/quality-levels/texture-streaming/)，一项画质设置）。
- **导航**按格子方块逐块烘焙并跟随常驻状态（见[导航](/docs/zh-cn/gameplay/ai/navigation/navmesh/#在流送世界里)），但智能体只在已加载的区域行走。
- **世界原点从不重定基准。** `setRenderOriginStep` 让远离原点处的绘制保持精确（见[相机](/docs/zh-cn/graphics/camera/multiple-cameras/#大世界)）；
  模拟精度的实测见下文。

### 远离原点的精度

位置、物理和导航使用 32 位浮点数，因此可分辨的最小位置步长随离原点的距离增大。以下为在导出包中测得的结果
（`node tools/measure-world-precision.mjs`），采用默认 3D 比例 100 单位等于 1 米，测试物体置于 x 和 z 方向的各个距离上：

| 离原点 | 运动父节点下子节点的最大误差 | 以 300 单位/秒（每帧 5）推动的物体，每步最大误差 | 绕墙的导航路线 |
|---|---|---|---|
| 0 | 0.00002 单位 | 0.0001 | 1216.06，作为基准 |
| 1 km | 0.008 单位（0.08 mm） | 0.008 | 完全相同 |
| 10 km | 0.06 单位（0.6 mm） | 0.06 | 完全相同 |
| 50 km | 0.5 单位（5 mm） | 0.5 | 完全相同 |
| 100 km | 1 单位（1 cm） | 1：每帧移动 4 或 6，而不是 5 | 完全相同 |
| 500 km | 4 单位（4 cm） | 3：每帧 2 到 8 | 拐角偏移 2 单位 |

离原点约 **10 km** 以内，误差均不超过 1 毫米。超过约 **50 km** 时，慢速运动会出现可见的阶跃：每帧移动量小于该处位置步长的物体无法平滑移动
（在 100 km 处，每帧移动几厘米的步行会抖动约三分之一）。世界的可玩区域应保持在离原点约 50 km 以内；玩家走得更远时，引擎不会随之移动原点。
