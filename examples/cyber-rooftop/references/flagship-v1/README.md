## 建模与接入

1. 优先使用 Tripo 的多视图输入，每个任务只生成一个资产。若界面只支持单图输入，应先准备独立的单视图；不要把三联图误当三个并列物体提交。
2. `asset-manifest.json` 记录尺寸目标、LOD0 三角形目标和任务状态。尺寸是制作目标，图上的楼层数、镜头投影、管线与五金位置必须在三维阶段核对，不能从图片推断为已测量值。塔楼的画面高宽比例与提示词的尺寸并不完全一致，应先统一体块和层高。
3. 正面控制主要造型、材质分区与身份；侧背面用于补足厚度、接口和维护结构。三面冲突时保留记录并修正，不能直接将冲突烘焙进模型。
4. 下载的原始模型先保留为候选。分别检查米制尺度、朝向、UV、法线、浮动碎片、重复面、薄壁、贴图和材质槽。罐体、灯管、管线和栏杆需要有实际厚度；植被不应与支架熔为一体。
5. 主角仍需拓扑整理、骨骼、权重与动作检查。第一人称手套和建造工具需按实际相机距离额外验证，完整人物生成成功不代表手部已通过近景验收。
6. 灯光、屏幕、广告、潮湿与雨雾由运行时材质和效果实现。优先保留可独立控制的发光面；广告图、文字与设备状态不固化为不可编辑的几何细节。
7. 核实 Tripo 当前账户与生成结果的使用／再分发条件后再纳入发布资源。原始候选、整理后的 GLB、可编辑源文件、审查结果与实机证据分别记录。
8. 本地仅用后台 Blender、CLI 与无界面 Chromium 验证；编辑器验收在 CI 进行。图像参考不改变现有 3D 场景、2D HUD 或建造交互的验收状态。

所有 `*-prompt.txt` 保存该参考图的完整制作规格。当前任务是否提交、模型是否下载及是否通过实机验证，以清单中的逐项状态为准。
